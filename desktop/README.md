# Ticklane Linux desktop

기존 Hoga 서버의 React 화면을 여는 Electron 클라이언트다. 로컬 서버와 Tailscale 서버를 선택할 수 있다. 앱을 닫아도 서버의 수집·저장·주문 처리는 계속된다.

## 빠른 실행

로컬 개발 환경의 앱 목록·바탕화면 바로가기는 다음으로 등록한다. 기존 연결 설정을 보존하고 별도 관리자 권한은 사용하지 않는다.

```sh
cd /home/dev/.codex/worktrees/7c78/hoga-ops/desktop
npm run install:shortcut
```

이후 앱 목록에서 **Ticklane**을 검색하거나 바탕화면 아이콘을 실행한다. 터미널에서는 어느 폴더에서든 `ticklane`으로 실행할 수 있다. 현재 워크트리의 Electron 실행기를 사용하고 `~/.config/hoga-ops-local-dev`의 연결 설정을 불러온다. 워크트리를 다른 경로로 옮기면 그 위치에서 바로가기를 다시 등록한다. 로컬 화면·API 서버는 기존 방식으로 실행해 두어야 한다. Ubuntu 샌드박스 초기 설정이 필요한 경우 아래 `setup:sandbox`를 먼저 적용한다.

이름 변경 전의 `hoga-ops-local` 명령도 `ticklane`으로 연결한다. 바로가기 재등록 시 기존 Hoga Ops 바로가기를 정리한다. 기본 Electron 저장 경로는 기존 `~/.config/Hoga Ops`를 유지하며, 로컬 바로가기는 계속 `~/.config/hoga-ops-local-dev`를 사용한다. 서버 환경변수와 설정 파일 형식도 유지한다.

Linux 실행 창은 `ticklane.desktop` 앱 ID로 바로가기의 아이콘과 연결한다. 앱 목록·바탕화면 등록도 같은 파일명을 사용하며, 이전 `ticklane-local.desktop` 바로가기는 재등록 시 정리한다. 실행 후 기본 톱니바퀴 아이콘이 보이면 `npm run install:shortcut` 후 앱을 완전히 종료하고 다시 실행한다.

### 서버와 Electron을 두 개의 아이콘으로 실행

총 두 개의 바로가기를 사용한다. 두 앱 모두 터미널 없이 열린다.

1. **Ticklane 서버**: 실행하면 프론트엔드(5173)와 백엔드(8000)를 자동 준비하고, 관리 창에서 중지·상태·로그를 확인한다.
2. **Ticklane**: 기존 차트·업무 화면을 여는 Electron 앱이다.

두 앱은 아이콘으로 구분한다. **Ticklane**은 기존 사선 틱 아이콘을, **Ticklane 서버**는 두 단의 서버 랙과 연결선 아이콘을 사용한다. 서버 아이콘은 바탕화면·앱 목록·실행 창·관리 창 헤더에 함께 적용된다.

프로젝트의 Python 가상환경과 프론트 의존성이 설치된 PC에서 서버 관리 앱을 등록한다.

```sh
cd desktop
npm run install:server
# 실행할 프로젝트가 다른 체크아웃인 경우
npm run install:server -- --project-root /home/dev/code/hoga-ops
```

바탕화면·앱 목록의 **Ticklane 서버**를 열면 실행 설정을 읽고 두 서버를 자동으로 시작한다. 이미 정상 실행 중인 서버는 재사용하며, 한쪽만 실행 중이면 없는 쪽만 시작한다. 다른 프로그램이 포트를 사용하거나 실행 환경에 문제가 있으면 자동 재시작을 반복하지 않고 오류와 **다시 시도**를 표시한다. 자동 시작은 관리 앱 프로세스가 처음 켜질 때 한 번만 실행하므로, 수동 중지 후 UI 리로드·창 다시 열기·같은 아이콘 재실행은 서버를 다시 켜지 않는다. 관리 앱을 완전히 종료한 뒤 다시 실행하면 자동 시작한다.

두 서버가 준비되면 주 버튼이 **Ticklane 열기**로 바뀐다. 이 버튼은 별도 Ticklane 앱을 열며, 이미 열려 있으면 기존 창을 보여준다. 로컬 바로가기에서 실행한 두 앱은 기존 `~/.config/hoga-ops-local-dev` 연결 설정을 함께 사용한다. 서버 관리 창의 프로필과 인스턴스 잠금은 별도로 유지한다. 관리 창은 현재 상태를 자동 갱신하고 서비스 옆 새로고침 버튼도 제공한다. 같은 서버 아이콘을 다시 실행하면 기존 관리 창을 보여준다.

바로가기는 `Terminal=false`로 등록하므로 관리 창만 열린다. 실행 스크립트를 파일 관리자나 터미널에서 직접 열어도 `setsid`가 있는 Linux에서는 앱을 터미널에서 분리하고 실행 명령을 끝낸다. 로그는 기존 `server-manager-launch.log` 파일에 기록한다.

**서버 중지**는 확인 창을 거쳐 서버와 자식 프로세스를 정상 종료한다. 서비스 행의 **중지…**는 해당 서버만, 외부 실행 서버가 있을 때의 **모두 중지…**는 두 서버를 대상으로 확인한다. 시작 중에는 **시작 취소**로 정리할 수 있다.

이미 다른 곳에서 켜진 서버는 **외부 실행**으로 표시한다. Linux에서 같은 사용자·같은 프로젝트의 hoga/uvicorn 또는 Vite/npm 개발 서버이고 루프백에만 바인딩한 경우, 실행 사용자·PID·경로·명령·프로세스 수를 확인한 뒤 중지할 수 있다. 확인 후에는 실행 정보를 다시 대조하며, PID·기동 시점·실행 파일·경로·명령이 달라졌다면 종료하지 않고 다시 확인하도록 안내한다. uvicorn 재로더와 npm 실행기의 확인된 자식 프로세스도 함께 정상 종료한다. 중지 후 **서버 시작**으로 다시 실행하면 관리 앱이 소유하는 서버가 된다.

다른 프로젝트·사용자의 프로세스, 무관한 프로그램, 공개/LAN/Tailscale 바인딩 서버, systemd 서비스 또는 실행 정보를 확인할 수 없는 대상은 중지하지 않고 이유를 표시한다. 전체 중지에서 일부 대상만 확인되면 중지 불가 대상을 함께 표시하고 **확인된 서버 중지**로 확인된 대상만 종료한다. 정상 종료는 최대 10초 기다리고 소켓 해제를 별도로 확인한다. 남은 프로세스가 있으면 해당 서비스에 **강제 종료…**를 제공한다. 강제 종료는 작업 유실 안내와 남은 대상의 별도 확인을 거치며, 이전에 확인한 프로세스만 재검증해 종료한다. 다른 실행기가 서버를 다시 켜면 원래 실행기를 확인하도록 안내하며 새 프로세스를 추적해 반복 종료하지 않는다. 포트는 자동 변경하지 않는다.

오른쪽 위에는 **최소화 · 최대화/복원 · 닫기** 버튼을 순서대로 제공한다. 최대화 상태는 OS의 창 상태와 동기화하며, UI가 다시 로드되어도 복원 버튼을 유지한다. **×**나 OS의 창 닫기는 관리 창만 숨기며 서버는 계속 실행된다. 최소화하거나 숨긴 창은 **Ticklane 서버** 아이콘으로 다시 연다. 관리 프로세스까지 종료하려면 하단의 **관리 앱 종료**를 사용한다. 관리 중인 서버가 있으면 **서버 중지 후 종료** 여부를 확인한다. Ticklane 업무 앱을 닫는 동작은 서버에 영향을 주지 않는다.

서버 관리 앱은 시스템 트레이에도 아이콘 하나를 표시한다. 밝은 서버 모양에 실행 중(초록)·중지됨(회색)·시작/중지/확인 중(앰버)·확인 필요(빨강) 표시를 붙이며 메뉴 첫 줄과 툴팁에도 상태를 적는다. 트레이 활성화 또는 **관리 창 열기**로 숨긴 창을 다시 열 수 있고, 메뉴에서 **Ticklane 열기**, **서버 시작/중지**, **로그 폴더 열기**, **관리 앱 종료…**를 사용할 수 있다. 서버 중지와 관리 앱 종료는 확인 후 실행하며 시작 중에는 **시작 취소**로 표시한다. 외부 서버 중지도 트레이에서 실행 정보를 확인한 뒤 수행하며, 강제 종료는 관리 창의 서비스 행에서 별도로 확인한다. UI 자동 리로드나 같은 실행 아이콘 재실행은 트레이를 추가로 만들지 않는다. Linux의 트레이 표시·클릭 방식은 데스크톱 환경에 따라 다르므로 기존 실행 아이콘으로 창을 여는 동작도 유지한다. 트레이를 만들지 못해도 서버 관리 창은 계속 사용할 수 있다. 트레이 기능은 Electron 메인 코드이므로 소스 UI 자동 리로드 대상은 아니다.

**실행 기록**은 기본적으로 접혀 있으며 오류가 발생하면 자동으로 펼쳐진다. 사용자가 접으면 상태 갱신 시에도 선택을 유지한다. 펼친 로그는 창의 남는 높이를 채우며 최대화·복원에 맞춰 늘어나거나 줄어든다. 큰 창에서는 로그 안에서 스크롤하고 작은 창에서는 본문도 스크롤할 수 있으며, 상단 창 제어와 하단 종료 버튼은 계속 표시한다. 최대화만으로 접힌 실행 기록을 펼치지는 않는다. 자동 스크롤을 켜 두면 크기를 바꾼 뒤에도 최신 줄을 보여 준다. 화면 시간은 PC의 로컬 시각으로 표시하며 파일에는 원래 UTC 시각을 보관한다. 로그는 `~/.config/ticklane-server/logs/server.log`에도 기록한다. 화면에는 최근 300줄을 표시하며 파일은 5MB를 넘으면 이전 파일 하나를 보관한다. **로그 폴더 열기**로 파일을 확인할 수 있다. 서버 실행기는 `~/.local/bin/ticklane-server`, 실행 설정은 `~/.local/lib/ticklane/servers.json`에 등록한다. 프로젝트나 Node/uv 설치 위치, Electron 체크아웃 경로가 바뀌면 다시 등록한다.

소스로 실행하는 서버 관리 창은 `desktop/src/server-ui/`의 `index.html`, `server.css`, `server.js`를 직접 읽는다. 파일을 저장하면 화면만 자동으로 다시 불러오므로 UI 수정마다 빌드하거나 관리 앱을 재시작할 필요가 없다. Electron 메인 프로세스와 서버 제어기는 유지되며 관리 중인 서버의 PID·로그·시작/중지 권한도 유지된다. 실행 기록의 펼침 상태와 자동 스크롤 선택도 복원한다. 창을 숨겨 둔 동안에는 파일이 바뀌어도 창이 자동으로 나타나지 않는다. 설치된 로컬 **Ticklane 서버** 바로가기에도 자동 적용된다. `.deb`/ZIP 배포본은 동봉된 UI를 사용하며 파일 감시를 하지 않는다. Electron 메인·preload·서버 제어 코드 변경은 기존대로 빌드와 관리 앱 재시작이 필요하다.

백엔드는 기존 uvicorn 개발 실행 명령을 사용하고 프론트는 Vite로 실행하므로 코드 변경 시 백엔드 재시작과 프론트 HMR을 유지한다. Python·Node와 프로젝트를 동봉한 독립 서버 배포 파일은 아니며, 이 PC의 개발 환경을 사용하는 관리 앱이다.

저장소의 Node 24 환경에서 실행한다.

```sh
cd desktop
npm ci
npm start
```

Ubuntu의 일반 터미널에서 `SUID sandbox helper ... not configured correctly` 오류가 발생하면 다음 설정을 **최초 한 번** 적용한 뒤 다시 실행한다.

```sh
npm run setup:sandbox
HOGA_DESKTOP_USER_DATA="$HOME/.config/hoga-ops-local-dev" npm start
```

`setup:sandbox`는 현재 워크트리의 Electron 실행 파일에만 user namespace를 허용하는 AppArmor 프로필을 `/etc/apparmor.d/`에 설치하고 로드한다. sudo 비밀번호가 필요하다. 전역 AppArmor 설정이나 `chrome-sandbox` 소유권·SUID 권한을 바꾸지 않으며 Chromium sandbox를 유지한다. 적용 전 내용은 `npm run setup:sandbox -- --print`, 제거는 `npm run setup:sandbox -- --remove`로 확인할 수 있다. 실행 파일의 경로가 달라진 워크트리에서는 다시 설정한다.

Codex처럼 별도의 AppArmor 프로필이 적용된 프로세스에서 실행한 결과와 일반 터미널의 결과는 다를 수 있다. `.deb`는 설치 과정에서 root 소유의 SUID sandbox helper를 제공한다. 관리자 설치로 적용된 권한과 일반 사용자로 임시 추출한 파일의 권한은 서로 다르다.

서버 연결 화면에서 이름과 **화면을 제공하는 서버의 origin**을 입력한다. 예를 들어 로컬은 `http://localhost:8000`, 원격은 기존 `http://<MagicDNS 이름>:8000`이다. URL에 `/live`를 붙이지 않는다. 원격 서버는 먼저 Tailscale로 접근 가능해야 한다. 서버 이름이나 IP를 자동 대체하지 않는다.

마지막으로 연결한 서버는 다음 실행 때 다시 연결한다. 연결이 실패하면 앱 안에서 주소 수정·재시도가 가능하다. 우측 레일 맨 아래 **설정 → 데스크톱 → 서버 선택** 또는 **Ctrl+Alt+S**에서도 변경할 수 있다. 데스크톱 설정에서 현재 서버 이름·주소를 확인하고 새 작업 창 열기와 화면 배율 조절·100% 복원도 할 수 있다. 일반 화면 우클릭에는 앱 전역 메뉴를 띄우지 않으며 입력칸의 편집 메뉴와 외부 링크 열기는 유지한다. 상단 네이티브 메뉴 행은 표시하지 않으며 복사·붙여넣기·새로고침 등 기존 단축키는 유지한다. 서버를 바꾸면 기존 작업 창이 닫힌다. 이전 서버에 접수된 주문·수집 작업은 계속되며 새 서버로 요청을 재전송하지 않는다.

## 화면 배율

업무 화면에서 `Ctrl + +`(또는 `Ctrl + =`)로 확대, `Ctrl + -`로 축소,
`Ctrl + 0`으로 100%로 돌아간다. macOS에서는 Ctrl 대신 Command를 사용한다.
우클릭 메뉴의 **화면 배율**에서도 현재 비율을 확인하고 확대·축소·복귀할 수 있다.
50~300% 범위이며 글자·버튼·호가창을 포함한 페이지 전체에 적용한다.
마지막 배율은 연결 서버별로 기존 연결 설정 파일에 저장하고, 같은 서버의 다른 작업 창과
새 창·새로고침·재실행에서 이어 쓴다. 차트의 Ctrl+휠 동작과 서버 관리 창은 변경하지 않는다.

단축키나 메뉴로 배율을 조절하면 해당 창의 정중앙에 **화면 배율 110%** 형태의 투명
팝오버가 나타난다. 배경은 35% 불투명도와 약한 블러를 쓰고, 마지막 조절 후 1.8초 뒤
사라진다. 클릭과 키보드 포커스는 가져가지 않으며 같은 서버의 다른 창에는 배율만 공유한다.
새 창·새로고침·앱 재실행으로 저장된 배율을 복원할 때는 팝오버를 표시하지 않는다.

이 기능은 Electron 메인 코드이므로 기존 앱을 완전히 종료하고 같은 바로가기로 다시 열어야
새 단축키가 적용된다. 서버 관리 앱이나 프론트·백엔드 서버를 재시작할 필요는 없다.

## 서버 설정

### 로컬 운영

먼저 기존 방식으로 백엔드를 실행한다. 프론트 빌드와 명시적인 origin 허용이 필요하다.

```sh
# 저장소 루트
cd frontend
npm ci
npm run build
cd ..
HOGA_FRONTEND_DIST="$PWD/frontend/dist" \
HOGA_ALLOWED_ORIGINS=http://localhost:8000 \
uv run --frozen hoga serve
```

이미 실행 중인 서버를 이 명령으로 중복 실행하지 않는다. 기존 서버의 실행 설정에 두 환경변수를 반영한 뒤 필요한 시점에 갱신한다. Ticklane 업무 앱은 서버를 자동으로 실행·재시작하지 않는다. `localhost`로 접속하기로 했다면 `127.0.0.1`로 바꿔 쓰지 않는다. 둘은 별도 origin이다.

### 원격 운영

서버는 기존 ADR-0134대로 Tailscale 인터페이스에만 바인딩하고, `HOGA_FRONTEND_DIST`와 자신의 고정 MagicDNS origin을 `HOGA_ALLOWED_ORIGINS`에 설정한다. 공개 또는 LAN 바인딩으로 확대하지 않는다. 서버가 제공하는 `/config.json`은 `{"api_url":""}`여야 한다.

데스크톱용 설정 이전과 엄격한 설정 실패 화면을 사용하려면 이 변경의 프론트 빌드도 서버에 배포해야 한다. 이전 프론트 빌드에서도 Electron의 요청 origin 제한은 적용되지만 최신 설정 UI는 추가되지 않는다.

### Vite 개발

소스 실행에서는 연결 모드를 **개발 Vite**로 선택하고 화면 주소와 API 주소를 각각 입력할 수 있다. `E2E_API_URL`을 지정하면 현재 Vite 설정이 해당 `/config.json`을 제공한다.

```sh
cd frontend
E2E_API_URL=http://localhost:8000 npm run dev -- --host 127.0.0.1
```

실제 실행 포트와 backend origin 허용 목록을 맞춘다. 설치본은 개발 모드를 제공하지 않는다. 개발·검증 서버는 워크트리별 데이터 경로와 무자격 환경을 사용한다.

## 창과 화면 설정

- 앱의 기존 Ctrl/Cmd+클릭 새 탭 동작은 별도 OS 창으로 열린다. 업무 화면 우클릭의 **새 작업 창**에서도 열 수 있다.
- 같은 서버 창끼리는 영속 설정을 공유하고 창별 sessionStorage는 분리한다. 다른 서버·개발 프로필은 별도 영속 세션이다.
- 기본 창의 위치·크기·최대화 상태를 복원한다. 여러 자식 창을 앱 시작 때 모두 자동 재개하지는 않는다.
- Wayland에서는 compositor의 위치·포커스 제약을 따른다. 절대 좌표 복원 동작은 X11과 다를 수 있다. 창 배치가 중요한 환경에서는 X11/XWayland 실행도 검증한다. sandbox를 끄는 실행 옵션은 사용하지 않는다.
- 외부 링크는 우클릭의 **링크를 외부 브라우저로 열기**를 사용한다. 외부 콘텐츠의 자동 팝업은 열지 않는다.
- CSV·PNG 다운로드는 네이티브 저장 대화상자를 사용한다. HTTP 환경의 클립보드 제약에는 기존 다운로드 대체 동작을 사용한다.

Chrome과 Electron은 별도 저장 프로필을 쓴다. 기존 브라우저의 **설정 → 앱 정보 → 화면 설정 내보내기**에서 JSON을 저장하고, Electron의 같은 위치에서 가져온다. 이전 대상은 현재 스키마의 창 배치·지표·차트 선호 설정·그리기·테마다. 선택 종목·핀·주문창 주문 설정과 서버 소유 관심종목·저장뷰·계좌·수집 데이터는 옮기지 않는다. 일회성 전달함·캐시·인증정보도 제외한다.

가져올 때는 다른 작업 창을 닫고 현재 설정 백업을 다운로드해 보관한 다음 적용한다. 표시된 원본과 대상 origin을 확인한다. 파일의 항목에 포함된 키를 덮어쓰며, 파일에 없는 설정은 유지한다. 현재 창의 배치 sessionStorage를 비우고 새로고침해 가져온 배치를 읽는다. 저장 실패 시 원래 localStorage 값을 복원한다. 손상 파일은 쓰기 전에 거부한다.

연결 프로필과 세션 데이터는 Electron의 `userData`에 보관한다. 별도 환경이 필요하면 **절대 경로** `HOGA_DESKTOP_USER_DATA`를 지정한다. 해당 경로만 삭제하면 그 환경의 연결·화면 설정이 사라지므로, 평소 복구는 설정 백업·서버 선택을 먼저 사용한다.

## Linux 배포

```sh
cd desktop
npm run make
```

`out/make/zip/linux/x64/`에 압축 배포본, `out/make/deb/x64/`에 Ubuntu 설치본이 생성된다. deb 빌드에는 `fakeroot`, `dpkg`가 필요하다. ZIP을 풀면 `ticklane` 바이너리를 일반 사용자로 실행한다. `.deb`는 다음과 같이 설치한다.

```sh
sudo apt install ./out/make/deb/x64/ticklane_0.16.6-rev.0_amd64.deb
ticklane
```

파일명은 현재 빌드 버전에 맞춘다. 업데이트는 앱 종료 후 새 ZIP 또는 `.deb`를 수동 설치한다. 같은 `userData`의 프로필·화면 설정은 유지된다. 시스템 패키지 제거는 `sudo apt remove ticklane`으로 하며 홈 디렉터리의 사용자 설정은 자동 삭제하지 않는다. 설치에 관리자 인증이 필요할 수 있다.

루트 `VERSION`의 `A.B.C.D`를 패키징용 `A.B.C-rev.D`로 변환한다. 예를 들어 `0.16.6.0`은 `0.16.6-rev.0`이며 네 번째 자리 증가도 구분된다. 앱 정보에는 원래 네 부분 버전과 소스 커밋을 표시한다. 프론트 패키지 버전은 기존 `0.0.0`을 유지한다.

## 검증

```sh
# 저장소 루트: 실제 앱 통합 테스트의 사전 준비
uv sync --frozen --extra dev
cd frontend
npm ci
npm run build
cd ../desktop
npm ci
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run make
npm run verify:deb
```

Electron E2E는 GUI 세션이 필요하다. `verify:deb`는 시스템 설치 대신 임시 디렉터리에 `.deb`를 풀고 그 안의 실제 바이너리로 E2E를 수행한다. 관리자 설치·메뉴 등록·제거 검증을 대체한다고 주장하지 않는다. 다른 패키지 실행 파일은 `HOGA_DESKTOP_EXECUTABLE=/absolute/path/to/ticklane npm run test:e2e`로 확인할 수 있다.

테스트는 실행별 임시 userData·서버 포트·데이터 디렉터리를 사용한다. 실제 FastAPI와 프론트 빌드로 화면·설정 이전을 확인하며 차트 데이터는 기존 무자격 fixture를 사용한다. 서버 자격증명을 비우고 체크아웃·데이터 경로를 검사한다. 사용자의 5173·8000 서버를 종료하거나 데이터를 변경하지 않는다. 테스트에 `--no-sandbox`를 넣지 않는다.
