# hoga-ops

Single-user local tool that captures Korean stock orderbook + trade replay data from `hogaplay.com` and exposes it for analysis.

## Language

**Regular Session**:
The continuous-trading window of the KRX day, 09:00:00–15:30:00 (includes the closing single-price auction 15:20–15:30).
_Avoid_: "session" alone, "market hours"

**Data Window**:
The full span of data hogaplay returns for a stock-date, broader than the Regular Session. Includes pre-market single-price activity from ~08:40 and any closing-auction residuals. Outer bounds are the earliest and latest event timestamps in the captured TSV.
_Avoid_: "session" alone, "trading day"

**Code**:
A 6-digit KRX ticker, e.g. `005930`. Strings, not integers — leading zeros matter.
_Avoid_: "symbol", "ticker"

**Stock-Date**:
The unit of capture and storage: one (Code, YYYYMMDD) pair. All paths and queries are scoped to a Stock-Date.

**Page**:
One `first.php` HTTP response. Bounded in size (~500–1000 events). Multiple Pages cover one Stock-Date's Data Window.
_Avoid_: "chunk", "batch", "section" (overloaded — see TSV Section below)

**Full Capture**:
The union of all Pages for one Stock-Date, deduplicated. The artifact the collector must produce before the parser runs.

**TSV Section**:
The first field of every row in a Page's TSV (`1` = events that occurred before the requested `time`, `2` = events from the requested `time` onward). A presentation marker dependent on the call's `time` parameter — *not* an intrinsic property of an event. The same event can appear as TSV Section 1 in one Page and TSV Section 2 in another with all other fields identical (verified 2026-05-19). Dropped during parsing.
_Avoid_: "section" alone (ambiguous with Regular Session, Page)

**Global Sequence (global_seq)**:
Field 4 of every event row. Strictly increasing per-Stock-Date counter across all event types. The dedup key when merging Pages into a Full Capture: verified unique-within-Page and stable-across-Pages.

**Page Step**:
The increment applied to the `time` query parameter between successive collector calls. Variable, not fixed. Default 60000ms (1 minute) matching hogaplay's UI step; collector halves the step (30s, 15s, ...) when a response fails to cover the requested window — indicating the response cap was hit before reaching `time + step`. A stagnation guard (ADR-0017) terminates the loop if `max_event_time` and `new_seqs` both fail to advance for `MAX_STAGNANT_PAGES` (200) consecutive iterations — protecting against hogaplay response freezes that would otherwise loop forever in the cap-hit branch.

**Auction Cross**:
A trade matched via a call auction (단일가 매매), not continuous trading. Occurs at the open (~09:00:00.000), the close (~15:30:00.000), and pre-market single-price periods. Recognizable in the trade schema by **absence of `+`/`-` sign** on the qty field (event type 1) OR by being an event type 3 row (single-price summary, used for both opening and closing auctions — confirmed in production 2026-05-20). Stored as `side = 0` (distinct from continuous-trading `+1` buy-aggressor / `-1` sell-aggressor). Excluded from CVD, aggressor-based metrics, and `cum_vol` monotonicity validation (`side=0` rows carry `cum_vol=0`).
_Avoid_: "auction trade" alone, "opening trade", "closing trade"

Multi-**Stock-Date** generalisation: each **Stock-Date** in a **Stock-Date Range** has its own opening Auction Cross (~09:00:00) and its own closing **Auction Window** + closing Auction Cross (15:20:00–15:30:00). Frontend consumers (e.g. CandlePane's "muted color from 15:20 onward" rule) must compute the threshold per segment, not from a single global `session_open_ms`. The wire surfaces this implicitly: each `RangeBundle.segments[i]` carries its own `session_open_ms` / `session_close_ms`.

**Auction Window**:
The period leading up to an **Auction Cross** during which limit orders accumulate but no continuous matching happens. KRX has two within the Regular Session: the closing **Auction Window** runs 15:20:00–15:30:00 and resolves with a cross at 15:30:00.000. The opening Auction Window (pre-market, part of the Data Window) is symmetric. **Snapshots are present and meaningful during an Auction Window** — bid/ask quantities at each level accumulate visibly. **Trades are absent** during the window itself; the cross at the window's close produces a single `side = 0` trade. By default (per-tab `auctionWindowMask` toggle, on), **all chart indicator panes other than CandlePane and VolumePane are visually suppressed during the closing Auction Window** — RatioPane (호가비), QuoteTotalsPane, FillStrength (histograms + Cumulative Net Fill) all hide their data points and break their lines at the 15:20 boundary (see ADR-0029). Earlier behaviour masked **호가비** values to 0 and rendered Quote Totals as raw accumulating levels; the unified "hide" semantics replaced both because the value-0 plateau and the one-sided accumulation curve both read as misleading signal to typical analysts. CandlePane and VolumePane are deliberately untouched — see ADR-0018 (candle) and the candle/volume carve-out in ADR-0029. The cross at 15:30 still produces a single FillStrength bar; that bar is also hidden when the toggle is on.
_Avoid_: "auction period", "auction phase", "auction time" (all overloaded)

**Auction Mask**:
The composite UI state that gates whether an indicator visualization should be suppressed at a given moment. Active iff (1) the per-tab `auctionWindowMask` toggle is `true` AND (2) the current **Cursor** (or per-point `t`) falls inside the closing **Auction Window** (per `VirtualAxis.inClosingAuctionWindow`). The toggle alone is _intent_ ("mask when applicable"); the mask is the _activated decision_ for a specific moment. **The rendering action varies by consumer**, not by the predicate: chart pane projectors (RatioPane, QuoteTotalsPane, FillStrength) emit each in-window point as `WhitespaceData` (no `value` field) — the line breaks naturally at the first whitespace AND the bar-index time scale keeps a mappable position at every in-window minute, which is load-bearing for the `AuctionWindowOverlay` band's `timeToCoordinate` lookups at `auctionStart` and `sessionClose`. Dropping in-window points entirely would shrink the chart's visible range past the auction window, hiding the highlight band as a side effect. Spot views (`TotalQtyBar` on the sidebar) replace the bar fill with a small "Auction" label instead. The frontend hook `useAuctionMaskActive(axis)` returns the boolean for spot views (single-cursor reading); series projectors inline the same 2-line check `mask && axis.inClosingAuctionWindow(p.t)` per point — there is no shared helper module, because the inline check is shorter than any abstraction's contract. CandlePane's "muted color from 15:20 onward" rule and VolumePane both deliberately do _not_ participate in the Auction Mask — see ADR-0018 (candle) and ADR-0029 (the candle/volume carve-out for the unified hide semantics). They share only the predicate with the Auction Mask; the action is different.
_Avoid_: "mask" alone (overloaded with any UI hide rule); "auctionWindowMask" used to mean the activated state (that name belongs to the underlying toggle, not the derived decision); "mask to 0" (legacy phrasing — chart panes now hide, not zero).

**Half-Day Session**:
A KRX trading day whose **Regular Session** is materially shorter than the typical 6h30m — year-end (12월 30일), 추석 / 설 전 영업일, etc. — and closes at 12:30 KST instead of 15:30. The closing **Auction Window** is still the last 10 minutes of the session (12:20–12:30 on these days), not a fixed wall-clock band. Session bounds are always read per-Stock-Date from the parsed TSV (`hoga/parser/__init__.py` parses `regular_session_open_ms` / `regular_session_close_ms`), never assumed — `sessionOpenMs + 6h20m` is a half-day footgun and the `SessionTime` predicates encode the duration-anchored rule.
_Avoid_: "short day", "early close" alone (ambiguous with intraday halts).

**SessionTime**:
The frontend module (`frontend/src/util/sessionTime.ts`) that owns KRX session-phase classification — pre-open auction, regular trading, closing auction, gap, pre-axis, post-axis. New chart and sidebar code consumes the named predicates (`isRegularSession`, `isClosingAuction`, `isPreOpen`, `sessionPhaseAt`) rather than re-deriving inequalities locally. Legacy `VirtualAxis.contains` and `VirtualAxis.inClosingAuctionWindow` delegate here for backward compatibility, so the bug class where pre-open auction closes leaked into MA windows or where half-day sessions disabled all auction masking cannot recur.
_Avoid_: hand-rolled `realMs >= sessionOpenMs && realMs <= sessionCloseMs` checks; new domain timing rules belong in `sessionTime.ts`.

**After-Hours Trading**:
The KRX 장후 시간외 종가매매 window that runs from the closing Auction Cross at 15:30:00 to 16:00:00. All trades during this window match at the closing price (the cross price from 15:30:00) — so the price stays flat while volume continues to accumulate. Both snapshots and trades are present in hogaplay's capture across this window. Trades have continuous-trading `side = ±1` (not `side = 0`) — they are aggressor-matched at a fixed price, not auction crosses. Outside `CONTEXT.md`'s strict Regular Session definition (09:00–15:30) but inside hogaplay's Data Window and inside the v1 frontend display range.
_Avoid_: "after-hours" alone (ambiguous with overnight or block-trade markets), "post-market"

**Price Tick**:
A 3-field `section=3 type=5 price` heartbeat broadcast emitted by hogaplay throughout the session. Carries only the current price — no qty, side, or seq. Discovered during E2E validation 2026-05-20. Parser drops these rows entirely; the same information is already present in trade events.

**Entity**:
The in-memory frozen-dataclass representation of one row of table data inside hoga-ops. Carries every field including **forensic** ones — fields whose meaning is partially or fully undecoded (`unknown_14`, `unknown_16`, `unknown_17`, `unknown_18`) kept to enable later decoding without re-collection. Used by the parser on the write path. Internal — never returned by the API. Examples: `Trade`, `Orderbook`, `BrokerRow`, `Candle` in `hoga/tables/*`.
_Avoid_: "model", "domain object", "record"

**Cursor**:
A single Unix-ms (UTC) point on the API contract — the value of the `?t=`
query parameter on spot endpoints (`/api/orderbook`, `/api/brokers`,
`/api/trades`), the frontend tab's `cursorMs`, and the right edge of the
viewport published by `ChartStage`. Always a real Unix-ms per ADR 0003 —
never the native HHMMSSmmm or ms-from-midnight encodings the Parquet
tables use. Conversion to native happens once at the route boundary via
`hoga.api.cursor::cursor_to_native`, which raises HTTPException(400) when
the Cursor falls outside the requested **Stock-Date**.
_Avoid_: "timestamp" alone (ambiguous with Entity ts_ms and Wire Model
ts_ms which may differ in encoding), "t param".

**Cursor Sidebar**:
The right-side panel of the Replay Viewer's Workarea that hosts three Cursor-aware cards — **10호가** (cursor-anchored orderbook snapshot), **거래원** (day-anchored broker list with per-row cursor-projected net; see **Broker Day-Trajectory** and ADR-0023), **체결** (cursor-anchored recent fills). Two of the three cards (10호가, 체결) are *cursor-keyed* — their list identity changes as the Cursor moves; the 거래원 card is *day-keyed* in identity but *cursor-projected* in its per-row net value. All three still consume the **Cursor**; the asymmetry is in what the cursor controls. Lives in `frontend/src/sidebar/CursorSidebar.tsx`; the connected variant `CursorSidebarConnected` binds each card to its hook — `useSpot`-family for the two cursor-keyed cards, `@tanstack/react-query` (via `useBrokerSeriesForDay`) for the day-keyed broker card. Treated as a single UI object for layout purposes — its width is user-adjustable and the whole panel can be collapsed (per the 2026-05-24 Replay Sidebar Splitter spec). The default width is seeded from the `--sidebar-w` design token; runtime width and collapsed state are owned by `state/replayLayout.ts` (per ADR-0022). The Cursor Sidebar **consumes** **Cursor**; it is not a synonym for Cursor — Cursor is the time-point on the API/UI contract, the Cursor Sidebar is the panel that renders Cursor-derived information (mixed point-in-time and day-aggregate readings).
_Avoid_: "sidebar" alone (the codebase has other panels that could be called sidebars — Inventory's left list, Capture's queue), "cursor panel" (loses the multi-card structure), "spot sidebar" (the prior internal name; superseded, and now also misleading since the 거래원 card is no longer spot-only), "Cursor-keyed cards" as a description of all three (the 거래원 card is day-keyed in identity per ADR-0023).

**Broker Day-Trajectory**:
The per-broker signed-net time series across one **Stock-Date** that the **Cursor Sidebar**'s 거래원 card renders as inline sparklines (per ADR-0023). One row per broker; the row's sparkline plots `net(ts_ms)` = `SUM(qty_today * sign(side))` aggregated per (broker, ts_ms) — same sign convention as the legacy `BrokerNetTable.computeNet` (`buy = +`, `sell = −`), so a broker on both top-5 lists at the same snapshot (rare market-maker case) shows as one signed line rather than two. Wire-shipped via `BrokerSeriesResponse.brokers[*].points` from `GET /api/brokers/series?code=&date=`; the response is sorted by `abs(final_net)` desc (the sort key the sidebar list uses) and truncated to top 10. **Data gaps** in the trajectory — spans where the broker was outside both top-5 lists and therefore has no snapshot row — are rendered as **dashed, dim** segments connecting the last observed point to the next observed point, deliberately distinguishable from solid (observed-continuous) segments. The gap-vs-continuous decision uses a single threshold `GAP_THRESHOLD_MS` (initially 30s); the convention is intentional honesty about the brokers parquet's top-5 truncation rather than forward-fill that would fabricate continuity. The Cursor Sidebar projects the per-row net-at-cursor value by binary-searching the row's `points` for the last `ts_ms <= cursorMs`. **Crossing a Day Boundary** in a multi-day **Stock-Date Range** swaps the entire trajectory — `useCursor().date` changes, the react-query key changes, the series reloads.
_Avoid_: "broker trajectory" alone (loses the Stock-Date scope — could be read as a multi-day cumulative), "broker history" (overloaded with capture history / SSE history), "sparkline" alone (the rendering, not the underlying series concept), "broker net" alone (collapses with the legacy cursor-snapshot reading — use "Broker Day-Trajectory" or "net at cursor" depending on which value is meant).

**Capture Frontier**:
The collector's next-request position for an in-flight **Full Capture** — the `t` value the next `first.php` call will use, equivalently the upper bound of the Data Window range already processed. Internally tracked as HHMMSSmmm (matches hogaplay's `first.php` `time` parameter and the `last_time_ms` field written to `_progress.json`, sourced from `PageStepController.next_t`); surfaced through the capture API as `frontier_ms` in Unix-ms per ADR-0003. Distinct from **Cursor** (which is an API/UI contract concept on the read path).
_Avoid_: "cursor" (overloaded with the API/UI **Cursor**), "current position", "progress timestamp", "last_time_ms" (the internal HHMMSSmmm field name — don't use on the API surface)

**Capture Queue**:
The FIFO ordering of (Code, **Stock-Date**) jobs scheduled to become **Full Captures**. A single uvicorn worker process holds the queue in memory across three buckets — `queued` (waiting), `active` (worker grabbed, in deciding/capturing/parsing), `done` (terminal: completed/failed/cancelled/skipped). Workers process N items in parallel up to `HOGA_MAX_CONCURRENT`. The queue can be `paused` (e.g. after `cookie_expired`) which holds active workers and prevents queued items from advancing. Persisted to `<data_dir>/.queue.json` so server restart auto-resumes the in-flight queue (ADR-0019); `done` is volatile and not persisted. Surfaced on the wire as `QueueSnapshot` and mutated via `POST /api/captures/items` / `items/retry` / `cancel` / `cancel-all` / `queue/resume`.
_Avoid_: "job queue" (overloaded with background-task semantics from web frameworks), "capture pool", "capture list" (ambiguous with **Stock-Date Range**).

**Retry**:
Re-enqueuing a terminal **Capture Queue** item with `attempt = prior + 1`. Two paths trigger it:
1. **Explicit Retry** — `POST /api/captures/items/retry` with one or more `item_id`s. `failed`-only by policy (per ADR-0031); the per-row ↻ button and header "Retry Failed" both use this path. Preserves the old item's `force_retry` flag.
2. **Implicit Retry** — `POST /api/captures/items` (the normal enqueue path) when a request's `(code, date)` collides with a `_done` item. The backend auto-dismisses the old `_done` row and enqueues a new attempt (uses the *request*'s `force_retry`, not the old item's). Dedupe table by `old.phase` × `req.force_retry`:

   | `old.phase` | `force_retry=false` | `force_retry=true` |
   |---|---|---|
   | `failed`    | auto re-enqueue | auto re-enqueue |
   | `cancelled` | auto re-enqueue | auto re-enqueue |
   | `skipped`   | dedupe `already_skipped` | auto re-enqueue |
   | `done`      | dedupe `already_complete` | auto re-enqueue (ADR-0035) |

   See ADR-0033 + ADR-0035. The `done + force_retry` branch is what makes inventory re-capture work — `decide_capture` still gates `COMPLETE` disk state at worker time, so this branch is safe for non-complete disk states (which is what inventory surfaces) and harmless for complete (skipped at worker).

Either path: backend removes the old `_done` entry, publishes `CaptureDismissedEvent` (so the frontend hides the old row), then publishes `CaptureQueuedEvent` for the new attempt. The `×N` attempt badge on the queue row counts every Retry regardless of trigger.

Distinct from **force_retry**: Retry is the *operation* of giving an item another try; `force_retry` is a *boolean flag* on each item that controls whether sentinels / partial raw artifacts are deleted before capture (see `No Upstream Data`). The two compose. `done`-phase items whose disk-state is `COMPLETE` are never effectively re-captured even with `force_retry=true` — `decide_capture` skips them as `already_complete` (per ADR-0035).
_Avoid_: "re-enqueue" (loses the attempt-counting semantics), "rerun" (ambiguous with replay / backtest reruns).

**Watchlist**:
The single set of **Code**s the user has marked for unattended daily capture. There is one Watchlist per `<data_dir>`; no per-user multiplexing because hoga-ops is a single-user local tool. Persisted to `<data_dir>/watchlist.json` as an insertion-ordered list of **WatchlistEntry** records. Mutated only via the `POST /api/watchlist` / `DELETE /api/watchlist/{code}` endpoints and the **Daily Scheduler**'s `bump_last_success` hook. A Code's presence in the Watchlist is independent of any individual **Capture Queue** state — removing a Code from the Watchlist does not cancel queued or active jobs for it.
_Avoid_: "subscription" (ambiguous with SSE topics), "auto-list", "follow list", "starred" (no UI star metaphor — the verb is "add to Watchlist").

**WatchlistEntry**:
One row of the **Watchlist**: `{code, name, registered_at_kst_date, last_success_date}`. `name` is captured at registration time from the symbol-master cache so the UI does not re-resolve it on every render. `registered_at_kst_date` is a YYYYMMDD KST-date stamp used as the floor for **Catch-up Run** when `last_success_date` is null — past history before registration is never backfilled. `last_success_date` is the most recent YYYYMMDD with a COMPLETE artifact on disk for this Code, regardless of whether the capture happened through the **Capture Queue** or already existed when the Code was added to the Watchlist. Seeded from the disk on `add_entry` (via `disk_state.latest_complete_date`) and reconciled on every startup by the **Catch-up Run** before its backfill pass — so Codes registered while prior data already lived on disk do not show "마지막 성공: 아직 없음". The marker only advances forward; out-of-order `phase = done` completions and disk reconciles cannot regress it. Null only if the Code has no COMPLETE captures anywhere.
_Avoid_: "watch item", "subscribed code".

**Daily Scheduler**:
The asyncio task that sleeps until the next KST 18:00, then enqueues `(entry.code, today_kst)` for every **WatchlistEntry**, then sleeps another 24 h. Runs in the same uvicorn process as the **Capture Queue** workers — wired into the FastAPI lifespan beside `start_capture_pool`. Skips non-trading days via `calendar.trading_days_in_range`. The Scheduler is a *client* of the **Capture Queue**: it always goes through `enqueue_items_core`, never touches `_queue` / `_active` / `_done` directly, so ADR-0033 dedupe, ADR-0019 manifest persistence, ADR-0031 retry policy, and cookie-expired auto-pause are all inherited automatically (see ADR-0034). The 18:00 `today_too_early` rule (Q14) is the one piece the Scheduler must consult separately (via `find_ineligible_dates`) before calling `enqueue_items_core`, because `enqueue_items_core` *rejects* the whole request on Q14 rather than trimming it.
_Avoid_: "cron" (no system cron is involved), "watcher" (overloaded with file-system watchers and uvicorn `--reload-dir`), "auto-capture" (ambiguous with retry-on-failure auto-capture).

**Catch-up Run**:
The one-shot async task that fires at server startup, immediately after the **Daily Scheduler**'s loop task is spawned. Two-phase: (1) a disk reconcile pre-pass that advances each entry's `last_success_date` to the latest COMPLETE Stock-Date on disk via `disk_state.latest_complete_date` (idempotent thanks to `bump_last_success`'s monotonic guard — auto-heals legacy entries registered before the disk-seed flow existed); (2) the backfill, which computes the trading-day range `[next_kst_day(last_success_date or registered_at_kst_date), today_kst]` for each **WatchlistEntry**, pre-trims today through `find_ineligible_dates`, and enqueues the result via `enqueue_items_core`. Errors are per-entry and logged (KRX list unavailable, credentials missing, etc.) — Catch-up never aborts the rest of the Watchlist when one entry fails. Catch-up runs exactly once per server startup; there is no manual re-trigger endpoint in v1.
_Avoid_: "backfill" (overloaded with parquet rewrite operations), "catch-up sync", "startup capture".

**Wire Model**:
The pydantic model returned by API endpoints — the shape clients see. Strips forensic fields (and any other internal-only data). Each table module pairs an **Entity** with its Wire Model: `Trade`↔`ApiTrade`, `Orderbook`↔`ApiOrderbookSnapshot`, `BrokerRow`↔`ApiBrokerEntry`, `Candle`↔`ApiCandle`. Query helpers (`query_at`, `query_up_to`, etc.) return Wire Models directly — there is no intermediate dict materialization.
_Avoid_: "API model" alone (ambiguous with response containers like `OrderbookResponse`), "DTO"

**Invariant**:
A declarative domain rule that a **Stock-Date**'s captured artifacts must satisfy — e.g. "`regular_session_close_ms` must be strictly greater than `regular_session_open_ms`". Lives in the central catalog at `hoga/api/invariants.py` as `(id, severity, description, check)` tuples where `check` is a pure function from a meta dict to an optional **Violation**. The catalog is the single source of truth — all four checkpoints (parser write-time archival, `DiskState.classify_from_meta`, `build_range_bundle` read-path, `hoga validate` CLI sweep) consume the same registry, so adding a rule is a one-line catalog entry rather than scattered ifs. Distinct from pydantic field validators (which guard wire shape) — Invariants encode cross-field semantic rules that wire validation can't express.
_Avoid_: "data check", "validation rule" (overloaded with pydantic field validators), "constraint" (overloaded with DB constraints).

**Violation**:
The output of an Invariant whose `check` returned non-None — a `(invariant_id, severity, message, ctx)` record where `ctx` carries the meta values that triggered the failure (so a future reader can reproduce the decision without re-querying disk). Two severities: **error** (data shape itself is broken — `build_range_bundle` excludes the affected **Stock-Date** silently and lists it under `RangeBundle.excluded_dates`) and **warn** (data shape is plausible but trust is low — the **Stock-Date** is included and surfaced under `RangeBundle.data_warnings`). Severity is intrinsic to the Invariant, not to the Violation instance. Surfaced on the wire as plain dicts so non-Python clients can consume without sharing the enum.
_Avoid_: "error" / "warning" alone (overloaded with logging concepts), "failure" (suggests an exception was raised).

**Stock-Date Range**:
A `(Code, fromDate, toDate)` tuple bounding N consecutive **Stock-Date**s (`fromDate <= toDate`, both YYYYMMDD KST). `fromDate == toDate` is the degenerate single-Stock-Date case; otherwise multiple. The unit the Replay Viewer's `DateRangePicker` produces and the `Workarea` consumes. Distinct from the **Data Window**'s intra-day range (08:40–16:00 of one **Stock-Date**) and from the collector's loop range / scrubber range surfaced via **Capture Frontier**. Maximum span enforced server-side (currently 90 days).
_Avoid_: "date range" (collides with Data Window range and capture loop range — both pre-existing), "range" alone (ambiguous across three meanings now), "selection" alone (what is being selected is unclear — use the compound).

**RangeBundle**:
The Wire Model returned by `GET /api/range` for one **Stock-Date Range** — bundles four pre-aggregated time-series (`candles`, `quote_ratio`, `volume_profile_range` / `volume_profile_by_day`, `fill_strength`) aggregated at the requested **Timeframe**'s `bucket_ms`, plus a `segments` array carrying each in-range **Stock-Date**'s `session_open_ms` / `session_close_ms`. The series with a per-day price-grid binding (`volume_profile_by_day`) ships as a per-segment list; series with flat point arrays (`quote_ratio.points`, `fill_strength.points`, `candles`) are concatenated across segments (the **Regular Session** bounds, in Unix ms per ADR 0003). `len(segments) == 1` is the degenerate single-**Stock-Date** case. The displayed window each segment covers spans the **Regular Session** plus the closing **Auction Window** plus the trailing **After-Hours Trading**. Built in `hoga/api/bundle.py::build_range_bundle`. The frontend hook `useRange(code, from, to, timeframe)` calls this endpoint; the frontend type `RangeBundle` mirrors the Wire Model verbatim per ADR-0004. RangeBundle is the single read-path Wire Model for **Stock-Date Range** queries — there is no separate single-day variant (the prior `SessionBundle` / `/api/session` was retired in ADR-0013; see relationships note below). A fifth series `depth_intensity_by_day` was retired alongside the IntensityPane removal — see the 2026-05-23 Quote Totals Pane design.
_Avoid_: "MultiSessionBundle", "StockDateBundle", dropping the "Bundle" suffix — "the range" alone collides with **Stock-Date Range** and is _Avoid_'d. Canonical reference: "the RangeBundle for {code}/{from}..{to}@{timeframe}".

**Quote Totals**:
The 매수 1–10호가 / 매도 1–10호가 quantity sums per **Timeframe** bucket — the raw orderbook depth metric from which **호가비** is derived. Exposed on the wire as `quote_ratio.points[*].bid_total` and `ask_total`, computed in `hoga/api/bundle.py::build_quote_ratio_slice` via `SUM(bid_q1..bid_q10)` / `SUM(ask_q1..ask_q10)` over each bucket. Rendered by the Replay Viewer's `QuoteTotalsPane` (chart pane 3) as two `LineSeries` — green = bid total, red = ask total — sharing a single auto-scaled price axis so the two values read on the same Y. Quote Totals and 호가비 share one wire field; the field's name reflects the historical (derived ratio) view but the underlying value pair is the primary data.
_Avoid_: "depth totals" (collides with the retired `depth_intensity_by_day` grid), "잔량" alone (ambiguous with broker net 잔량), "bid/ask total" alone (loses the 1–10호가 scope and may be read as a cumulative aggregate over time).

**Volume Profile**:
The per-price-bucket cumulative volume histogram derived from a **RangeBundle**'s trade aggregation — surfaced on the wire as two sibling series with the same shape but different scoping: `volume_profile_range` (one profile spanning the entire **Stock-Date Range**) and `volume_profile_by_day` (one profile per in-range **Stock-Date**, indexed by `segments[i]`). The Replay Viewer's `VolumeProfileOverlay` renders one of the two based on the per-tab `volumeProfileMode: 'range' | 'per-day'` preference; the UI surface for that toggle lives in the Settings modal's "차트" category (relocated from the sidebar header per the 2026-05-23 Volume Profile Settings Relocation design). `range` mode paints a single profile anchored to the right ~30% of the entire viewport; `per-day` mode paints one profile per segment, each anchored to its own segment's right ~30%.
_Avoid_: "volume histogram" alone (collides with the candle-pane volume bars — distinct concept), "bid/ask profile" (loses the trade-volume scope and may be read as orderbook depth), "VP" abbreviation (unclear to readers outside the chart layer).

**호가비**:
The signed bid/ask imbalance ratio derived from **Quote Totals** per **Timeframe** bucket. Positive when asks are heavier (sell-side pressure, formatted "Nx S"); negative when bids are heavier (buy-side pressure, "Nx B"); zero-centered when balanced. Computed frontend-side in `frontend/src/util/imbalance.ts` from `quote_ratio.points[*].{bid_total, ask_total}` and rendered by the Replay Viewer's `RatioPane` (chart pane 2) as a single teal `LineSeries`. Each rendered point passes through two independent mask gates before reaching the series, **applied in distinct ways**: the value-based **Outlier Mask** replaces the point's value with 0 (see ADR-0026), while the time-based **Auction Mask** drops the point entirely and inserts a `WhitespaceData` boundary marker so the line breaks cleanly at 15:20 (see ADR-0029). The two are no longer symmetric in action; they remain symmetric only in predicate-driven activation. Sibling of **Quote Totals** — same source field, different question: 호가비 reads "which side is heavier", Quote Totals reads "how much is on each side".
_Avoid_: "quote ratio" alone (the wire field name; the user-facing concept in Korean is 호가비), "imbalance" alone (ambiguous with **FillStrength**'s buy/sell trade imbalance), "ratio" alone (overloaded across price ratio / time ratio).

**Outlier Mask**:
The composite UI state that gates whether a **호가비** point should be suppressed because its magnitude would dominate the **RatioPane**'s autoscale. Active for a given point iff (1) the per-tab `ratioOutlierFilterEnabled` toggle is `true` AND (2) the chart-label value `1 + |raw imbalance|` is `>=` the per-tab `ratioOutlierThreshold` (default 100, range `[2, 10000]`, integer; expressed in label units — `max(ask/bid, bid/ask)` — to match what the user reads off the Y axis). When active, `projectRatio` emits `value = 0` for that point (the data point is kept on the time axis, not dropped). Sibling of **Auction Mask** in trigger structure — both gate 호가비 visibility — but the **rendering actions differ**: Outlier Mask still emits a value-0 baseline-touch (BaselineSeries's 0-crossing styling reads it as "clamped"), while Auction Mask drops the point and breaks the line (see ADR-0029). The two are applied with logical OR per point; when both fire on the same point, the Auction Mask's "drop + break" wins (no point reaches the series at all). Unlike Auction Mask, Outlier Mask applies to the time-series RatioPane only — not to spot views (e.g. TotalQtyBar). The asymmetry is intentional: outlier suppression exists to keep autoscale honest across a window of points, and a single spot reading has no autoscale to protect; if the cursor sits on an extreme moment the user should see it. The toggle + threshold pair are stored alongside `auctionWindowMask` in **ChartViewPrefs** and surfaced in the Settings modal's "차트" category; the threshold input is dimmed and disabled (but value preserved) when the toggle is off. See ADR-0026 for the frontend-layer / label-unit / user-tunable decisions; ADR-0029 for why the two masks no longer share a rendering action.
_Avoid_: "outlier filter" alone (the user-facing UI label; in prose the masking concept is paired with **Auction Mask**), "ratio clamp" (no clamping happens — values are replaced with 0, not bounded), "outlier rejection" (suggests data deletion; values are masked at render time, never removed from the wire or disk).

**FillStrength**:
The per-**Timeframe**-bucket trade-side imbalance metric — buy-aggressor volume vs sell-aggressor volume — derived from the trade aggregation over a **RangeBundle**. Wire field `fill_strength.points[*].{t, buy_qty, sell_qty}`, computed in `hoga/api/bundle.py::build_fill_strength_slice` by summing per-side `qty` from continuous-trading rows (`side != 0`) bucketed at the requested `bucket_ms`. Rendered by the Replay Viewer's FillStrength pane (chart pane 4) as two `HistogramSeries` sharing a single zero-baseline price axis — buy quantities painted upward in KRX 빨강 (`--price-up`), sell quantities painted downward in KRX 파랑 (`--price-down`) by emitting `-sell_qty` to the same axis. Continuous-trade only — **Auction Cross** rows (`side = 0`) are excluded by the backend filter; the closing **Auction Window** therefore has no points natively. By default, the cross moment's single bar at 15:30 is also visually hidden when `auctionWindowMask` is on (per ADR-0029); when the user toggles the mask off, the cross bar reappears. Sibling of **호가비** in pane-positioning ("how much was traded each way" vs "how much rests on each side"), and distinct from **Volume Profile** in axis ("trade side at time t" vs "trade volume at price p").
_Avoid_: "imbalance" alone (collides with 호가비's bid/ask imbalance — qualify as "체결 imbalance" or "fill imbalance" when needed), "체결강도 막대" alone (loses the buy/sell split; ambiguous after **Cumulative Net Fill** overlay is added), "trade strength" (overloaded with VWAP / momentum readings outside this codebase).

**Cumulative Net Fill** (체결강도 누적):
The per-**Stock-Date** running sum of `(buy_qty − sell_qty)` over **FillStrength**'s bucketed continuous-trade series — a single signed LineSeries overlaid on the FillStrength pane that reads as "which side has been winning the day, and by how much, as of cursor t". Resets to 0 at each `segments[i].session_open_ms`; pre-open and after-hours points (outside `[session_open_ms, session_close_ms]`) are excluded from the sum. Two predicates apply independently in the projector: an **in-session** predicate gates whether a point contributes to the running sum, an **in-viewport** predicate (`axis.contains`) gates whether the resulting cumulative value is emitted to the series — so zooming into mid-session keeps the line starting from the correct 09:00-anchored baseline rather than re-zeroing at the viewport edge. Closing **Auction Window** handling: `runningSum` keeps accumulating from 15:20 onward (in practice no points exist there because **FillStrength** is continuous-trade only — so the sum is unchanged), but emission is suppressed and the line breaks at 15:20 when `auctionWindowMask` is on (per ADR-0029). The legacy "flat through 15:20–15:30 with a jump at the cross" visual is gated behind toggling the mask off. The reset is also made visually explicit at each day boundary by emitting two extra points per segment: a **line break** (lightweight-charts `WhitespaceData` — `time` only, no `value`) one virtual-second before session open so the prior day's last value doesn't draw a diagonal into the new day, and a **zero anchor** at session open (only when in viewport and not pre-empted by an actual fill point at the same timestamp) so the new day's line visibly starts from 0. Rendered with `--fg-dim` (mid gray) — neutral enough to read as "derived signal" without colliding with the **Zero Baseline Guide**'s darker `--fg-dimmer`. `priceScaleId: ''` (invisible overlay scale) keeps the line's magnitude — typically 1–2 orders larger than per-bucket histogram values — from compressing the buy/sell bars on the shared right axis. A **Zero Baseline Guide** is drawn at price 0 to mark the buy/sell-cumulative-pressure transition point. Per-tab `fillStrengthCumulative` toggle (entry in `CHART_TOGGLES` with `category: 'indicators'`, default `true`); surfaced in the Settings modal's "보조지표" category alongside Moving Average.
_Avoid_: "체결강도 라인" alone (overloaded — the histogram is also a series in the same pane), "누적 델타" (델타 is loaded; collides with options Greek and with CVD-style "cumulative delta volume" definitions that differ in side-classification rules), "buy-sell cumulative" alone (loses the per-day reset — could be read as a multi-day running total).

**Zero Baseline Guide**:
A horizontal 0-price reference line drawn on chart panes whose data straddles zero and whose cross-zero moment is itself the signal (sign-flip = polarity reversal). Visual contract: dotted, 1px, neutral color (`--fg-dimmer`), no axis label, no title. Currently rendered by the **RatioPane** (호가비 BaselineSeries draws no line at its `baseValue`, so the reference must be explicit) and the **Cumulative Net Fill** line on the FillStrength pane. Implemented as `addZeroBaselineGuide(series, color)` in `frontend/src/chart/util/zeroBaseline.ts`; a future indicator that needs the same affordance reuses the helper rather than re-asserting the visual contract.
_Avoid_: "baseline" alone (collides with lightweight-charts' `BaselineSeries`, which switches color at its baseValue but doesn't draw a visible line — the Zero Baseline Guide is what closes that gap); "zero line" (too generic — used in trading UIs for unrelated VWAP / pivot references).

**RangeSeriesPane**:
The deep module that owns chart-pane lifecycle for any indicator derived from a **RangeBundle**. Replaces the prior pattern of five near-clone pane components (CandlePane, VolumePane, RatioPane, QuoteTotalsPane, FillStrengthPane), each repeating the same useEffect → addSeries → `axis.contains` filter → `axis.toVirtual` mapping → `setData` → `try { removeSeries } catch` shape with only the per-series projection differing. Takes a **PaneSpec** describing series count, type, options, and a `(bundle, axis, ctx?) => DataPoint[]` projection per series; the module owns the lifecycle invariants (pre-open auction point drop, real-ms → virtual-second mapping, ChartErrorBoundary teardown race guard around `removeSeries`). New indicators add one PaneSpec entry instead of a new component file; cross-cutting policy changes (e.g., a chart-wide setting toggle, a label format change) land in one place. Lives at `frontend/src/chart/RangeSeriesPane.tsx`; the five historical panes survive as named PaneSpec exports (`CANDLE_SPEC`, `VOLUME_SPEC`, `RATIO_SPEC`, `QUOTE_TOTALS_SPEC`, `FILL_STRENGTH_SPEC`).
_Avoid_: "ChartPane" (collides with lightweight-charts' own "pane" terminology), "BundlePane" (loses the per-`paneIndex` series semantic), "SeriesView" (loses the multi-series-per-pane semantic).

**Virtual Axis**:
The stitched, gap-compressed ms time axis on which the Replay Viewer's chart renders. Constructed from a **Stock-Date Range**'s `segments`: each segment's `[sessionOpenMs, sessionCloseMs]` interval is laid end-to-end with a fixed 1-second `INTER_SEGMENT_GAP_MS` separating adjacent segments, so the inter-session **Day Boundary** gap (~17.5 hours of weekday non-trading) collapses to a single second on the axis. The 1-second gap is too small to perceive at any realistic bar spacing but large enough to keep day N's closing candle (`sessionCloseMs`) and day N+1's opening candle (`sessionOpenMs`) on distinct integer-second `UTCTimestamp` values — otherwise lightweight-charts' `setData` rejects the N-1 boundary collisions for multi-day ranges. A real Unix-ms value `t` inside any segment maps to `virtualMs = segments[i].virtualStart + (t - segments[i].sessionOpenMs)`; values in a Day Boundary map to the prior segment's virtual end (the gap "belongs to the day just closed"); values before the first segment map to the axis sentinel (no preceding real time). Lives in `frontend/src/util/virtualAxis.ts` as a frozen factory: `createVirtualAxis(rawSegments)` returns a `VirtualAxis` with `axis.segments` (frozen), `axis.dayBoundaries` (derived), `axis.toVirtual(ms)` / `axis.toReal(ms)` (projections), `axis.findByReal(ms)` / `axis.findByVirtual(ms)` (lookups), and `axis.contains(ms)` / `axis.isInGap(ms)` (predicates). All consumer panes receive `axis: VirtualAxis` as a single prop rather than threading raw `segments`. lightweight-charts receives virtual-ms values directly; tick labels are rebuilt into KST via a custom `tickMarkFormatter` (see spec §6.6(b) — implementation detail kept out of this glossary per grill D4).
_Avoid_: "compressed timeline" alone (ambiguous with replay-speed compression), "virtual time" (ambiguous with synthetic time / mock clocks in tests), "axis" alone (chart has price axis too — always qualify).

**Day Boundary**:
The non-trading gap between two adjacent **Stock-Date**s in a **Stock-Date Range** — from segment `i`'s `session_close_ms` (15:30 KST) to segment `i+1`'s `session_open_ms` (09:00 KST), plus any tail past the final segment's close. Compressed to a 1-second `INTER_SEGMENT_GAP_MS` on the chart's virtual axis (see `util/time.ts`) — visually contiguous but large enough to keep boundary candles on distinct `UTCTimestamp` values — and surfaced as a thick vertical line plus a `MM/DD` chip at each boundary. The frontend predicate `isDayBoundary(segments, realMs)` returns true exactly when `realMs` falls inside such a gap. Distinct from intra-day non-trading periods (lunch break does not exist in KRX continuous trading; pre-open auction at 08:40–09:00 is part of the **Data Window** but outside any segment's **Regular Session** bounds — those are NOT Day Boundaries, they sit before `segments[0].sessionOpenMs`). A **Stock-Date Range** with N segments has N-1 Day Boundaries plus a post-tail region; N=1 has zero Day Boundaries.
_Avoid_: "overnight gap" (collides with after-hours overnight quote moves that aren't part of this codebase's window), "session gap" alone (ambiguous — Regular Session is part of the term).

**Timeframe**:
Chart candle time resolution. Six fixed values: 1m / 3m / 5m / 10m / 15m / 30m. Surfaced as `bucket_ms` on the wire (60_000, 180_000, 300_000, 600_000, 900_000, 1_800_000). All five **RangeBundle** series share the same Timeframe — `candles` re-aggregates OHLC, the other four use their existing `bucket_ms` parameter set to the same value. User-selectable via the Replay Viewer's `TimeframeSelector` in the toolbar. Distinct from **Page Step** (collector loop's `time` increment, write-path concept) and from the Cursor's intra-Stock-Date sampling resolution.
_Avoid_: "interval" (collides with **Page Step**), "resolution" (ambiguous with chart pixel density / display resolution), "bucket" alone (overloaded — `bucket_ms` is fine as a field name, but "the bucket" in prose is unclear).

**StockDateGroup**:
The frontend in-memory rollup of all **Stock-Date**s sharing one **Code** — the unit displayed in the Inventory page's left list (Master-Detail). Carries the grouping key (`code`), display name (`name`), the child `dates: StockDate[]` sorted desc, plus two aggregates used by the left list: `lastCapturedAt = max(captured_at)` (the parent sort key — most-recent first) and `totalSizeBytes = sum(file_size_bytes)`. Built client-side by `useStockDateGroups(rows, search)` from `useStockDates()`'s `StockDate[]` — no backend grouping endpoint. Single-level tree: parent is the StockDateGroup, children are Stock-Dates. Distinct from **Symbol Master** (the catalog of all `(Code, name, market)` from pykrx, including codes that have never been captured); a StockDateGroup exists only for Codes that already have at least one captured Stock-Date.
_Avoid_: bare "StockGroup" (loses what is being grouped — collides with bare "Stock" which is _Avoid_'d), "CodeGroup" (loses the Stock-Date scope and may be read as a grouping of Codes themselves), "inventory entry" (the Inventory page is a page, not a domain concept).

**Disk State Severity**:
The ranked ordering of **DiskStateValue** values by how "bad" the state is for a captured **Stock-Date** — `invalid > client_incomplete > source_partial > complete` (higher rank = worse). Shared SSOT for two consumers that both need to answer "which state is worse?": (1) `aggregateDiskState` in [DiskStateBadge.tsx](frontend/src/inventory/DiskStateBadge.tsx) — picks the worst state across a **StockDateGroup**'s children for the left-list dot, and (2) the Inventory detail table's State column sort (per the 2026-05-25 column-sort design) — orders rows by severity when the user clicks the State header. Exposed as `STATE_SEVERITY: Record<DiskStateValue, number>` in `DiskStateBadge.ts`; changing the order is a one-line edit and both consumers update in lockstep. The `'none'` DiskStateValue does not participate — by construction it never reaches the inventory rows (no `meta.json` means no row at all, per `api/types.ts` comment).
_Avoid_: "disk state priority" (overloaded with task/queue priority), "disk state rank" alone (loses what is being ranked), bare "severity" (overloaded with **Violation** severity which is a different two-level error/warn axis).

**Upstream No-Data**:
The signal that hogaplay's `info.php` endpoint returns HTTP 200 with an empty body for a given (Code, Stock-Date) — meaning the upstream source has no data for that day. Distinct from a network failure (5xx), an auth failure (4xx via `CookieExpiredError`), or a partial **Full Capture** (`SOURCE_PARTIAL`). The system records this signal as a `.no_upstream_data` sentinel file inside `raw/{date}/{code}/` and classifies the **Stock-Date** as `DiskState.NO_UPSTREAM_DATA`; the worker terminates the queue item as `skipped` with `skip_reason="no_upstream_data"`. The sentinel takes precedence over all other disk-state markers — by invariant the directory contains the sentinel alone (other zero-byte artifacts are cleaned up by `_record_no_upstream_data`). `force_retry=True` deletes the sentinel and re-runs the collector, so the state is recoverable when upstream coverage gaps close later. Confirmed trigger case: `003490/20260319` (2026-05-24).
_Avoid_: "missing data" alone (ambiguous with a not-yet-captured **Stock-Date** in `DiskState.NONE`), "empty capture" (collides with `CLIENT_INCOMPLETE` where pages exist but parsing was interrupted), "no-data" alone without the "Upstream" qualifier (the user-facing label "no upstream data" in the calendar legend makes the source explicit; in prose use the compound).

**Symbol Master**:
The catalog of `(Code, name, market)` tuples sourced from pykrx — the lookup layer that lets a user type a Korean name fragment (e.g., "삼성") and resolve it to a **Code** (`005930`). **Disk-persisted** at `~/.local/share/hoga-ops/symbol-master.json` (machine-global XDG path; see ADR-0015) and mirrored in memory by `hoga/api/symbols.py` as module-level state (`_cache`, `_fetched_at_ms`, `_state: SymbolCacheState`) per ADR-0006's single-module pattern. Surfaced through `GET /api/symbols/all` (full catalog with per-Code captured-Stock-Date breakdown), `GET /api/symbols?q=…` (in-memory search), `GET /api/symbols/info` (lightweight metadata for the Settings page), and `POST /api/symbols/refresh` — **the sole pykrx entry point**. Boot and read endpoints never trigger fetches; a fetch happens only when the user explicitly clicks Update (Settings page) or Refresh (SymbolSearch unavailable/stale states). The catalog has no automatic-refresh TTL — staleness is signalled by the Settings page's "Last fetched: N days ago" row and by an empty-result nudge in SymbolSearch when the disk file is ≥ 7 days old. The frontend's `useSymbols()` hook and `SymbolSearch` component (`frontend/src/capture/`) bind to these endpoints. This compound is sanctioned despite the bare "symbol" noun being _Avoid_'d elsewhere — the established class names across backend (`SymbolHit`, `SymbolsAllResponse`, `SymbolMasterInfo`, `SymbolCacheState`) and frontend (`SymbolSearch`, `useSymbols`) make it the canonical term. Do not rename to `CodeCatalog` or `TickerMaster`; the compound is the term.
_Avoid_: bare "symbol" (use **Code** for the 6-digit ticker, or **Symbol Master** for the catalog/lookup layer), "ticker", "symbol list" (use "the Symbol Master" or "Symbol Master entries"), "force re-fetch" (the predecessor 24h-TTL model is gone — refresh is always user-initiated, never "forced" over an automatic schedule). The class names `SymbolHit` and `SymbolSearch` are sanctioned compounds — do not rewrite them in prose as bare "symbol".

**Replay Tab**:
The user-managed container at the top of the Replay Viewer that pairs one **TabSelection** (`code` + `fromDate` + `toDate` + **Timeframe**) with its own per-tab state — chart **ChartViewPrefs** (moving-average slots, **Auction Mask** toggle, **Outlier Mask** toggle + threshold, **Volume Profile** mode), the loaded **RangeBundle**s keyed by `from_date`, the **Cursor**'s current ms, and a transient toolbar draft. Multiple Replay Tabs can be open simultaneously (cap: `TABS_SOFT_CAP = 8`); switching the active tab swaps the entire workarea (chart + **Cursor Sidebar**) to that tab's selection. Lives in `frontend/src/state/tabs.ts` (Zustand store), `frontend/src/replay/TabStrip.tsx` (header strip), and `frontend/src/pages/ReplayViewer.tsx` (orchestration). Identity is an opaque `nanoid(8)` regenerated on hydration — durable identity is the (code, range, timeframe) tuple in `?tabs=…` URL params. Persistence is two-tier: every change writes simultaneously to the URL (shareable, browser-tab-scoped) and to `localStorage["replay.tabs.v1"]` (single-slot last-session snapshot for clean re-entry); on load the URL wins, then localStorage, then a single fresh empty tab. `bundles`, `cursorMs`, `status`, and the toolbar draft are deliberately NOT persisted — bundles refetch via `useRange`, cursor is per-session, status is derived, drafts are pre-commit input.
_Avoid_: bare "tab" without qualifier (collides with browser tab and OS tab), "session" (collides with **Regular Session**), "view" or "workspace" (loses the multi-instance semantic), "panel" (overloaded with **Cursor Sidebar** and lightweight-charts panes). The CSS id `replay-sidebar` and the URL param name `tabs` are sanctioned — do not rewrite them in prose.

**Drawing**:
A user-authored chart annotation persisted to the browser — one of three primitives: **horizontal line** (single price, full chart width), **trendline** (two-point segment), **pencil** (freehand polyline). Every Drawing is **bound to one chart pane** via a stable `paneId: PaneId` (string literal mirroring `PaneSpec.name` — `'candle'`, `'volume'`, `'ratio'`, `'quote-totals'`, `'fill-strength'`); the binding fixes both which clip region it renders into and how its `price` coordinate is interpreted (KRW on the candle pane, share count on the volume pane, signed −1..1 on the ratio pane, etc.). All coordinates are real Unix-ms (ADR-0003) plus pane-relative price, so a Drawing remains valid across different **Stock-Date Range** loads of the same **Code**. Persisted to `localStorage` under `replay.drawings.v1.<code>` (per **Code**, not per **Replay Tab** or per **Stock-Date Range**). Selectable, draggable, and deletable in select mode (body-translate clamps to the origin pane — drawings never visually migrate between panes); created by activating a tool from the **Drawing Menu** in the Replay Viewer toolbar and clicking the destination pane. Lives in `frontend/src/state/drawings.ts` (store) and renders via `frontend/src/chart/DrawingOverlay.tsx` (canvas overlay). See ADR-0024 for the realMs-vs-virtualMs decision and ADR-0028 for the `paneId`-vs-`paneIndex` decision.
_Avoid_: "annotation" alone (overloaded with `data-*` attributes used for E2E selectors), "shape" alone (collides with lightweight-charts' own primitives terminology), "line" (ambiguous across hline / trendline / pencil), "pane-bound Drawing" as a separate kind (pane binding is a property of every Drawing, not a sub-classification).

**Drawing Overlay**:
The canvas layer (`frontend/src/chart/DrawingOverlay.tsx`) above the `lightweight-charts` canvas in `ChartStage` that renders all **Drawing**s and captures pointer events when a **Drawing Tool** is active (or when there are drawings present in select mode). Sibling of **DayBoundaryOverlay** / **AuctionWindowOverlay** in z-stack order; sits at z-20 versus z-10 for the read-only overlays because it consumes pointer events. Mounts a DPR-scaled `<canvas>` and coalesces redraws through a single `requestAnimationFrame` driven by `subscribeVisibleLogicalRangeChange` and a `ResizeObserver`, identical to **DayBoundaryOverlay**'s pattern. Pane-aware: each Drawing renders inside a clip rect computed from its `paneId`, and Y conversion reads from a `Map<PaneId, ISeriesApi>` registry owned by `ChartStage` (each **RangeSeriesPane** registers its first series on mount). Pointer-down picks a `paneId` via cumulative-height lookup; the drag then sticks to that pane (clamp).
_Avoid_: "drawing canvas" alone (loses the React-component identity), "overlay" alone (chart has multiple overlays).

**Drawing Tool**:
The user's currently selected drawing mode — one of `select` / `hline` / `trendline` / `pencil` / `eraser`. **Global** UI state (not per **Replay Tab**, not per **Code**) because it reflects the user's current intent, not data. The **Drawing Menu** button in the toolbar shows the active tool's glyph and reverts to `select` via the menu's "선택" entry or the `Escape` key. When the active tool is `select` the **Drawing Overlay** uses dynamic pointer-events gating (chart pan flows through unless the cursor is over a hit-testable drawing); when any drawing tool is active the overlay captures pointer events outright.

After a drawing tool commits a new **Drawing**, the active tool auto-reverts to `select` **and the just-added Drawing becomes the selected one** — the **Drawing Property Panel** attaches to it and the canvas renders the new shape with selection emphasis (halo + 2× stroke). The companion behaviour from ADR-0030 — clicking on empty chart space in `select` mode clears the current selection — is preserved, so a stale halo cannot linger across an unrelated chart interaction. Chart pan/zoom on that empty-space click is preserved. See ADR-0032 for the rationale and ADR-0030 for the prior, partially-superseded decision. `eraser` is intentionally excluded from auto-revert because continuous erasure of multiple drawings is the common flow. Each tool also has a keyboard shortcut (`Alt+H/T/P/E/V` for hline/trendline/pencil/eraser/select) declared on its spec; the **Drawing Overlay** keydown handler iterates `TOOLS` to dispatch and bails out while any pointer gesture is in flight (drag, trendline draft, or pencil draft) to avoid stranding draft refs in a zombie state.

The deep module that owns per-tool pointer behaviour is `frontend/src/chart/drawing/tools.ts` — each tool is a `DrawingToolSpec` value carrying `{kind, label, glyph, cursor, shortcut?, onPointerDown?, onPointerMove?, onPointerUp?}`. The **Drawing Overlay** dispatches into `TOOLS[activeTool]` per pointer event through a `ToolCtx` (coordinate helpers, hit-test, store actions, draft refs, plus a `revertToSelectMode()` helper that clears `selectedId` and switches the active tool to `select`); the same helper backs the `Escape` keyboard handler so there is one canonical "return to neutral" path. The **Drawing Menu** iterates the `DRAWABLE_TOOLS_ORDER` registry to render its rows. Adding a tool primitive is one new `DrawingToolSpec` plus a `TOOLS` entry — the **Drawing Menu** picks up the new row automatically. Mirrors the **RangeSeriesPane** deepening pattern.

The data-shape side of a primitive (render, hit-test, body-drag translate, hit-threshold) is currently scattered across four switch-on-`d.kind` sites: `drawing/render.ts` (`renderDrawing`), `drawing/translate.ts` (`translateDrawing`), `drawing/types.ts` (`HIT_THRESHOLD`), and `chart/DrawingOverlay.tsx` (`hitTestAt`). The deepening follow-up tracked in `docs/superpowers/specs/2026-05-24-drawing-kind-spec-design.md` introduces a sibling **Drawing Kind Spec** registry (`drawing/kinds.ts`) that collapses these four switches into a single `KIND_SPECS[d.kind].xxx(...)` lookup, so a new primitive becomes truly two registry entries (one in `TOOLS`, one in `KIND_SPECS`) with no edits to **Drawing Overlay**.
_Avoid_: "drawing mode" alone (ambiguous with chart pan/zoom modes), "tool" alone (overloaded across toolbar buttons).

**Drawing Property Panel**:
The floating DOM affordance (`frontend/src/chart/DrawingPropertyPanel.tsx`) that appears when a **Drawing** is selected in `select` mode, lets the user change the selected Drawing's color, stroke width, and line style, and provides a delete button. Sibling of the **Drawing Overlay** in `ChartStage`; both subscribe to `useDrawingsStore` but the overlay handles canvas hit-testing/drag and the panel handles DOM popovers, the property edits, and panel drag-in-DOM. **Visibility gate**: `activeTool === 'select' && selectedId != null` — both clauses required so the panel hides when the user switches to a drawing tool to draft a new shape (the previously-selected drawing's panel must not linger over the draft). On selection change, the panel re-positions in the chart container's local coordinate space near the just-selected Drawing (hline: pane-left + 14px, y(price) − 38px; trendline: midpoint − 38px; pencil: bounding-box top-left − 38px), clamped to the chart container's visible rect. The user can drag the panel via the grip handle; the dragged position lives only in component-local state (session-scoped, no persistence). Three independent popovers (color = 4×4 swatch grid from a fixed sixteen-entry palette, thickness = list of `STROKE_WIDTHS = [1,2,3,4,5]`, line style = list of `LINE_STYLES = ['solid','dashed','dotted']`); at most one popover open at a time, dismissed by outside mousedown or `Escape`. Property edits dispatch `update(id, patch)` and `setDefaults(patch)` so the chosen color/width/style become the **Drawing Defaults** seeded into the next new Drawing of any kind. The post-commit halo + selected state that makes the panel point at a freshly-drawn shape (instead of clearing selection) is the part of ADR-0030 that ADR-0032 supersedes; the empty-click-deselects companion from ADR-0030 is preserved. See ADR-0032.
_Avoid_: bare "panel" (collides with **Cursor Sidebar** which is _Avoid_'d on its own as "panel"; always qualify), "property bar" or "inspector" (Figma terms — this codebase has its own term), "drawing toolbar" alone (collides with the **Drawing Menu**, which is the tool-picker dropdown, not the per-drawing editor).

**Drawing Defaults**:
The sticky `{color, width, lineStyle}` triple the **Drawing Property Panel** seeds into the next new **Drawing** of any kind. Lives as a single slice on the `useDrawingsStore` (`state.defaults`); every property edit through the panel (`update + setDefaults`) updates it, and every drawing-tool constructor in `chart/drawing/tools.ts` reads it for the initial value of a new Drawing. Persisted globally to `localStorage["replay.drawingDefaults.v1"]` (no per-**Code** scoping — the user's color preference is a tool preference, not a per-stock annotation). Debounced 250ms on write, same pattern as the per-Code Drawing persistence. On absent or unreadable key, falls back to `INITIAL_DEFAULTS = { color: '#14B8A6', width: 2, lineStyle: 'solid' }`.
_Avoid_: "default style" alone (ambiguous with `DESIGN.md`'s system tokens), "last-used settings" (overloaded with chart **ChartViewPrefs** and **TabSelection** carry-over), "sticky settings" (technical jargon).

## Relationships

- A **Stock-Date** has exactly one **Data Window** and exactly one **Full Capture**.
- A **Stock-Date**'s **Regular Session** sits inside its **Data Window**.
- A **Full Capture** is built from N **Pages**; consecutive Pages may overlap.
- The collector captures the entire **Data Window**; UI and analysis default to the **Regular Session** but can extend to the **Data Window**.
- Each Parquet table has one **Entity** type (for the parser write path) and one **Wire Model** type (for the API read path). Both live in the same `hoga/tables/*.py` module.
- A **Stock-Date Range** contains N consecutive **Stock-Date**s (N ≥ 1). The **RangeBundle** is its sole read-path Wire Model; the prior single-day `SessionBundle` was retired in ADR-0013 in favor of unifying the read path on RangeBundle. Each in-range **Stock-Date** appears as one element of `RangeBundle.segments` carrying that day's **Regular Session** bounds; series data is concatenated across segments on a stitched virtual axis.
- A **Drawing** belongs to one **Code**. Same-**Code** **Replay Tab**s render the same Drawings because both subscribe to the same `byCode.get(code)` slice of the store. Switching the active **Replay Tab** to a different **Code** swaps the **Drawing Overlay**'s render list and resets `selectedId`.
- The **Drawing Property Panel** is visible iff `activeTool === 'select'` and a **Drawing** is selected. Editing color / width / line style through the panel writes simultaneously to that Drawing (per-Code persistence) and to **Drawing Defaults** (global per-user persistence), so the next new Drawing inherits the style. **Drawing Defaults** is the only piece of Drawing-related state that does not live under a `byCode` slice.

## Flagged ambiguities

- "session" was used ambiguously to mean both **Regular Session** (info.tsv's `session_open`/`session_close` fields) and **Data Window** (collector loop range, scrubber range) — resolved 2026-05-19: these are distinct, use the precise term.
- "cursor" was used in early Capture UI mockups to label the collector's progress marker; this clashes with the API/UI **Cursor** — resolved 2026-05-21: in-flight progress is **Capture Frontier**, **Cursor** is reserved for read-path API/UI use.
- "symbol" was used as a bare noun in early `symbols.py` code and the 2026-05-22 KRX env spec — clashes with the **Code** glossary entry that _Avoid_'s "symbol" — resolved 2026-05-22: bare "symbol" remains _Avoid_'d (use **Code** for the 6-digit ticker), but the compound **Symbol Master** is sanctioned as the catalog/lookup-layer term, mirroring the **SessionBundle** precedent. Class names `SymbolHit`, `SymbolsAllResponse`, `SymbolSearch`, `useSymbols` are sanctioned compounds — not renamed.
