# 창 간 동기화 `/browse` QA 전략

크로스헤어 · 기간 · 줌 동기화를 실브라우저로 검증할 때 쓰는 절차와 도구.
드라이버는 [`chart-sync-qa.driver.js`](chart-sync-qa.driver.js).

이 문서는 취향이 아니라 **실제로 거짓 결론을 낸 지점들**의 기록이다(2026-08-21).
넷 다 "테스트는 초록인데 브라우저에서 아니다" 가 아니라 **"브라우저에서 쟀는데 답이
틀렸다"** 쪽이라, 도구를 바꾸지 않으면 다시 밟는다.

## 여섯 규칙

### ① 좌표로 조준하지 말고 **그 창 서브트리 안에서** 히트테스트한다

`document.elementFromPoint(x, y)` 는 **화면 맨 위** 요소를 준다. `/live` 워크스페이스는
창이 겹치므로 뒤 창을 조준할 방법이 없다 — 실제로 앞 창을 휠질해 놓고 "그룹 게이트가
샌다" 는 거짓 결론을 냈다.

캔버스에 직접 dispatch 하는 것도 안 된다: lwc 는 캔버스가 아니라 그 위에 덮인
**이벤트 오버레이**에 리스너를 걸어서, 캔버스는 그 오버레이의 **형제**라 버블링으로도
안 닿는다(실측: 드래그·호버 둘 다 무반응).

정답은 `elementsFromPoint`(복수) + 서브트리 필터 — `__qa.hit(id)` 가 그것이다.

### ② `hover` 명령을 쓰지 않는다

요소 **중심**을 노리므로 큰 캔버스가 옆 창에 가리면 actionability 5s 타임아웃이 난다.
`__qa.hoverAt(id, fx)` 가 enter+move 시퀀스를 좌표 지정으로 쏜다(단일 `mousemove` 로는
lwc 크로스헤어가 안 걸린다).

### ③ **음성 결과는 탐침이 양성을 낼 수 있음을 확인한 뒤에** 믿는다

"크로스헤어가 안 온다" 를 두 번 냈는데 두 번 다 **탐침이 틀렸다.**
`chartElement().parentElement.querySelector('[data-testid=study-cursor-sync]')` 는 항상
`false` 다 — 오버레이가 그 박스 아래에 없다. 전역으로 세어 보니 1개가, 그것도 옳은
창에 떠 있었다(2026-08-21).

`__qa.syncOverlaysAll()` 로 **전수와 소속을 먼저** 보고, 그 다음에 창별 판정을 쓴다.
같은 규칙이 아래 ④에도 적용된다 — 발행이 없는 것과 게이트가 막은 것은 다르다.

### ④ 끝점만 보지 말고 **버스를 본다**

`window.__liveCursorStore`(dev 전용)로 `syncRange` 를 직접 읽는다. 이게 없으면
"발행자는 움직였는데 소비자가 안 움직인다" 에서 원인을 **가정으로만** 좁히게 된다 —
발행이 없는가 · 게이트가 막았는가 · 적용이 실패했는가가 구별되지 않는다.

그룹 게이트 검증이 이 구별 위에 선다: `발행=True` 인데 소비자 불변이어야 "게이트가
막았다" 가 증명된다. 발행조차 없으면 아무것도 증명하지 못한다.

### ⑤ 창별 차트 핸들을 쓴다

`window.__liveChart` 는 **마지막 생성 차트**만 가리킨다. 창이 여럿이면 원하는 창을
읽을 수 없어, 한때 소비 창을 읽으려고 봉을 W→D 로 토글해 차트를 **재생성**시켰다 —
관측이 관측 대상을 바꾸는 오염이다. `window.__liveCharts`(창 id → `IChartApi`)를 쓴다.
`chartElement()` 로 DOM 까지 내려갈 수 있어 ①의 히트테스트도 여기서 나온다.

### ⑥ 자극과 관측을 **계약의 해상도**에 맞춘다

세 가지가 각각 물린다.

- **자극이 계약보다 작으면 안 움직이는 게 정답이다.** 분봉→일봉 다리는 **날짜**다.
  같은 날 안에서 143봉을 팬해도 일봉은 안 움직인다 — 버그가 아니다.
- **소비 창이 넓으면 며칠 이동이 안 보인다.** 일봉이 8개월을 보여주고 우측 클램프에
  붙어 있으면 대상 날짜가 계속 화면 안이라 움직일 이유가 없다. 검증 전에
  `setVisibleLogicalRange` 로 **좁혀 둔다**(폭 60 정도).
- **줌은 클램프 바닥·천장을 피해서 잰다.** 폭 10에서 확대는 `MIN_FOLLOW_SPAN_BARS`
  에 걸려 무변화가 정답이다.

**논리 인덱스는 백필 prepend 로 밀린다** — 발행자의 이동량은 `getVisibleRange()`
(시각)로 재고, 소비자의 위치·폭은 논리 범위로 잰다.

## 절차

```bash
B=/home/dev/.claude/skills/gstack/browse/dist/browse
# 드라이버는 단일 식이어야 한다 — IIFE 로 감싸서 주입
python3 -c "import io;s=io.open('docs/agents/chart-sync-qa.driver.js',encoding='utf-8').read();\
io.open('/tmp/d.js','w',encoding='utf-8').write('(() => {\n'+s.replace(\"'driver ready'\",\"return 'driver ready';\")+'})()')"
$B js "$(cat /tmp/d.js)"
$B js "(() => { window.__D=__qa.find(m=>m.tf==='D'); window.__M=__qa.find(m=>m.tf==='1m');
  return { daily: __qa.verify(__D), minute: __qa.verify(__M) }; })()"   # ← 조작 전 반드시
```

`verify()` 를 건너뛰지 말 것. 그게 ①의 거짓 결론을 막는 유일한 장치다.

## 매트릭스 (2026-08-21 실측)

일봉 폭을 60으로 좁히고, 분봉만 조작했다.

| 구성 | 조작 | 자극 | 발행 | 일봉 `from/span` |
|---|---|---|---|---|
| g1 → g1, 줌 OFF | 드래그 팬 | ✓ | ✓ | `231/10 → 227/10` (위치만) |
| g1 → g1, 줌 OFF | 휠 확대 | ✓ | ✓ | 폭 불변 |
| g1 → g1, 줌 ON | 휠 확대 ×6 | ✓ | ✓ | `180/60 → 215/30` (정확히 절반) |
| g1 → g1, 줌 ON | 휠 축소 ×6 | ✓ | ✓ | `215/30 → 185/60` (원복) |
| **g1 → g2** | 드래그 팬 | ✓ | **✓** | **불변** |
| **g1 → g2** | 휠 확대 ×6 | ✓ | **✓** | **불변** |
| **g1 → g2** | 호버 | ✓ | — | 오버레이 **없음** |

마지막 세 줄이 창번호 게이트의 증거다 — **발행은 되는데** 소비가 막힌다.
