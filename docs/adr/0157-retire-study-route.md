# 0157 — `/study`(복기) 라우트 폐지 — 저장뷰는 `/live` 가 연다

**Status:** accepted (2026-08-23) — **ADR-0123·0155 를 supersede, ADR-0077·0144·0149 를
부분 supersede.**

## 무엇을 뒤집고 무엇을 남기는가

**무효가 되는 것:**

- **ADR-0077 의 「별도 라우트」 결정** — 저장뷰는 이제 `/live` 의 차트 창에서 열린다.
  그 ADR 의 v1 레거시 절도 함께 무효다: v1 **스냅샷 학습뷰**는 스키마가
  `Literal[2]` 하나가 되면서 이미 소멸했고(백엔드 `models.py` · 프론트
  `api/studyViews.ts`), 이 삭제 이전부터 그랬다.
- **ADR-0123 전체** — 창 워크스페이스가 붙어 있던 페이지가 사라졌다. `study.workspace.v1`
  키는 **승계 전용**으로만 남는다(아래 §잔여).
- **ADR-0155 전체** — 링크 그룹(그룹 → 저장뷰)은 수락 이틀 만에 그 페이지와 함께
  사문화됐다. 「저장뷰 여럿을 한 화면에」라는 워크플로를 **유지하지 않는다**는 것이
  2026-08-23 사용자 결정이고, 이 ADR 의 실질 내용이다.
- **ADR-0149 §Decision 2 의 잔재** — `study.activeView.v1` 은 0155 가 이미 승계 전용으로
  내렸고, 이제 그 승계 대상도 없다.

**그대로 남는 것** (0077·0144·0149 의 `Status` 를 `accepted` 로 두는 이유다):

- **ADR-0077 의 v2 재현 계약** — 저장뷰는 *동결된 화면*이 아니라 **기간의 좌표**다:
  종목·봉·구간·뷰포트·메모·태그를 저장하고, 열 때 range/candle API 로 그 기간을 다시
  받아 **오늘의 지표 셋업**으로 분석한다. 재현성의 뜻은 "같은 저장 구간"이지 "같은
  지표 출력"이 아니다. **이 계약은 그대로이고 무대만 `/live` 로 옮겼다.**
- **ADR-0144 의 KRX 고정** — 저장뷰가 걸린 창은 전역 거래소 선택과 무관하게 KRX 다.
  가장 눈에 안 띄는 생존자라 명시한다: 상수가 `savedRangeFocus.ts` 의
  `SAVED_RANGE_VENUE = STUDY_VENUE` 로 남아 **같은 상수를 참조**한다. 근거도 그대로다
  — `SOURCE_VENUES` 에서 `hogaplay = {KRX}` 이고 디스크의 78%가 hogaplay 라, NXT·통합을
  요청하면 그 소스가 후보째 빠져 빈 응답이 온다. 창 헤더가 전역 선택과 어긋나므로
  칩에 「KRX 기준」을 병기하는 것도 유지.
- **ADR-0149 의 탭 판정** — 탭 스트립은 돌아오지 않는다. `disposition`·`[`/`]` 탭 순환도
  마찬가지다. 여기서 「탭」은 **브라우저 탭**만을 뜻한다.
- **ADR-0149 §7 의 `?view=` 딥링크가 저장뷰 전환의 정식 경로라는 것** — 경로만
  `/study?view=` → **`/live?view=`** 로 바뀐다.
- **봉의 소유자는 차트 창이라는 것**(#1326). 페이지가 사라져도 갈리지 않는다.

**직교하므로 건드리지 않는 것**: ADR-0145·0146·0152(창별·페이지별 지표 스코프). 그
축들의 `'study'` 값은 이제 **거주자가 없지만** 기존 사용자의 영속 데이터가 그 경로를
타므로 코드에 남긴다(§잔여).

## Context — 왜 지금인가

**진입로가 먼저 사라졌다.** 2026-08-21(#1452) 사용자 결정으로 저장뷰 행 클릭·Enter·행
메뉴 「열기」의 목적지가 전부 `/live` 로 옮겨갔다. 그 시점에 `/study` 로 가는 길은
ctrl/⌘+클릭(새 브라우저 탭)과 상단 nav 뿐이었고, 코드 주석이 이미 다음 단계를 적어
두고 있었다 — *"`/live?view=` 딥링크는 `/study` 제거 시 함께 만든다."*

**기능 델타를 1차 출처로 세어 보니 사실상 0 이었다.** 문서가 기록한 최대 차이 —
*"`/study` 만 캘린더 봉에서 호가 지표를 본다"*(CONTEXT.md) — 는 **코드에서 이미 사라진
서술**이었다. `useStudyReferenceBundle` 이 쿼리 입력의 봉을 창이 표시 중인 봉으로 덮고,
`studyReferenceQueryInputs` 가 캘린더 봉이면 `code: null` 을 내며,
`rangeRequest` 가 그것을 `enabled=false` 로 막는다. 즉 두 페이지 다 D/W/M 은 캔들+거래량
뿐이었다. 그 병합 경로는 **액면분할 종목에서 봉 하나가 1/5 로 튀는** 문제로 제거됐고,
문서만 남아 있었다.

**유지 비용은 쌍둥이 세금이었다.** 최근 60일 `frontend/src/studyViews/` 를 건드린 커밋
243건 중 **133건(55%)이 `frontend/src/live/` 를 함께 건드렸다.** 두 페이지가 같은 차트
창·같은 워크스페이스·같은 지표 스토어를 쓰면서 소유권 축만 갈라져 있어, 기능 하나가
들어올 때마다 "이 축은 페이지별인가 창별인가"를 두 번 결정하고 두 번 배선했다.
ADR-0145·0146·0152 가 그 결정의 화석이다.

## Decision

`/study` 라우트·nav 항목·페이지 구현을 삭제한다. **저장뷰 도메인은 삭제하지 않는다** —
백엔드 `/api/study-views/*`, 저장 파일, 우측 레일 드로어, 차트 창의 저장 버튼, 저장
구간 밴드·착석은 전부 그대로다. 사라지는 것은 **그것을 여는 두 번째 페이지**다.

### 능력 이전 지도

| `/study` 가 갖던 것 | 어디로 갔나 |
| --- | --- |
| `?view=` 딥링크 | **`/live?view=`** (`useSavedRangeDeepLink`). 종목 활성화 → 기간 슬롯 순서가 계약 |
| 저장뷰 열기(행 클릭·Enter·메뉴) | 이미 `/live` (2026-08-21, #1452) |
| ctrl/⌘+클릭 새 탭 | 같은 `/live?view=` 로 통일 — 그전엔 같은 행의 두 제스처가 갈렸다 |
| 메모 편집 | **드로어 인라인 편집** (이전부터 존재) |
| 미캡처 안내 | **저장 구간이 걸린 차트 창** (`showNotCapturedNotice`). 근거가 페이지가 아니라 *구간을 사용자가 명시했다*는 성질이었으므로 조건이 그대로 옮겨간다 |
| 열린 저장뷰 하이라이트 | `livePage.savedRangeFocus` 슬롯 — 그룹 맵이 아니라 **하나** |
| KRX 고정 재현 | `SAVED_RANGE_VENUE` (ADR-0144, 위) |
| 저장 구간 클립 | **뷰포트 이동**(착석). `/live` 차트는 실시간 스트림을 함께 받아 클립할 수 없다 — 계약은 「데려다주되 가두지 않는다」 |
| 저장뷰 여럿 나란히 | **없앤다** (ADR-0155 supersede) |
| `/study` 레이아웃 프리셋 | 없앤다. `/live` 프리셋은 무관 |

옛 `/study` 북마크는 `/live` 로 리다이렉트하며 **`?view=` 를 들고 간다.** 쿼리를 버리는
리다이렉트면 저장뷰 딥링크가 종목 없는 `/live` 가 되므로, 그 한 가지를 e2e 가 지킨다
(`tests/e2e/study-route-retired.spec.ts`).

### 잔여 — 나중에 걷은 것 (**후속 PR 에서 완료**)

**한 페이지짜리로 남은 일반화**는 삭제 PR 에서 걷지 않고 후속으로 넘겼다. 그 후속이
완료됐고, 결과는 셋이 갈렸다:

- **걷었다** — `IndicatorPageScope`(`'live' | 'study'`). 마이그레이션은 **필요 없었다**:
  `persistIndicators` 가 스토어에서 필드를 명시로 조립하므로, 정규화가 안 읽고 거기서
  안 쓰면 저장된 `studyByTimeframe` 키가 **다음 쓰기에 자연 소멸**한다(그 성질에 가드를
  달았다). 단 `byWindow` 키의 **`live:` 접두는 남긴다** — 그건 축이 아니라 영속 키의
  화석이고, 떼면 기존 창별 설정이 전부 조회 불가가 된다.
- **걷었다** — `WindowWorkspaceAdapter` 주입 seam(#907). 훅들이 `useWorkspaceStore` 를
  직접 본다. seam 이 막던 결함("훅이 조용히 다른 스토어를 봄")은 스토어가 하나가 되며
  **구조적으로 불가능**해졌다.
- **걷었다** — `h-live-header` 토큰. 이 리포 토큰 표의 첫 삭제다. 지우며 확인된 것:
  마지막 소비처마저 `min-h-12` 를 얹고 있었으므로 **한 번도 화면 높이를 정한 적이 없다**.
- **걷지 않았다 — 애초에 걷을 것이 아니었다**: `workspace/zOrder.ts` · `groupId.ts`.
  분류가 틀렸다. `zOrder` 는 제네릭 16줄 순수 함수이고 `groupId` 는 `/live` 링크 그룹의
  현역 모듈이다 — 「거주자가 하나」가 「걷어야 한다」를 자동으로 함의하지 않는다.
  낡은 것은 코드가 아니라 **도크스트링**이었고 그것만 고쳤다.

`state/indicatorsWindowMigration.ts` 는 **의도적으로 `study.workspace.v1` 을 계속 읽는다**
— 1회성 승격 사다리를 아직 안 거친 사용자가 있고, 빼면 그 사용자의 지표가 공장값으로
회귀한다. 상수는 그 모듈 지역 리터럴로 내렸다.

목록과 근거는 `docs/superpowers/plans/2026-08-23-study-page-deletion-review.md` §9-4 에
있다. 여기서 되풀이하지 않는다.

## Consequences

**얻는 것**: PR #1509 전체로 101 파일 **+1,008 / −10,400** 라인(삭제 커밋 단독은
83 파일 +442/−10,207). 「이 축은 페이지별인가 창별인가」라는 질문이 사라진다 — 위 쌍둥이 세금의 원천이다. 초기 로드는 **−8.1 KB** 로, 지운 라인 수에 비하면
작다(페이지 구현이 원래 lazy 청크였고, 초기 그래프에 있던 것은 드로어가 끌어오는
잔존 파일이다. CLAUDE.md 가 인용하는 「study-views 72KB」는 **청크 크기**이지 초기 로드
몫이 아니다).

**잃는 것**: 저장뷰를 한 화면에 여럿 펼치는 워크플로. 되살리려면 `savedRangeFocus` 를
창(또는 그룹)별 슬롯으로 승격해야 하고, 그건 삭제가 아니라 이식이다.

**감수하는 위험**: 대체 경로가 굳지 않았다. 저장 구간 착석/벽은 2026-08-21 하루에
도입 → revert(#1457) → 재도입(#1461) 을 겪었고, 현행 계약은 그날 정해졌다. 사용자가
소킹 없이 한 PR 을 택한 결정이며, 되돌리기는 그 PR 의 revert 하나다.

**삭제가 조용히 죽일 뻔한 것**: `showNotCapturedNotice` 는 `true` 를 주던 유일한 곳이
페이지였다.

> **후속 (2026-08-23)**: 그때 급히 옮긴 배선(`savedRange !== null`)이 **축을 잘못
> 잡았다.** 같은 파일의 형제 술어 둘(`isSavedRangeSubject` · `savedRangeFreeze`)과
> 달리 「저장뷰가 열려 있기만 하면」이라, 저장뷰와 무관한 다른 종목 창까지 자기 평소
> 구간의 미캡처를 말하게 됐다 — 이 함수가 애초에 막으려던 소음 그 자체다. 별도 프롭을
> 없애고 **`savedRangeFrozen` 에서 파생**하도록 고쳤다(얼린 창은 fetch 범위가 곧 저장
> 구간이다). 프롭이 사라져 「켜는 사람만 없어지는」 재발도 어려워졌고, `LiveChartRoot`
> 하네스로 양방향 가드가 붙었다. 프롭·파생·순수 함수·그 테스트가 전부 남고 **켜는 사람만 사라지는** 모양
이라 타입체크도 테스트도 빨개지지 않는다. 라우트 삭제에서는 *"이 기능을 켜는 곳이 아직
있는가"* 를 컴파일러가 아니라 **손으로 세야 한다** — 같은 grep 에서 `WorkspaceShell` 의
프리미티브 4개도 소비처 0 으로 나왔다.
