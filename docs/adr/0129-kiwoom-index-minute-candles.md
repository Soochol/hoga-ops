# ADR-0129 — 지수 분봉만 키움 REST로 이관 (KIS 102행 상한 우회)

- 상태: 채택 (2026-07-29)
- 관련: **ADR-0080(지수 분봉은 walk-back이 아니라 source-unit 선택 — 본 ADR은 이를
  뒤집지 않고, 그 "Trigger Conditions" 4번째 항목의 발동으로서 KIS 밖으로 나간다)**,
  ADR-0116(키움 WS 병행 브로커 — 그 "REST 분담" 절을 다시 개정),
  ADR-0120(키움 분봉 walk-back 제거 — 기각 논거의 적용 범위를 좁힌다),
  ADR-0039(source preference = 선호+폴백), ADR-0109(소스 사다리 문법)
- 실측: `docs/research/2026-07-29-kiwoom-index-minute-tr-spec.md`
- 선행 PR: #939(지수 분봉 커버리지 3배 + 장중 갱신 복구)

## 배경

`/live` 에서 지수를 고르면 분봉이 "fetch 되지 않는" 것처럼 보였다. 원인 3개 중 둘은
#939 로 해결했고(소스 주기 다운샘플, 오늘 창 TTL 부재), **하나가 코드로 우회 불가한
채 남았다.**

KIS 업종분봉 `FHKUP03500200` 의 `FID_INPUT_HOUR_1` 은 종목분봉 `FHKST03010230` 과
**의미가 다르다**. 종목 쪽은 시각 앵커(HHMMSS)라 페이지를 시간 주소로 걸어갈 수
있지만(`_minute_page_anchors`), 업종 쪽은 **주기 선택자**라 시간 커서가 없다. 어떤
주기를 넣어도 응답은 **최신 102행 고정**이고(목록 밖 값은 0행), 요청 날짜 범위를
넓혀도 과거가 채워지지 않는다.

결과적으로 **1분봉은 최근 ~102분이 하드 상한**이다. 프론트는 5거래일을 요청하는데
오늘 100봉만 온다. 좌측 팬 백필은 매번 새 `(from,to)` 로 캐시를 미스시키며 같은
102행을 다시 받는 헛일이 된다.

### ADR-0080 이 이미 여기까지 와 있었다

이 계약은 **새 발견이 아니다.** ADR-0080(2026-06-23)이 같은 결론에 먼저 도달했다 —
`FID_INPUT_HOUR_1` 은 조회 커서가 아니라 source unit이고, `FID_INPUT_DATE_1` 을 넣어도
무시되며, `tr_cont` 를 강제해도 같은 102행이 반복된다. KIS 내 다른 후보
(`FHPUP02110200` 시간별지수(분) · `FHPUP02110100` 시간별지수(초) · `FHKST03010200`
+`FID_COND_MRKT_DIV_CODE=U`)도 그때 전부 실측해 기각했다(앞의 둘은 빈 `output`, 마지막은
30행으로 더 얕음).

그래서 ADR-0080 은 **KIS 안에서 할 수 있는 최선**을 정했다: 표시 timeframe별로 가장 넓은
exact source unit을 고르고 필요할 때만 상위 버킷으로 aggregate. 그리고 그 한계를 스스로
명시했다:

> 진짜 장기 지수 분봉 이력이 필요하면 **별도 source가 필요하다**: KIS 실시간 index
> stream을 자체 축적하거나, KRX/벤더/DB feed를 도입해야 한다.

또한 재검토 트리거 4번째로 **"제품 요구가 'KIS REST 최신 page' 수준을 넘어 장기 지수
intraday history를 필수로 요구한다"** 를 걸어 두었다. 본 ADR 은 그 트리거의 발동이다.
ADR-0080 의 판단은 **KIS 안에서는 여전히 옳다** — 본 ADR 은 그것을 뒤집지 않고, KIS
밖에 ADR-0080 이 예견한 "별도 source"가 실재함을 확인해 채택한다.

### #939 가 ADR-0080 의 매핑 표를 갱신했다 (문서 미반영)

ADR-0080 의 원칙("가장 넓은 exact source unit")은 옳았지만 **후보 집합이 불완전했다.**
당시 실측한 단위는 `30`·`60`·`120`·`300`·`600`·`3600` 이었고 **`180`·`900`·`1800` 은
시험되지 않았다.** 그래서 3m→`60`, 15m→`300`, 30m→`600` 으로 잔 소스를 고르고 aggregate
하는 표가 만들어졌는데, 102행 상한이 고정이므로 이는 커버 구간을 정확히 1/3로 깎는다.

2026-07-29 실측에서 `180`·`900`·`1800` 이 모두 유효함이 확인돼 #939 가 매핑을 표시 버킷
그대로로 고쳤다(3m 34→100봉, 15m 34→94봉, 30m 34→88봉). **이는 ADR-0080 의 원칙을 더
정확히 실현한 것이지 뒤집은 것이 아니다.** 다만 ADR-0080 본문의 매핑 표는 지금 코드와
어긋나 있으므로 갱신이 필요하다(§후속).

키움 `ka20005`(업종분봉조회)를 **실콜로 검증**한 결과 이 상한이 사라진다:

| | KIS `FHKUP03500200` | 키움 `ka20005` |
|---|---|---|
| 페이지당 | 102행 (하드 상한) | **900행** |
| 시간 커서 | **없음** | `cont-yn` / `next-key` 동작 |
| 1분봉 커버 | 최근 ~102분 | 1페이지 2.1거래일, 3페이지면 5거래일 |
| 30분봉 커버 | 6거래일 | **3개월 (1콜)** |
| 응답 시간 | — | 97~213ms |

오늘 KOSPI 1분봉에서 KIS 와 겹치는 89봉 중 **88봉 OHLC 완전 일치**. 유일한 차이는
15:30 종가(KIS 5663.08 / 키움 5663.24)인데 **키움 값이 화면 최종 종가와 맞다**.

### 이것이 개정하는 정책

ADR-0116 의 REST 분담 절은 이렇게 적었다:

> 나머지 REST(일봉·스크리너 배치·거래원·프로그램·**지수**·투자자·캘린더·토큰) 전부
> KIS 잔류 — 상시·대량은 KIS 유량(15/s×4)이 강점, 키움 1/s 는 퇴보.

"지수"가 명시적으로 KIS 잔류 목록에 있다. 그러나 그 **근거 두 개가 지수 분봉에는
적용되지 않는다**:

- "상시·대량" — 지수 분봉은 대상이 **5개 고정**이고 3분봉 이상은 1콜로 끝난다.
  상시·대량의 정반대(희소·소량·유계)다.
- "키움 1/s 는 퇴보" — 퇴보할 기준선이 없다. KIS 는 1분봉 과거를 **아예 못 준다**.

또한 ADR-0120 의 "**키움의 REST 소비자는 이제 없다**"는 서술은 이미 사실이 아니다.
현재 키움 REST TR 이 5개 돌고 있다:

| 모듈 | 경로 | TR | 도입 |
|---|---|---|---|
| `kiwoom_stock_info` | `/api/dostk/stkinfo` | `ka10001` | #772 |
| `kiwoom_rankings` | `/api/dostk/rkinfo` | `ka10027`/`10023`/`10030`/`10032` | #823 — **ADR-0120 이후** |

순위 4종은 ADR 갱신 없이 들어갔다. 본 ADR 은 `ka20005` 를 추가하면서 **그 서술까지
현실에 맞게 정정한다.**

### ADR-0120 기각 논거의 적용 범위

ADR-0120 은 **종목** 분봉(`ka10080`)을 세 근거로 제거했다. 지수에 대입하면:

| ADR-0120 근거 | 지수에 적용되는가 |
|---|---|
| ① 랜덤 액세스 불가 — 임의 과거에 닿으려면 매번 '오늘'부터 재순회 | **약화.** 대상이 5개 고정이라 임의 종목 점프가 없고, KIS 에 대안 자체가 없다("느림" vs "불가능") |
| ② 직렬 + 1 req/s → 팬 전체 O(D²) | **약화.** 3분봉 이상 1콜, 1분봉 5거래일도 3페이지. 46거래일을 걸을 일이 없다 |
| ③ 순회분 폐기 — pending 날짜만 저장하고 나머지 버림 | **회피 가능.** 구현 실수였다. 900행을 통째로 적재하면 재순회가 없다 |

ADR-0120 은 여전히 **종목 분봉에 대해 유효하다.** 본 ADR 은 그것을 뒤집지 않고,
적용 범위가 "3000종목 인터랙티브 팬"이었음을 명시한다.

## 결정

**지수 분봉(1m~30m)의 소스를 키움 `ka20005` 로 한다.** 지수 D/W/M 과 그 밖의 REST 는
ADR-0116 대로 KIS 에 잔류한다.

### D1 — 새 추상화를 만들지 않는다

포트는 **이미 있다**. `collect_index_minute_candles_with_cache(cache, key, from, to,
fetch_batch)` 의 `fetch_batch: (from_s, to_s) -> IndexCandleFetchResult` 가 그것이고,
캐시·집계·경고 파이프라인은 이미 누가 fetch 하는지 모른다. 키움 어댑터를 이 자리에
꽂는다.

`LiveCollector` 류의 Protocol 추출은 **하지 않는다** — ADR-0116 이 "지금(N=2)은
Adapter 만, Protocol + waterfall 은 3번째 증권사 때(Rule of Three)"로 정해 두었고,
그 조건은 아직 오지 않았다.

### D2 — 결과 타입 2개를 중립 모듈로 옮긴다

이것이 **유일한 실제 리팩터**다. `IndexCandleFetchResult` 와
`DailyInvariantViolation` 이 지금 `kis_endpoints.py` 에 있는데, 이 모듈은 **KIS HTTP
어댑터 그 자체**라 키움 어댑터가 import 하면 ADR-0116 규율 1(상호 import 금지) 정면
위반이다. WS 쪽 `ticks.py`(`WsTick`)와 같은 자리 — 접두 없는 중립 모듈
`candle_fetch_result.py` 로 옮기고 `kis_endpoints` 는 re-export 로 하위호환을 유지한다.

`DailyCandleFetchResult` 도 함께 옮긴다. 셋이 같은 `DailyInvariantViolation` 을 참조하는
한 덩어리라, 둘만 옮기면 정의가 두 모듈에 갈려 "이 타입은 어디 있나"가 매번 헷갈린다.

`IndexCandlePoint`(`kis_models.py`)는 **옮기지 않는다.** 바로 옆 `KisCandle` 이
"브로커 중립 캔들 포트 — 이름의 Kis 는 역사적이다. 리네임은 22개 사용처 파급이라
보류 — 이 주석이 실체를 말한다"로 이미 선례를 세웠다. `kis_models` 는 어댑터가 아니라
모델 모듈이므로 같은 처리로 일관성을 지킨다.

### D3 — 소스 선택은 정적, 런타임 폴백 사다리는 만들지 않는다

요청마다 `try 키움 except KIS` 로 떨어지는 사다리를 **금지**한다. 소스는 부팅·설정
시점에 정해지고, 한 요청 안에서 브로커가 바뀌지 않는다.

- 키움 자격증명 있음 → 분봉은 키움
- 없음 → KIS (현행 동작 그대로 · degraded)

근거 셋:

1. **값이 미세하게 다르다.** 실측 15:30 종가 불일치 — 병합하거나 구간별로 소스가
   갈리면 **경계에서 값이 튄다.**
2. **선례.** `useLiveBundle` 은 "캔들 소스의 유일한 분기 축(4옵션 우선순위-병합 모델
   **폐기**). 우회 OFF=KIS만, 우회 ON=디스크만 — **모드당 소스 1개라 병합 없음**"으로
   이미 한 번 우선순위-병합을 걷어내고 정적 이분법으로 갔다. ADR-0039 의 "선호+폴백"
   의미론은 **디스크에 있는 과거 캡처**를 고르는 축이지, 살아있는 두 브로커를
   요청마다 저울질하라는 뜻이 아니다.
3. **진단 가능성.** 폴백은 캐시 키·경고·소스 표기를 전부 이원화시키고, "지금 어느
   소스를 보고 있나"가 요청마다 달라져 장애 재현이 어려워진다. 설정 한 줄로 되돌릴
   수 있는 정적 선택이 롤백 수단으로도 낫다.

### D4 — 캐시 키에 소스를 넣고, 페이지를 통째로 적재한다

키를 `(index_id, tf, bucket)` → `(source, index_id, tf, bucket)` 로 넓힌다. 소스를
바꿨을 때 이전 소스의 캔들이 stale 로 살아남는 것을 막는다.

받아온 **900행을 통째로 캐시에 적재**한다 — ADR-0120 ③(순회분 폐기 → 다음 스텝이
같은 페이지를 다시 삼킴)을 반복하지 않기 위한 명시적 조건이다.

`TODAY_TTL_SECONDS = 60` 오늘 창 만료(#939)는 소스와 무관하게 그대로 적용된다.

### D5 — 관측성 shape 을 통일한다 (규율 3)

- `data_warnings` 의 `reason` 문자열은 **소스 무관**으로 유지한다. 키움 전용 reason 을
  신설하지 않는다.
- 캐시 stats snapshot 형태 유지.
- 응답 shape 무변경 → **프론트는 손대지 않는다.** 이미 5거래일을 요청하고 있고,
  응답이 채워지기만 하면 좌측 팬 백필도 그대로 살아난다.

## 구현

```
api.py  ← 조립 지점. 유일하게 두 브로커를 아는 곳
  ├─ kis_endpoints.fetch_index_minute_candles       (기존, 그대로)
  └─ kiwoom_index_candles.fetch_index_minute_candles (신규)
        ↓ 같은 반환 타입
     IndexCandleFetchResult  ← 중립 모듈 (D2)
        ↓
  collect_index_minute_candles_with_cache  ← 브로커 무지, 변경 없음
        ↓
  /api/live/index-candles  ← 응답 shape 무변경
```

### 어댑터가 흡수하는 것

`kiwoom_frames.py`(WS 파서)가 "KIS 와의 두 차이(가격 등락부호 접두·venue 는 코드
접미)를 여기서 흡수한다"고 한 것과 같은 역할을 REST 에서 한다:

- **가격 포맷.** `cur_prc: "-566324"` → `5663.24`. 부호 접두는 등락 방향이고 값은
  소수점이 제거된 정수다. `pred_pre: "--36042"` 처럼 부호가 이중으로 붙는 필드가
  있으니 부호 문자를 모두 제거한 뒤 파싱한다.
  ⚠️ **같은 값을 `ka20003` 은 `"-5663.24"` 로 소수점째 준다 — TR 간 파서 공유 금지.**
- **업종코드 매핑** (실측 확정): `001` KOSPI · `101` KOSDAQ · `201` KOSPI200 ·
  `150` KOSDAQ150 · `701` KRX100.
  ⚠️ `701` 은 이름 때문에 KOSDAQ150 으로 오인하기 쉬우나 **KRX100** 이다.
- **`cntr_tm`** `YYYYMMDDHHMMSS`(KST, 봉 시작) → `t_ms`.

### 페이징은 어댑터 안에 봉인한다

1분봉만 `cont-yn`/`next-key` 루프가 필요하다(3분봉 이상은 1콜). 이 루프는 키움 어댑터
내부에 가둔다 — **캐시도 라우트도 페이징의 존재를 몰라야 한다.** 페이지당 1초 페이싱
(ADR-0120 의 키움 TR 유량 실측 1 req/s)을 지키고, 중단 조건은 셋이다:

1. 응답의 최과거 날짜가 요청 `from` 이하 — 목표 달성
2. `cont-yn != "Y"` — 서버가 더 줄 게 없음(요청 `from` 을 못 덮어도 멈춘다)
3. `_MAX_PAGES`(12) — 폭주 방지

(3)에 걸리면 `out_of_range` violation 을 남긴다. **조용한 절단을 만들지 않는다** —
절단된 결과는 화면에서 "데이터 없음"과 구별되지 않아 원인 추적이 불가능해진다.

### 미지원 버킷은 KIS 로 보낸다 (집계 폴백 없음)

`supports_bucket_seconds()` 가 False 면 소스 판정이 `"kis"` 로 떨어진다. 어댑터 안에서
잔 소스를 받아 접는 폴백을 두지 않는 이유: 키움을 쓰는 유일한 근거가 depth 인데, 잔
소스로 집계하면 그 depth 이점이 배수만큼 깎여 KIS 대비 우위가 사라진다(KIS 쪽에서
같은 실수가 ADR-0080 원안이었다). 지원 버킷만 정직하게 가져간다.

### 키움 실패는 KIS 로 떨어지지 않는다

`KiwoomIndexCandlesError` 는 라우트에서 **빈 캔들 + `kis_api_error` 경고**로 변환된다.
D3 의 직접적 귀결이다 — 여기서 KIS 로 폴백하면 그게 곧 런타임 사다리이고, 값 경계 튐과
"지금 어느 소스인가"의 불확정성이 함께 돌아온다. 실패는 조용히 메꾸지 않고 드러낸다.

### 테스트

`kiwoom_frames` 의 parity 테스트 패턴을 복제한다 — 두 어댑터가 같은 구간에 대해 같은
shape 을 내는지 계약으로 고정하고, 2026-07-29 실측 응답을 fixture 로 박제해 실콜 없이
회귀를 잡는다.

## 대안과 기각 사유

**(A) KIS 안에서 더 해본다.** ADR-0080 이 이미 전부 실측해 기각했다 — `FID_INPUT_DATE_1`
무시, `tr_cont` 강제 시 같은 102행 반복, `FHPUP02110200`/`FHPUP02110100` 빈 `output`,
`FHKST03010200`+`U` 는 30행으로 더 얕음. 남은 lever 였던 source-unit 선택은 #939 로 이미
최대치를 뽑았다.

**(B) KIS 유지 + 자체 수집·저장.** ADR-0080 이 제시한 "KIS 실시간 index stream 자체
축적". 과거를 소급 복원할 수 없고(오늘부터 쌓임), 수집기·완결성 게이트·보존 정책이
딸려와 비용이 훨씬 크다. `ka20005` 가 과거를 그냥 준다면 먼저 쓸 이유가 없다.

**(C) 키움 우선 → KIS 폴백 사다리.** D3 참조 — 값 경계 튐, 이미 폐기된 우선순위-병합
전례, 진단 어려움.

**(D) `LiveCollector` Protocol 추출.** ADR-0116 의 Rule of Three 결정에 반한다.
브로커가 셋이 될 때 추출한다.

## 결과

- `/live` 지수 1분봉이 최근 102분 → **요청 범위 전체**로 늘어난다. 좌측 팬 백필이
  의미를 갖게 된다. 착지 후 실측(KOSPI, `from=20260715`):

  | tf | KIS | 키움 |
  |---|---|---|
  | 1m | 100봉 (07-29 13:53~) | **3600봉 (07-15 11:42~)** |
  | 3m | 100봉 (07-29 10:33~) | **1262봉 (07-15 09:00~)** |
  | 30m | 88봉 (07-21 14:00~) | **140봉 (07-15 09:00~)** |

  캔들 단조 증가, 주말·정규장 밖 캔들 0, OHLC 위반 0, 경고 0. KIS 와 겹치는 89봉 중
  88봉 일치(나머지 1봉은 15:30 종가로 키움이 화면 최종가와 맞다).
- 키움 REST 소비자가 5 TR → 6 TR. ADR-0116 의 "지수 = KIS 잔류"가 **분봉에 한해**
  개정된다.
- KIS 유량이 지수 분봉만큼 해방된다(부수 효과, 작다).
- 자격증명이 KIS 만 있는 환경은 **현행 동작 그대로** 유지된다.

### 미검증 · 후속

- **ADR-0080 본문 갱신 (문서 부채, 본 ADR과 독립).** 매핑 표가 #939 이후 코드와 어긋나
  있다(3m→`60`/15m→`300`/30m→`600` 으로 적혀 있으나 실제는 `180`/`900`/`1800`).
  "검증한 서버 동작" 목록의 단위 집합에 `180`·`900`·`1800` 실측 결과를 추가하고, 상태에
  본 ADR 링크를 단다. **본 ADR이 채택되지 않더라도 해야 한다** — 지금 그 표를 읽고
  작업하는 사람은 틀린 매핑을 참조하게 된다.
- **장중 실시간성.** 실측이 장 마감 후였다. 장중에 직전 분봉이 지연 없이 나오는지
  확인이 필요하다(15:30 봉이 최신으로 나왔고 값이 KIS 와 일치해 신뢰도는 높다).
- **`next-key` 수명.** `00120260727120700`(업종코드+커서 시각) 형태라 무상태 커서로
  보이나 서버측 만료는 미확인.
- **더미 행 — 키움 쪽 확인 필요.** KIS 가 거래일마다 끼우는 `stck_cntg_hour` 99/88시
  자리표시자 행은 #940 으로 조용히 skip 하도록 해결됐다(그전엔 `invariant_violation`
  으로 승격돼 "일부 과거구간 로딩 실패" 칩이 상시 떴다). **키움 응답에 같은 성격의
  행이 있는지는 미확인** — 어댑터 작성 시 실측 fixture 로 확인하고, 있다면 같은
  "알려진 값만 정확히 맞을 때 skip" 방식을 쓴다(진짜 malformed 와 구분).
- **지수 D/W/M.** 일봉 캐시(`index_candles_cache`)에 오늘 TTL 이 없어 장중 갱신이
  멈춰 있다(#939 에서 프론트 폴링을 분봉으로 한정한 이유). 본 ADR 스코프 밖.
