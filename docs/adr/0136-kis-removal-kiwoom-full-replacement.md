# 0136 — KIS 완전 제거, 키움 전면 대체

**Status:** accepted (2026-08-03)

**Related:**
- 지도 [#1005](https://github.com/Soochol/hoga-ops/issues/1005) — 이 결정을 도출한 wayfinder 맵. 조사 4건·결정 5건.
- ADR-0116 / ADR-0118 — 브로커 특화(WS=키움, 폴링 REST=KIS). 이 ADR 이 그 분담의 **REST 절을 폐기**한다.
- ADR-0120 — 키움 walk-back 제거. **전제가 사실이 아니었음이 실측으로 드러나 supersede** 한다.
- ADR-0100 — KIS 계정별 병렬 슬롯. KIS 소멸과 함께 폐기.
- ADR-0109 — 저장뷰 캡처 공백 KIS 분봉 복구. 생산자 소멸(데이터는 존치).
- ADR-0121 — 캔들 차원 소스 사다리. `kis_api` 단이 **legacy 읽기 전용**으로 강등된다.
- ADR-0095 — 분봉 memory-only 재확인. **재개봉하지 않는다**(트리거 미충족).
- ADR-0129 — 지수 분봉 키움 이관. 이 결정의 **선례이자 유일한 성공 사례**.
- ADR-0134 — dev 무자격 프로필. 종목 마스터 이관이 이 계약을 건드린다.

## Context

`hoga` 는 두 브로커를 쓴다 — 실시간 WS 는 키움 전담(ADR-0118), 폴링 REST 는 KIS 전담. 두 벤더의 토큰·유량·장애모드·venue 규칙을 모두 알아야 하고, 같은 도메인 개념이 벤더마다 다른 이름으로 존재한다.

**동기(사용자 확정 2026-08-03)는 둘이다: ① 브로커 단일화(운영 복잡도) ② 데이터 품질·일관성.** 유량 제약과 자격증명 관리 부담은 **동기가 아니다** — 따라서 "키움이 더 빠르다" 는 가산점이 아니고, 성능 회귀도 그 자체로 기각 근거가 아니라 "얼마나" 의 문제다.

### 조사가 뒤집은 것

지도 #1005 의 조사 4건이 사전 통념 셋을 반증했다:

1. **ADR-0120 의 전제가 틀렸다.** "`ka10080` 은 시작 날짜 파라미터가 없어 매 요청마다 오늘부터 되걸어야 한다(O(D²))" — 실측하니 **`base_dt` 로 날짜 랜덤 액세스가 된다**([#1008](https://github.com/Soochol/hoga-ops/issues/1008)). 보유 밖 날짜에 **빈 센티넬**이 오는 것이 파라미터가 해석된다는 증거다.
2. **유량은 TR별 5 req/s 다.** 벤더가 429 응답에 `유량=5, API ID=ka10080` 을 실어 보낸다. **TR 간 독립**이라 한 TR 이 막혀도 다른 TR 은 즉시 통과한다([#1015](https://github.com/Soochol/hoga-ops/issues/1015)). ADR-0120 이 쓴 1 req/s 는 당시의 보수 설정이었다.
3. **갭이 0이다.** 초기 조사는 갭 2건(투자자 추정·휴장일)을 보고했으나, 투자자 추정은 `ka10064` 로 대응하고(#1007 정정) 휴장일은 **지수 일봉에서 역산**해 KIS 와 8개월 대조 불일치 0 이었다([#1013](https://github.com/Soochol/hoga-ops/issues/1013)). **은퇴하는 기능이 없다.**

귀결로 **과거 팬이 20~50배 빨라진다**(46거래일 98초 → ~5초). 감수할 회귀가 아니라 개선이다.

## Decision

**KIS 를 코드에서 완전히 제거하고 키움으로 전면 대체한다.** 네 축으로 나뉜다.

### 1. 대응 매핑 — 11개 표면 전부

| KIS | 키움 | 경로 |
|---|---|---|
| `FHKST03010230` 과거 분봉 | `ka10080` | `/api/dostk/chart` |
| `FHKST03010100` 과거 일봉 | `ka10081` | `/api/dostk/chart` |
| `FHKUP03500100` 지수 일봉 | `ka20006` | `/api/dostk/chart` |
| `FHPUP02100000` 지수 현재가 | `ka20001` | `/api/dostk/sect` |
| `FHKUP03500200` 지수 분봉 | `ka20005` | (ADR-0129 로 **이미 이관**) |
| `FHPTJ04040000` 시장 투자자 | `ka10051` | `/api/dostk/sect` |
| `FHKST11300006` 관심종목 복수시세 | `ka10095` | `/api/dostk/stkinfo` |
| `FHPTJ04160001` 종목별 투자자 | `ka10059` | `/api/dostk/stkinfo` |
| `HHPTJ04160200` 투자자 추정 | `ka10064` | `/api/dostk/chart` |
| `CTCA0903R` 휴장일 | **지수 일봉 역산 + 리포 커밋** | — |
| `.mst` 종목 마스터 | `ka10099` + **시드 스냅샷** | `/api/dostk/stkinfo` |

venue 는 `FID_COND_MRKT_DIV_CODE`(`J`/`NX`/`UN`) 대신 **종목코드 접미**(`_NX`/`_AL`)로 표현된다.

### 2. 키움 REST 계층 — 선언적 seam + TR별 거버너

**KIS 계층을 복제하지 않는다.** KIS 가 큰 것은 설계가 나빠서가 아니라 **와이어가 불균일**해서다(TR 마다 path·tr_id·params·파서가 다름 → 전용 파서 11개 / 1,162줄). 키움은 전부 `POST` + `api-id` 헤더 + `return_code` 봉투 + `cont-yn` 커서로 **균일**하다 — 프로브가 8개 TR 을 84줄로 처리한 것이 증거다.

- **선언적 TR 스펙 테이블 + 단일 호출기.** TR 추가 = 테이블 한 줄.
- **단일 우선순위 큐 + TR별 토큰 버킷(5 req/s).** 큐가 옮겨야 할 기계는 **넷**이다 — 2단 우선순위·중복제거·**승격**(백그라운드 대기분을 사용자 재요청 시 끌어올림)·**양보**(user_visible 대기 시 background 미룸). 뒤 둘이 빠지면 "팬이 백필 뒤에 줄 서는" 회귀가 재현된다.
- **계정 차원은 소멸한다** — 계정 풀 선택·health/failover·`cooldown_scope`. 키움 유량이 TR별이라 계정을 고를 이유가 없다.
- **async seam**(`httpx.AsyncClient`), 기존 3모듈(`kiwoom_index_candles`·`kiwoom_rankings`·`kiwoom_stock_info`)도 이주. `to_thread` 는 요청을 워커 밖으로 내보내 거버너 페이싱을 우회한다.
- **에러 모델은 `error_policy.py` 재사용.** 단 **유량 초과만 HTTP 429** 이고 나머지(`1504` 경로·`1511` 파라미터·`1513` 인증)는 HTTP 200 + `return_code != 0` 이므로, 분류기는 **두 축을 모두** 봐야 한다.
- **테스트 이음매 2층**: 소비자는 큐 제출 함수 **한 곳** 몽키패치(`kis_access.run_with_capacity` 대칭), seam 자체는 `httpx.MockTransport` 주입.

### 3. 과거 팬 — 커서는 "최古 날짜", 완결성은 **구조로** 판정

`base_dt`=커서로 1콜(900행 ≈ 2.35 거래일) → **응답의 최古 날짜만** 앞이 잘렸을 수 있으므로 캐시에 넣지 않고 **다음 콜의 `base_dt` 로 재사용**하고, 나머지는 적재한다. 실측 **콜당 신규 2.00일**.

**완결성을 데이터로 판정하지 않는다.** 첫 봉이 `09:02` 인 날, **333봉짜리 정상 거래일**이 실재해 "첫 봉 시각" 도 "봉 개수" 도 잘린 날과 원래 짧은 날을 구분하지 못한다. 한 응답에서 잘릴 수 있는 것이 최古 하나뿐이라는 것은 **프로토콜의 성질**이라 반례가 없다.

**ADR-0095(분봉 memory-only)는 재개봉하지 않는다** — 그 ADR 이 명시한 트리거 셋이 전부 반대 방향이다.

### 4. 데이터 — 지우는 것은 코드이지 데이터가 아니다

디스크의 `kis_api` 라벨 과거 데이터는 **읽기 전용으로 존치**한다. 신규 생성만 중단하고 ADR-0121 사다리는 그 라벨을 계속 이해한다. 재캡처·라벨 마이그레이션은 하지 않는다.

## Consequences

**얻는 것**
- 벤더 1개. 토큰·유량·장애모드·venue 규칙이 한 벌.
- `/settings` 데이터소스 패널이 단순해진다 — 현재 그 패널은 "KIS 냐 아니냐" 를 축으로 조직돼 있고 `kis_rest_bypass_enabled` 토글은 "KIS 가 못 미더울 때 쓰는 비상구" 다. 그 축이 통째로 사라진다.
- 과거 팬 20~50배 개선, 콜당 수확량 7.5배(120행 → 900행).
- 유량 지표가 **처음으로 생긴다** — 기존 `kis_calls_today`/`kis_rate_limit_remaining` 은 하드코딩 `0`/`None` 에 프론트 렌더 0곳인 **죽은 필드**였다. 거버너 `snapshot()` 이 큐 깊이·대기시간·TR별 카운트를 낸다.

**잃는 것 / 새 부담**
- **단일 장애점이 넓어진다.** ADR-0118 은 실시간에 대해서만 키움 단독을 수용했다. 이제 과거 데이터까지 키움 단독이다. **달력만은 예외** — 역산 결과를 리포에 커밋하므로 키움 장애에도 산다.
- **dev 무자격 부트스트랩**: 종목 마스터가 토큰을 요구한다. 캐시가 머신 단위 공유이고 Tier 3 가 stale 서빙을 하므로 실제 깨짐은 **캐시가 없는 완전 신규 환경**뿐이고, **시드 스냅샷**이 그것을 덮는다.
- **달력 시드 갱신 책임**이 생긴다(새 거래일은 하루 하나).
- 분봉 보유 1년 — **다만 KIS 도 1년이라 이 축의 손실은 0** 이다.

**사용자에게 보이는 변화**
- 실시간 화면 **무변화**(이미 키움).
- 과거 데이터 조회 **무변화**(`kis_api` 존치).
- 은퇴하는 기능 **없음**(갭 0).
- 배너·토스트·설정 문구가 키움 기준으로 바뀐다.

## Trade-offs and what we considered

- **(거부) `.mst` 존치** — 무자격 정적 파일이라 위험이 0 이지만 목적지가 "완전 제거" 에서 후퇴하고 `dws.co.kr` 런타임 의존이 남는다.
- **(거부) 휴장일을 런타임에 키움 조회** — 키움 장애 = 달력 정지, dev 무자격에서 달력 사망.
- **(거부) 휴장일 정적 달력 수동 커밋** — 연 1회 사람 갱신이라 잊으면 **다음 해 1월에 캡처 enqueue 가 조용히 틀린다**.
- **(거부) KRX 공개 데이터** — 제3 벤더 추가로 단일화 동기와 정면 충돌.
- **(거부) 마스터를 런타임까지 정적으로** — 403 KB 를 자주 커밋하면 하루 몇 건 바뀌는데 파일 전체가 새 blob 이 된다. 달력(2 KB/년)과 비용이 다르다.
- **(거부) 앱키 증설** — 예산이 열위가 아니라 개선이므로 필요가 실증되면 그때. 대가는 앱키당 유량 독립 여부가 미검증으로 남는 것.
- **(거부) KIS 계층 구조 복제** — 불균일한 와이어를 위한 구조를 균일한 와이어에 씌우면 "이름만 바뀐 3,280줄" 이 된다.

## Trigger Conditions (재검토)

- **`base_dt` 가 동작을 멈춤** — 공식 문서화 여부를 확인하지 못했다. 벤더가 예고 없이 바꾸면 과거 팬 설계 전체가 무너진다. 착수 전 확인이 필요하고, 사후에는 통합 테스트가 조기 경보 역할을 한다.
- **키움 단독 장애가 실사용을 반복 중단** — 단일 장애점 수용을 재검토한다.
- **TR별 유량이 5 가 아닌 TR 발견** — `ka10080` 에서만 확인했다. 거버너 버킷을 TR별 설정값으로 열어둔다.
