# 0140 — venue 3옵션(KRX·NXT·통합)과 NXT·통합 저장

**Status:** accepted (2026-08-05)

**Amends:**
- **ADR-0118 §2** (저장셋 전량 시간대 venue 스왑) — 시분할을 폐지하고 **동시 구독**으로 간다.
- **ADR-0118 §3** (저장 = 저장셋 ∧ KRX ∧ 정규장) — 저장에 **venue 축**이 생긴다.
- **ADR-0118 §4** (표시 3옵션·UN 상시 병합) — **결정된 그대로 구현**한다. 다만 UN 병합은
  프론트 합성이 아니라 키움 `_AL` 서버 병합을 쓴다.
- **ADR-0062** (동시호가 배제) — 범위가 **"저장+표시"에서 "표시"로 축소**된다(§6).

**Supersedes:**
- **#523의 표시 결정** — NXT 옵션 삭제와 `'통합'`→`'시간대 자동'` 리라벨을 되돌린다.

**Unchanged:** ADR-0115(per-source 완결성) · ADR-0038(hot-path JSONL) · ADR-0121(캔들 소스
사다리) · ADR-0134(dev 무자격) · ADR-0136(KIS 축소) · ADR-0138(REST 앱키별 병렬).

**결정 출처:** 웨이파인더 맵 [#1104](https://github.com/Soochol/hoga-ops/issues/1104)의 티켓
[#1106](https://github.com/Soochol/hoga-ops/issues/1106)–[#1113](https://github.com/Soochol/hoga-ops/issues/1113)
(2026-08-05). 실측은 전부 장중 실계좌(운영 미사용 앱키 3)로 수행했다.

## Context

### ADR-0118이 자기 자신과 충돌한다

§2는 *"저장셋 전량 시간대 venue 스왑 — 정규장 창은 무접미(KRX), NXT 창은 `_NX`"* 를 정했고
구현됐다. §4는 *"표시 = 시분할 폐지, KRX/NXT/UN 3옵션 직결, UN = 상시 병합"* 을 정했으나
**구현되지 않았다.** §4는 동시 구독을 요구하는데 §2는 시점당 한 시장만 구독하므로 두 절은
양립 불가능하다. 구현은 §2를 택했고, #523은 아예 반대 방향으로 갔다 — NXT 옵션을 삭제하고
`'통합'` 라벨을 `'시간대 자동'` 으로 낮췄다. `liveVenue.ts` 주석이 그 경위를 담고 있다.

따라서 본 ADR은 새 기능이 아니라 **§4의 미구현분을 복원**하고, 그 과정에서 §2·§3을 개정한다.

### ADR-0118 시절의 기각 근거 둘이 실측으로 무너졌다

§2는 `_AL`(통합) 전면 미사용을 이렇게 정당화했다: *"0B는 KRX∪NXT 병합과 정보 동치, 0D는
venue 필드가 없어 **정체 미상** + **산술 불가**(관심 전체 +76 = 1,028 > 1,000)."*

- **정체는 미상이 아니다** — `_AL` 0D는 **BBO 통합 + 가격대 잔량 합산**이다(실측 §1).
- **산술은 가능하다** — 저장셋이 설계치 876이 아니라 **실측 272**다(§1).

### 저장이 표시보다 먼저다

hogaplay 업스트림은 정규장 KRX만 보유한다. 따라서 **NXT·통합의 유일한 사본은 우리 WS
캡처**이고, 하루 늦으면 하루만큼 영구 결손이다. 표시는 나중에 붙여도 과거 데이터가 기다린다.

## Decision

### 1. 구독 — 시분할 폐지, 동시 구독

```
기대 wire = {(c,"KRX") : c ∈ 저장셋}
          ∪ {(c,"NXT") : c ∈ 저장셋, nxt_enabled(c)}
          ∪ {(c,"UN")  : c ∈ 저장셋, nxt_enabled(c)}
          ∪ 표시 부족분
```

파생식에서 **시각 축이 빠지고 `nxtEnable` 축이 들어온다.** 부팅·킥 복구가 "지금 몇 시냐"를
묻지 않게 되어 2026-07-15 인시던트가 낳은 파생-집합 규율이 오히려 단순해진다.

`nxtEnable=false`인 98종에 `_NX`/`_AL`을 걸지 않는다 — 키움 REG는 코드 유효성을 검사하지
않으므로(쓰레기 코드도 `rc=0`) 걸면 **슬롯만 조용히 타고 틱은 0**이다.

### 2. 성역 격리 계약 폐기 — NXT·UN은 KRX와 완전 대칭인 1급 venue

`stream.py`의 `venue != "KRX"` 가드 **2곳을 삭제**한다(PROGRAM 전용 조기 return + 성역 격리).
저장·분봉 합성·피크·시그널 알림 **넷 모두** venue를 받는다.

⚠ 이 가드 한 줄이 **자료구조 넷이 venue를 모른다는 사실을 가리고 있었다** — `split_venue`가
bare code를 돌려주므로 `TickDownsampler._codes` · `MinuteCandleAggregator._codes` ·
`_ask/_bid_peak_state` · `SignalAlertMonitor`가 전부 `code` 로 키잉돼 있다. 가드를 여는 순간
KRX·NXT가 **조용히 섞인다.** 전부 `(code, venue)` 키잉으로 바꾸고 **조회 표면까지 전파**한다
(`get_today_ask_peak(code)` → `(code, venue)`).

### 3. 저장 레이아웃 — 경로 세그먼트, `kiwoom_live` 에만

```
parquet/{date}/{code}/kiwoom_live/{KRX|NXT|AL}/{file}.parquet
live_kiwoom/{date}/{venue}/{code}.jsonl
```

판단 기준은 **빠뜨렸을 때의 실패 모양**이었다 — 경로는 파일을 못 찾아 즉시 터지고(loud),
파케이 컬럼은 필터 없이 두 시장을 섞은 값을 조용히 낸다(silent), 코드 접미(`{code}_NX/`)는
종목 순회를 오염시킨다.

구조적 근거: **`source`는 경쟁 사본이라 사다리가 하나를 고르지만, `venue`는 둘 다 참이다.**
그래서 `source` **아래**에 둔다(ADR-0121이 사다리를 호가/캔들 두 차원으로 쪼갠 전례).

**`kiwoom_live` 에만 적용**한다 — NXT가 생길 수 있는 유일한 source다(hogaplay 16,304 디렉터리
=78%는 정규장 KRX 업스트림, kis_live는 삭제된 계층, kis_api는 캔들 전용). 읽기 규칙은
`SOURCE_HAS_VENUE` source별 상수로 봉인한다.

기존 `kiwoom_live` **2,694 디렉터리를 `KRX/` 로 마이그레이션**한다(같은 파일시스템 rename).
*"venue 세그먼트가 없으면 KRX"* 하위호환을 택하지 않는 이유: 경계가 날짜가 아니라 "있느냐"라
배포 이후에도 두 모양이 영구히 섞이고 그 분기가 조립부 11곳에 각각 남는다.

JSONL은 보유일이 2일뿐인 과도 트리라 **마이그레이션 없이 날짜 경계 컷오버**한다.

### 4. `nxtEnable` 은 캡처 시점 값을 source 레벨 meta 에 스냅샷

```
kiwoom_live/meta.json        ← 신설: nxt_enabled(as-of) · expected_venues
           /KRX/meta.json    ← 기존 완결성 필드
           /NXT/meta.json
           /AL/meta.json
```

**함정 둘을 동시에 막는다.** ① `nxtEnable`은 시점 의존이다 — 넥스트레이드가 종목을 단계적으로
늘리므로 현재 플래그로 과거일을 판정하면 오판한다. ② `meta.json`을 venue 아래에만 두면
**NXT가 없는 날엔 "없음의 이유"를 적을 자리가 사라진다.**

선례는 이미 있다 — 기존 `meta.json`은 `regular_session_open_ms`를 캡처 시점 값으로 박아 둔다.

**판정 규칙(디스크만으로):**

| `NXT/` | `nxt_enabled` | 판정 |
|---|---|---|
| 있음 | — | 데이터 있음 |
| 없음 | `false` | **정상**(미상장) |
| 없음 | `true` | **결손** |
| 없음 | meta 부재 | **모름** — 결손으로 단정 금지 |

마지막 행이 중요하다. 판별 실패의 기본값은 *"모름"이지 "미상장"이 아니다*(거래일 달력이
커버리지 밖을 `None`으로 두는 것과 동형).

### 5. 저장 창 — 연결 창 그대로 `08:00–20:00`

목적이 **"NXT 전체 데이터 저장"** 이므로 **누락 위험이 있는 선택지는 전부 탈락**하고 초과
저장만 허용된다. 틱-흐름 기반은 carry 만료 임계값이 조용한 종목을 자르고, 세션 구조 상수는
벤더 시각과 어긋나면 그 구간이 통째로 빠진다 — 둘 다 영구 결손이다.

KRX 저장 창은 무변경(정규장 09:00–15:30). carry는 창 전체 유지하되 **행에 표식**을 남겨
읽을 때 "조용했다"와 "닫혀 있었다"를 구분한다 — **저장은 최대로, 해석은 읽을 때.**

### 6. 완결 판정 — 모든 기대 venue 가 닫혀야 COMPLETE

`_collection_finished`는 오늘을 **15:35에 확정**하는데 NXT·AL은 그 뒤 4.5시간을 더 쌓는다.
그대로 두면 **거짓 COMPLETE**이고, 그 COMPLETE는 hogaplay 워커의 `already_complete` 스킵까지
유발한다.

**stock-date COMPLETE = `expected_venues` 전부 닫힘.** 미상장 98종은 `["KRX"]`이므로 15:35
그대로 — 지연은 NXT 상장 174종에만 붙는다.

### 6.1. ADR-0062 범위 축소 — 저장+표시 → 표시

**NXT 예상체결(FID 23/24)은 저장한다.** NXT의 단일가 국면 시각을 우리가 모르므로
`is_auction_window`(KRX 시계)로는 올바르게 게이트할 수 없고, 모르는 채 버리면 영구 결손이다.
표시 오염 방지라는 원래 목적은 표시 게이트가 그대로 수행한다.

**NXT에는 VI가 없다**(실물 앱 확인: 상승/하락VI `-`) — VI 배제는 NXT에 적용 대상이 없다.

거래일 달력은 KRX 것을 쓴다. ⚠ **NXT가 KRX 휴장일에 열면 연결 창이 닫혀 그날이 통째로
결손**이라는 비대칭이 남는다(확인 필요).

### 7. 표시 — 3옵션 직결, `_AL` 채택

```
LIVE_VENUE_OPTIONS = ['KRX', 'NXT', 'UN']
LIVE_VENUE_LABELS  = { KRX: 'KRX', NXT: 'NXT', UN: '통합' }
```

**'시간대 자동'은 삭제**한다 — 시분할이 폐지되어 가리킬 대상이 없다. 저장 키
`live.venue.v1`·값 `'UN'`은 승계한다. ⚠ `migrateStoredVenue`의 `'NXT'→'UN'` 변환을
**제거**해야 한다(안 지우면 NXT를 골라도 되돌아간다). 제거하면 #523 이전 NXT 사용자가 원래
의도를 되찾는다 — 옛 `'NXT'`와 새 `'NXT'`는 같은 뜻이라 충돌이 없다.

**통합 호가는 `_AL` 직결**이다. 실시간·복기 모두 같은 값이라 병합 로직이 0줄이고 두 경로
불일치가 원천 차단된다. ⚠ `_AL`만으로는 출처 분해가 불가능하다(0D에 9081 없음) — 분해가
필요하면 이미 저장 중인 KRX·NXT를 함께 읽는다. 계층: **통합 사다리 = `_AL` 정본 / 출처 분해
= 선택적 부가정보.**

`liveVenueAcceptsFrame`에서 **시각 축이 사라진다**(태그 직결). `liveSubscriptionVenueForMs` ·
`liveHogaVenueNow` · 상태바 호가 배지 · 08:50/15:31 화면 점프는 **소멸**한다.

### 7.1. 호가창 21행 — `중` 행

매도10 + **중간 행** + 매수10. 중간값은 `(매도1 + 매수1) ÷ 2` 하나로 정상·lock·역전 세 경우를
**분기 없이** 덮는다. `중` 뱃지로 "주문 가능한 호가가 아님"을 구분한다 — **키움 앱이 이미
쓰는 규약**이다(호가 단위 1,000원인데 `중 1,685,500`을 띄운다).

**교차 시 경고·색·문구를 넣지 않는다.** 교차는 데이터 오류도 장애도 아니라 서로 다른 거래소의
주문이 자동으로 만나지 않는다는 구조 그 자체이고, 000270처럼 80% 교차하는 종목은 경고가 상시
켜져 **없는 문제를 찾게 만든다.** 겹치는 가격이 양쪽에 보이는 것으로 충분하다.

이 21행 구조는 **전 venue 공통**이다. 지금 호가창은 매도10과 매수1이 맞붙어 스프레드를 보여줄
자리가 없다 — venue 기능이 없어도 정당한 개선이다.

### 7.2. 보관함 — 한 행에 venue 별 상태

날짜 행 구조를 유지하고 `DiskStateBadge`를 venue 개수만큼 붙인다. 미상장 종목은 NXT·AL
뱃지 **자리가 아예 없어** §4의 판정이 "뱃지가 없다"로 자연 표현된다. 재캡처도 venue 단위다.

`/study` 거래소 선택기를 **부활**시킨다 — 디스크에 세 venue가 생겨 숨김 사유가 사라진다. 단
`hogaplay`는 KRX 전용이므로 venue별 가용성을 함께 보여야 한다.

### 8. 롤아웃 — 전량 동시 투입, fix-forward

저장셋 272종을 한 번에 세 venue로 전환한다. 단계적 활성화를 두지 않는다.
**킬스위치·토글·env 노브를 만들지 않는다**(ADR-0118 §5 승계) — 저장은 끄는 것이 더 위험하다
(영구 결손). 마이그레이션만 역방향 스크립트를 갖는다.

## Consequences

### 얻는 것

- NXT를 **단독으로 볼 수 있게 된다** — #523 이후 불가능했다. 정규장 중 NXT 호가·체결을 봐
  양 시장 스프레드를 관찰할 수 있다.
- 통합이 **진짜 병합**이 된다. 08:50/15:31 화면 점프가 사라진다.
- **복기 가능 시간이 6.5h → 12h**. 장 전후 구간이 처음으로 디스크에 남는다.
- 프리마켓·애프터마켓의 **거래원·프로그램 빈 창이 채워진다**(2026-08-05 신고 증상).

### 치르는 것

- 슬롯 272 → **620/800**. 히트맵을 키우면 재계산이 필요하다.
- 디스크 하루 507MB → **639~727MB**. 연 245거래일 기준 +32~54GB/년.
- NXT 상장 174종의 **완결 판정이 4.5시간 늦어진다**(복기·스크리너 진입 지연).
- **KRX 캡처 경로가 더는 byte-for-byte 불변이 아니다** — 회귀 검증이 필수다(§검증).

### ⚠ 구현 지뢰 셋 — 전부 "지금은 안 터지지만 여는 순간 발현"

1. **자료구조 넷이 bare code로 키잉돼 있다**(§2). `stream.py:388` 가드가 가려 주고 있을 뿐이다.
2. **`VENUE_SUFFIX`가 둘인데 서로 다르다.** `kiwoom_fields.py:114`는 `{"_NX":"NXT"}`로
   **`_AL`이 없어** `split_venue("005930_AL")`가 `("005930_AL","KRX")`를 돌려준다 — 접미가
   안 벗겨지고 venue가 오분류된다. `kiwoom_multi_quote.py:46`에는 제대로 있다. **같은 이름의
   다른 진실이 둘**이므로 근본 해결은 통합이고, 정본은 **새 모듈 `hoga/live/kiwoom_venue.py`** 다
   (`venue.py`는 docstring이 wire 인코딩을 배제하고, `kiwoom_fields`는 WS 전용인데 접미는 REST에도
   실리며, `kiwoom_multi_quote`는 기능 모듈에 상수가 얹힌 꼴이다).
3. **15:35 완결 확정**이 NXT·AL 저장을 4.5시간 앞질러 거짓 COMPLETE를 만든다(§6).

### 검증 — 미검증 랜딩 금지

#524가 세운 규율이 그대로 적용된다. 캡처 경로 인접 PR은 **개정 전후 같은 거래일의 KRX
parquet를 행 단위 대조**해 통과시킨다(행 수·`ts_ms`·값이 전부 동일해야 한다). 키잉 변경이
KRX 쪽 출력에 영향을 주지 않았다는 직접 증거다.

## 열린 항목

- **히트맵·스크리너에서 NXT·통합의 의미** — 두 화면은 전역 `useLiveVenueStore` 를 이미 공유하므로
  3옵션이 켜지는 순간 **결정 없이 동작이 바뀐다.** 히트맵 272종 중 98종은 NXT 데이터가 없고, 히트맵은
  "잔량이 없다"와 "시장에 없다"를 구분할 수단이 없다. venue 가 전역이어야 하는지 자체가 명시적으로
  결정된 적이 없다 → [#1132](https://github.com/Soochol/hoga-ops/issues/1132).
- **연결 창이 이제 진짜 상한이다.** `ws_connection_window`의 `08:00–20:00`은 구독 스왑
  스케줄로 들어온 값이지 검증된 NXT 운영시간이 아니다. 이 창 밖 틱은 저장 이전에 수신 자체가
  안 된다.
- **NXT 휴장일이 KRX와 다른가** — KRX 거래일에 NXT가 쉬면 무해(틱 0 = 행 0)지만, 반대면
  그날이 통째로 결손이다.
- **저장셋 크기가 심볼 마스터 캐시 상태에 따라 248~272로 흔들린다**(`_compute_heatmap_codes`의
  fail-open). venue 정책과 직교하는 선재 이슈로 분리했다.
- **통합 스프레드는 음수가 될 수 있다** — 소비 코드 감사가 필요하다.
