# 0165 — 레이아웃 프리셋은 창 핀의 **여부**를 담고, 적용이 현재 종목으로 물질화한다

**Status:** accepted (2026-08-31)

**Amends:**
- [ADR-0159](0159-presets-carry-window-indicator-sets.md) 결정 7 — "종목·창 핀은 여전히
  담지 않는다". 종목 절반은 그대로 유효하고, 핀 절반이 **여부에 한해** 풀린다.
  핀 **종목**은 여전히 payload 에 싣지도 읽지도 않는다.
- [ADR-0119](0119-live-multi-window-workspace.md) PR-E 의 "프리셋 = 창·배치" 경계.

**Related:**
- PR #1664 — 적용 시 핀 이월(id 가 살아남는 창은 나가는 상태의 핀 유지). 이 ADR 의
  물질화는 그 위에 얹히며, **이월이 물질화보다 우선**한다.
- `frontend/src/live/presets/layoutPresetSnapshot.ts`(캡처·적용),
  `frontend/src/state/workspace.ts` 의 `pinWindows`.

## Decision

1. **캡처는 핀 창 원소에 `wasPinned: true` 를 싣는다** — boolean 플래그뿐, 종목은
   싣지 않는다. 핀 없는 창은 키 자체가 없다(하위호환 판정은 키의 부재).
2. **레거시 `pinned` 키(심볼 객체)와 별도 키다.** `pinned` 는 적용 경로가 전량 버리는
   키로 남고(`normalizeWorkspaceSnapshot` 의 `keepPin: false` — 종목 주입 차단 불변),
   `wasPinned` 는 `applyPresetPayload` 가 `=== true` 로만 읽는다. 옛 payload 에 우연히
   실린 심볼 핀(truthy 객체)은 물질화되지 않는다.
3. **적용은 스냅샷 적용 뒤, 플래그 창을 적용 시점의 표시 종목으로 물질화한다**
   (`pinWindows`). 창이 스토어에 존재해야 물질화 대상이 있으므로 순서가 계약이다.
4. **물질화는 켜기 전용이다.** 이미 핀인 창은 건너뛰고(이월 우선 — 사용자가 붙잡은
   종목이 유지된다), 플래그 없는 프리셋이 기존 핀을 **풀지 않는다**. 표시 종목이 없는
   창(종목 미배정 그룹)도 건너뛴다(`toggleWindowPin` 과 같은 규칙 — 빈 핀은 표현 불가).
5. **백엔드·wire 계약·`schema_version` 무변경.** 서버 payload 창 원소는
   `dict[str, Any]` 통과라 새 키가 그대로 실린다(ADR-0159 결정 5 와 동일).

## Context

### 왜 boolean 인가 — 핀 필드의 두 성질을 가른다

핀은 "고정돼 있음(링크 토폴로지)" × "무엇에 고정됐나(종목 사본)" 가 한 값에 붙은
하이브리드다. 프리셋의 판정축(ADR-0159)으로 가르면 전자는 **작업 환경**이라 담기는
쪽이고, 후자는 **"지금 보고 있는 것"** 이라 담지 않는 쪽이다 — 종목째 실으면 배치를
바꾸려고 누른 프리셋이 창의 종목을 갈아치우는, v3 `groupSymbols` 철회를 부른 바로 그
손해가 재발한다. 그래서 여부만 싣고, 값은 적용 시점의 표시 종목으로 채운다 —
물질화 직전과 직후의 화면이 같으므로 **핀 복원이 종목을 바꾸는 일이 없다.**

사용자 요청이 동기다: "핀을 켜고 저장한 프리셋을 다시 불러오면 핀도 돌아와야 한다."
PR #1664 의 이월만으로는 "핀을 켠 채 쓰는 동안 유지" 까지만 되고, 핀을 푼 뒤나
다른 기기에서 불러오는 경우 복원되지 않았다.

### 왜 켜기 전용 비대칭인가

플래그 없는 프리셋이 기존 핀을 **풀면** 그 창이 그룹 종목으로 복귀해 표시 종목이
바뀐다 — "프리셋은 보던 종목을 안 바꾼다" 는 상위 계약 위반이다. 끄기 복원을
포기하는 대가는 작다(핀 해제는 클릭 한 번), 종목을 잃는 손해는 크다. **이 비대칭은
의도이며 결함이 아니다** — "핀 끈 프리셋을 불러왔는데 핀이 안 풀린다" 는 문의가
오면 이 절이 근거다.

### blocked 상태의 새 진입로

물질화는 (이월과 달리) 새 핀을 만들 수 있으므로, 전 창이 핀인 프리셋을 불러오면
클릭 종목 교체가 막히는 상태가 프리셋에서 재현된다. 기존 복구 경로가 그대로 받는다:
다음 클릭에서 `activationTarget` 이 `blocked` 를 돌려주고 토스트 + `unpinAllWindows`
가 뜬다. 사용자가 스스로 저장한 구성에 대한 정직한 결과다.

## Alternatives considered

### A. 핀 종목째 싣기 — 기각
v3 `groupSymbols` 철회와 같은 손해의 재발. 위 Context 참조.

### B. 이월만 (PR #1664 현상 유지) — 기각
"저장 → 복원" 이라는 사용자 기대를 못 채운다 — 핀을 푼 뒤·다른 기기에서 불러오면
핀이 돌아오지 않는다.

### C. 레거시 `pinned` 키 재사용(`=== true` 판별) — 기각
동작은 하지만 "payload 의 `pinned` 는 전량 버려진다" 는 기존 방어선 문장과 "`pinned
=== true` 는 물질화된다" 는 새 코드가 같은 키를 두고 모순으로 읽힌다. 별도 키면
두 계약이 독립으로 남는다.

## Consequences

**Positive:** 백엔드·wire·저장 스키마 무변경, 되돌리기 쌈(캡처에서 플래그를 안 실으면
옛 동작). 물질화가 `windowSymbolOf` 를 지나므로 창→종목 해석 SSOT 유지.

**Negative / watch:**

- **끄기는 복원되지 않는다**(결정 4 의 비대칭). 의도된 동작.
- **전 창 핀 프리셋은 클릭 막힘 상태를 재현한다.** 기존 토스트 복구가 받는다.
- **물질화 종목은 저장 시점이 아니라 적용 시점 것이다.** "그때 그 종목" 복원을
  원하게 되면 그것은 종목 탑재 요구라 이 ADR 이 아니라 v3 철회 결정을 다시 열어야
  한다 — 그 시점의 재검토 트리거다.
