# 0147 — RangeBundle 슬라이스는 손으로 등록하고, 가드가 양방향으로 대조한다

**Status:** accepted (2026-08-16)

**Related:**

- ADR-0004 — 프론트가 wire model 을 손으로 미러한다. **codegen 은 기각됐고 이 ADR 도
  되살리지 않는다.** 같은 ADR 의 "both must be updated in the same PR" 을 이 등록이 잇는다.
- ADR-0013 — `RangeBundle` 은 **Stock-Date Range** 의 단일 read-path Wire Model.
- ADR-0092 — 캐시 프리미티브 추출. 백엔드 축(`KIND_VERSIONS` 파편화)은 그 이월분에서 다룬다.
- `frontend/src/api/rangeSlices.ts`, `tests/unit/api/test_range_slice_registry_contract.py`.

## Decision

1. **RangeBundle Slice** 를 도메인 용어로 세운다(`CONTEXT.md`). `RangeBundle` 의 배열·구조
   필드 하나가 슬라이스이고, 범위를 식별하는 스칼라 4개는 슬라이스가 아니다.
2. 슬라이스마다 **7축을 손으로 선언**한다 — HTTP `Query` 플래그 · 프론트 요청 옵션 ·
   캐시 키 인덱스 · placeholder 호환 · 백엔드 게이트 · 델타 병합 규칙 · 차트 번들 조립 ·
   과거일 캐시 kind. 선언은 **프론트 프로덕션 모듈**에 둔다(테스트 파일이 아니다).
3. 파이썬 가드가 그 선언을 코드와 **양방향**으로 대조한다. 역방향의 발견원은 **pydantic
   `RangeBundle`** 이다 — 이름 규칙 자동 발견이 아니다.
4. **비대칭은 지우는 것이 아니라 적는 것이다.** 축이 빈 슬라이스는 `note` 에 사유를 갖고,
   가드가 그 사유의 존재를 요구한다. `note` 가 비어 있지 않은 목록이 곧 미해결 비대칭 목록이다.
5. **척도 축은 이 등록에 넣지 않는다.** `test_range_price_scale_contract.py` 가 필드 단위로
   이미 덮으므로, 같은 사실을 두 목록이 들면 그 둘이 갈리는 것이 다음 사고가 된다.
6. 소비처의 **런타임 파생은 지금 하지 않는다.** 선언과 가드를 먼저 세우고, 접히는 축부터
   나중에 옮긴다.

## Context

슬라이스 하나가 화면에 닿으려면 서로를 모르는 명시 열거 목록을 전부 지나가야 한다.
실측: 프론트 **12곳**(`wall_surge` 기준) · 백엔드 **14곳**(`depth_delta` 기준).

그 대가를 이미 치렀다. 호가벽 급증은 PR **세 건**에 걸쳐 들어왔고(#1321 → #1325 → #1333)
마지막 커밋 제목이 "3중 누락을 잇는다" 였다. 같은 클래스가 계속 나온다 —
`missing_dates` 가 차트 경로 번들에서 빠져 있던 것(#1338), placeholder 호환 목록에서
`venue`·`depth_delta` 가 빠져 있던 것(#1340).

**타입은 이 부류를 원리적으로 못 잡는다.** `{ mode: 'sidecar', ...rangePlan.options }` 처럼
스프레드로 넘기면 TypeScript 가 excess property check 를 걸지 않아 `wallSurgeEnabled` 가
에러 없이 증발한다. 그리고 이 축들은 **부재가 무증상**이다 — 병합 목록에서 빠지면 청크를
이어 붙일 때만, placeholder 목록에서 빠지면 옵션을 바꿀 때만 드러난다.

### 왜 "선언 + 가드" 이고 런타임 파생이 아닌가

병합 규칙이 슬라이스마다 다르고(4종) 그 선택의 판별식은 **백엔드가 prefix 집계인가** 라는
도메인 판단이다. 지금 접기 시작하면 그 판단이 특수 분기로 레지스트리에 들어와 오히려
depth 가 준다. 어느 축이 진짜 접히는지는 소비처를 옮겨 보며 알게 되므로, 그때까지
선언은 **사실의 목록**으로만 둔다.

### 왜 자동 발견이 아닌가

#1199 가 이름 규칙 매칭을 실측으로 기각했다 — 오탐과 누락이 **둘 다 조용하다**. 대신
역방향의 발견원을 pydantic 모델로 고정하면 추측 없이 "빠진 것" 을 셀 수 있다.

## Consequences

### 이 가드가 막는 것

`RangeBundle` 에 슬라이스가 생겼는데 등록이 없거나, 등록이 적은 축이 코드와 다른 상태.

### 이 가드가 **못 보는 것** (실패 메시지·docstring 에도 적혀 있다)

- 병합 규칙이 **옳은지**는 안 본다. `unfiltered` 라 적혀 있고 코드도 그렇다는 것만 본다.
- 프론트가 그 데이터를 **실제로 렌더하는지**는 안 본다. 배선과 픽셀은 다른 층이다.
- 등록과 코드를 **함께** 고친 드리프트는 못 본다.

### 등록을 편집할 때의 제약

가드가 TS 를 **문자열로 스캔**하므로 엔트리는 중첩 없는 평평한 리터럴이어야 하고, 배열
안에는 주석을 쓰지 않는다(사유는 `note` 로). 파서가 못 읽는 엔트리는 에러가 아니라 조용한
미등록이 되므로, `test_registry_parser_sees_every_entry` 가 엔트리 **개수**를 wire 필드 수와
직접 맞춘다. 실제로 이 파서는 착수 중 두 번 조용히 틀렸고(배열의 `[` 대신 첫 원소의 `{` 를
잡음, 타입 표기 `RangeSliceSpec[]` 의 빈 괄호를 잡음) 그때마다 이 테스트가 잡았다.
그중 한 번은 다른 테스트가 **0건을 순회하며 초록**이었다 — 루프형 단언은 개수를 따로 못
박지 않으면 아무것도 증명하지 않는다.

## 등록으로 드러난 미해결 비대칭

`note` 가 비어 있지 않은 슬라이스가 현재 **9개**다. 그중 판단이 필요한 것:

- **`wall_surge`** — 빌더는 `wall_surge_enabled` 를 받는데 `routes.py` 가 전달하지 않아
  HTTP 로 도달 불가이고, 그래서 프론트에도 요청 옵션·캐시 키 축이 없다. 차트 번들 조립
  목록에도 없어 `useLiveBundle` 이 사후 대입한다. **토글을 살릴지 지울지가 미결이다.**
- **`price_level_hits`·`volume_profile_range`·`volume_profile_by_day`** — 백엔드가 상시 빈
  값을 넣는다(`mode=full` 퇴역의 잔재). 지울 dead 인지 살릴 미완성인지 미결.
- **`excluded_dates`·`data_warnings`** — 델타 병합 규칙은 있는데 차트 경로 번들에는 없다.
- **`program_trade`** — 옵션 슬라이스 중 유일하게 과거일 캐시 kind 가 없다.

이 목록이 곧 다음 작업의 후보다. 지금 고치지 않은 이유는 각각이 별도 판단을 요구하기
때문이고, **기록되지 않은 상태로 두지 않는 것**이 이 ADR 의 요점이다.
