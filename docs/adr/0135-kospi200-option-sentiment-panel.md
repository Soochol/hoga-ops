# 0135 — KOSPI200 옵션 심리 패널: 전광판 TR 기각과 2계층 수집

**Status:** accepted (2026-08-03)

**Related:**
- ADR-0129 (지수 분봉 키움 이관) — KIS output 행수 상한이 커버리지를 조용히 잘라낸
  선례(102행 상한 → 커버리지 1/3). 본 ADR 의 전광판 기각은 같은 계열의 함정이다.
- ADR-0100 (KIS REST 앱키당 유량 실측) — 전수 수집 시간 산정의 근거(~15/s).
- ADR-0101 (WS 연결당 등록 상한 41) — 실시간 WS 경로가 구조적으로 불가능한 근거.
- ADR-0134 (dev 무자격 관례) — 자격증명 없으면 휴면하고 배너를 띄우는 계약.
- 구현점: `hoga/api/kis_option_master.py` · `hoga/live/kis_option_endpoints.py` ·
  `hoga/live/option_sentiment.py` · `hoga/live/option_sentiment_runtime.py` ·
  `hoga/api/sentiment_routes.py` · `frontend/src/pages/Sentiment.tsx`

## Context

개별 종목의 방향성을 옵션으로 읽고 싶다는 요구에서 출발했으나, 한국거래소의 **개별
주식옵션은 유동성이 사실상 없다**(상장 종목 수도 적고 하루 거래 0인 종목이 흔하다).
반면 KOSPI200 지수옵션은 세계 최상위권 거래량이다. 그래서 대상을 **시장 전체 심리**로
좁히고, 지표 4종(P/C 비율 · 미결제 분포+Max Pain · 감마 익스포저 · IV 스큐)을
KOSPI200 근월물에서 계산하기로 했다.

데이터 경로 후보는 셋이었고, **실측이 둘을 탈락시켰다**.

### 1. 실시간 WS (`H0IOCNT0`) — 구조적으로 불가능

필드는 이상적이다(미결제·미결제증감·IV·델타/감마/베가/세타·매수매도 체결건수까지
서버가 계산해서 준다 — 블랙숄즈 자체 구현이 불필요하다). 그러나 **근월물 한 만기가
콜 390 + 풋 390 = 780종목**인데 WS 등록 상한은 연결당 41이다(ADR-0101 실측).
19배 초과라 어떤 배분으로도 불가능하다.

### 2. 옵션 전광판 REST (`FHPIF05030100`) — 상한이 ATM 을 잘라낸다

`display-board-callput` 은 콜/풋 체인을 한 번에 주지만 output1/output2 가 **각 100건**
상한이다. 2026-08-03 장중 실측:

```
응답 행사가 범위 : 1350.0 ~ 1597.5   (콜 100행 전부 OTM, 풋 100행 전부 ITM)
당시 KOSPI200    : ~1007  →  ATM 은 근월물 행사가 390개 중 내림차순 234번째
풋 100행 거래량 합계 : 1계약
```

즉 정렬이 **행사가 내림차순**이라 상한 100은 언제나 위쪽 끝 100개만 준다. ATM 은
134칸 밖이라 구조적으로 도달할 수 없고, 받은 데이터는 거래량 합계 1계약짜리 죽은
구간이다. "적당히 잘린 표본"이 아니라 "한쪽 끝 전부"라는 점에서 ADR-0129 와 동형이다.

### 3. 종목별 REST (`FHMIF10000000`) — 채택

행사가를 직접 지정하므로 상한 문제가 없다. 필드 완비도 교차검증했다: 전광판이 거래량
3,004 로 보고한 종목(`B01608C42`)을 개별조회하니 3,015 였다(수 분 간격). 즉 이 TR 의
`acml_vol` 은 정상 동작하며, ATM 종목의 거래량 0 은 API 한계가 아니라 **비(非)라운드
행사가에 유동성이 없다**는 시장 사실이다(행사가 1012.5 거래량 0 vs 1000.0 거래량 227).

덤으로 응답 `output3` 에 기초자산 지수가 실려 온다 — KOSPI200 현재가를 위한 별도 TR
호출이 없다.

## Decision

### D1. 종목별 조회(`FHMIF10000000`)를 유일한 시세 경로로 쓴다

전광판 TR 은 사용하지 않는다. 종목 코드는 `fo_idx_code_mts.mst` 마스터에서 얻는다
(무자격 다운로드).

**마스터 파싱에서 필드 4를 콜/풋으로 쓰면 안 된다.** 값이 2/3 으로 깔끔히 갈려
콜풋처럼 보이지만 한글명과 대조하면 절반이 어긋난다(f4=2 안에 콜 1,884 · 풋 2,251).
판별은 단축코드 첫 글자로 한다 — **B=콜 / C=풋 이 4,592/4,592 예외 없이 일치**하고
개별조회의 델타 부호로도 교차 확인된다. 이 버그가 위험한 이유는 조용하지 않고 **절반만
틀리기** 때문이다: 콜과 풋이 뒤섞여도 개수는 그대로라 P/C 비율이 1 근처의 그럴듯한
값을 계속 낸다.

시리즈도 코드 접두로 가른다(B01/C01 정규 · B05/C05 미니 · B09/C09 위클리목 ·
BAF/CAF 위클리월). **정규와 미니는 계약 승수가 달라 합산하면 안 된다.**

### D2. 2계층 수집 — 지표마다 요구 커버리지가 다르다

```
전수 계층 (5분)  : 근월물 전 종목. 202608 기준 780종목 · 실측 60.7초 / 12.9 req/s / 드롭 0
                   → P/C 비율, Max Pain, OI 분포, GEX, IV 스마일 곡선 전체
ATM 계층 (30초)  : ATM ±20 행사가 ~82종목
                   → ATM IV 와 25델타 리스크리버설의 빠른 갱신만
```

**체인 크기는 만기마다 다르다** — 실측 `202608=780` · `202609=1012` · `202610=682`.
따라서 780 은 상수가 아니라 이 결정 시점의 관측값이다. 소요 시간도 종목 수에
비례하므로 함께 움직인다. 화면의 대기 안내가 쓰는 종목 수는 응답의 `chain_size`
로 흘려보내고 UI 에 상수를 박지 않는다 — 박으면 만기 롤오버 때 조용히 틀린 안내가
된다(#1034).

원안은 "P/C·IV스큐 = ATM 고빈도"였으나 **설계 중 정정했다**: P/C 비율의 표준 정의가
전 종목 거래량·미결제 비율이라 ATM ±20 창으로 계산하면 이름만 같은 다른 지표가 된다.
IV 스마일 곡선도 양 날개가 있어야 모양이 나온다.

`Max Pain`·`GEX` 는 부분 체인을 받으면 `InsufficientChainCoverage` 로 **계산을 거부**
한다. 조용히 틀린 값을 내느니 없는 편이 낫다.

### D3. 요청 구동 — 아무도 안 보면 수집하지 않는다

첫 요청이 수집 루프를 깨우고, 마지막 요청 후 10분 조용하면 스스로 멈춘다. 자격증명이
없으면 루프를 아예 띄우지 않는다(30초마다 깨어나 아무것도 못 하는 루프는 낭비다).
`/live` 와 KIS 유량을 나눠 쓰므로 유휴 시 회수가 중요하다.

### D4. 계층별 `as_of` 를 각각 싣는다

응답에 `full_as_of_ms` 와 `atm_as_of_ms` 를 따로 둔다. 하나로 뭉치면 5분 전 GEX 와
30초 전 ATM IV 가 같은 시각으로 표시되어 오독을 부른다. 화면도 둘을 각각 표시한다.

### D5. 해석 한계를 화면에 명시한다 (테스트로 고정)

지표가 말하지 *못하는* 것을 함께 적는다. 이건 장식이 아니라 이 화면의 설계 요구사항
이며, 문구가 사라지지 않도록 `Sentiment.test.tsx` 가 고정한다.

- P/C 비율은 **헤지와 투기를 구분하지 못한다**(풋 매수 = 하락 베팅 or 보유 보험).
- GEX 는 **방향이 아니라 변동성 체제** 지표이고, 부호는 "딜러가 콜을 팔고 풋을 산다"는
  **검증 불가한 관례적 가정**에서 나온다.
- Max Pain 은 만기 시 매도자 손실 최소점일 뿐 가격 예측이 아니다.
- IV 절대값은 정보량이 적다 — 주식 옵션은 구조적으로 항상 풋이 비싸다.

### D6. 극외가 편중을 화면이 드러낸다

2026-08-03 전수 스냅샷(KOSPI200 1007.83):

```
콜 1597.5 (+58.5% OTM, 델타 +0.0002)  OI 14,444  거래량 3,079
풋   625.0 (−38.0% OTM, 델타 −0.0001)  OI 14,402  거래량 4,981
ATM 1000.0 (델타 +0.514)               OI  1,674  거래량   227
상위 4종목이 전체 OI 209,929 의 21.5%
```

**델타가 사실상 0인 극외가에 OI 와 거래량이 몰린다.** 그 결과 Max Pain 1100(현재가
대비 +92)과 감마 플립 702.5 는 정의대로 정확히 계산됐음에도 이 로또성 물량에 끌려간
값이다. 미국 시장 기준으로 쓰인 GEX/Max Pain 해설을 그대로 적용하면 오독한다. 그래서
원값만 크게 띄우지 않고 **미결제 상위 기여 행사가 표**를 함께 보여준다.

### D7. 옵션 표면은 KIS 존치 — ADR-0134 계열의 "KIS 완전 제거"에 대한 명시적 예외

이 기능은 **KIS 표면을 2개 늘린다**(시세 TR `FHMIF10000000` + 마스터
`fo_idx_code_mts.mst`). 진행 중인 KIS 제거 지도(이슈 #1005, 티켓 #1006~#1016)의
목표가 "KIS 11개 표면 전부 제거"이므로 정면으로 부딪힌다. 대안 벤더를 전수 조사한
결과 **대체 경로가 없어 예외로 존치한다**(사용자 결정 2026-08-03).

| 소스 | KOSPI200 옵션 | 이 프로젝트에서 사용 |
|---|---|---|
| KIS REST | 시세·미결제·IV·그리스 완전 | ✅ 채택 |
| 키움 REST (`api.kiwoom.com`) | **없음** | — |
| 키움 Open API+ (OCX) | 완전 (FID 189~195) | ❌ **Windows 전용** + 유량 1,000건/시간 |
| KRX 정보데이터시스템 | 미결제만 (IV·그리스 없음) | ⚠️ 계정 필요 · 일별 |

**키움 REST 부재의 근거 4종**(전부 2026-08-03 실측):

1. 공식 명세 `kiwoom_api_spec.json` **337개 전수** — 국내주식 206 · 미국주식 129 ·
   OAuth 2, 파생 카테고리 **0건**.
2. 공식 문서 카테고리 순회(`apiguide?jobTpCode=N`) — 같은 결과. 명세 파일이 낡아서
   빠진 게 아니다.
3. **실측 대조군** — 같은 TR·같은 호출에서 `005930`(삼성전자)은 값이 채워지고
   옵션 코드(`B01608A01`·ISIN·키움형식 추정)는 전 필드가 빈 문자열. 게다가
   `return_code=0` `"정상적으로 처리되었습니다"` 를 돌려주는 **조용한 fail-open** 이라
   rc 만 보면 성공으로 오인한다.
4. 키워드로 걸리는 `ka10048`·`ka10095`·`ka30001~30012`·실시간 `0m` 의 그리스/미결제
   필드는 **전부 ELW** 다 — `ka10095` 의 행사가·만기 필드명이 `elwexec_pric`·
   `elwexpr_dt` 로 ELW 접두를 달고 있다.

경로 추측(`/api/dofo/*` 등)은 전부 HTTP 500 이고, `/api/dostk/fo` 가 1504 를 내는
것은 **`/api/dostk/*` 가 와일드카드**이기 때문이다(존재할 리 없는
`/api/dostk/zzzzzz` 도 동일 응답). 키움 REST 는 URL 이 아니라 `api-id` 로 라우팅한다.

**재개봉 조건**: 키움 REST 에 파생이 추가되면 이 예외는 즉시 무효다. #1005 메모의
독법대로 이 기각 사유는 "불가능"이 아니라 **"신형 REST 가 아직 안 옮겼다"** 이므로,
전제가 바뀌면 다시 열어야 한다.

## Consequences

- 새 라우트 `/sentiment` (독립 페이지). 시장 전체 지표라 `/live` 워크스페이스 창의
  링크그룹(종목 스코프) 모델과 맞지 않아 창으로 넣지 않았다.
- **#1005 의 완료 정의가 바뀐다** — "KIS 11개 표면 전부 제거" 가 아니라 "옵션 2개
  표면(`FHMIF10000000` · `fo_idx_code_mts.mst`)을 제외한 제거" 가 된다. 그 지도의
  티켓을 닫을 때 이 예외를 함께 적어야 "완전 제거 실패" 로 오독되지 않는다.
  브로커 단일화 동기(데이터 일관성) 관점에서는 **옵션만 단일 벤더에 남는 잔여
  결합**이 생긴다 — KIS 자격증명이 죽으면 `/sentiment` 만 휴면한다(ADR-0134 계약대로
  배너 표시).
- KIS REST 유량이 늘어난다: 전수 780호출/5분 + ATM 82호출/30초 ≈ 정상 사용 시 평균
  5.3 req/s. `/live` 와 같은 앱키 예산을 나눠 쓰므로, 페이지를 열어 둔 채 `/live` 를
  무겁게 쓰면 양쪽이 느려질 수 있다. 유휴 자동 정지(D3)가 완화책이다.
- 콜드 스타트가 ~60초다. 그 사이 응답은 `unavailable: "warming"` 이며, 화면은 이것을
  `kis_credentials_missing`(설정 필요)과 **다른 문구**로 안내한다.
- 위클리 옵션과 KOSDAQ150 옵션은 파싱되지만 지표 대상이 아니다(마스터에 분류만 남김).
- 만기일 근처의 롤오버(근월물 교체)는 마스터의 최소 만기를 따라 자동으로 넘어간다.
  다만 만기 당일 잔존 유동성이 차월물로 옮겨간 상태는 아직 감지하지 않는다 — 근월물
  거래량이 차월물보다 작아지는 시점을 잡는 것은 후속 과제다.
