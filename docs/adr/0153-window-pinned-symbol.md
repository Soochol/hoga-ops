# 0153 — 창 종목 고정(핀)은 boolean 자물쇠가 아니라 링크 그룹 분리다

**Status:** accepted (2026-08-21)

**Amends:** ADR-0119 / #711 의 "종목 SSOT = 링크 그룹". 그 결정을 뒤집는 것이 아니라
**기본값으로 강등**한다 — 그룹이 기본이고, 사용자가 명시적으로 고정한 창만 갈린다
(ADR-0145 가 지표에 대해 취했던 것과 같은 형태의 완화다).

**Related:**
- ADR-0119 · #711 — 멀티창 워크스페이스, 링크 그룹이 종목을 소유한다.
- ADR-0122 — 창 rect 는 비율. 프리셋이 무엇을 담는가의 선례.
- `frontend/src/state/workspace.ts` (`windowSymbolOf`·`activationTarget`·`toggleWindowPin`),
  `frontend/src/live/liveNavigate.ts`, `frontend/src/live/workspace/WorkspaceCanvas.tsx`.

## Context

요구(사용자, 2026-08-21): **"창 헤더에 핀을 만들어, 고정한 창은 관심종목·히트맵·스크리너를
클릭해도 종목이 안 바뀌게. 사용자가 드래그로 직접 그 창에 놓을 때만 바뀌게."**

문제는 자물쇠를 걸 자리가 창에 없다는 것이다. 창이 가진 것은 `group`·`rect`·`chart` 뿐이고
종목은 `groupSymbols[group]` 에 산다. 그래서 **창에 boolean 자물쇠를 걸면 원리적으로
샌다**: 같은 그룹의 다른 창에 종목이 들어오는 순간 `setGroupSymbol` 한 번이 잠긴 창의
표시 종목까지 바꾼다. 지키려는 값이 창 밖에 있기 때문이다.

기각한 대안 둘:

1. **그룹 단위 잠금.** 구조와는 맞지만 요구가 아니다 — 공장 기본 배치가 창 3개를 전부
   그룹 1 에 두므로(`liveDefaultLayout.ts`), 기본 상태에서 핀 하나가 워크스페이스 전체를
   잠근다. 사용자가 "창 단위"를 명시적으로 선택했다.
2. **핀을 누르면 그룹을 자동 분리.** 창 단위처럼 보이지만, 같이 쓰던 10호가·거래원 창이
   조용히 다른 종목으로 갈라진다. 링크 그룹은 사용자가 정하는 값이라 코드가 바꿀 것이 아니다.

## Decision

**핀 = 이 창을 링크 그룹에서 뗀 상태이고, 값이 곧 그 창이 붙든 종목이다.**

```ts
interface WorkspaceWindow { …; pinned?: GroupSymbol }
```

1. **읽기는 `windowSymbolOf` 하나를 지난다** — `win.pinned ?? groupSymbols[win.group]`.
   창→종목 해석이 두 갈래가 된 이상 소비처의 `groupSymbols[win.group]` 직독은 버그다.
2. **`setGroupSymbol` 은 여전히 무조건 쓰는 문이다.** 핀은 그 문에 조건을 다는 것이 아니라
   **목적지를 고르는 규칙**(`activationTarget`)으로 표현한다. #711 의 "종목을 바꾸는 문은
   하나" 불변식이 유지되고, 정책은 순수 함수 하나에 모인다.
3. **클릭은 핀 창을 건너뛴다.** `activationTarget` 이 z순서 위에서부터 핀 아닌 첫 창을
   고르고, 그 창을 포커스로 올린다. 결과는 셋으로 구분한다 — `window`(착지) ·
   `empty`(창 0개 → 그룹 1 시드, 종전 동작) · `blocked`(전부 핀 → 토스트).
4. **드롭만 핀 창에 쓴다.** `setWindowSymbol(id, symbol)` 이 핀 창이면 창 슬롯에, 아니면
   그 창의 그룹에 쓴다. 클릭 경로는 이미 핀 아닌 창을 받으므로 항상 그룹 쓰기로 떨어진다.
5. **프리셋·딥링크 탭에는 실리지 않는다.** 핀 슬롯은 종목이므로 `groupSymbols` 와 같은
   규칙이다. 저장(`snapshotWorkspace`)과 적용(`normalizeWorkspaceSnapshot`) **양쪽**에서
   막는다 — 서버에 이미 핀이 실린 프리셋이 있을 수 있어 읽기가 최종 방어선이다.
   딥링크 탭(`?code=`)은 하이드레이션에서 핀을 지운다. 안 지우면 공유 시드의 핀을 물려받아
   그 URL 이 조용히 죽는다.

## Consequences

- **같은 그룹의 형제 창에 드롭하면 핀 창은 안 바뀌지만 그룹은 바뀐다.** 그룹 모델이 정직하게
   드러나는 지점이고, 버그가 아니다.
- **히트맵에서는 핀 창에 종목을 넣을 수 없다.** 히트맵의 `DndContext` 는 폴더 재정렬 전용이라
   차트-드롭 경로가 없다(`resolveDropOnChart` 소비처는 관심종목·스크리너·랭킹 셋뿐).
   핀을 풀거나 다른 목록에서 끌어야 한다. 히트맵 드래그 확장은 별도 범위.
- **전 창을 핀하면 클릭이 아무 데도 못 간다.** 창을 닫아서도 도달하므로 "마지막 창은 고정
   금지" 로는 못 막는다 → 조용한 무반응 대신 토스트 + 「전체 고정 해제」로 설명한다.
- **활성 종목의 출처가 바뀌었다.** `groupSymbols[activeGroupOf(s)]` → `focusedWindowSymbol`.
   포커스 창이 핀이면 그룹 종목과 화면이 갈리므로, 종전 식은 관심종목 하트·검색 하이라이트·
   탭 제목을 화면에 없는 종목에 걸어 놓는다.
- **핀 차트는 그룹 차트 링크를 발행하지 않는다**(`groupTargetChartWindow`). 발행 payload 가
   종목 종속(`code`·`bundle`)이라 발행해 봐야 소비자의 `link.code === code` 가드에 전량 걸리고,
   그 사이 그룹 데이터 창(매물대·프로그램)은 **영구히** 링크를 잃는다. 핀 창을 건너뛰면 그룹
   종목을 실제로 따르는 차트가 발행자가 된다. 그룹의 차트가 핀 하나뿐이면 발행자가 없어
   데이터 창은 폴백이다 — 그 종목의 차트 파이프라인이 없으니 파생할 것도 없다.
- **구독 코드 집합이 핀을 반드시 포함해야 한다**(`liveOpenCodesKey`). 빠지면 증상이 화면이
   아니라 데이터로 나온다 — 캐시가 축출돼 창이 종목명을 띄운 채 조용히 빈다.
