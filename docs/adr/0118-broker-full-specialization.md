# 0118 — 브로커 완전 특화: 실시간 WS=키움 전담, 폴링 REST=KIS 전담, KIS WS 삭제

**Status:** accepted (2026-07-17)

**Supersedes:**
- ADR-0096 (UN venue 하이브리드) — 시간대 하이브리드 게이트가 "상시 병합 + 시간외단일가
  제외 필터"로 대체된다.
- ADR-0101/0102의 KIS WS 용량 설계(39등록·venue 시분할 스왑·4앱키 500종목) — KIS WS
  계층 자체가 삭제된다. KIS REST 용량 부분(ADR-0100·capacity scheduler)은 존속.
- ADR-0116의 "병행(parallel) 브로커" 프레임 — 키움이 병행이 아니라 실시간 전담이 된다.
  (ADR-0116의 슬롯 실측·세션 규율·kiwoom_live 소스 설계는 본 ADR의 기반으로 존속.)

**Amends:** ADR-0111 (거래원 WS→REST) — REST 공급은 과도기 유지하되 주입처가 키움
스트림으로 바뀌고, 최종적으로 키움 0F push로 교체된다(검증 전제).

**Unchanged:** ADR-0115 (per-source 완결성·hogaplay 게이트), ADR-0062 (동시호가 배제),
ADR-0038 (hot-path JSONL), ADR-0043 (Today Promotion).

## Context

KIS WS는 연결당 41등록(종목당 2 TR → 계좌당 19종목)이라 관심종목 76종에 4계좌가
필요하고, NXT 표시를 위해 08:50/15:31 venue 시분할 스왑이라는 복잡한 기계(재구독
사다리·스왑 유실 인시던트 2026-07-15)를 유지해야 했다. 키움 WS는 연결당 200종목
(타입 무관), 5앱키 = 1,000슬롯으로 관심종목+히트맵+온디맨드를 전부 수용한다
(실측 2026-07-16, ADR-0116). 히트맵 800종은 이미 키움 캡처로 설계됐다(ADR-0116).

## Decision

### 1. 역할 절단선

| 역할 | 담당 |
|---|---|
| 실시간 WS (호가·체결, 관심종목+히트맵+온디맨드) | **키움 전담** |
| 거래원·프로그램 실시간 | 목표 = **키움 0F/0w push** (정규장 스모크 검증 전제); 과도기 = KIS REST 폴링 유지 |
| 장중 폴링 REST (캔들·지수·투자자·백필) | **KIS 전담** (기존 capacity scheduler 체계 존속) |
| 딥 배치 (분봉 백필) | 키움 우선(900봉/콜) → KIS 폴백 |
| KIS WS 계층 | **완전 삭제** (휴면 아님) |
| KIS 2s REST 표시 폴러(rest_poller) | **완전 삭제** (역할 0 — §5) |

### 2. 구독 모델 — 5키 1,000슬롯 (#680·#681 v2)

- **저장셋 876** = 관심 76 + 히트맵 800 (특례 없음). 5키에 균등 파티션.
- **시간대 venue 스왑(전량)**: 정규장 창(08:50–15:31, `target_ws_venue` 경계 재사용) =
  전부 무접미(KRX) / NXT 창(08:00–08:50·15:31–20:00) = 전부 `_NX`.
- **온디맨드 풀 = 항상 124**: 열람 종목의 화면 옵션이 요구하는 venue 중 상시 구독에
  없는 부족분만 추가(표시 전용). 만석 시 신규 실시간 차단 + 사용자 알림(강등 없음).
- **`_AL`(통합) 전면 미사용**: 0B는 KRX∪NXT 병합과 정보 동치, 0D는 venue 필드가
  없어 정체 미상 + 산술 불가(관심 전체 +76 = 1,028 > 1,000).
- **venue 태깅 = 구독 코드 접미**(무접미=KRX, `_NX`=NXT — `split_venue` 그대로).
- 기대 구독 집합은 `f(시각, 저장셋, 표시셋)`으로 **파생**(저장 금지) — 킥 복구·부팅은
  현재 창 기준 재파생(2026-07-15 KIS 인시던트의 파생-집합 교훈).
- (종목, venue)는 **전역 1회 등록**: 두 연결 이중 등록 = 동일 틱 2벌 수신 →
  UN 병합 거래량 2배 오류. 참조 카운트 장부가 강제(#685).

### 3. 저장 — 단일 술어 (#681·#683)

```
저장 = (code ∈ 저장셋) AND (venue == KRX) AND (정규장 게이트)
```

NXT·온디맨드 틱은 어느 조합이든 저장되지 않는다. 성역 가드·ADR-0062/0115·15:35
컷·달력 `*_live` 전부 불변. 저장 소스는 kis_live → kiwoom_live로 **칼 컷오버**
(비장중 원자 전환, 하루=한 소스 — 듀얼라이트 없음). read-path 사다리는 기존
`kiwoom_live` 인접 배치가 혼재를 자동 처리(기배선, 무변경).

거래원(BROKER) 행은 키움 스트림에 주입돼 `kiwoom_live/brokers.parquet`으로
승격된다 — 과도기 공급자는 KIS REST(BrokerRestPoller), 최종은 키움 0F. 어느
쪽이든 착지·소비자 무변경(ADR-0111의 합성 틱 원칙 승계). cntr_tm 라벨 가정은
정규장 스모크 확정에 위임(런타임 가드 없음).

### 4. 표시 — 시분할 폐지, 3옵션 직결 (#681 v2)

- **KRX 옵션** = KRX 스트림만, **NXT 옵션** = NXT 스트림만 (직결).
- **UN 옵션 = 상시 병합**(시간대 전환 아님):
  - 체결·캔들 오버레이·현재가 = KRX∪NXT 시각순 병합. KRX 시간외단일가(15:40–16:00)
    체결은 병합 제외(ADR-0096의 오염 방지 필터 승계 — UN REST 캔들 정본과 정합).
  - 호가 패널 = 가격대 잔량 합산 병합 뷰(KRX 10단계+NXT 10단계 → 상위 10단계).
    실물 호가장이 아닌 **합성 뷰**임을 UI에 명시.
  - UN 캔들 정본은 계속 KIS REST(UN div) — 병합 오버레이는 실시간 층.
- 표시 규칙은 종목 출신(관심/히트맵/온디맨드)과 무관한 단일 규칙.

### 5. 장애·관측성 — 폴백 없음, fix-forward (#684·#686)

- **키움 워치독 루프(30s) 신설**(KIS watchdog 후계): 죽은 연결 재빌드 · 시간대 스왑
  실행 · **08:50 KRX 복귀 후 09:00 전 저장셋 등록 완결 술어 + 재시도**(유일한 저장
  리스크 창) · 미확인 구독 표적 재송신.
- 감지 = 앱 내 표면만: 정규장 틱0 120s → 재빌드, kicked_by_peer(연속 킥 5회)·토큰
  발급 실패 → 즉시 배너, 부분 장애 → 커버리지 칩, 상세 → 진단 패널 + 구조화 로그.
- **재난 표시 폴백 없음**: 키움 전면 장애 시 배너 + 실시간 정지(저장 폴백 없음은
  기존 정책). 이로써 rest_poller의 역할이 0 → 삭제.
- **되돌림 없음(fix-forward)**: 킬스위치·토글·env 노브를 만들지 않는다. 컷오버 후
  문제는 즉시 수정으로 전진 해결. 기록은 `analyze_gaps`가 자동(partial/gap_ranges).

## Rationale

- **단순화가 본질**: KIS WS의 41등록 제약이 강제하던 기계(시분할 스왑·재구독
  사다리·dynamic-N 파티션·계좌 헬스 프로브)가 키움 용량에서는 불필요하다. 두
  브로커의 어중간한 병행은 두 벌의 장애 모드를 유지하는 비용이다.
- **venue 확실성 > 슬롯 절약**: `_AL` 미사용·접미 태깅은 "저장 호가 = KRX 정규장"
  불변식을 실측 불확실성 없이 보장한다.
- **폴백 제거는 의도된 트레이드오프**: 단일 운영자 도그푸딩 환경에서 폴백 기계의
  유지비·오판 위험이 장애 시 표시 공백(배너로 정직하게 노출)보다 크다.

  `ws_frames` 파서·`get_approval_key`·watchdog/venue 스왑/사다리·스크립트 2종·
  픽스처 — 테스트 약 76개 삭제 + 6파일 대수정 (전수조사 문서 §5 + rest_poller 증보).
