# 0152 — 지표 세트는 창별이다. 페이지 세트는 시드 뿌리로 남는다

**Status:** accepted (2026-08-21)

**Amends:** [ADR-0146](0146-page-scoped-indicators.md) — 그 ADR 이 명시한 재검토
트리거("한 페이지 안에서 창마다 다른 지표를 보고 싶어질 때. 그때는 이 축 **위에**
창 축을 얹는다")가 실제로 왔다. 페이지 축은 **그대로 살아 있고**, 그 위에 창 축을
얹는다.

**Revives:** [ADR-0145](0145-per-window-indicator-scope.md) 의 창 축(`byWindow`).
그때는 **opt-in**(기본 연동 + 분리 버튼)이었고 그 기본값 때문에 사용자 검수에서
탈락했다 — 이번에는 **항상 독립**이다(아래 §"왜 opt-in 이 아닌가").

**Related:**
- #712 — 창 소유 지표를 전역 1세트로 되돌린 작업. 그 사고의 원인은 창-스코프라는
  개념이 아니라 **내용물을 창 스냅샷(탭별 sessionStorage)에 담은 것**이었다.
- ADR-0072 — 한 지표의 prefs 가 `livePage`·`chartPrefs` 두 store 에 나뉜다.
- ADR-0114 §3 — pane 순서·크기는 전역 1세트(이 ADR 이 바꾸지 않는다).
- `frontend/src/state/indicatorSettingsV2.ts` (`byWindow`),
  `frontend/src/state/indicatorScopeGc.ts`,
  `frontend/src/live/workspace/windowView.ts`.

## Decision

1. **차트 창은 항상 자기 지표 세트를 갖는다.** 같은 페이지·같은 봉의 두 창이 서로를
   따라가지 않는다. 연동 스위치도, 분리 버튼도 없다.
2. **스코프는 (페이지 × 창 × 봉)** 이다. 페이지 축(ADR-0146)은 유지되고, 창 축이
   그 위에 얹힌다. 봉 축은 **창 안에서** 그대로 산다 — 호가·체결 계열 지표는 일봉
   버킷에서 의미가 없고 `indicatorPaneProfiles` 가 봉별 유효성을 이미 강제한다.
3. 저장 모델은 `live.indicators.v2` 안에서 확장한다:

```
{ paneOrder, paneStretch,                              // 전역 레이아웃
  byTimeframe:      { minute|D|W|M: sparse diff },     // /live  페이지 세트
  studyByTimeframe: { minute|D|W|M: sparse diff },     // /study 페이지 세트
  byWindow: { "live:<id>"|"study:<id>": {같은 4버킷} } // 창 세트
}
```

   읽기는 한 줄이다: **`byWindow["<page>:<id>"] ?? 페이지 세트`**.

4. **내용물은 전역 localStorage 에 남고 창이 갖는 것은 키뿐이다.** 워크스페이스
   스냅샷 스키마는 무변경 — `ChartWindowConfig` 는 여전히 봉만 갖는다.
5. **창은 빈손으로 열리지 않는다(시드).** 새 창은 **포커스 차트 창**의 세트를,
   그 밖의 모든 경로는 **페이지 세트**를 복사한다. 시드는 **멱등**이고, 버킷
   객체까지 깊은 사본이다. 시드가 걸리는 자리는 셋이다:
   - `addWindow` (포커스 창 복사) — `set` 콜백 **밖에서** 원본을 잡는다. 안에서
     잡으면 새 창이 이미 목록에 있어 포커스 차트가 자기 자신이 된다.
   - 창 컴포넌트의 마운트 effect — `addWindow` 를 안 거친 경로의 안전망.
   - **쓰기 경로**(`patchIndicatorsScoped`·`resetIndicatorsScoped` 및 chartPrefs 대응물)
     — 아래 §"왜 쓰기 시점 보장이 필요한가".
6. **멤버십은 키의 존재**다. 값이 `{}` 여도 자기 세트다(공장값 상태의 창은 복사할
   diff 가 없다). 정규화는 `byTimeframe` 과 달리 **빈 엔트리를 걷어내지 않고**,
   창 지표 초기화는 **키 삭제가 아니라 `{}` 쓰기**다.
7. **회수는 창 닫기·워크스페이스 스냅샷 교체에서만.** 로드 시 일괄 청소는 하지
   않는다(딥링크 탭은 워크스페이스를 공유 저장소에 미러하지 않아, 스냅샷 대조
   청소가 **살아 있는** 창의 설정을 지운다).
8. **`chartPrefs` 의 indicator-modal 키도 같은 창 축으로 갈린다**(ADR-0072 의 두
   store 가 한 드로어에 함께 뜨므로). 멤버십의 SSOT 는 `livePage.indicatorsByWindow`
   이고 `chartPrefs.indicatorModalByWindow` 는 그 미러다 — 시드·회수는 항상 동반 호출.
9. **레이아웃(pane 순서·크기)은 전역 1세트 유지**(ADR-0114 §3).

## Context

### 왜 opt-in 이 아닌가 (ADR-0145 의 실패)

ADR-0145 는 같은 `byWindow` 축을 열었지만 **기본이 연동**이었다. 사용자의 검수는
"창 두 개를 띄우고 한쪽을 바꿔서 다른 쪽이 안 따라오는지" 보는 것인데, 기본이
연동이면 그 워크스루가 **그대로 실패한다** — 실제로 #1327 은 머지된 날 걷혔다.
같은 형태의 실패를 두 번 겪지 않기 위해 기본을 뒤집는다.

### 왜 "항상 독립" 의 옛 기각 사유가 더는 성립하지 않는가

ADR-0145 는 항상-독립을 한 문장으로 기각했다: *"새 창을 열 때마다 지표를 처음부터
켜야 한다"*. 시드(결정 5)가 그 대가를 없앤다. `addWindow` 는 이미 **포커스 창의
봉**을 물려받고 있었으므로(`win.chart = src?.chart ? {...src.chart} : ...`), 지표도
같은 규칙을 따르게 하는 것이 오히려 일관적이다.

### 왜 #712 의 재발이 아닌가

#712 의 사고 원인은 창-스코프라는 개념이 아니라 **설정의 내용물을 창 스냅샷에 담은
것**이었다: 워크스페이스는 탭별 sessionStorage 라 새 브라우저 탭에서 지표가 공장값
으로 리셋됐고 탭마다 구성이 갈렸다. 여기서는 내용물이 전역 localStorage 에 남는다.
따라서 크로스탭 동기화(`subscribeToIndicatorsStorage` → `hydrateIndicatorsFromStorage`)
가 창별 설정까지 그대로 덮고, 새 탭에서도 같은 구성이 재현된다. 재발 여부를 가르는
것은 "창별인가" 가 아니라 **"설정이 어느 저장소에 사는가"** 다.

### 왜 쓰기 시점 보장이 필요한가

`WindowViewValue` 를 만드는 곳은 **넷**이다: 창 컴포넌트 둘(`ChartWindow`·
`StudyChartWindow`)과 **지표 드로어 둘**(`WorkspaceIndicatorDrawer`·
`StudyIndicatorDrawer`). 드로어는 창 컴포넌트가 아니라서 마운트 시드를 거치지
않는데, **사용자가 지표를 켜고 끄는 주 표면이 바로 드로어다.**

시드를 컴포넌트 배선으로만 두면 그 창의 엔트리가 없는 상태에서 드로어 편집이
**페이지 세트로 새고**, 증상은 "드로어에서 켰는데 차트가 안 바뀜" 이다 — 이 기능의
인수 워크스루가 통째로 실패하는 모양이다. 초기화 경로는 더 나쁘다: 엔트리 없는 창의
"현재 봉 초기화" 가 **페이지 세트를** 지워 그 뒤 열리는 모든 새 창에 번진다.

그래서 보장을 배선이 아니라 **쓰기 경로 한 곳**에 둔다. 다섯 번째 생산자가 생겨도
같은 결함이 돌아오지 않는다. `chartPrefs` 는 미러이지만 **자기 쓰기 경로에서 스스로**
보장한다 — 이 스토어만 건드리는 키(급증 마커 등)를 토글하면 `livePage` 쓰기가 아예
없어 그쪽 보장이 오지 않기 때문이다(SSOT 규칙의 유일한 예외이고, 그 예외는
`seedIndicatorModalScope` 도크스트링에 적혀 있다).

### 왜 마운트 effect 가 안전망인가

창이 생기는 경로는 `addWindow` 만이 아니다 — 업그레이드 직후의 기존 창, 레이아웃
프리셋 적용, 워크스페이스 스냅샷 복원, 딥링크 탭의 시드 복제, 공장 기본 배치가 전부
그 함수를 거치지 않는다. 그 창들이 페이지 세트를 **공유**하면 이 기능은 조용히
절반만 동작한다. 마운트 시점 시드는 저장소 하이드레이션 순서(워크스페이스=탭별
sessionStorage, 지표=전역 localStorage)에 기대지 않는다는 이점도 있다.

언마운트를 회수 신호로 쓰지 **않는** 이유는 대칭이 아니다: 페이지 이탈·탭 전환에서도
언마운트가 나는데, 그때 지우면 사용자는 돌아왔을 때 이유 없이 초기화된 창을 본다.

## Alternatives considered

### A. opt-in 분리 (ADR-0145 그대로) — 기각
검수 워크스루를 통과하지 못한다(위 Context). #1327 이 그 증거다.

### B. 창당 1세트(봉 축 제거) — 기각
호가잔량·체결강도·매물대·깊이히트맵 같은 분봉 전용 지표가 일봉 버킷에서 의미가
없고, `indicatorPaneProfiles` 가 이미 봉별 유효성을 강제한다. 사용자의 "일봉 분봉에
따라 공유" 는 현재의 **공유 메커니즘**을 가리킨 말이지 봉 축을 없애 달라는 요구가
아니었다(제안 단계에서 확인).

### C. 창 스냅샷에 설정을 되돌려 놓기 — 기각
#712 를 그대로 재현한다.

### D. 명명 프로파일(창이 이름 붙은 세트를 **참조**) — 유예
여러 창이 한 세트를 공유하게 만드는 상위 호환 모델이지만 CRUD·이름·삭제 시 참조
처리 UI 가 통째로 따라온다. 이 축 **위에** 얹을 수 있다.

## Consequences

**Positive:** 지표 소비자 73개 호출부 무변경 — 절단면은 `useWindowIndicators` /
`useWindowIndicator` / `useIndicatorActions` 세 훅뿐이다. 되돌리기가 싸다(정규화에서
`byWindow` 를 버리면 전 창이 페이지 세트로 돌아온다). 페이지 축은 그대로라 ADR-0146
의 검수 결과가 유지된다.

**Negative / watch:**

- **닫은 창의 지표 구성은 사라진다.** 종전에는 창을 닫아도 잃을 것이 없었다. 완화는
  시드뿐이다 — 새 창이 포커스 창을 복사하므로 재구성이 한 단계다. 사용자가 명시적
  으로 감수한 트레이드오프다.
- **크로스탭 회수 과잉의 영향 범위가 넓어진다.** 워크스페이스는 탭별이지만 공유
  시드에서 복제되므로 두 탭이 같은 창 id 를 가질 수 있고, 탭 A 에서 그 창을 닫으면
  전역 `byWindow` 에서 회수되어 **탭 B 의 같은 창이 페이지 세트로 되붙는다.**
  ADR-0145 시절엔 "분리한 창" 만 해당됐지만 이제 모든 창이 해당된다. 회수를 포기하면
  대신 영구 누수가 남고, 스코프 키에 탭 식별자를 넣으면 새 탭에서 창별 구성이
  재현되지 않아 #712 의 증상으로 되돌아간다. 빈도가 낮아 감수한다.
- **페이지 세트의 역할이 강등된다.** `byTimeframe`/`studyByTimeframe` 를 직접 보는
  것은 Provider 밖 소비자(단일 차트·테스트 픽스처)뿐이고, 화면의 창은 자기 세트를
  본다. ADR-0146 이 경계한 "아무도 안 쓰는 스테일 키" 의 부분적 재발이다. 완화:
  **새 창의 시드 뿌리**라 매 로드 읽히고, 창이 하나도 없는 상태에서 열리는 첫 창이
  여기서 복사한다 — 완전히 죽지는 않는다.
- **번들 요청 증가는 8개 필드에만 걸린다.** 쿼리 키에 실리는 것은
  `studyReferenceQuerySettings` 의 8필드(askPeak·bidPeak·brokerLateEntry·
  tradeVolumePoc·depthHeatmap·volumeDistribution 계열)뿐이라, MA 기간·색·pane 토글을
  아무리 달리해도 키가 같아 캐시를 공유한다. 증가분은 "창 수" 가 아니라 **"그 8개를
  실제로 다르게 켠 창 수"** 이고, 그건 사용자가 명시적으로 요구한 것 자체다. 이
  목록에 필드를 추가하면 그때 창별 요청 분기가 넓어진다.
- **`applyIndicatorPreset` 은 페이지 세트를 갈아끼운다 — 즉 어느 창에도 안 보인다.**
  현재 UI 진입점이 없는 휴면 표면이라 그대로 뒀다. 되살릴 때는 "호출한 창에 적용"
  으로 스코프를 실을 것.
- **두 store 의 멤버십이 어긋나면 절반만 창별인 드로어가 된다.** 동반 호출이 그
  유일한 방어이므로, `indicatorModalByWindow` 를 직접 만지는 코드를 새로 만들지 말 것.
- **두 store 의 64개 상한은 서로 독립이다.** 한쪽 저장 키만 손상돼 맵 크기가 갈리면
  시드가 `livePage` 에는 들어가고 `chartPrefs` 에는 안 들어갈 수 있다 — 위 "절반만
  창별" 상태다. 실사용 창 수보다 한참 큰 값이라 감수하지만, 상한을 낮출 일이 생기면
  그때는 두 store 를 함께 봐야 한다.
- **테스트 격리**: 창 id 를 고정으로 재사용하는 테스트 파일은 `indicatorsByWindow` 를
  **매번 비워야 한다**. 안 비우면 앞 테스트가 심은 창 세트가 뒤 테스트의 페이지 세트
  주입을 가리고, 증상 서명이 "혼자 돌리면 통과, 파일 전체로 돌리면 실패" 라 머신
  부하 flake 와 헷갈린다.
- **재검토 트리거**: 분리된 창이 많아져 "이 창들이 같은 설정을 쓰게" 하고 싶어질 때 —
  그때가 대안 D(명명 프로파일)의 시점이다.
