# 0116 — 키움 WS 병행 도입: 고정 역할 공존으로 실시간 커버리지 76→876종목

**Status:** proposed (2026-07-16)

**Related:**

  전혀 다른(연결당 200종목·타입 무관) 별개 스택이라 이 산식을 공유하지 않는다.
- ADR-0111 (거래원 WS→REST) — 소비자 무변경 합성 `WsTick` 주입 패턴의 선례. 키움

- ADR-0115 (per-source 완결성 게이트) — `SourceName` 레지스트리에 `kiwoom_live` 추가.
  종목 소유권 단일 원칙이 소스 태그 충돌을 막는다.
- ADR-0099/0102 (rest30 폴러·4앱키 500종목/10초) — 키움 도입 후 rest30이 "주전 폴링"에서

- ADR-0109 (hogaplay_first 소스 사다리) — 분봉 백필 키움우선→KIS폴백의 문법 원류.
- `docs/plans/2026-07-16-kiwoom-ws-integration.md` — 실측표·PR 분할·모듈 맵 상세.

## Context

`/live` 실시간 시세는 전량 KIS에 강결합돼 있다. 수집 클라이언트(`Kis*`)는 브로커 추상화가
없고, 소스 다형성은 저장·조회 read-path(`hoga/api/sources.py`)에만 존재한다.

WS 실시간 커버리지가 병목이다. KIS WS는 연결당 등록 상한 39(하드 41), 종목당 2 TR
(호가+체결)이라 계좌당 19종목, 4앱키 = **76종목**뿐이다. 나머지(히트맵 등 ~500종목)는
REST 10초 폴링(rest30, ADR-0102)으로 덮여 push가 아니다.

키움증권 REST API를 실계좌 4앱키로 실측(2026-07-16)한 결과, WS 용량이 KIS의 10배 이상이다:

| 항목 | 실측값 |
|---|---|
| WS 등록 상한 | 연결당 총 **200종목** (grp_no 늘려도 총합 200 불변) |
| 카운트 단위 | **종목당 1건, 타입 무관** (`0B`+`0D` 쌍 등록해도 200종목) |
| 앱키당 세션 | **1개** — 동일 앱키 2번째 LOGIN이 기존을 킥(close 1000) |
| 앱키 간 독립 | 확정 — 4앱키 동시 각 200, disjoint 800종목 동시 수신 |
| REG 유량 | ~5 REG/s per 연결 (배치 50종목/REG로 회피) |
| NXT | `_NX` 접미 코드로 수신 확정 |
| 분봉 REST | 900봉/콜 (KIS 120봉/콜) |
| REST 유량 | TR당 ~1/s (폴링 엔진 불가) |

커뮤니티 통설("97건, 종목×타입당 카운트")은 실측으로 반증됐다.

## Decision

키움을 **평행 수집 스택**으로 신설하고, KIS와 **고정 역할 공존**한다. 동적 샤딩(한
universe를 두 브로커에 섞기)이 아니라 소유권을 고정한다 — 한 종목의 실시간 소유자는 항상
하나다.

**WS 분담**
- 관심종목(76) = KIS WS (venue 스왑·유실 사다리 검증 자산 유지)
- 히트맵(≤800) = 키움 WS (`0B`+`0D`, 슬롯당 200×4)
- 그 외 열람 종목 = 키움 온디맨드 WS (표시 전용, writer 금지)

**REST 분담**
- 과거 분봉 딥 백필만 키움 이관(900봉/콜, 키움우선→KIS폴백). 나머지 REST(일봉·스크리너
  배치·거래원·프로그램·지수·투자자·캘린더·토큰) 전부 KIS 잔류 — 상시·대량은 KIS 유량
  (15/s×4)이 강점, 키움 1/s는 퇴보.

**장애·용량 대응** = 키움 계좌 추가(WS). rest30 폴백 열화 정책은 만들지 않는다. 브로커
전체 장애는 계정 수와 무관(운명 공동체)함을 인지하고 수용한다. rest30·2s 폴러 코드는
삭제하지 않고 휴면(대상 빈 집합 = 호출 0).

**아키텍처 = Ports & Adapters.** 포트 = `WsTick` + `LiveStream.on_tick`(소스 무관 단일
진입점). 코어(표시·저장·지표)는 브로커를 모른다. 지금(N=2)은 **Adapter만**
(`kiwoom_frames`); `LiveCollector` Protocol + waterfall 배분은 3번째 증권사 때 추출한다
(Rule of Three). 상속 베이스(Template Method) 금지 — 킥 vs 거부, 배치 REG vs 개별 TR로
골격이 다르다.

**지금 지킬 규율**: (1) `kis_*`↔`kiwoom_*` 상호 import 금지 (2) 공유 코드에 브로커 분기
금지, 주입만 (3) 관측성 shape 통일 (4) `WsTick` 계약 테스트 공용화.

## Consequences

- WS push 커버리지 76 → 876종목(3.5배 이상). 히트맵이 10초 폴링에서 틱 push로.
- rest30 상시 부하(최대 ~50콜/s) 소멸 → KIS REST 예산이 백필·폴백으로 해방.
- 키움 클라이언트 신설(수집·인증·슬롯 층). 소비 경계·저장 태깅은 재사용.
- 킥 의미론이 KIS(거부)와 달라 이중 기동 가드가 필수. 76→876 틱 볼륨 ~10배 →
  0D 파싱은 필요 FID만, 계측 첫날부터.
- 미해결: 정규장 `_AL`이 KRX·NXT를 한 스트림으로 주면 UN 통합을 키움 1슬롯으로 해결
  가능 — "NXT=KIS 전담"이 재평가된다(후속 ADR).
