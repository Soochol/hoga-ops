# ADR-0122 — /live 창 좌표계를 절대 px → 캔버스 비율로

- 상태: 채택 (2026-07-21)
- 관련: ADR-0119(멀티창 워크스페이스), 반응형 바닥 플랜
  (`docs/plans/2026-07-21-zoom-responsive-toss-hybrid.md`)

## 배경

브라우저 줌인은 유효 뷰포트를 줄이고, 그만큼 워크스페이스 캔버스도 줄어든다.
창 rect 가 절대 px 라 캔버스가 줄어도 창은 제 크기를 유지하고, 캔버스는
`overflow-hidden` 이라 밖으로 나간 창은 **스크롤로도 못 닿는다**. 실측
(2026-07-21): 뷰포트 1026px 에서 캔버스 972×638 vs 창 extent 1428×776 —
기본 3창이 전부 도달 불가.

반응형 바닥(셸 `--app-floor-min-w`)은 이 문제를 **못 푼다**. 바닥은 셸이 더 이상
눌리지 않게 할 뿐이고, 캔버스가 바닥 크기로 줄어드는 것 자체는 정상 동작이기
때문이다. 절대 px 인 한 캔버스 축소는 언제나 창 소실을 뜻한다.

## 결정

**창 rect 를 캔버스 대비 비율(0~1)로 저장한다.** 캔버스가 줄면 창도 같은 비율로
줄어, 사용자가 만든 **배치는 보존되고 창은 사라지지 않는다**.

하한은 **셸 바닥이 담당한다**(양축). 바닥 위에서는 비례로 줄고, 바닥 아래에서는
셸이 압축을 멈추고 스크롤로 넘긴다 — 즉 창이 판독 불가 크기로 계속 작아지는 일이
없다. 비례와 바닥은 대체재가 아니라 **짝**이다.

### 왜 순수 비례(하한 없음)가 아닌가

프로토타입(`/prototype/window-scaling`, 4모델 비교) 실측, 줌 200%(캔버스 773×350):

| 모델 | 화면 밖 | 가독 미달 | 결과 |
|---|---|---|---|
| 절대 px (기존) | 3 | 0 | 창이 잘려 도달 불가 |
| 순수 비례 | 0 | **3** | 10호가 10단→7단, 거래원 4행→3.5행 — **내용이 조용히 잘림** |
| **비례 + 바닥 (채택)** | 3 | **0** | 창은 온전, 캔버스 동결 + 스크롤 |
| 비례 + 최소크기 보장 | 0 | 0 | 창끼리 겹침 — 사용자 배치 파괴 |

순수 비례의 실패는 "창이 작아짐"이 아니라 **호가 단수가 말없이 줄어드는** 형태로
나타나 오히려 발견하기 어렵다. 최소크기 보장은 수치상 완벽하지만 자유 배치
워크스페이스에서 겹침은 배치 파괴다.

**병목은 가로가 아니라 세로였다** — 줌 200%에서 10호가 창은 폭 340px(하한 260
여유)인데 높이 210px(하한 240 미달)이었다. 패널 대부분이 행 리스트라 높이에 먼저
부딪힌다. 따라서 바닥은 **세로도** 필요하다(가로만 있으면 반쪽).

## 구현 형태

- **런타임 = 비율, 픽셀 계산 = 그대로.** 스토어가 비율을 들고, 캔버스가 렌더 직전
  `px = frac × surface`, 커밋 직전 `frac = px / surface` 로 변환한다. `snapEngine`·
  `tidy` 는 **무변경** — 여전히 px 와 `Canvas` 를 받는 순수 함수다. 좌표계 전환의
  표면적을 캔버스 한 곳으로 가둔다.
- **스키마 v2 + 지연 마이그레이션.** 기존 저장값은 px 인데 *어떤 캔버스에서 만든
  px 인지*를 모른다. 고정 기준으로 나누면(예: 1546) 넓은 모니터에서 만든 레이아웃이
  비율 1 을 넘어 화면 밖으로 나간다. 그래서 하이드레이션에서는 px 를 그대로 두고
  `pendingNormalize` 로 표시한 뒤, **캔버스가 처음 자기 크기를 실측한 시점**에
  그 크기로 나눠 비율화한다. 사용자 화면 기준이므로 마이그레이션 직후 배치가
  **눈에 보이는 변화 없이** 그대로다.
- **`overflow-hidden` 유지.** 비율이 [0,1] 로 클램프되므로 창이 캔버스 밖으로 나갈
  수 없다 — 스크롤은 캔버스가 아니라 셸(바닥 아래)이 담당한다.

## 되돌리는 결정

반응형 바닥 플랜 PR-4 의 "캔버스 밖 창 어포던스"(`workspace-offcanvas-notice`)를
**제거한다**. 그 알림은 절대 px 에서 창이 소실되는 것을 드러내려던 완화책인데,
비율 좌표계에서는 소실 자체가 구조적으로 불가능해져 영원히 뜨지 않는다. 뜨지 않는
어포던스는 부패하므로 남기지 않는다.

"자동으로 창을 옮기지 않는다"(ADR-0119 창 소유권)는 **유지된다** — 비례 스케일은
창을 옮기는 게 아니라 좌표계의 단위를 바꾸는 것이고, 상대 배치는 완전히 보존된다.

## 결과

- 정상 사용(줌 100~150%)에서 창이 사라지는 일이 없어진다. 배치는 그대로 유지된다.
- 저장된 레이아웃이 **해상도 독립**이 된다 — 다른 크기의 모니터/창에서 열어도
  같은 배치로 보인다. 레이아웃 프리셋도 같은 성질을 얻는다.
- 대가: 창의 절대 크기가 캔버스에 종속된다. "이 창은 항상 680px" 같은 고정은 더
  이상 표현되지 않는다. 자유 배치 워크스페이스에서 절대 크기를 고집할 이유가 없어
  수용한다.
