# ADR-0123 — /study 창 워크스페이스 전환: 탭 유지 + 자유 배치 창

- 상태: 채택 (2026-07-21)
- 관련: ADR-0119(멀티창 워크스페이스), ADR-0122(비율 좌표계), ADR-0113(/live 멀티탭
  제거), **ADR-0149(/study 탭 제거 — 이 ADR 을 부분 supersede)**,
  플랜 (`docs/plans/2026-07-21-study-window-workspace.md`), 지도 #797

## 배경

ADR-0119 는 범위를 /live 전용으로 못박고 /study 전환을 "live 선 검증 후 별도
효력"으로 미뤘다(#713). live 창 시스템(자유 배치·스냅·Tidy·비율 좌표계)이 착지해
검증된 지금, /study 의 고정 2열 grid(차트 카드 + 상세 aside 4카드)를 같은 창
워크스페이스로 전환한다.

/study 는 /live 와 달리 **탭을 유지한다**. /live 가 탭을 버린 건(ADR-0113) "멀티
종목을 한 화면에"를 탭 대신 멀티창+링크 그룹으로 풀었기 때문 — 창이 탭의
대체재였다. /study 탭은 종목이 아니라 **저장뷰**(어느 날·어느 종목·어느 봉) 단위라
창과 직교한다: 탭 = 무엇을 볼까, 창 = 어떻게 배치할까.

## 결정

**방안 A — 레이아웃 공유, 탭 = 콘텐츠 선택자.** 창 배치는 워크스페이스 하나를 전
탭이 공유하고, 탭 전환은 모든 창의 데이터 소스(활성 저장뷰 번들 + 커서)를 통째로
바꾼다. 링크 그룹은 도입하지 않는다 — 활성 저장뷰가 단일 암묵 그룹이다.

기각한 대안:

- **탭별 창 배치** — 영속이 탭 수만큼 증식하고, "복기 도구 배치"는 탭이 바뀌어도
  같은 게 자연스럽다.
- **링크 그룹 이식(여러 저장뷰 동시 표시)** — 탭과 정면 충돌(탭 무의미화). range
  번들이 무거워 캐시 축출(#689~691)까지 있는 /study 에서 동시 멀티뷰는 메모리 부담.
- **/live 에 저장뷰 렌더(역방향)** — 두 페이지의 차이는 레이아웃이 아니라 데이터
  파이프라인(live=스트림+LATEST, study=디스크 range+커서)에 있어, 창 콘텐츠 전부에
  이중 모드 분기가 필요하다. /live 의 "지금" 정체성도 훼손된다.

## 구현 형태 (PR 분할)

1. **PR-1 — 캔버스/프레임 일반화**: 창 프레임워크를 페이지 중립 코어
   (`src/workspace/`)와 /live 결합부(`src/live/workspace/`)로 분리. 순수 엔진
   (`snapEngine`·`tidy`·`rectSpace`·`workspaceCanvasControls`)은 이동만, 캔버스는
   스토어 어댑터+`renderWindow` 주입형 코어와 live 래퍼(entryDrag 드롭·링크 그룹
   팔레트·창 콘텐츠)로, 프레임은 헤더 주입형 코어와 live 크롬 래퍼로 나눈다.
   합격 기준 = /live 동작·영속 무변경.
2. **PR-2 — `study.workspace.v1` 스토어**: kind 6종(chart/book/broker/vdist/
   program/**memo 승격**), 그룹 없음, 처음부터 비율 rect(레거시 px 마이그레이션
   불필요), `study.layout.v1` 카드 순서/숨김에서 1회 시드. v1 은 차트 창 1개 고정 —
   timeframe 은 탭(`tab.timeframe`)이 계속 SSOT.
3. **PR-3 — StudyPage 본문 교체**: 상세 aside·rail·dnd 재배열 제거, 기존 카드
   resolver 를 창 단위로 재배선. 탭바·헤더·URL sync·viewport 복원 무변경. 키보드는
   `[`/`]`=탭 순환 유지(의도적으로 /live 와 다름), `d` 제거, `t`=Tidy.
4. **PR-4 (보류)** — 창별 timeframe 멀티 차트는 `tab.timeframe` SSOT 를 흔드는
   모델 변경이라 PR-3 도그푸딩 후 별도 판정(#801).

windowView 의 전역 폴백(`useLivePageStore`)은 v1 에서 불변 — /study 차트 창은
Provider 없이 현행 전역 지표 경로를 유지한다. 창별 지표는 PR-4 판정에 묶인다.

### 갱신 (2026-07-29, 지도 #900)

위 §PR-2 의 **"timeframe 은 탭이 계속 SSOT"** 와 §PR-4 의 **"창별 지표는 PR-4 판정에
묶인다"** 는 무효다. `/study` 차트 창 헤더 자족화(#900)가 그 둘을 앞당겨 결정했다:

- **봉**: 창이 런타임 소유자, `tab.timeframe` 은 탭별 저장소로 역할 재정의(write-through
  거울). 재활성 시 탭 값으로 창을 재시드한다 — #902.
- **지표**: 창 소유. 기존 설정은 `live.indicators.v2` 에서 1회 시드한다(그 키는 이름과
  달리 `/live` 가 쓰지 않아 사실상 `/study` 의 저장소였다) — #904.
- 따라서 `StudyWorkspaceWindow.chart` 가 신설됐고 타입은 `/live` `ChartWindowConfig` 를
  **공유**한다 — #906.

**차트 창 1개 고정은 그대로다.** #900 은 그 구조를 *가능하게* 만들 뿐 창을 늘리지
않는다. PR-4(#801)에 남은 판정은 이제 "구조를 어떻게 만들까"가 아니라 **"창을 늘릴
가치가 있는가"** 하나다.

### 갱신 (2026-08-10, #801 판정: 도입)

**차트 창 1개 고정은 해제됐다.** 위 §PR-2 의 "v1 은 차트 창 1개 고정" 과 바로 위
문단의 "그대로다" 는 무효다. 판정 근거와 실측 비용은 #801 의 해소 코멘트에 있다 —
결정적 입력은 #1240(일봉 저장구간 맥락 밴드)이었다. 일봉이 저장 구간만 보이던
시절에는 "3m+D 나란히" 라는 조합 자체가 무의미했다.

도입 범위는 **단계 1** 이다:

- 차트 창 N개, **전부 활성 저장뷰에 묶인다**. 창별 저장뷰는 범위 밖 — 탭이 뷰
  선택자라는 ADR 의 골격("활성 저장뷰 = 단일 암묵 그룹")을 그대로 둔다. 그래서
  `studyWindowWorkspace.getCode()` 도 활성 탭 그대로다.
- 봉·지표는 창 소유(#902/#904/#906 그대로). **번들도 창별**이 된다 —
  `useStudyReferenceBundles` 가 `useQueries` 로 4×N 을 펴고 창 id 로 접는다.
  키가 같은 창끼리는 접어서 넘긴다(react-query 의 `Duplicate Queries` 경고 방지).
- **포커스된 차트 창**(zOrder 최상단 차트)이 셋을 소유한다: 탭 라벨
  write-through(#902), 커서 해석의 폴백, 뷰포트 캡처. 탭 재활성 재시드도 포커스
  창만 대상이다 — 전 창을 재시드하면 탭을 한 번 오갈 때마다 멀티 타임프레임 배치가
  무너진다.
- 상세 창(호가·거래원·매물대·프로그램)은 **커서를 발행한 창의 봉**으로 커서를
  해석한다. `sidebarCursorOrigin`(ADR-0119 PR-D)이 이미 그 값을 싣고 있다.
- 남은 불변식은 **"차트 창이 0개가 되지 않는다"** 하나다(`canCloseStudyWindow`).
  스토어 거부·창 프레임 어포던스·창 목록 메뉴가 이 술어 하나를 공유한다.
- 영속 스키마는 `study.workspace.v1` 그대로다 — 배열 모양은 처음부터 다중을
  허용했고 "정확히 1개" 는 동작 불변식이었지 형태가 아니었다.

`N=1` 은 기존 동작과 동일하다 — 그게 이 변경의 수용 기준이다.

### 갱신 (2026-08-17, 탭 제거 — ADR-0149)

**§배경의 "`/study` 는 탭을 유지한다" 문단과 §결정의 "탭 = 콘텐츠 선택자" 표현,
§구현 형태 PR-3 의 "탭바 … 무변경"·"`[`/`]`=탭 순환 유지" 는 무효다.** 저장뷰 탭
스트립·탭 스토어(`study.tabs.v1`)·공용 탭바(`src/tabs/`)가 전부 제거됐고, `/study` 는
저장뷰를 **한 번에 하나만** 본다.

**방안 A 의 골격은 그대로다.** 창 배치는 워크스페이스 하나를 공유하고, 콘텐츠 선택자가
모든 창의 데이터 소스를 통째로 바꾼다 — 그 선택자가 탭에서 단일 활성 뷰 스토어
(`study.activeView.v1`)로 바뀌었을 뿐이다. §갱신(2026-08-10)의 N개 차트 창도, "전 창이
활성 저장뷰 하나에 묶인다" 는 성질도, `canCloseStudyWindow` 불변식도, 봉·지표의 창
소유(#902/#904/#906/#1326)도 불변이다. 그래서 이 ADR 의 `Status` 는 `accepted` 로 남는다.

전환 수단은 우측 레일 저장뷰 드로어와 `?view=` 딥링크 둘이다. 근거·손실 목록·되돌리기
비용은 ADR-0149 에 있다.

## 결과

- /study 가 /live 와 같은 배치 자유도(드래그·스냅·Tidy·줌 대응)를 얻고, 저장뷰
  워크플로우(탭·드로어·URL)는 그대로 남는다.
- 창 프레임워크가 2계층(중립 코어 / 페이지 결합부)으로 정리되어, 이후 페이지가
  창 모델을 채택할 때 스토어와 창 콘텐츠만 쓰면 된다.
- 대가: 캔버스 코어의 API(어댑터·renderWindow·overlays)가 공용 표면이 되어 /live
  단독 시절보다 변경 시 고려 범위가 넓어진다.
