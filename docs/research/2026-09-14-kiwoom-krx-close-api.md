# 키움 API: Live 10호가 KRX 정규장 종가 조사

조사일: 2026-09-14 KST. 공개 공식 문서와 저장소 코드만 확인했다. 인증된 실계좌 REST/WS 호출, 주문, 제품 코드 수정은 하지 않았다.

## 결론

키움 REST에는 `close_pric`(종가) 필드가 있다. 특히 `ka10095`는 현재가와 종가를 각각 제공하고, `ka10086`·`ka10015`·`ka10005`는 날짜별 종가를 제공한다. 따라서 전용 종가 필드가 없다고 결론 내리면 안 된다. 다만 공개 필드 설명만으로 **2026-09-14 신설 KRX 애프터마켓 중에도 그 값이 당일 15:30 정규장 종가로 고정되는지**는 확인되지 않았다. `ka10081.cur_prc`를 즉시 확정 종가로 채택하는 것도 이 검증 전에는 이르다. [키움 공식 API 가이드](https://openapi.kiwoom.com/guide/apiguide), [공식 명세 JSON](https://github.com/Kiwoom-Securities/Kiwoom-REST-API/blob/main/kiwoom/_data/kiwoom_api_spec.json)

상품에서 표시할 의미는 **선택 거래소와 무관한 해당 날짜 KRX 정규장 종가**다. 2026-09-14부터 KRX 애프터가 16:00~20:00 열리지만 당일 종가는 15:30 정규장 기준이라는 공식 안내가 있다. 최신 KRX 현재가와 구별해야 한다. [카카오페이증권 시행 공지](https://www.kakaopaysec.com/customer/notice/dynamicBoardPageDetail.do?id=7452)

## WS는 가격 확정 근거보다 갱신 계기

`0B`는 현재가 FID `10`, 체결시간 `20`, 장구분 `290`, 거래소구분 `9081`을 제공한다. 전용 정규장 종가·확정 플래그는 확인되지 않았다. 웹 가이드는 `9081`을 KRX/NXT 문자열로 설명한다. `290`은 장전/장중/장후 구분이지만 새 KRX 애프터 실제 값은 실측해야 한다. 마지막으로 받은 WS 현재가는 연결 누락·NXT·애프터 체결 때문에 확정 종가로 승격하면 안 된다. [키움 API 가이드](https://openapi.kiwoom.com/guide/apiguide)

`0s`의 `215`에는 `4` 장마감, `8` 정규장마감이 있어 REST 재조회 계기로 사용할 수 있다. 단, 최신 웹 명세는 폐지된 시간외단일가 `c/d`를 삭제했으나 `9`의 18시 전체장마감 설명은 남아 있다. GitHub에는 `c/d`도 남아 있다. 시간·상태 매핑 전체가 새 세션에 맞게 검증됐다고 볼 수 없다. `8` 수신 여부·지연을 개장일 실측해야 하고 늦은 접속·재연결을 위해 REST 복구 경로가 필요하다. [키움 API 가이드](https://openapi.kiwoom.com/guide/apiguide), [기존 제도 변경 조사](2026-09-11-krx-aftermarket-official-sources.md)

## 구현 제안 — 실측 결과에 따라 공급자 선택

1. KRX 기본 코드로 `ka10095.close_pric`, `ka10086.close_pric`, `ka10015.close_pric`, `ka10081.cur_prc`를 15:30 직후와 16시 이후·20시 이후 비교한다. 알려진 정규장 종가, 다음 거래일 역사 행과도 비교한다. 애프터에서 실제 가격이 바뀐 종목을 반드시 포함한다. 필요한 경우 `ka10005/06`으로 교차 확인한다.
2. 고정되는 날짜별 종가 필드가 검증되면 이를 공급자로 선택한다. 우선 후보 `ka10095`는 이미 `hoga/live/kiwoom_multi_quote.py`에서 사용하지만 `parse_row`가 `close_pric`와 `dt`를 버린다. 기존 어댑터를 확장하되 선택 거래소 현재가와 분리한 KRX 강제 조회·캐시를 사용한다. 기존 `hoga/live/kiwoom_daily_candles.py`의 `adjust=False`, `venue='KRX'` 경로는 일봉이 검증된 경우 재사용한다. 검증 전 `cur_prc`라는 필드명을 `close`로 바꾸는 것만으로 확정성을 만들지 않는다.
3. 별도 KRX종가 조회 응답은 `code/date/price/status/source`를 가진다. `(code, date)` 단위 single-flight와 확정값 디스크 캐시로 재시작을 견딘다. 장중 `ka10001` 날짜 캐시를 공유하면 장중 값이 장후에도 남으므로 사용하지 않는다.
4. 당일 정규장 종료 전은 `price=null`, 상태 대기. 종료 직후 공급자 반영 지연은 제한된 재조회로 처리한다. 오늘 행이 없거나 날짜가 다르면 전일 행을 당일 종가로 표시하지 않는다. 휴장·미체결·특별 거래시간도 고정 15:30 비교만으로 확정하지 않는다.
5. 검증된 장후 조회원이 없다면 15:30~16:00 사이 정규장 가격을 확인해 스냅샷을 저장하는 보조안은 가능하다. 다만 그 시간에 앱이 꺼져 있거나 늦게 접속하면 복구할 수 없으므로 완전한 해결책이 아니다. 미확인은 `—`로 남겨야 한다.
6. `BookPanel.tsx`의 최저 바로 아래 `KRX종가` 행을 추가하고 `SUMMARY_ROWS`를 11→12로 조정한다. 전역 KRX/NXT/통합 선택과 무관하다. 과거 날짜·과거 커서에서는 해당 날짜와 시점을 적용해 미래의 종가를 미리 노출하지 않는다. 기존 DataWindow summary는 선택 거래소 현재시세이므로 재사용하지 않는다.

검증 항목은 정규장 전/후, 공급자 지연, 날짜 rollover, KRX/NXT/통합 전환, 재시작, 늦은 접속, 과거 커서, 애프터 현재가 변화, 거래정지·미거래 종목, 10호가 상세 영역 높이와 정렬이다. 이번 조사에서는 인증 시세 실측 및 기능 구현을 수행하지 않았다.


## 후속 실측 및 구현 (2026-09-14 16:58~17시 KST)

사용자 요청으로 실행 중인 서비스의 유효한 디스크 토큰을 메모리에서만 재사용해 읽기 전용 REST를 호출했다. 새 토큰 발급·WS 연결·서버 재시작은 하지 않았다. [선별 실응답](2026-09-14-krx-close-evidence.json)에 인증정보 없이 가격과 시각만 기록했다.

- SK하이닉스 KRX ka10095: 당일 현재가와 close_pric 모두 1,692,000원. ka10086 종가와 ka10081 일봉도 1,692,000원.
- 같은 종목 ka10080 KRX 원주가 1분봉: 15:30은 1,697,000원, 16:58은 1,692,000원. **REST의 종가 명칭은 정규장 종가 고정을 보장하지 않음을 실측으로 확인했다.**
- 삼성전자 KRX 15:30 분봉은 249,000원으로 당시 현재가와 같았다. 두 값이 같은 종목만 확인하면 위 차이를 놓친다.

따라서 우선 후보였던 ka10095.close_pric를 기각하고, ka10080에서 해당 날짜의 정규장 마감 시각과 정확히 일치하는 원주가 1분봉을 선택한다. 애프터·전일·마감 직전 봉으로 대체하지 않는다. 당일 마감 1분 뒤부터 조회하며 값이 없으면 대시와 제한된 재조회를 유지한다. `(날짜, 종목)`별 확정값을 디스크에 저장해 이후 애프터·재시작에서 유지한다.

이번 구현은 현재 날짜의 live 요약에만 표시한다. 과거 커서에서는 미래정보를 보여주지 않도록 비운다. 정규장 마감은 기본 15:30이며 캡처 메타데이터의 특별 마감시각이 있으면 우선한다. 메타데이터 없는 특별 거래시간의 정확성은 별도 거래시간 공급원이 필요한 잔여 한계다. 1페이지에 마감 봉이 없거나 종가 체결이 없는 종목도 임의 추정 없이 비운다.

UI는 최저 아래 KRX종가 한 줄을 추가한다. 조사 당시 제안했던 SUMMARY_ROWS 12 변경은 매수 가격·잔량 정렬을 깨므로 기각했다. 요약 전체 11호가 높이를 유지하고 12개 요약 행의 높이를 균등 조정한다.
