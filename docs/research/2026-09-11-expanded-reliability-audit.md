# 확장 안정성 점검 — 2026-09-11

범위: 애프터마켓 변경을 포함한 시세 표시·거래소 전환·캐시·예외 세션·연결 복구·검증 체계. 최초 점검은 읽기 전용으로 진행했고, 후속 진행 요청에 따라 아래 5개 확정 결함을 수정했다. 기존 미커밋 변경은 보존했다. 운영 API 호출·배포·사용자 서버 변경 없음.

## 재현한 동작

### 1. P1 — 이전 WS 틱이 새 REST 시세를 계속 덮음

- 위치: `frontend/src/api/liveQuotes.ts:187` (`withTickPrice`), `frontend/src/api/liveTickOverlay.ts:56` (`LiveTickSample`).
- 재현: REST 가격 100 → WS 체결 110 → REST 재조회 성공 200. Query 캐시에는 200이 있지만 훅 출력은 110이다.
- 원인: 체결 표본에는 거래소 시각·수신 시각이 없고, 합성은 틱이 존재하면 우선한다. 틱 구독의 정리는 코드 집합·거래소·해석기 변경에 묶여 있다. 같은 종목을 계속 보면 REST 재조회만으로 틱을 교체할 수 없다.
- 영향: WS 체결이 멈췄을 때 REST가 정상화돼도 표시가 오래된 가격에 머무를 수 있다. 단순히 마지막 가격을 유지하는 것과, 새 근거를 받아도 무시하는 것을 구분해야 한다.
- 개선: 틱/REST에 거래일·데이터 시각·수신 시각을 보존하고 소스 선택 정책을 명시한다. 연결 단절/거래일 변경 시 틱의 우선권을 재평가한다. 저유동 종목에 일률적 TTL을 적용해 정상 마지막 체결까지 삭제하지 않도록 설계한다.

### 2. P1 — 거래소 전환 대기 중 이전 거래소 가격 표시

- 위치: `frontend/src/api/liveQuotes.ts:150`.
- 재현: KRX 가격 100 조회 후 NXT로 전환하고 NXT 응답을 대기 상태로 유지하면 출력에 100이 남는다.
- 원인: Query 키에는 venue가 있지만 `placeholderData: prev => prev`는 이전 Query의 venue를 확인하지 않는다.
- 개선: 종목 목록 변경에는 같은 venue의 이전 값만 유지하고 venue 변경에는 새 거래소 캐시 또는 명시적인 대기 표시를 사용한다. 이전 값을 표시한다면 출처를 함께 표시한다.

### 3. P1 — 새 거래소 응답에 이전 거래소 등락률 혼합

- 위치: `frontend/src/api/liveQuotes.ts:269,320,344`.
- 재현: KRX 가격 100/+10%/+9를 받은 뒤, NXT 가격 200/등락률 unavailable 응답을 받으면 출력은 가격 200/+10%/+9다.
- 원인: 마지막 정상 등락률 Map의 키가 code뿐이다. venue 변경이나 코드별 유효 venue 변경에 맞춰 분리하지 않는다. 2번의 placeholder만 고쳐도 이 문제는 남는다.
- 개선: 마지막 정상 값의 키에 실제 거래소·거래일·기준가 출처를 포함하고 호환되는 값만 재사용한다.

### 4. P2 — 집계 캐시에 세션 경계가 빠짐

- 위치: `hoga/api/bundle.py:410` 부근의 과거 ratio 캐시 및 single-flight 키, `hoga/api/past_indicators_cache.py`.
- 재현: 동일한 날짜/종목/거래소의 15시·17시 호가로 15:30 종료 범위를 먼저 캐시했다. 다음 20:00 종료 요청은 잔량 [100,0], 캐시 없는 같은 요청은 [100,100]을 반환한다.
- 조건: 동일한 원본 세대에서 호출자가 서로 다른 세션 경계를 전달해야 발생한다. 일반 range와 prewarm은 현재 같은 메타 경계를 사용하며, 메타 수정 시각을 통한 기존 무효화도 존재한다. 따라서 모든 일반 조회가 잘못된다는 뜻은 아니다.
- 개선: 집계 입력 경계를 캐시/동시 요청 합치기 키에 포함하거나, 집계 경계의 단일 소유자를 두고 다른 경계 요청을 거부한다. 캐시 의미가 바뀌면 영향받는 종류/날짜만 무효화한다.

### 5. P2 — 예외 시간표의 결손 판정이 단일 구간으로 되돌아감

- 위치: `hoga/api/disk_state.py:695`.
- 재현: 10:00–15:19:59, 16:00–19:59:59의 1초 간격 호가를 생성했다. 09:00/20:00 경계에서는 33,600행·결손 0건이지만, 10:00/20:00 경계에서는 33,000행·15:19:59–16:00 결손 1건이다. 저녁 마지막 600행도 빠진다.
- 조건: 실제 지연 개장/특별장 확정 공지를 주장하지 않는다. 예외 경계를 입력했을 때의 함수 동작을 검증한 것이다.
- 원인: 분리된 구간 규칙이 정확히 09:00/20:00일 때만 적용된다. 그 밖에는 종료 전 10분을 동시호가로 처리하는 일반 분기로 돌아간다.
- 개선: 거래소·거래일별 접속매매 구간 목록을 수집 게이트·메타·결손 분석·차트가 공유하도록 한다.

## 검증 및 권장 순서

프론트 임시 훅 검사 3건으로 1–3의 현재 동작을 재현했다. 결함을 정상 기대값으로 고정하지 않도록 확인 후 임시 테스트를 삭제했다. 4는 임시 Parquet와 실제 QueryEngine으로 캐시/비캐시 결과를 비교했다. 5는 동일한 1초 자료에 세션 경계만 바꿔 실행했다. 임시 자료는 자동 정리했다. 전체 테스트를 다시 실행한 점검은 아니다.

권장 순서: (1) 시세 소스·거래소·거래일 일관성(1–3), (2) 캐시 계약(4), (3) 구간 목록 기반 세션 정책(5), (4) 장애 관측과 E2E 기준 복구.

## 후속 수정 — 2026-09-11

1. WS 체결에 거래소 시각·클라이언트 수신 시각·거래소·수신일을 보존한다. 정상 REST 조회를 시작하기 전에 받은 틱은 해당 REST 응답으로 대체한다. 조회 도중 받은 틱은 유지하고 stale REST는 틱을 덮지 않는다. 역순 체결도 제외한다.
2. 시세 Query 키에 KST 날짜를 추가하고, placeholder는 같은 날짜·거래소에만 적용한다. 코드별 유효 거래소가 바뀌면 이전 파티션 응답도 걸러낸다.
3. 마지막 정상 등락률은 종목·실제 거래소·KST 날짜·기준가 날짜·기준가로 분리한다. 거래소나 기준가가 다른 값을 재사용하지 않는다.
4. 지표 빌더는 생략한 세션 경계를 메타데이터에서 해석한다. 메타의 표준 경계와 일치하는 요청만 영속 캐시와 해당 single-flight를 공유한다. 임의 경계 요청은 별도로 계산하므로 표준 구간 결과를 오염시키지 않는다. 기존 캐시의 메타 세대 무효화는 유지한다.
5. KRX 접속매매 구간을 명시적으로 전달하고 수집 메타에도 기록한다. 수집 완료 판정·기존 메타 재계산·조회·시계열 검증에서 휴장 구간을 제외하고 저녁 마지막 10분을 포함한다. 지연 개장 입력도 같은 규칙으로 처리한다. 다른 거래소와 도입 전 날짜는 기존 정책을 유지한다.

회귀 검증은 `frontend/src/api/liveQuoteContinuity.test.tsx`와 `tests/unit/live/test_krx_aftermarket.py`에 추가했다. 실제 QueryEngine과 임시 Parquet로 정규장 한정 조회 후 저녁장을 포함한 조회의 캐시 일관성을 확인한다. 시계열 가드는 구간 전달을 의도적으로 제거하면 테스트가 실패하고, 복원하면 통과하는 것도 확인했다.

- 백엔드 전체: 5,115 passed / 2 skipped / 13 deselected (`not wallclock`).
- 프론트 전체: 7,390 passed / 566 files.

## 추가 보완 — 시세 복구·지연 프레임·메타 재계산

후속 점검에서 재현한 세 경계 조건을 수정했다.

- 정상 WS 체결을 반영하면 현재가의 `stale`·`stale_reason`을 해제한다. 가격이 그대로인 새 체결도 복구 신호로 처리하며, 기준가 부재로 체결을 적용하지 못하면 기존 시세 판정을 유지한다.
- 거래 프레임의 실제 KST 날짜를 수신 단계에서 검사한다. 전날·다음 날·비정상 시각의 프레임이 오늘 첫 체결 표본을 차지할 수 없도록 한다. 유효한 오늘 체결은 정상 반영한다.
- 기존 KRX 메타를 재계산할 때 `indicator_continuous_windows`도 비교·저장한다. 결손 여부와 범위가 이미 맞아도 구간 정보가 없으면 보완한다. kiwoom_live와 hogaplay 경로에 적용하고 dry-run·멱등성·기존 필드 보존을 실제 임시 Parquet로 검증했다.
- 기존 시장 수급 E2E는 화면 본문에 없는 문구 대신 `마지막 정상 수신 시각` title의 실제 요소를 찾고, `13:00:10 수신`과 `수집 종료` 표시를 검증하도록 정리했다. 화면 디자인은 변경하지 않았다.

날짜 가드는 임시 검사에서 날짜 변환을 강제로 같은 날로 돌려 회귀 테스트 실패를 확인했다. 검사 후 임시 파일과 mock은 제거했다. 기존 체결 테스트의 `t_ms: 1` fixture는 실제 현재 날짜로 보완했다.


추가 보완 최종 검증:

- 백엔드 5,119 passed / 2 skipped / 13 deselected (`not wallclock`).
- 프론트 7,395 passed / 566 files. 타입 검사·Vite 빌드·Ruff·diff 공백 검사 통과.
- Playwright 전체 117 passed. 기존 수급 표시 실패 2건도 해결됐다.
- 실시간 틱 3개·수급 표시 2개를 각각 5회 반복해 25 passed.
- 브라우저 합성 체결은 실행 당일 KST 10시를 기본 시각으로 사용한다. 실제 performance 시계는 보존해 기존 수신→DOM 지연 측정도 계속 검증한다.

운영 자료 재계산이나 배포는 실행하지 않았다. 메타데이터 보완은 기존 재계산 명령을 실행할 때 적용된다.


## 추가 점검 — 예상체결 수명과 예외 종료 구간 (후속 수정 완료)

제품 코드는 수정하지 않았다. 임시 훅 검사 3개와 순수 함수 비교로 다음 동작을 재현했고, 임시 테스트는 제거했다. 전체 테스트 재실행은 하지 않았다.

1. **P2: 예상체결가 만료가 새 응답에 의존한다.** `liveQuotes.ts:268`의 30초 TTL은 합성 재실행 시에만 검사한다. 2026-09-14 15:30의 closed REST 응답 뒤 15:29:59 예상 프레임을 수신하고 새 프레임 없이 31초를 진행해도 expected_price가 남았다. closed 폴링은 600초이며 별도 만료 타이머가 없다. 예상가가 실제로 오래 남는 조건은 수신 중단·후속 응답 부재다. 만료 시각에 상태를 갱신할 필요가 있다.
2. **P2: 지연된 예상 프레임의 날짜·순서 검증이 빠져 있다.** 실제 체결에는 날짜와 역순 검사가 있지만 ob 예상체결 경로는 그대로 저장한다(`liveTickOverlay.ts:246–254`). 전 거래일 금요일 15:29:59 프레임을 월요일 15:30에 받으면 표시된다. 오늘 15:30 체결을 반영한 뒤 오늘 15:29:59 예상 프레임이 오면 예상값이 다시 생긴다. 이는 지연 프레임 주입으로 확인한 경계 조건이며 운영에서 해당 순서가 발생했다고 주장하는 것은 아니다. 날짜·최근 예상 표본·최근 체결 시각을 함께 비교해야 한다.
3. **P2: 조기 종료 입력에서 마지막 동시호가 구간이 결손으로 잡힌다.** 09:00–12:19:50의 10초 간격 자료와 12:30 종료 경계를 사용했다. 도입 전 정책은 결손 없음, 도입 후 `krx_continuous_windows`는 12:30까지 연속 구간에 포함해 12:19:50–12:30을 결손으로 보고한다. 현재 helper는 정규장 종료 시각을 별도로 받지 않고 15:20 경계를 고정한다(`stock_sessions.py:94`). 예외 시간표 정책을 실제 정규장·동시호가 구간과 연결해야 한다. 이 재현은 합성 조기 종료 입력이며 실제 특정일의 단축장 공지를 의미하지 않는다.

우선순위: 예상체결 수명·순서 규칙을 하나로 보완(1–2), 예외 시간표 입력 계약 정리(3).


### 예상체결·예외 종료 후속 수정

- 예상 표본 전용 만료 타이머를 추가했다. 정상 시세 폴링이나 새 프레임이 없어도 표본을 제거하고 화면을 갱신한다. 같은 값의 새 예상 프레임은 만료 시각을 연장하며, 구독 정리 시 타이머도 취소한다. 표본 제거의 화면 반영에는 기존 150ms flush 주기를 사용한다.
- 예상 프레임의 KST 날짜와 유효 시각을 검사한다. 최근 예상 프레임보다 오래된 값, 이미 반영한 체결과 같거나 앞선 시각의 예상값을 제외한다. 만료 후에도 최근 예상 시각을 기억해 오래된 프레임이 표본을 되살리지 못하게 한다.
- 연속매매 구간 계산에 실제 정규장 종료 시각을 별도로 전달한다. 메타 기반 조회·재계산은 해당 정규장 종료 전 10분을 제외한다. 지표 조회 범위를 잘랐다는 이유만으로 새로운 동시호가 구간을 만들지 않는다. packed HHMMSSmmm에서 직접 빼지 않고 시각 변환 후 계산해 12:00 → 11:50도 처리한다.
- 훅 회귀 테스트 7개와 백엔드 회귀 테스트 3개를 추가했다. 조기 종료 자료를 Parquet로 저장해 메타 보완과 시계열 검사까지 확인한다.
- 새 브라우저 테스트는 실제 관심종목 행에서 36,000 예상가가 표시된 뒤, 31초 동안 추가 REST 응답 없이 30,000 체결가로 돌아오는 것을 검증한다. 5회 반복 통과했다.

- 프론트: 7,402 passed / 567 files.

## 확장 점검 — 복원·보완 명령·캐시 세대 (후속 수정 완료)

시세 UI 이외의 데이터 복원과 관리 명령까지 넓혀 점검했다. 제품 코드는 수정하지 않았다. 아래 재현은 TemporaryDirectory 안에서만 실행했고 자료는 정리됐다. 전체 테스트는 다시 실행하지 않았다.

1. **P1 — 수정 시각을 보존한 백업 복원 후 오래된 지표 캐시가 유효 처리된다.** 실제 QueryEngine과 snapshots.parquet로 잔량 100을 캐시한 다음, 원본을 잔량 200으로 바꾸고 meta 수정 시각을 이전보다 60초 과거로 돌렸다. 기존 엔진의 캐시 조회와 새 엔진의 캐시 조회는 모두 100, 캐시 없는 조회는 200이었다. `_sync_generation`은 토큰 변경으로 메모리를 비우지만, `_is_stale`은 원본 수정 시각이 캐시 생성 시각보다 큰지만 검사해 디스크의 옛 결과를 다시 읽는다(`past_indicators_cache.py:337–340`). 복원이나 세대 교체는 단순한 시간 증가로 가정할 수 없다. 원본 세대를 캐시 생성 시 함께 저장해 일치 여부를 검증하고, 복원 경로의 캐시 무효화도 명시할 필요가 있다.
2. **P2 — 지표 구간 보완 명령이 저장된 예외 시간표를 기본값으로 덮는다.** KRX 메타에 정규장·지표 구간 10:00–12:30, 연속매매 구간 10:00–12:20, 애프터마켓 제외를 명시했다. `backfill_indicator_session_bounds` 실행 뒤 지표 구간은 09:00–15:30으로 바뀌고 연속매매 구간은 10:00–12:20으로 남았다. 기본 시간표로 재설정하면서 기존의 명시된 구간과 의미가 어긋난다(`meta_backfill.py:280–295`). 유효한 예외 값과 복구해야 할 과거 기본값을 구분하고, 관련 메타 변경을 일관되게 적용해야 한다. 합성 예외 시간표이며 실제 단축장 공지를 주장하지 않는다.
3. **P2 — 스키마가 잘못된 파일 하나가 전체 메타 보완을 중단한다.** 첫 종목의 meta가 유효한 JSON 배열 `[]`이면 AttributeError, `regular_session_open_ms:null`이면 TypeError가 발생했다. 뒤에 둔 정상 종목은 처리되지 않았다(`meta_backfill.py:125–137`). JSON 구문 오류는 건너뛰지만 자료형·필드 오류는 같은 보호를 받지 못한다. 파일 단위 검증과 오류 격리, 처리하지 못한 파일·이유의 결과 보고가 필요하다.

추가 설계 후보: 시간표·연속매매 구간·결손 판정·지표 캐시 세대의 일관성을 검증하는 복원/보완 사전 점검을 하나로 제공한다. 현재는 구간 보완과 결손 재계산이 별도 명령이라 실행 순서에 따라 중간 불일치가 남을 수 있다. 이 후보는 위 재현 세 건과 구분한 운영 개선 제안이다.


### 복원·보완 명령 후속 수정

- 모든 지표 디스크 캐시에 원본 `meta.json`의 파일 세대(dev/inode/size/mtime_ns/ctime_ns)를 저장하고 일치 여부로 유효성을 검사한다. 메모리에도 저장 시점부터 세대를 연결하며, 누락됐던 `peak_rep`를 세대 변경 시 제거 대상에 포함했다. 시각이 과거로 돌아간 복원, 같은 시각·크기·내용의 재작성, 파일 교체·삭제를 회귀 테스트로 검증한다.
- 원본 메타가 있는 구형 캐시에 세대 정보가 없으면 다음 조회에서 재계산한다. 해당 첫 조회 비용은 증가할 수 있다. 원본 메타 갱신을 동반하는 기존 수집·복원 계약을 사용하며, 재계산 도중 동시 복원을 트랜잭션으로 격리하는 기능은 이번 범위가 아니다.
- 지표 구간 보완은 명시된 예외 경계를 보존한다. 경계가 없는 예외일에는 정규장 예외 경계를 사용하며, 변경한 경계와 연속매매 창·결손 판정을 함께 저장한다.
- 메타 보완 명령 4개에 파일 단위 스키마 검증을 적용했다. 비객체 JSON·null/잘못된 시각 필드를 건너뛰고 경로와 이유를 기록하며, CLI 결과에 `invalid` 수를 추가했다. `invalid`는 `skipped`에 포함된다. dry-run에서도 오류 파일과 정상 파일을 함께 집계한다.
- 회귀 테스트 27개를 추가했다. 실제 QueryEngine과 임시 Parquet 재현에서도 복원 후 기존 엔진·새 엔진·캐시 없는 조회가 모두 잔량 200을 반환했다(수정 전 캐시 조회는 100).

운영 자료의 보완 명령 실행이나 배포는 수행하지 않았다.

복원·보완 명령 수정 최종 검증:

- 백엔드 전체: 5,149 passed / 2 skipped / 13 deselected (`not wallclock`).
- 관련 테스트 162 passed. 동일 크기·내용의 복원 조건을 강화한 캐시 테스트도 86 passed.
- Ruff·`git diff --check` 통과.
- 이번 차수는 백엔드만 변경했으며 프론트·E2E는 재실행하지 않았다.
