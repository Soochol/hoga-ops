## 변경

- 일별 데이터 창의 커서는 같은 그룹의 KST 날짜로 구독한다. 동일 날짜의 분봉 이동은 일별 표를 갱신하지 않는다.
  프로그램 당일 누적 보기는 기존 ms 커서를 유지한다.
- 투자자와 프로그램의 숫자 셀·합계는 데이터/표시 설정으로 memo한다.
  행은 안정된 셀 참조와 날짜 강조 여부를 받으므로 커서 변경 시 이전/새 강조 행만 갱신된다.
  따라가기 target/안내 상태가 바뀌어도 숫자 셀은 다시 포맷하지 않는다.
- 프로그램 rows/totals를 memo해 같은 날짜의 반복 렌더가 300ms 따라가기 타이머를 취소하지 않는다.
- 가격·수량·금액·K·exact 툴팁의 Intl.NumberFormat 인스턴스를 locale/옵션에 맞춰 모듈에서 재사용한다.
  기존 부호, 반올림, K 임계값, null 표시와 title/aria-label은 유지한다.
- 차트 동기화 훅은 원시 커서 대신 게이트와 스냅 결과를 구독한다.
  자기 창/다른 그룹/같은 일봉에 머무르는 분봉 이벤트는 결과가 같으면 렌더하지 않는다.
  꺼진 캔들 툴팁은 enabled=false로 결과를 고정한다.

## 최종 성능 결과

JS 시간은 **한 시나리오 전체의 ScriptDuration 누적 ms 중앙값**이다. 한 번의 호버 지연이 아니다.
최종 구현은 각 조건 3회 반복했다. 수정 전 dwell은 2회, 나머지 기본 비교는 3회다.

| 시나리오 | 수정 전(ms) | 수정 후(ms) | 감소 | 수정 후 범위(ms) |
|---|---:|---:|---:|---|
| 두 표 · 연속 60회 · 일봉 | 662.53 | **207.67** | 68.7% | 189.82–223.10 |
| 두 표 · 연속 60회 · 분봉 | 691.83 | **191.22** | 72.4% | 188.67–209.10 |
| 두 표 · 12회 ×450ms · 일봉 | 830.49 | **76.64** | 90.8% | 73.47–81.14 |
| 두 표 · 12회 ×450ms · 분봉 | 283.42 | **59.42** | 79.0% | 57.81–62.91 |
| 차트만 · 연속 60회 · 일봉 | 381.90 | **209.36** | 45.2% | 203.49–249.38 |
| 차트만 · 연속 60회 · 분봉 | 426.10 | **277.56** | 34.9% | 264.92–280.89 |
| 차트만 · 같은 봉 60회 · 일봉 | 140.44 | **100.41** | 28.5% | 89.84–103.50 |
| 차트만 · 같은 봉 60회 · 분봉 | 211.62 | **149.80** | 29.2% | 148.96–151.41 |

두 표의 일봉 dwell은 **각 run 스크롤 쓰기 4회**를 그대로 유지했고,
50ms 이상 long task는 수정 전 run마다 4회 → 수정 후 **0 / 0 / 0회**였다.
로드된 날짜의 모든 최종 panel run에서 투자자/프로그램 추가 API 요청은 **0회**였다.
최종 기본 시나리오의 frame p95는 **16.7–16.8ms**, long task는 모두 0회였다.

과거 날짜 확장 탐색(각 버전 1회)은 **1,649.82 → 126.69ms**였다.
투자자 60→120행 확장, 프로그램 60행 유지, 추가 API 요청 3회, 스크롤 쓰기 4회가 보존됐다.
long task는 11→0회였으나, 두 프레임이 25ms를 넘었고 최대 frame interval은 **49.9ms**였다.
즉 과거 확장까지 모든 프레임이 16.7ms였다는 뜻은 아니다. 실제 API 지연·더 깊은 백필은 별도 실사용 조건이다.

빠른 이동은 처리 시간이 달라지면 120ms throttle의 발행 횟수도 달라진다.
위 감소율은 같은 60회 사용자 입력 전체의 결과이며 개별 formatter 함수만의 속도 향상률이 아니다.

- `npx vite build`: 통과. 기존 큰 청크 경고는 남아 있다.
- 관련 Playwright 6개 파일/9개 테스트: **9개 통과**.
  `investor-daily-scroll`, `chart-daily-program-trade`, `chart-investor-side`,
  `chart-legend-toggle`, `day-extreme-lines`, `extreme-label-clearance`.
- 전체 `npx playwright test --reporter=line`: **119 통과 / 12 실패**.
  그중 투자자 2건은 이미 제거된 문구를 찾는 오래된 검사였다. 현재 선택 상태·실제 강조 행·스크롤 위치를
  검사하도록 고치고 위 관련 실행에서 통과했다. 전체 E2E를 모두 통과했다고 주장하지 않는다.

남은 10건은 이번에 수정하지 않은 저장뷰 1건, 스크리너 7건, 관심종목 메뉴 2건이다.
저장뷰는 과거의 긴 날짜 안내 문구를 기대한다. 스크리너는 현재 결과 행에서 제거된
`발생 N건` 버튼을 찾는다(현재 `ResultTable.test.tsx`는 그 버튼이 없음을 명시적으로 검사한다).
관심종목은 소스에 없는 `watchlist-menu-remove` / `watchlist-menu-edit-groups`를 찾는다.
이 범위의 UI·테스트 수정은 호버 작업에 포함하지 않았다. 수정 전 checkout에서 전체 E2E를 재실행한 것은 아니다.

검증 과정에서 `liveVenuePolicy.test.ts`가 과거 bounds와 현재 날짜의 장 라벨을 비교하는 문제도 확인했다.
테스트 의도대로 양쪽에 동일한 고정 날짜를 넘기도록 바로잡았다. 전체 Vitest의 두 번째 고부하 실행에서는
30ms 고정 대기를 쓰는 CaptureQueue 테스트 1건이 실패했고, 동시 worker 수를 2로 제한한 마지막 전체 실행은 통과했다.
제품의 캡처 코드나 해당 테스트를 변경하지 않았다.


## 적용 범위와 후속 조건

계획 0·1단계와 2단계의 동기화 구독 축소를 반영했다. 목표였던 데이터 창 dwell JS 50% 감소,
차트 단독 일봉/분봉 20% 감소를 모두 넘었고, 같은 봉 이동도 개선됐다.

로컬 범례의 같은 봉 Y 이동 자체를 생략하는 추가 로직, 고저 라벨 DOM/극값 캐시,
series.data 전체 복사 제거는 이번 변경에 넣지 않았다. 현재 측정에서 기본 시나리오의 긴 작업이
사라졌고, 추가 캐시는 지표 provider·라이브 데이터·축 변경의 무효화까지 다뤄야 한다.
실사용에서 특정 지표/백필 조합의 긴 작업이 남으면 그 경로를 다시 측정한 뒤 이어간다.
동일 날짜의 일별 표와 동기화 훅 렌더 생략을 로컬 범례 전체의 렌더 생략으로 해석하지 않는다.

사용자 개발 서버 5173/8000은 재시작하지 않았다. 변경은 현재 워크트리에 적용됐으며 배포/머지는 수행하지 않았다.
