## 반영 내용

1. **오늘 캔들부터 표시:** 실제 오늘을 보는 평일 /live 분봉의 cold 요청은 오늘만 먼저
   가져온 뒤 기존 청크 병합 경로로 과거를 채운다. 서버의 오늘 전용 조회는 수정계수
   외부 호출 2회를 생략한다. 임시 1.0 계수를 공유 캐시에 넣지 않으므로 이후 과거 조회는
   실제 수정계수를 정상 조회한다. 복원된 캐시·과거 점프에는 오늘 bootstrap을 적용하지 않는다.
   오늘 응답 오류·blocking 경고 시 기존 전체 head 요청으로 폴백하며, 빈 오늘 응답도 과거 조회를 계속한다.
2. **보조지표 요청 분리:** 최대벽·히트맵·거래원·프로그램은 캔들과 동시에 요청한다.
   가격 범위가 필요한 매물대·POC만 캔들을 기다린다. 각 요청은 기존 취소·캐시·주기 갱신 경로를
   사용하고, 병합 후 수정주가 환산을 한 번 적용한다. 느린 요청의 커버리지를 유지해
   좌측 백필이 조기 종료되지 않게 했다. 캔들 축이 생긴 뒤 지표를 표시한다.
3. **히트맵 캐시 사전 준비:** 기존 과거 1분 최대벽 prewarm에 1분 히트맵도 포함했다.
   최대벽만 warm인 날짜도 히트맵이 없으면 채운다. 기존 관심종목 우선·건수 상한·과거 전용
   정책과 일일 스케줄을 유지한다. 기본 KRX 범위는 동일하다. 굵은 분봉은 기존 1분 캐시에서 파생한다.

외부 HTTP 지연 원인(1번), SQL 재작성 및 응답 압축(5번)은 변경하지 않았다.
운영 캐시를 지우거나 직접 채우지 않았으며, 사용자 서버의 재시작이나 토큰 발급도 하지 않았다.

## 브라우저 지연 주입 검증

기존 서버에서 읽은 삼성전자 데이터로 별도 QA 서버 `:21010/:20010`에서 실행했다.

대체했다. 오늘 응답 180ms, 과거 응답 4,000ms 등의 지연을 주입했다.
1분 캔들, 최대벽, 히트맵, 매물대, POC, 호가 잔량, 체결강도, 프로그램 지표를 활성화했다.

이는 **과거 응답을 기다리지 않고 표시하며 화면 위치를 유지하는지 확인한 제어 실험**이다.

운영 개선 폭은 적용 후 별도로 측정해야 한다.
