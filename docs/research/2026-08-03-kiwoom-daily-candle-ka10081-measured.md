# 키움 일봉 `ka10081` 실측 — PR-F(#1042) 착수 근거

- 일자: 2026-08-03 · 지도 [#1005](https://github.com/Soochol/hoga-ops/issues/1005) · 티켓 [#1042](https://github.com/Soochol/hoga-ops/issues/1042)
- 대상: `ka10081`(주식일봉) · 종목 005930
- 성격: 실측. [#1008 문서](2026-08-03-kiwoom-minute-daily-chart-tr-spec.md)가 **"일봉 venue 미검증"** 으로 남긴 항목과 **필드 스키마**를 여기서 닫는다.

## 한 줄 결론

**함정은 필드 이름이 아니라 값의 규약에 있었다.** 세 가지가 조용히 틀릴 수 있고, 그중 하나(`upd_stkpc_tp` 극성)는 **액면분할 종목에서만** 증상이 난다.

---

## 1. `upd_stkpc_tp` — KIS 와 극성이 반대다

```
upd_stkpc_tp=0 → 20180427 종가 2,650,000원   (원주가)
upd_stkpc_tp=1 → 20180427 종가    53,000원   (수정주가)
                 2,650,000 ÷ 50 = 53,000 ✓
```

삼성전자 2018-05-04 액면분할(50:1)을 리트머스로 썼다. [#1008](https://github.com/Soochol/hoga-ops/issues/1008) 의 관측을 이 PR 에서 재현했다.

| | 수정주가 | 원주가 |
|---|---|---|
| KIS `FID_ORG_ADJ_PRC` | `"0"` | `"1"` |
| 키움 `upd_stkpc_tp` | **`"1"`** | **`"0"`** |

**값을 그대로 옮기면 스크리너가 원주가를 수정주가 자리에 담는다.** 액면분할이 없는 종목에서는 두 값이 같아 증상이 없다 — 그래서 테스트 없이는 오래 살아남는 종류의 버그다.

`screener_backfill.py` 가 요구하는 2벌(수정주가 `fetch_adj` / 원주가 `fetch_raw`)이 이 플래그 하나로 갈린다.

## 2. 종가 전용 필드가 없다

응답 필드 10개:

```
cur_prc  dt  open_pric  high_pric  low_pric
pred_pre  pred_pre_sig  trde_qty  trde_prica  trde_tern_rt
```

KIS 는 `stck_clpr`(종가)와 `stck_prpr`(현재가)를 나눠 주지만 **키움 일봉은 `cur_prc` 한 칸이 그날의 종가**다. 검산으로 확인했다:

```
20260731  cur_prc 262500
20260803  cur_prc 239500 · pred_pre -23000     262500 + (-23000) = 239500 ✓
20260730  cur_prc 207000
20260731  pred_pre +55500                      207000 + 55500 = 262500 ✓
```

## 3. 가격이 무부호 — `ka10095` 와 규약이 다르다

복수시세(`ka10095`, [#1040](https://github.com/Soochol/hoga-ops/issues/1040) 실측)는 `cur_prc` 에 `'-239500'` 처럼 **등락 방향을 부호로** 실어 보낸다. 일봉은 무부호이고 부호는 `pred_pre` 에만 붙는다.

**같은 벤더 안에서도 TR 마다 다르다.** 어댑터는 가격에서 절대값을 취한다 — 부호가 오더라도 가격으로는 절대값이 맞다.

## 4. venue — 종목코드 접미 (문서의 "미검증" 을 닫는다)

`base_dt=20260803`, 1페이지:

| `stk_cd` | 행 수 | 당일 종가 | 당일 거래량 |
|---|---|---|---|
| `005930` (KRX) | 600 | 239,500 | 27,825,493 |
| `005930_NX` (NXT) | **333** | 233,500 | 25,198,903 |
| `005930_AL` (통합) | 600 | 233,500 | **53,024,396** |

- `_NX` 가 333행뿐인 것은 **NXT 출범 이후 이력만** 있기 때문이다.
- `_AL` 거래량 53,024,396 ≈ KRX 27,825,493 + NXT 25,198,903 = 53,024,396 — **정확히 합**이다.
- `_AL` 종가가 KRX 와 다른 것(233,500 vs 239,500)은 통합 venue 의 마지막 체결이 NXT 쪽이기 때문이다. `_AL` 병합 시맨틱은 ADR-0118/[#681](https://github.com/Soochol/hoga-ops/issues/681) 이 이미 다룬 축이다.

## 5. 페이지·보유

```
base_dt=20260803 → 600행  20260803 ~ 20240214   (≈ 2.4년)
base_dt=19900101 → 600행  19891226 ~ ……        ← 1989년까지 간다
```

[#1008](https://github.com/Soochol/hoga-ops/issues/1008) 이 "2007년 이상" 으로 적었는데 실제로는 **1989년**까지 닿는다. `base_dt` 랜덤 액세스가 되므로 요청 구간의 끝 날짜를 그대로 주소로 주면 되고, KIS 처럼 `[DATE_1, DATE_2]` 양끝을 밀고 당길 필요가 없다.

**귀결**: ADR-0120 이 남긴 "키움은 과거가 얕다" 는 인상은 **분봉의 성질**(1년 롤링)이지 일봉이 아니다.

## 6. 종료 조건이 하나로 줄어든다

KIS `fetch_past_daily_candles` 는 60회 루프 안에 커서 분기가 **4갈래**였다(양끝 커버 / 하단 반환 venue 예외 / 통상 walk-back / break). 각 갈래가 KIS 가 `[DATE_1, DATE_2]` 를 어떻게 해석하는지에 대한 경험칙이었다.

`base_dt` 는 그 전부를 없앤다. 종료 조건은 **구조적 술어 하나**다:

> 페이지에서 `from` 보다 오래된 날짜를 봤으면 덮은 것이다.

프로토콜의 성질이지 데이터의 성질이 아니라, 종목·기간·venue 에 무관하게 성립한다.

---

## 미측정 · 리스크 — 정직하게 남긴다

- **`base_dt` 가 공식 문서화된 파라미터인지 여전히 미확인.** [#1008](https://github.com/Soochol/hoga-ops/issues/1008) 이 남긴 숙제가 그대로다. 일봉은 페이지가 600행(≈2.4년)이라 `base_dt` 없이도 커서만으로 걸어갈 수 있어 분봉([#1043](https://github.com/Soochol/hoga-ops/issues/1043))만큼 치명적이지는 않다 — 다만 그 경우 오늘부터 되걸어야 해서 콜 수가 늘어난다.
- **종목 1개(005930)만 측정.** 신규 상장·거래정지·관리종목에서 페이지 크기나 보유가 다를 가능성은 배제하지 못했다.
- **보유 바닥이 1989년인지, 그보다 더 가는지 미확인.** `base_dt=19900101` 이 600행을 채웠으므로 바닥에 닿지 않았다.
- **`_NX` 333행의 시작일 미확인** — NXT 출범일과 대조하지 않았다.
