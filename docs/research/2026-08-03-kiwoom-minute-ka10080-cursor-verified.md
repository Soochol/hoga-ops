# 키움 분봉 `ka10080` — 커서 규칙 1차 검증 + `base_dt` 문서화 확인

- 일자: 2026-08-03 · 지도 [#1005](https://github.com/Soochol/hoga-ops/issues/1005) · 티켓 [#1043](https://github.com/Soochol/hoga-ops/issues/1043)
- 성격: 착수 전 필수 확인([#1043](https://github.com/Soochol/hoga-ops/issues/1043) 게이트)의 결과 + 설계가 기대는 성질의 1차 실측

## 1. `base_dt` 는 공식 문서화된 파라미터인가 — **부분 확인**

티켓이 착수를 막아 둔 게이트다. ADR-0120(2026-07-20)이 *"`ka10080`은 시작 날짜 파라미터가 없다"* 고 기록했기 때문이다.

### 확인한 것

**독립 3rd-party 래퍼([KiwoomRestApi.Net](https://github.com/dongbin300/KiwoomRestApi.Net))의 changelog 가 벤더 스펙 개정으로 기록하고 있다**:

```
### v0.7.0 (2026-03-18)
- 변경: | ka10080 | 주식분봉차트조회요청 기준일자 (`date`) 파라미터 추가
- 변경: | ka20005 | 업종분봉조회요청 기준일자 (`date`) 파라미터 추가
```

같은 릴리스의 다른 항목들이 전부 벤더 API 변경 추적(파라미터 타입·enum 변경)이라, 이 두 줄도 벤더 스펙 개정을 옮긴 것으로 읽힌다.

**중요한 시점 대조**: 이 changelog 는 **2026-03-18** 이고 ADR-0120 은 **2026-07-20** 이다. 즉 파라미터는 ADR-0120 을 쓰던 시점에 **이미 있었다** — ADR-0120 의 "없다" 는 벤더 변경이 아니라 **조사 누락**이었다. [#1008](https://github.com/Soochol/hoga-ops/issues/1008) 의 결론("ADR-0120 의 근거 ①이 사실이 아니었다")과 일치한다.

### 확인하지 못한 것 — 정직하게 남긴다

**키움 공식 문서 페이지를 직접 읽지 못했다.** `openapi.kiwoom.com/guide/apiguide` 는 SPA 이고, 헤드리스 브라우저로 열면 봇 차단(`에러 : CD-14005`)에 걸린다. WebFetch 도 동적 로딩 전 껍데기만 받는다.

그리고 이 리포에는 **같은 래퍼가 틀렸던 이력이 있다** — `ka10026` 의 `pertp` 매핑이 어긋나 있었다(`docs` 의 키움 순위 TR 조사). 다만 그건 **값의 의미**에 대한 오류였고 여기 쟁점은 **파라미터의 존재**라, 실측과 교차하면 신뢰도가 다르다.

### 판단

착수한다. 근거 셋:

1. 3rd-party 래퍼가 벤더 개정으로 기록(2026-03-18)
2. **우리 실측이 파라미터가 해석됨을 확인**([#1008](https://github.com/Soochol/hoga-ops/issues/1008)): 보유 밖 날짜를 주면 900행이 아니라 **빈 센티넬 1행**이 온다. 무시되는 파라미터라면 기준선과 같은 응답이 와야 한다(대조군 `strt_dt` 는 실제로 무시됐다).
3. **이미 의존하고 있다** — `ka20006`/`ka20007`/`ka20008`(지수 일·주·월봉)은 `base_dt` 가 **필수**이고 PR-C([#1039](https://github.com/Soochol/hoga-ops/issues/1039))에서 이미 그 위에 서 있다.

**잔여 리스크**: 문서화되지 않은 동작이면 벤더가 예고 없이 뺄 수 있다. 그때의 성질은 "느려진다" 이지 "깨진다" 가 아니다 — `cont-yn`/`next-key` 커서는 그대로 있으므로 오늘부터 되걸으면 된다(ADR-0120 이 측정한 그 비용으로 회귀). 감시 지점으로 남긴다.

## 2. 설계가 기대는 성질 — 1차 실측

ADR-0136 §3 의 커서 규칙은 **"최古 날짜만 잘렸을 수 있다"** 위에 선다. 그 재수신이 실제로 되는지가 핵심이라 직접 쟀다(005930, `tic_scope=1`).

```
base_dt=20260803  →  900행  20260803 15:30 ~ 20260730 13:03
                     20260803  381봉
                     20260731  380봉
                     20260730  139봉   ← 잘렸다

base_dt=20260730  →  900행  20260730 15:35 ~ 20260728 12:36
                     20260730  382봉   ← **온전해졌다**
                     20260729  352봉
                     20260728  166봉   ← 다음 커서
```

**139봉 → 382봉.** 커서 규칙이 성립한다. 버려지는 데이터가 없다 — 최古 날짜는 다음 콜에서 온전하게 돌아온다.

### 무한 루프 조건도 함께 보인다

보유 바닥([#1008](https://github.com/Soochol/hoga-ops/issues/1008) 실측: `base_dt=20250801 → 382행, 하루치만`)에서는 **최古 == 커서**가 된다. 커서가 전진하지 않으므로 가드가 없으면 같은 콜을 영원히 반복한다. 티켓 체크리스트의 "진행 보장 가드" 가 정확히 이 지점이다.

### 경계 하나 — `<=` 가 아니라 `<`

목표 구간의 하한에서 멈출 때 `page.oldest <= oldest_target` 으로 판정하면 **그 날짜를 영원히 못 받는다**. 최古 날짜는 `complete` 에서 빠져 있기 때문이다. 목표보다 **더** 오래된 날짜를 봐야 그 날이 온전하게 들어왔다는 뜻이다.

`kiwoom_index_candles.py` 가 지수 분봉에서 같은 자리에 같은 실수를 했었다(from=20260723 요청에 07-23 이 09:52 부터 시작).

## 3. 부호 규약이 일봉과 **반대**다

```
ka10081 (일봉)  cur_prc '239500'     ← 무부호
ka10080 (분봉)  cur_prc '-239500'    ← 등락 방향 부호 (900행 중 439행)
```

같은 경로(`/api/dostk/chart`)의 TR 인데도 다르다. [PR-F](https://github.com/Soochol/hoga-ops/pull/1053)에서 확정한 일봉 규약을 복사했다면 분봉에서 100% 틀렸을 것이다 — 부호가 붙은 절반이 음수 가격이 된다.

## 4. 응답 필드

```
cntr_tm  cur_prc  open_pric  high_pric  low_pric
trde_qty  acc_trde_qty  pred_pre  pred_pre_sig
```

- `cntr_tm` 은 `YYYYMMDDHHMMSS` (일봉의 `dt` 와 달리 시각 포함)
- **종가 전용 필드가 없다** — `cur_prc` 가 그 봉의 종가(일봉과 동일)
- `trde_qty` 가 봉 거래량, `acc_trde_qty` 는 **누적**이다. 후자를 봉 거래량 자리에 쓰면 단조증가 막대가 된다

## 미측정 · 유의

- 종목 1개(005930)만 측정했다.
- `tic_scope` 1분 외 스코프에서 커서 규칙을 재검증하지 않았다(페이지가 항상 900행이라 같은 규칙이 성립할 것으로 보이나 실측은 아니다).
- 보유 바닥이 롤링인지 고정인지 여전히 미확인.
- 공식 문서 직접 확인 실패(위 §1).
