# KRX 애프터마켓 프로젝트 영향 조사

조사 당시 기준: 2026-09-11. **후속 구현은 [구현·검증 기록](2026-09-11-krx-aftermarket-implementation.md)을 참조한다.** 대상: 현재 체크아웃의 `hoga-ops`. 구현 변경 없이 소스 조사와 격리된 시계 함수 실행으로 확인했다. 운영 자격증명·실시간 API는 사용하지 않았다.

## 결론

**9월 14일 KRX 16:00–20:00 접속매매 도입에 맞춰 이 프로젝트는 수정이 필요하다.** 시행일·시간·단일가 폐지는 [KB증권 공식 공지](https://www.kbsec.com/go.able?idt=20260904&linkcd=s060901010000&seq=10010298)로 확인했다. 현재 구현에는 KRX 저장 15:30 종료, 15:35 수집 완료, 16:00–18:00 시간외단일가 REST 표시가 실제 분기로 남아 있다. 연결 자체는 이미 20:00까지 유지하므로, 연결 시간 상수만 바꾸는 작업으로 해결되지 않는다.

시행 사실과 API 계약의 확인 수준은 [공식 출처 조사](2026-09-11-krx-aftermarket-official-sources.md)를 참조한다. 사용자가 제시한 [이데일리 기사](https://marketin.edaily.co.kr/News/ReadE?newsId=04893766645578808)는 2026-09-10 보도로 열람했다. 기사만으로 키움 데이터 타입·대상 종목·과거 데이터 제공 범위를 확정해서는 안 된다.

가장 먼저 보호할 것은 **애프터마켓 호가 저장**이다. 분봉 재조회 가능성과 달리 과거 호가 전체를 공급자가 복원해 준다는 보장이 없다. 이어서 화면 출처 선택과 완료 판정을 함께 고쳐야 한다.

사용자 요약의 보완점: ETF·ETN 외에도 관리·투자경고/위험·초저유동·당일 정규장 미거래 등 제외 종목이 있다. 호가는 지정가 외 최우선/최유리 및 IOC/FOK도 KB 공지에 안내돼 있다. 같은 날 NXT 정적 VI 신설과 VI/거래재개 단일가 변경도 적용된다([KB증권 공지](https://www.kbsec.com/go.able?idt=20260904&linkcd=s060901010000&seq=10010298)). 공식 종가는 계속 15:30 정규장 기준이다([카카오페이증권 공지](https://www.kakaopaysec.com/customer/notice/dynamicBoardPageDetail.do?id=7452)). 후속 공식 조사에서 키움 9/9·9/10 공지로 ±30%, 폐지 TR 및 VI 추가 값을 확인했다. 상세 링크는 공식 출처 조사에 보완했다.

## 단순 시간 연장으로 생기는 2차 문제

1. **정규장 경계는 15:30으로 보존해야 한다.** `regular_session_*`를 20:00으로 바꾸면 종가 단일가·복기 의미가 변한다. 이미 `promote.py:63`에 지표 범위를 별도 메타로 두는 이유가 명시돼 있다. 시행 이전 날짜도 새 스케줄로 덮어쓰면 안 된다. `meta_backfill.py:238–274`가 현재 venue 상수로 과거 메타를 채우므로 함께 점검한다.
2. **하나의 open/close 구간으로는 휴지 구간과 단일가를 설명하기 어렵다.** 정규 접속매매, 종가 단일가, 장후 종가매매, 애프터 접속매매를 구분해야 한다. `disk_state.py:648,692`의 결손 검사에는 `close - 10분`을 쓰는 가정이 있어 20:00만 넣으면 19:50부터를 종가 단일가처럼 제외할 수 있다. 15:30–16:00의 비연속 구간도 결손으로 오인하지 않아야 한다.
3. **120·240분봉과 D/W/M은 정책 확인이 필요하다.** `aggregateCandles.ts:15–26`, `useLiveBundle.ts:916`, `hoga/api/bundle.py:251`의 정규장 클립은 기존 의도다. 이를 일괄 삭제하면 큰 봉에 세션이 섞인다. 애프터 포함 분봉을 지원하려면 세션별 집계 경계를 정하고, 정규장 종가와 공급자 일봉 OHLCV 정의가 일치하는지 확인한다.
4. **복기 소스 커버리지를 확인해야 한다.** `hoga/api/sources.py:165,179`는 기본 키움 우선, 사용자 옵션으로 hogaplay 우선이다. 저장소에 기록된 hogaplay 범위는 KRX 정규장 중심이다. 공급자가 확장하지 않는 경우 애프터 요청에서 정규장만 있는 사본을 하루 전체 사본으로 고르지 않도록 커버리지 판정이 필요하다. 날짜 전체 소스를 무조건 교체하거나 서로 다른 소스를 무검증 합산하지 않는다.
5. **17시 배치와 16시 EOD는 목적별 검토 대상이다.** `hoga/api/scheduler.py:45`는 17시 일배치, `screener_calendar.py:7`은 16시 기준이다. 정규장 종가 업무는 그대로일 수 있지만 애프터 포함 하루 최종 지표는 그때 확정할 수 없다. 모든 작업을 일괄 20시로 미루기보다 확정 대상과 원천 제공 시각별로 나눈다.
6. **VI와 예상체결은 시계만으로 판정할 수 없다.** `session_gate.py:54–62`와 `kiwoom_frames.py:256`에는 예정 단일가 시각 게이트가 있다. 접속매매 전체를 단일가 창에 추가하지 않는다. 애프터 VI를 표시하려면 실제 VI 이벤트와 신규 국면을 연결한다. 특히 `session_gate.py:54`의 'NXT에는 VI 자체가 없다'는 주석은 개편 후 사용할 수 없는 전제다. NXT VI/거래재개 단일가 도입은 공식 확인됐으며, 애프터 시작시각 변경 여부는 별도 미확인이다.

## 기존에 갖춰진 부분 / 직접 변경으로 단정하지 않을 부분

- WS 연결 창은 이미 08:00–20:00이다(`session_gate.py:188–217`). venue 격리 저장, 동시 구독, `(code, venue)` 집계 기반도 있다. 따라서 전면 재작성 사안은 아니다.
- 실시간 주식 호가·체결은 **키움 전담**이다(`coverage.py:1`, `kiwoom_ws_client.py:58`). KIS 주식 WS 코드 `H0STCNT0/H0UNCNT0/H0STASP0/H0UNASP0`는 현재 `hoga` 코드 검색에서 발견되지 않았다. KIS 공식 변경 공지는 제도 변화의 근거와 잔존 REST 검토에는 유용하지만, 그 WS 파서를 이 프로젝트에서 수정한다고 주장할 수 없다.
- 상하한가를 계산하는 새 ±30% 상수를 넣을 필요는 확인되지 않았다. `/stock-limits`는 키움이 내려주는 상하한가·기준가를 사용한다(`hoga/live/api.py:3022`). 신규 시장에서도 동일 의미인지 확인한다.
- 실제 매수·매도 주문 실행 경로는 이번 코드 조사에서 확인되지 않았다. 지정가 제한/SOR 주문 기능 구현을 이번 대응에 포함할 근거가 없다. 이 프로젝트의 직접 영향은 데이터 수집·분석·표시다.
- 대표 지수, 파생상품, 선물 야간장과 정규장 기준 저장뷰를 주식 애프터마켓 시간표로 일괄 변경하지 않는다. 상품별 거래·산출 정의를 따른다.

## 현재 코드 시계 동작 재현

저장소 함수 AST를 Python 3 표준 라이브러리만으로 추출하여 실행했다. `is_trading_day_now`만 True로 대체하여 **9/14가 거래일이라는 가정 아래 시계 분기만** 검증했다. 운영 캘린더/벤더/통합 테스트가 아니다.

| 2026-09-14 KST | `market_phase` | 저장 허용 venue | 기존 시간외단일가 창 |
|---|---|---|---|
| 15:29 | regular | KRX, NXT, UN | false |
| 16:00 | closed | NXT, UN | true |
| 17:00 | closed | NXT, UN | true |
| 19:59 | closed | NXT, UN | false |
| 20:00 | closed | 없음 | false |

이는 제도 추정과 무관하게 **현재 코드가 오후 KRX 캡처를 허용하지 않는다**는 직접 증거다. 구현 변경이 없어 전체 테스트 스위트는 실행하지 않았다.

## 권장 작업 순서와 인수 조건

1. **키움 계약 확인:** 무접미 KRX/`_NX`/`_AL`의 체결·호가 타입, 새 시장 구분 FID, 호가 단계 수, 누적 거래량 리셋, 기준가, VI, 대상 종목/ETF·ETN 동작, 분봉·일봉 포함 범위와 NXT 개편 시간표를 확인한다. 기존 `0B/0D` 재사용은 아직 가정이다. 확인된 공식 문서와 승인된 환경의 관측을 테스트 fixture로 남긴다.
2. **데이터 보존 및 완료 판정:** 유효일·거래일·종목 능력을 반영하는 공통 세션 정책을 수집/승격/메타/백필에 적용한다. KRX 애프터 대상 종목의 16:00·19:59가 저장되고 15:35/17:00에는 미완료, 마지막 세션 정산 뒤 완료인지 확인한다. 20:00 경계 체결 drain 및 재시작도 확인한다.
3. **호가와 차트:** 새 접속매매 구간에서 정상 실시간 소스를 사용하고 구형 시간외단일가 폴링·5단 표시·당일 종가 기준이 새 데이터 위에 덮이지 않게 한다. KRX-only/NXT 가능/ETF·ETN/능력 미상 각각 검증한다.
4. **지표·과거 호환:** 시행 전후 날짜 혼합 복기, 정규장 종가 단일가, 세션 사이 휴지, 오후 VI, 120·240분봉, D/W/M, REST 우회 ON/OFF, hogaplay 우선 옵션, 시그널·최대벽 범위를 확인한다. 과거일에 가짜 오후 결손을 만들지 않아야 한다.

연관 회귀 테스트: `tests/unit/live/test_session_gate.py`, `tests/unit/live/test_kiwoom_session.py`, `tests/unit/api/test_orderbook_venue_session_bounds.py`, `frontend/src/api/liveAfterHoursBook.test.ts`, `frontend/src/live/bookSessionMode.test.ts`, `frontend/src/live/workspace/DataWindow.test.tsx`, `frontend/src/live/aggregateCandles.test.ts`.

기존 결정과의 충돌: **ADR-0140 §5(KRX 정규장만 저장)·§6(KRX 15:35 완료)를 개정할 사안**이다. ADR-0144/0157의 저장뷰 KRX 고정은 유지 가능한 별도 축이다. 새 ADR이나 이슈 생성, 제품 코드 수정, 배포는 이번 조사에서 수행하지 않았다.
