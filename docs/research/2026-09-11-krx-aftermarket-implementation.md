# KRX 애프터마켓 대응 구현

작성일: 2026-09-11. 사용자 승인에 따른 현재 워크트리의 변경 사항이다. 운영 배포나 실계좌 API 호출은 수행하지 않았다.

> 후속 안정성 수정과 최종 검증 결과는 [확장 점검 기록](2026-09-11-expanded-reliability-audit.md)을 따른다. 아래 단계별 검증 기록의 초기 E2E 실패는 후속 수정에서 해결했으며, 마지막 전체 E2E는 118개 통과했다.

## 적용 범위

- 2026-09-14부터 거래일 KRX 저장 창을 09:00–15:30, 16:00–20:00으로 연다. 15:30에는 정규장 carry 상태를 비우고 16:00 실제 새 틱부터 저장한다. 휴일 캘린더와 기존 NXT/UN 연결 창은 유지한다.
- 잠든 프로세스가 15:30 전환을 놓쳐도 이전 호가를 오후 호가로 복제하지 않는다. 지연 도착한 정규장 프레임은 새 오후 상태를 덮지 못하며, 첫 체결 집계 시각은 16:00보다 앞설 수 없다.
- 수집 완료 시계 판정을 20:05로 미룬다. 공식 정규장 종가는 계속 15:30이며, 지표 범위 메타만 확장한다. 15:20–16:00을 접속매매 결손에서 제외하고 19:50–20:00은 결손 검사에 포함한다.
- 확인된 ETF·ETN은 오후 범위를 부여하지 않는다. 심볼 마스터의 `security_type`을 화면에도 미러해 대상 제외로 표시한다. NXT 상장 여부로 KRX 애프터마켓 참여 가능 여부를 추론하지 않는다.
- 시행 이후 구식 시간외단일가 `ka10087` 폴링 및 해당 캐시의 화면 노출을 중단한다. 기존 WS 10호가를 사용하며, 실제 오후 호가가 없으면 수신 대기로 표시한다.
- 분봉 API·화면 축·시세 폴링을 20시까지 확장한다. 120/240분봉은 16:00에서 새 버킷을 시작한다. 15:30 동시호가 접기는 보존하고 저녁 마지막 10분을 평탄화하지 않는다. KRX 일·주·월봉의 정규장 종가는 오후 실시간 체결로 덮지 않는다.
- 오후 실제 호가를 최대벽·시그널 입력에 포함한다. 키움 VI 연장 값 `9068=4`를 보존하고 KRX/NXT/통합 VI 상태와 조회 캐시를 분리한다.
- 시행 전 날짜의 시간표와 과거 단일가 조회·표시 로직은 보존한다. 주문 실행 기능, 파생·지수 시간표, 정규장 종가 기준 스크리너 배치는 변경하지 않는다.

## 공식 계약과 남은 실측

[키움 9/10 공지](https://openapi.kiwoom.com/board/Board0101View?seqid=60)는 `ka10087`, `ka10098` 삭제 및 VI 연장 값을 안내한다. [키움 9/9 공지](https://openapi.kiwoom.com/board/Board0101View?seqid=59)는 KRX 16:00–20:00 및 기준가 ±30%를 안내한다. 조사 근거 전체는 [공식 출처](2026-09-11-krx-aftermarket-official-sources.md)에 있다.

공개 키움 마스터에서 KRX 애프터마켓 일별 대상 플래그는 확인하지 못했다. 일반 주식은 `krx_aftermarket_eligible=null`로 남기고 실제 수신을 기다린다. 경고·관리·저유동 등 기타 제외 종목의 오후 무수신은 장애로 확정할 수 없다. 메타의 부분 수집 판정은 보수적으로 유지한다.

현재 공개 공지에는 기존 0B/0D를 대체하는 데이터 타입·새 시장 접미가 없다. 기존 bare/_NX/_AL을 유지했다. 개장 후 실제 KRX 16시·20시 프레임, 누적거래량 경계, 과거 분봉 응답, VI 연장·해제 순서는 운영 관측으로 확인해야 한다. 새 장운영 코드와 불규칙 VI/거래재개 예상체결 국면은 추정값으로 추가하지 않았다. 이 변경은 모든 신규 VI 예상체결 호가를 지원한다고 주장하지 않는다.

## 추가 개선: 호가 전용 최대벽과 명시적 거래소 집계

- 체결 파일이 없는 Stock-Date의 매수·매도 최대벽 SQL에 시행일/거래소별 버킷 규칙을 적용했다. 120분에서 14시 잔량 1,000이 15시 잔량 10에 밀려 사라져 최대벽을 20으로 보고하던 사례를 수정했다. 240분에서도 12시 대표 호가를 보존한다. 원본 조회와 반복 캐시 조회 모두 검증했다.
- 프론트 호가비·체결강도·히트맵은 세션 경계가 정확히 09:00/20:00인지로 거래소를 추론하지 않는다. 호출자가 거래소를 전달하며 시행일은 실제 틱 날짜로 판정한다. 지연 개장/짧은 표시 범위에서도 같은 버킷을 사용하고 거래소 변경 시 증분 상태를 재계산한다. POC의 정규장 동시호가 경계 처리도 거래소를 명시적으로 받는다.
- `frontend/tests/e2e/krx-aftermarket.spec.ts`는 실제 `/live` 화면에 WS 호가·체결을 보내 15:30 마지막 정규장, 16:00 수신 대기/첫 오후 호가와 캔들, 19:59 캔들 및 20:00 마지막 호가를 검증한다. 폐지 API 요청 0건도 확인한다. 5회 연속 통과했다. 시간을 크게 건너뛸 때 정상적인 WS watchdog 재연결과 재구독을 기다린다.
