# 조건검색 선택 UX 수정

사용자 보고: 전체 스크리너 왼쪽의 기본 select를 클릭하면 목록이 바로 사라짐. 기존 동작을 별도 Chrome에서 검사했을 때는 열림이 유지되어, 인앱 브라우저에서 발생한 원인은 확정하지 못했다. 브라우저 기본 팝업을 제거하고 페이지와 우측 패널이 같은 HTML 선택기를 사용하도록 변경했다.

- 선택기 내부의 검색창과 포털 목록을 바깥 클릭으로 취급하지 않는다. 부모가 다시 렌더되어도 열림과 검색어를 유지한다.
- 이름 검색, 선택 표시, 긴 이름 줄바꿈/툴팁, 방향키와 Enter 선택, Escape 취소, 바깥 클릭과 키보드 포커스 이탈 닫기를 지원한다. 선택·Escape 후 트리거로 포커스를 돌려준다.
- 현재 저장본을 다시 선택하면 편집 내용을 유지한다. 원본 복원은 별도 `저장본으로 되돌리기`로 수행한다.
- 미저장 수정이 있을 때 다른 저장본 선택·새 조건·복원은 `계속 편집` 또는 `변경 버리고 이동/복원`을 거친다. 취소하면 값과 선택을 유지한다.
- 저장 중에는 저장본 전환·새 조건·복원·관리 작업을 막아 저장 완료가 다른 조건의 편집 상태를 바꾸지 않게 한다. 같은 조건의 입력 편집과 기존 dirty 보호는 유지한다.
- `새 조건검색`은 목록에서 제거하고 `＋ 새 조건`으로 분리했다. 명시적으로 만든 빈 초안은 새로고침 후에도 유지하며, 늦게 도착한 저장 목록이 덮지 않는다. 기존 저장 데이터에는 없는 선택적 `isNewDraft` 필드를 사용한다.
- 저장본 선택은 자동 조회를 하지 않는다. 우측 패널의 기존 모니터링 중 선택 전환 동작은 유지한다.

검증: Vitest 7,214개와 Playwright E2E 38개 통과. 앱·테스트·E2E 타입 검사, 프로덕션 빌드 및 변경 코드 ESLint 통과. 새 E2E는 31초의 폴링 주기를 시계로 진행시킨 뒤 열림/포커스 유지, 검색과 실제 마우스·키보드 선택, 미저장 변경 취소/이동/복원, 빈 초안 재진입, 페이지·패널 공유와 944px 화면을 검증한다. 해당 시나리오의 브라우저 오류는 0건이다. 5174 인앱 페이지에 새 선택기 반영을 확인했다. 원래 증상의 인앱 클릭 재현은 별도로 확인되지 않았으므로 이를 원인 확정의 근거로 삼지 않는다.
