# /live 분봉 개선 적용 후 실제 서버 검증

2026-09-07, 장중. [수정·회귀 검증](./2026-09-07-live-minute-fix-validation.md) 이후
실행 중인 사용자 서버에서 실제 API 응답으로 측정했다. 응답 모의나 지연 주입은 없다.

## 적용 상태와 조건

- backend `/health`: `0.12.45.0`, `4e0cd6704`, 정상. pull 후 uvicorn의 자동 reload로
  이미 적용돼 있었다. frontend가 제공한 모듈에서도 최종 초기 sidecar 진행 신호를 확인했다.
  따라서 이 측정을 위해 중복 재시작하거나 별도 자격 증명 서버를 띄우지 않았다.
- localhost:5173 / :8000, gstack browse. 로드된 앱에서 종목 전환을 0ms로 측정한다.
  번들 최초 다운로드 시간은 제외한다. 사용자 main의 미커밋 WS 계측 코드는 유지했다.
- KRX 1분, 20260831–20260907, `source_pref=hogaplay`, 매물대·POC 10 bins.
  MA·거래량·총잔량·호가비·체결강도·최대벽·히트맵·프로그램·매물대·POC 활성.
  거래원 sidecar는 비활성이다. 네트워크 파라미터를 증거에 별도로 보관했다.
- 3종목 모두 오늘 응답 `fresh_dates=[20260907]`, 과거 응답은 5거래일 전체가
  `fresh_dates`였다. `cached_dates`는 주말 2일뿐이다. **분봉 서버 캐시 미스**를 확인했다.
  지표의 기존 디스크 캐시는 유지했으므로 지표까지 모두 cold인 측정으로 해석하지 않는다.
- 각 종목 20초 관측, 차트 상태 75ms 간격 샘플링. 첫 표시는 reveal cover의 opacity가
  0이면서 캔들 데이터가 존재하는 시각이다. 160ms fade 종료와 동일하지 않다.

재사용했다. 9.37초에 발생한 오늘 지표 갱신은 첫 로딩과 구분했다.

## 이전 조사와 비교

[수정 전](./2026-09-07-live-minute-cold-load.md)의 첫 공개는 현대차 9.320초,
인투셀 2.180초였다. 이번에는 각각 0.901초, 0.751초였다.
SK하이닉스의 수정 전 8.899초 표본은 지표 설정이 더 단순했으므로 직접 비교 대상에서 뺀다.

같은 날짜·종목·범위라도 장중 데이터와 외부 API 지연, 서버 수정계수 캐시 및 지표 캐시는
달라진다. 따라서 이 숫자로 일반적인 개선율이나 p95를 산출하지 않는다.
오히려 인투셀은 과거 포함 기존 요청이 1.402초였고 이번 과거 응답은 2.875초에 도착했다.
**전체 수집이 더 빨라야만 첫 표시가 빨라지는 의존성을 제거했다**는 것이 확인된 효과다.

## 4번: 실제 저장소에서 히트맵 사전 준비 확인

NAVER(035420), 20260904, KRX, hogaplay/kiwoom_live 두 소스에 한정했다.
기존 최대벽은 모두 cache hit였고 히트맵은 둘 다 miss였다. 실제 prewarm 함수를
날짜·종목 제한 및 `limit=2`로 실행해 누락된 두 항목만 채웠다. 외부 API는 호출하지 않았다.

- 최초 prewarm: 2건 성공, 실패 0, **385ms**. 원본 depth 스캔 2회(209ms/36ms).
- 새 QueryEngine으로 1분·5분 조회: 원본 depth 스캔 **0회**.
  hogaplay 13.2/13.3ms, kiwoom_live 9.7/37.2ms. 모두 비어 있지 않은 결과다.
- 재실행: 2건 모두 skip, 새 계산 0건, **24ms**.

기존 캐시 삭제 없이 실제 캐시를 두 항목 추가했다. 전체 종목을 즉시 워밍하지 않았으며,
나머지는 기존 일일 작업의 관심종목 우선·상한 정책으로 처리된다. 이 캐시 검증은 위
3종목 브라우저 측정 이후 수행했으므로 그 측정 수치에 영향을 주지 않았다.

## 남은 사항

이번 3표본에서는 첫 표시 8~10초 지연이 재현되지 않았다. 남은 사용자 대기는 주로
과거 봉 수집 완료(약 1~3초)다. 외부 응답 수신 지연을 수정한 것은 아니므로 간헐적인
느린 오늘 조회까지 해결됐다고 보지 않는다. 그 현상이 다시 나타날 때 1번 HTTP 수신
경로의 단계별 trace로 이어가는 것이 다음 검증이다.

원본 지표 응답에는 일부 날짜의 `collection.finished`, `series.snapshots_no_gaps`
경고가 있었다. 이는 저장 캡처의 부분 데이터 경고이며 응답 JSON에 보존했다. 경고가 없는
완전한 시장 데이터로 검증했다고 주장하지 않는다.
