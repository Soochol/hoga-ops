# 스크리너 결과 활용 1차 구현

대상: 성능·기능 검토 문서의 ② 조회 당시 값 구분 및 ③ 결과 검색·선택·CSV.
관심그룹 일괄 추가, 충족 근거, 자동 재조회 확대는 후속 범위다.

- 결과 위에서 **현재 시세 / 조회 당시** 보기를 전환한다. 가격·등락률의 정렬도 선택한 보기의 값을 따른다. 거래대금은 두 보기 모두 조회 당시 추정값이다.
- 조회 당시 가격 아래의 날짜는 **가격을 가져온 마지막 일봉의 날짜**다. 기간내 신고가나 거래대금 조건의 충족 발생일이 아니다. 장중 미반영 종목은 이전 일봉 날짜를 갖는다.
- 종목명·코드 검색은 받은 결과 안에서만 수행한다. 전체 선택은 가상 DOM에 나타난 행 수와 무관하게 검색에 맞는 모든 행에 적용한다.
- 검색이나 정렬·시세 갱신으로 선택을 잃지 않는다. 검색에 가려진 선택 건수를 따로 표시한다. 새 조회 완료와 페이지 재진입에서는 선택을 초기화한다.
- **선택 CSV**는 숨겨진 선택도 포함한다. **검색 결과 CSV**는 현재 검색어에 맞는 행 전체를 현재 정렬 순서로 내보낸다.
- CSV에는 조회 당시 가격·등락률·거래대금·가격 기준일, 현재 시세의 마지막 수신값, 예상체결값, 조회 기준·완료시각, 내보낸 시각, 저장본 이름, 실제 요청 JSON, 경고와 상한 여부를 함께 담는다. 현재 시세의 수신 시각을 내보낸 시각으로 대체해 주장하지 않는다.
- UTF-8 BOM/CRLF와 CSV 인용을 사용한다. 외부 텍스트의 수식 시작 문자는 텍스트 접두사로 처리하고 종목코드에도 작은따옴표 접두사를 넣어 Excel의 선행 0 손실을 방지한다.

서버는 `ScreenerRow.price_date`와 `ScreenerResponse.scanned_at_ms`를 추가한다. 페이지와 드로어는 실행 전에 요청 원문을 보관하며, 편집된 조건을 이전 결과의 CSV에 섞지 않는다. 구버전 서버나 저장 상태는 없는 날짜를 추측하지 않고 ‘기준일 미기록’으로 표시한다. 기존 페이지 요청 기록(scanKey)은 CSV에 재사용할 수 있다.

기존의 선택 한 종목 WS 정책을 유지한다. 검색·체크박스·CSV는 WS 등록이나 관심그룹 추가를 수행하지 않는다.

부수 수정: 가상 목록의 스크롤 셸을 위치 계산의 기준으로 고정했다. 페이지 상단 도구 높이가 행 시작 오프셋에 섞여 목록 끝의 행이 빠지는 문제를 해결했다. 총잔량 배지도 현재 편집 내용 대신 실행 당시 조건에서 side를 고르고 기간내 조건을 포함한다.

검증: Vitest 7,198개, pytest 4,867개(2개 skip, wallclock 13개 제외), Playwright E2E 36개 통과. 앱·단위 테스트·E2E 타입 검사, Vite 빌드 및 Ruff 통과. E2E에서 1,000건 전체 선택, 숨겨진 선택 포함 CSV, 다운로드 행 수·조건 JSON, 조회값 복원, 마지막 행 접근과 944px 화면을 검증했다. 스크리너 시나리오의 브라우저 오류와 측정 인덱스 경고는 0건이다.

프론트 미리보기는 `http://localhost:5174/screener`이며 실행 중인 메인 API는 변경하지 않았다. 새 가격 기준일과 서버 조회완료시각은 백엔드 변경 반영 후 제공된다.
