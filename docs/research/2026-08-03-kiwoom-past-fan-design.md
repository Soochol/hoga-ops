# 과거 팬 설계 확정 — 커서는 "최古 날짜", 완결성은 **구조로** 판정한다

- 티켓: [#1012](https://github.com/Soochol/hoga-ops/issues/1012) (지도 [#1005](https://github.com/Soochol/hoga-ops/issues/1005))
- 조사일: 2026-08-03 · 실계좌 실측(005930, `ka10080`, 페이싱 0.25 s)
- 대체 대상: ADR-0120(키움 walk-back 제거) — 그 ADR 의 전제가 무너졌다([#1008](https://github.com/Soochol/hoga-ops/issues/1008))

## 확정 설계

```
1. base_dt = 커서 로 1콜 (900행 ≈ 2.35 거래일)
2. 응답의 **최古 날짜**만 앞이 잘렸을 수 있다 → 캐시에 넣지 않는다
3. 나머지 날짜는 **구조적으로 온전** → 캐시 적재
4. 커서 = 그 최古 날짜. 다음 콜에서 온전하게 재수신된다
```

**"반쪽을 버린다" 가 아니라 "반쪽 날짜를 다음 커서로 쓴다".** 버려지는 데이터가 없다 — 그 날짜는 다음 콜에 온전한 형태로 들어온다.

## 실측


## 왜 완결성을 **데이터로** 판정하면 안 되는가

첫 실험은 "그 날의 첫 봉이 개장 시각이면 온전" 으로 판정하려다 **실패**했다. 실측이 두 반례를 냈다:

- **첫 봉이 `09:00` 이 아니라 `09:02` 인 날이 있다** — 첫 체결이 늦었을 뿐 잘린 것이 아니다.
- **확보한 날들의 봉 수가 최소 333 / 중앙 382** — **333봉짜리 정상 거래일이 존재**한다.

즉 **"첫 봉 시각" 도 "봉 개수" 도 "잘린 날" 과 "원래 짧은 날" 을 구분하지 못한다.** 데이터 기반 판정을 골랐다면 333봉 정상일을 "불완전" 으로 오판해 무한히 재요청했을 것이다 — 실제로 첫 실험이 그렇게 멈췄다.

**구조적 술어가 답이다**: 한 응답에서 앞이 잘릴 수 있는 것은 **최古 날짜 하나뿐**이다. 이것은 데이터의 성질이 아니라 **프로토콜의 성질**(900행 고정 페이지가 날짜 경계와 무관하게 끊긴다)이라 반례가 없다.

선례도 있다 — `kiwoom_index_candles.py:258-270` 이 지수 분봉에서 같은 문제를 이미 풀었다:

> `from` 날짜의 캔들이 페이지에 하나라도 걸치면 `<=` 는 "덮었다"고 판단하는데, 그날 **앞부분은 다음 페이지에 있다**(실측: from=20260723 요청에 07-23 이 09:52 부터 시작, 09:00~09:51 누락). `from` 이전 날짜를 볼 때까지 걸어야 그날이 온전해진다.

## 티켓 질문 7개의 답 — 6개는 조사가 이미 결정했다

| 질문 | 답 | 근거 |
|---|---|---|
| 커서 재사용 계층을 지을 것인가 | **불필요** — `base_dt` 랜덤 액세스 | [#1008](https://github.com/Soochol/hoga-ops/issues/1008) |
| 순회분 전량 적재 | **문제 자체가 소멸** — 순회가 없어져 버려질 순회분이 없다. 최古 날짜는 커서로 재사용 | 본 문서 실측 |
| 분봉 디스크 영속(ADR-0095) 재개봉 | **거부** — 아래 | ADR-0095 자체 트리거 |
| 수용 가능한 지연 | **회귀 없음**(0.6초/step) | [#1015](https://github.com/Soochol/hoga-ops/issues/1015) |
| 팬 UX 를 바꿀 것인가 | **불필요** — 무한 팬을 유지할 수 있다 | 위와 같음 |
| 일봉 경로(수정주가 2벌) | `upd_stkpc_tp` **1=수정 / 0=원주가** | [#1008](https://github.com/Soochol/hoga-ops/issues/1008) |
| ADR-0100 계정 병렬 소멸의 귀결 | **TR별 토큰 버킷**이 대체 | [#1015](https://github.com/Soochol/hoga-ops/issues/1015) |

### ADR-0095(분봉 memory-only) — 재개봉하지 않는다

ADR-0095 는 되돌림 재검토 트리거 셋을 스스로 명시했다. **셋 다 충족되지 않고 오히려 반대 방향으로 움직인다**:

| 트리거 | 현재 |
|---|---|
| 재시작이 잦은 배포 형태 등장 | ❌ prod 전환(#997)으로 systemd 상시 운영 — 재시작이 **줄어든다** |
| 딥스크롤 콜드가 상시 UX 불만으로 **측정** | ❌ 측정된 바 없고, 본 설계로 **20~50배 빨라진다** |
| KIS quota 가 실질 제약 | ❌ **KIS 가 사라진다.** 키움은 TR당 5 req/s 로 넉넉 |

memory-only 를 유지한다. 캐시 구조(`past_candles_cache.py` 의 코드-지역성 2단 LRU)도 그대로다.

## 일봉 경로

`ka10081` 도 `base_dt` 랜덤 액세스가 되고 600행 ≈ 2.4년이라 **한 콜로 대부분 구간이 덮인다**. 같은 커서 규칙(최古 날짜는 커서로)이 그대로 적용되지만, 일봉은 페이지가 훨씬 넓어 경계 비용이 거의 없다.

`screener_backfill.py:257,272` 의 수정주가/원주가 **2벌** 요구는 `upd_stkpc_tp` 로 충족된다(#1008 에서 삼성전자 2018 액면분할 50:1 로 확증).

## 구현 체크리스트 (→ [#1016](https://github.com/Soochol/hoga-ops/issues/1016))

- 커서 규칙: **응답의 최古 날짜는 캐시에 넣지 않고 다음 `base_dt` 로 재사용**
- **진행 보장**: `다음 커서 == 현재 커서` 이면 중단(첫 실험이 이 가드 없이 무한 루프에 빠졌다)
- **폭주 방지 + 조용한 절단 금지**: `_MAX_PAGES` 상한과 도달 시 `out_of_range` violation — `kiwoom_index_candles` 선례를 따른다
- 완결성 판정에 **봉 개수·첫 봉 시각을 쓰지 말 것**(333봉 정상일·09:02 개장일 반례)
- 1년 보유 밖 구간의 표시 정책 — 디스크의 `kis_api` 존치본과의 이음매(**KIS 도 분봉 보유가 1년**이라 이 축의 손실은 0, #1008 정정 참조)

## 미측정 · 유의

- 종목 1개(005930)·20거래일 구간만 측정했다. 거래정지·신규상장 종목에서 날짜 분포가 다를 수 있다.
- **하루 봉 수가 종목·날짜마다 다르다**(333~382 관측). 이 분산이 어디서 오는지(반차·단축장·유동성) 파고들지 않았다 — 구조적 술어를 쓰면 알 필요가 없기 때문이다.
- `tic_scope` 1분 외의 스코프에서 커서 규칙을 재검증하지 않았다(페이지가 항상 900행이므로 같은 규칙이 성립할 것으로 보이나 실측은 아니다).
- 실험 페이싱은 0.25 s(4 req/s)였다. 5 req/s 상한(#1015)에는 닿지 않았다.
