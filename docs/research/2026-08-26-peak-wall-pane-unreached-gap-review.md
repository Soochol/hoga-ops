# 최대벽 강도 pane — 「미도달(미체결) 벽」 계단의 빈 구간 검토

**날짜** 2026-08-26 · **상태** 검토(구현 전) · **요청** "미체결 표현도 체결 최대벽처럼
pane 에서 빈 공간 없이 나왔으면"

> 용어: 사용자가 말한 **미체결** = 코드의 **미도달(`unreached`)** 계열이다.
> `chartPrefs.ts:433` 이 그 선의 옛 이름으로 "미체결" 을 그대로 쓴다(ADR-0156).

---

## 0. 결론 세 줄

1. **빈 구간의 대부분은 결함이 아니라 데이터의 진실이다** — "그 시점에 당일 고가를
   아직 넘지 못한 매도벽이 **없었다**". 후보를 아무리 늘려도 채워지지 않는다(실측).
2. 따라서 "빈 공간 없이" 를 정직하게 달성하는 길은 **없는 구간을 0(바닥)으로 잇되,
   그 구간을 눈에 띄게 다르게 그리는 것** 하나뿐이다.
3. 0-fill 은 종전 docstring 이 기각했었다. 기각 근거 둘 중 **하나(거짓 0)는 후보 풀
   확장으로 해소된다** — 그래서 이 둘은 **한 묶음의 변경**이다. 나머지 하나(급락 오독)는
   데이터가 아니라 **표기**로 푼다.

## 1. 지금 무엇이 그려지고 있나

| | 체결된 벽(traded) | 미도달 벽(unreached) |
|---|---|---|
| pane 빌더 | `buildPeakWallStepPoints` (running max, 단조) | `buildUnreachedStepPoints` (봉별 재판정, 비단조) |
| 입력 | 기록 갱신 시퀀스(`traded_record_*`, 하루 6~118점) | `unreached_peaks` **top-3** |
| 계단 시작 | 그날 첫 기록(실측 **09:00:50~09:00:59**) | 살아남은 벽의 기립 시각 |

`buildPeakWallStepPoints` 가 "빈 공간 없이" 보이는 이유는 빌더가 아니라 **입력**이다 —
체결 계열에는 개장부터 촘촘한 기록 시퀀스(`traded_record_peaks`)가 붙어 있다.
미도달 계열은 비단조라 그 record 아날로그가 **원리적으로 존재할 수 없다**.

## 2. 실측 — 빈 구간이 얼마나, 왜 생기는가

005930 · 1m · 2026-08-20~26 · `/api/range?mode=sidecar` + `mode=candles` 실응답.
빌더와 같은 판정(`ask: price > 당일누적고가`)을 봉마다 재현했다.

### 2.1 커버리지 (점이 찍히는 봉 / 전체 봉)

| 거래일 | ask 현재 | ask 후보풀 확장 | bid 현재 | bid 후보풀 확장 |
|---|---|---|---|---|
| 20260820 | 111/356 (31.2%) 13:26~ | 131/356 (36.8%) 13:06~ | 349/356 (98.0%) | 349/356 (98.0%) |
| 20260821 | 57/385 (14.8%) 14:24~ | 68/385 (17.7%) 14:08~ | 381/385 (99.0%) | 381/385 (99.0%) |
| 20260824 | **0/388 (0%)** | **0/388 (0%)** | 140/388 (36.1%) | 140/388 (36.1%) |
| 20260825 | 80/386 (20.7%) 14:02~ | 96/386 (24.9%) 13:46~ | 358/386 (92.7%) | 358/386 (92.7%) |
| 20260826 | 142/383 (37.1%) 12:59~ | 142/383 (37.1%) 12:59~ | 322/383 (84.1%) | 322/383 (84.1%) |

「후보풀 확장」 = 그날 wire 가 나르는 벽 전부(`unreached` ∪ `traded` ∪ `traded_record`
∪ `all`, 후보 3개 → **33~150개**).

### 2.2 이 표가 반증한 것

착수 시 가설은 **생존 편향**이었다 — "`unreached_peaks` 는 *마감 시점* 생존자 top-3 이라
오후에 선 벽만 남고, 그래서 계단이 늦게 시작한다. 후보를 넓히면 채워질 것이다."

**틀렸다.** 후보를 50배로 늘려도 커버리지는 **+0~6%p**, 20260824 는 **0% 그대로**다.

### 2.3 진짜 원인 — 판정 기준이 「당일 **누적** 극값」이다

미도달 판정은 현재가가 아니라 **세션 시작부터의 누적 고가**를 쓴다. 매도벽은 *현재가*
위에 서지 *당일 고가* 위에 서는 게 아니다. 그래서 가격이 되돌린 뒤 선 벽은 **기립하는
순간 이미 도달 상태**다. 오전~오후 초반에 미도달 매도벽이 없는 것이 **정상**이다.

20260824 가 교과서적 사례다:

```
시가 281,500 = 그날 고가   종가 257,000   저가 255,000
그날 알려진 매도벽 최고가 272,000  →  고가 초과 벽 0/5개
```

갭상승 후 종일 하락 → **모든 매도벽이 개장 시점부터 도달 상태**. ask 미도달 0% 는
정직한 값이고, 화면의 빈 하루는 "매도벽이 전부 뚫린 하루" 라는 **정보**다.

### 2.4 ask/bid 비대칭 (bid 84~99% vs ask 0~37%)

매수벽은 **누적 저가 아래**에 서고, 저가는 개장 초에 대개 확정된다 → 한 번 미도달이면
오래 산다. 매도벽은 **신고가 행진이 차례로 지운다** → 상승일수록 빈다. 즉 사용자가 보는
"매도 쪽만 유난히 비는" 현상은 지표가 아니라 **시장 구조**다.

## 3. 권장안 — 후보 풀 확장 + 「없음 구간」 명시 표기 (한 묶음)

### 3.1 왜 한 묶음인가

`buildUnreachedStepPoints` docstring 이 0-fill 을 기각한 근거는 둘이었다.

- **(a) 거짓 0** — 입력이 top-3 뿐이라 4위 이하가 살아 있어도 0 으로 보인다.
- **(b) 급락 오독** — 0 이 "미도달 벽이 0주로 줄었다" 로 읽힌다.

(a) 는 **후보 풀 확장이 해소한다**: 후보 143개로도 0 이면 그건 진짜 0 에 가깝고,
실측상 0 구간은 *가격이 그날 알려진 최고 벽 위에 있던* 구간이다.
(b) 는 데이터로 안 풀린다 — **표기 층에서** 푼다. 그래서 풀 확장 없는 0-fill 은
docstring 이 기각한 바로 그것이고, 둘은 같이 가야 한다.

### 3.2 변경 지점

1. **입력** — pane 의 미도달 계단 입력(`usePeakWallRender.unreachedStepSegments`)을
   그날 알려진 벽 전체로 넓힌다. **빌더는 그대로다** — 이미 봉별 재판정을 한다.
   화면의 수평선 3개(캔들 표면)는 **건드리지 않는다**. 넓어지는 것은 pane 계단의
   *후보* 이지 사용자가 보는 벽의 개수가 아니다.
2. **0-fill** — `best === null` 인 봉에서 선을 끊는 대신 `value: 0` 을 낸다.
   `closedToday` 조기 종료가 사라진다.
3. **표기** — 0 구간의 점은 계열 본색이 아니라 **낮은 알파의 같은 색**으로 낸다.
   LineSeries 의 per-point `color` 오버라이드는 이미 이 리포가 쓰는 기법이다
   (`auctionHide.ts` — 거래일 경계·마감 동시호가가 같은 방식). 추가 primitive 불필요.

### 3.3 검증된 불변식 두 개 (실측 10/10)

- **마감 시점 pane 최종 높이 = 캔들 rank-1 수평선**. 풀을 넓혀도 마감 재판정이 생존자만
  남기므로 성립한다. 5일 × 2방향 전부 일치(20260824 ask 는 양쪽 다 `None`).
  → 두 표면이 어긋날 걱정이 실측으로 닫혔다.
- **`(price, t_ms)` 중복키에서 `qty` 가 갈리는 후보 0건** (풀 39~150). 같은 벽이 여러
  필드로 들어와도 `max` 판정이라 무해하고, 값이 갈려 순위를 흔드는 사례도 없었다.
  ⚠ 다만 이 풀을 **표시 개수 카운트**에 연결하면 별개의 함정이 생긴다(가격 중복으로
  개수가 무효가 된 전례) — pane 계단 입력 전용으로 유지할 것.

## 3.5 구현 후 실측 — 같은 데이터를 **실제 파이프라인**에 태운 결과

`toUnreached*PeakInputs` → `buildPeakWallOverlaySegments` → `buildUnreachedStepPoints`
전 구간에 위 실응답을 그대로 흘렸다(일회성 vitest, 리포에는 남기지 않음).

| | 세그먼트 | 총 점 | 거래일별 점(그중 0) |
|---|---|---|---|
| ask 현재(top-3) | 12 | 1,500 | 08-20:356(245) · 21:381(324) · **24: 없음** · 25:382(302) · 26:381(239) |
| ask 제안(풀 확장) | 416 | **1,881** | 08-20:356(225) · 21:381(313) · **24:381(381)** · 25:382(286) · 26:381(239) |
| bid 현재 | 15 | 1,881 | 20:356(7) · 21:381(0) · 24:381(241) · 25:382(24) · 26:381(59) |
| bid 제안 | 266 | 1,881 | **위와 동일** |

읽을 점 셋:

1. **풀 확장의 실제 효과는 커버리지가 아니라 "하루가 통째로 사라지는 것" 을 막는 것**이다.
   ask 20260824 는 `unreached_peaks` 가 0이라 종전 배선에서는 세그먼트조차 없어 0-fill 이
   **발화할 기회가 없었다**. 확장 후 381봉 전부가 0 으로 채워진다.
2. **bid 는 값이 한 점도 안 바뀐다**(0 개수 동일) — 확장이 기존 판정을 흔들지 않는다는
   증거다.
3. **0 의 비중은 크다** — ask 20260821 은 381봉 중 313봉(82%)이 0 이다. "빈 공간 없이" 의
   실체는 **값이 계속 있는 선**이 아니라 **바닥에 붙은 흐린 선이 대부분인 하루**다.
   이건 표현이 아니라 데이터이므로(§2.3), 화면에서 흐린 색이 자주 보이는 것이 정상이다.

## 4. 그래도 정직하게 못 채우는 것

- **개장 첫 벽 이전** — 실측 09:00:50~09:00:59, 1봉 이내. 무시 가능.
- **그날 벽이 하나도 안 남은 날** — 0-fill 로 *선은* 이어지지만 값은 0 이다. 이건
  채워야 할 결함이 아니라 그날의 사실이다(§2.3).
- **pane 오토스케일 하한** — 0 점이 대량으로 생기므로(위 표: ask 08-21 은 381봉 중
  313봉) pane y축 하한이 0 으로 내려간다. 여섯 계열이 축을 공유하므로 체결 계단과 함께
  보면 티가 안 나지만, **미도달만 켠 사용자는 값 구간이 위쪽에 압착**될 수 있다.
  ⚠ 이 표면은 **실화면으로 검증하지 않았다**(단위·e2e·파이프라인 실측으로는 축 스케일이
  안 보인다). 화면에서 압착이 거슬리면 손댈 곳은 `peakWallPaneSpec` 의 스케일 옵션이지
  0-fill 이 아니다.
- **top-3 밖 4위 이하 벽** — wire 가 나르지 않는다. 지금보다 훨씬 완화되지만 0 이
  100% 확실해지는 것은 **아니다**. 그 이상은 백엔드/wire 변경이라 **별도 스코프**다
  (ADR-0004: BE `Literal`·필드 추가는 FE 미러와 같은 PR).

## 5. 검토했으나 권장하지 않는 대안

| 대안 | 결과 | 기각 사유 |
|---|---|---|
| **span 미러** — 캔들 수평선처럼 `time0~time1` 전 구간을 그날 최댓값으로 | 갭 완전 제거, 표면과 1:1 | 하루 내내 **평선**이 된다. pane 이 답하는 질문("그 벽이 언제 얼마나 자랐나")을 통째로 잃는다 |
| **마지막 값 유지(hold)** | 갭 제거 | 이미 깨진 벽이 계단 높이로 영원히 남는 **틀린 선**. docstring 이 기각, 근거 유효 |
| **후보 풀 확장만** (0-fill 없이) | +0~6%p | 실측이 무효를 보였다(§2.2). 단독으론 의미 없음 |

## 6. 캔들 표면과의 관계 (헌장 시비 예방)

`peakWallSteps.ts` 머리말은 pane 을 "캔들 표면이 실제로 그리는 것의 다른 표현이고
판정을 다시 하지 않는다" 로 규정한다. 조사 중 확인된 사실:

- 캔들 표면의 미도달 **수평선은 `time0`(그날 개장) ~ `time1`(마감/라이브 엣지) 전 구간**을
  덮는다(`PeakWallSegment`).
- pane 계단은 `peakTime` 부터 그린다.

즉 **두 표면의 시간 span 은 이미 다르다**. 이는 위반이 아니라 역할 분담이다 — 수평선은
"그날 벽이 어느 가격에 있었나", 계단은 "그 벽이 언제 얼마나 자랐나". 이번 변경은 그
비대칭을 **더 벌리지 않는다**: 마감 높이 일치(§3.3)가 유지되고, 넓어지는 것은 계단의
후보이지 화면의 벽이 아니다.
