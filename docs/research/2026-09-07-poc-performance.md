# POC 폴백 및 작은 서버 개선

POC는 서버 seed와 오늘 체결값을 먼저 결정하고, 채워지지 않은 날짜만 캔들 폴백을 계산한다. 오늘 체결만 바뀌고 캔들·설정·세션이 같으면 과거 폴백도 재사용한다. 정렬된 캔들 배열은 순서를 한 번 확인하고 세션마다 이진 탐색으로 [open, close)를 찾는다. 역순/비정상 시각 배열은 기존 filter 순서를 보존한다. 분포 격자·수량·동률 선택 규칙은 바꾸지 않는다.

히트맵은 마지막 연속호가 시각 대신 기존 존재 확인 helper를 쓴다. 개장 전 deep book이 있어도 존재로 보던 기존 규칙, 마감 후 deep만 있는 경우와 퇴화 폴백을 유지한다. 체결강도는 요청이 1분이면 불변 캐시 배열을 그대로 반환하고 더 큰 봉의 합산은 그대로다.

## 측정과 검증

합성 세션당 390봉, rangeCount=100, 워밍업 2회 후 11회 중앙값. 다음은 순수 캔들 POC 계산 비용이며 React/Canvas/오늘 체결 집계는 제외한다.

| 거래일 | 기존(ms) | 변경 후 전체 폴백(ms) | 모든 날짜 seed 보유(ms) |
|---|---:|---:|---:|
| 5 | 0.499 | 0.391 | 0.001 |
| 30 | 3.157 | 1.448 | <0.001 |
| 90 | 5.692 | 3.080 | <0.001 |

rangeCount 미지정/1/10/100, 정순·역순 입력에서 원본 함수와 출력 동등성을 확인했다. 빈 fallbackSegments는 캔들 순서 검사조차 생략한다. 실제 브라우저의 React 훅 확인에서 seed qty=99일 때 캔들 가격 읽기 0회, seed 제거 시 폴백 qty=10, seed 복원 시 qty=99로 전환됐고 불필요한 추가 가격 읽기나 콘솔 오류는 없었다. 임시 페이지는 제거했다.

JSON과 benchmark.test.ts.txt를 옆에 보존했다. 재현 시 기준 함수는 `git show 8b2646e96:frontend/src/live/tradeVolumePoc.ts`를 `frontend/src/live/tradeVolumePoc.before.ts`에 저장하고 하네스를 같은 폴더로 복사해 Vitest로 실행한다. 끝나면 임시 두 파일을 제거한다.

서버 후보의 실데이터 측정은 전체 조사 자료의 candidates.json에 있다. 세 종목에서 히트맵 존재 helper 후보는 기존과 결과가 같았으며 약 2~9ms/일 감소했다. 이번 회귀 테스트는 마지막 시각 MAX 스캔을 다시 호출하면 실패하도록 하고, 개장 전/장중/마감 후/호가 없음 네 경우를 검증한다. 체결강도는 1분 배열 identity와 coarse 합산 동등성을 검증한다.
