# 키움 분봉·일봉 차트 TR 실측 — ADR-0120 의 전제가 틀렸다

- 티켓: [#1008](https://github.com/Soochol/hoga-ops/issues/1008) (지도 [#1005](https://github.com/Soochol/hoga-ops/issues/1005))
- 조사일: 2026-08-03 · 실계좌 프로브(`scripts/probe_kiwoom_rest_tr.py`, [#1006](https://github.com/Soochol/hoga-ops/issues/1006))
- 대상: `ka10080`(주식분봉) · `ka10081`(주식일봉)
- 성격: 실측. **설계 판단은 [#1012](https://github.com/Soochol/hoga-ops/issues/1012) 소관** — 여기서는 수치만 확정한다.

## 한 줄 결론

**`ka10080` 은 `base_dt` 로 날짜 랜덤 액세스가 된다.** [ADR-0120](../adr/0120-remove-kiwoom-minute-walkback.md) 이 walk-back 을 되돌린 근거 세 가지 중 **첫 번째가 사실이 아니었다.**

> ADR-0120 원문: *"`ka10080`은 시작 날짜 파라미터가 없고 `cont-yn`/`next-key` 순차 페이지네이션만 있다. 특정 과거 구간에 닿으려면 **매 요청마다 '오늘'부터** D/2.3 페이지를 다시 걸어야 한다."*

`base_dt` 를 실으면 그 날짜부터 과거 900행을 **직접** 준다. 매 요청이 오늘부터 되걸을 이유가 없다.

### 1. 랜덤 액세스 — `base_dt`

```
base_dt 없음      → 900행  20260803 11:47 ~ 20260730 09:30
base_dt=20260601  → 900행  20260601 15:35 ~ 20260528 13:05
base_dt=20250901  → 900행  20250901 15:35 ~ 20250828 ……
base_dt=20240102  →   1행  전 필드 빈 센티넬, cont-yn=N   ← 보유 밖
```

`base_dt` 는 **무시되지 않는다** — 보유 밖 날짜를 주면 900행이 아니라 **빈 센티넬 1행**이 온다. 즉 파라미터가 해석된다는 증거다. (`strt_dt` 는 무시됐다 — 기준선과 동일한 응답.)

휴장일도 알아서 처리한다: `base_dt=20260101`(신정) → `20251230` 부터 반환.

**비용 모델**: 900분봉 ≈ **2.3 거래일**. 목표 날짜를 직접 주소로 지정하므로 **날짜당 1콜**이면 되고, ADR-0120 의 O(D²) 는 성립하지 않는다.

### 2. 보유 기간 — 분봉 1년 롤링

```
base_dt=20250804 → 764행,  최古 20250801 09:00   ← 바닥
base_dt=20250801 → 382행,  20250801 하루치만
base_dt=20250731 →   0행,  빈 센티넬
```

바닥이 **2025-08-01 09:00** 이고 조사일이 2026-08-03 이므로 **약 367일 = 1년 롤링**이다.

**귀결**: 1년보다 오래된 분봉은 키움에서 **신규 수집이 불가능**하다.

> **정정(2026-08-03)**: 이 문서의 초판은 여기에 "지도가 확정한 `kis_api` 읽기 전용 존치는 이 구간에서 **선택이 아니라 필연**" 이라고 덧붙였다. 그 문장은 **키움 전환이 제약을 새로 만든다**는 뉘앙스를 주는데 **틀렸다** — **KIS 도 분봉 보유가 약 1년**이다(`kis_endpoints.py:356`: *"KIS retains roughly 1 year of historical minute candles per the portal docs"*).
>
> 즉 1년 밖 분봉은 **KIS 로도 지금 받을 수 없다.** 디스크의 오래된 `kis_api` 분봉은 "그때 수집해 둔 것" 이지 KIS 가 현재 제공하는 것이 아니다. **존치 결정은 여전히 옳지만 이유가 다르다** — 키움의 제약 때문이 아니라 **양쪽 벤더의 공통 제약** 때문이다. 이 축에서 키움 전환의 손실은 **0** 이다.
>
> 교훈: 한쪽 벤더만 실측하면 그 제약이 **그 벤더 고유의 단점**처럼 보인다. 비교 기준을 같이 재야 "원래 그런 것" 과 "이번에 나빠지는 것" 이 갈린다.

일봉은 대조적이다 — `base_dt=20100101` → 600행, `20091230 ~ 20070803`. **2007년까지** 간다.

### 3. 유량 — 1 req/s 는 벤더 한계가 아니었다

```
10페이지 연속, --pace 0.3 (≈3.3 req/s)
→ 에러 0, 지연 min 30 / 평균 51 / max 172 ms
```

ADR-0120 이 페이지당 1초를 더한 것은 **당시의 보수 설정**이었지 실측된 벤더 상한이 아니다.

**KIS 와 나란히 놓을 때 주의**: `kis_client._RATE_LIMIT_CALLS_PER_SEC = 15.0` 도 **우리 추정치**다 — 같은 파일 주석이 *"KIS doesn't publish an exact retail limit — 20/sec is the commonly-cited figure; 15 gives ~25% headroom"* 라고 적는다. 키움의 5 req/s 는 **벤더가 429 응답에 명시한 값**(#1015)이므로, 두 수치를 그대로 비교해 "3배 느려진다" 고 읽으면 안 된다. 한쪽은 추정, 한쪽은 측정이다.

**주의**: 이것은 "3.3 req/s 까지 안전" 의 증명이 아니라 "3.3 req/s 에서 에러가 없었다" 는 관측이다. 실제 상한과 지속 가능 유량은 [#1015](https://github.com/Soochol/hoga-ops/issues/1015) 에서 별도로 재야 한다 — 이 프로브는 상한을 찾으러 간 것이 아니다.

### 4. `tic_scope` — 8종 전부 작동하고, 페이지는 항상 900행

| `tic_scope` | 900행이 덮는 구간 | 하루 봉 수 | 측정일 |
|---|---|---|---|
| 1분 | 2.3 거래일 (`20260803 11:50 ~ 20260730 09:33`) | — | 08-03 |
| 3분 | 약 8 거래일 (`~ 20260724 14:39`) | 130 | 08-04 |
| 5분 | 약 3주 (`~ 20260715 14:05`) | — | 08-03 |
| 10분 | 약 1개월 (`~ 20260701 13:40`) | 39 | 08-04 |
| 15분 | 약 1.5개월 (`~ 20260617 12:00`) | 27 | 08-04 |
| 30분 | 약 3개월 (`~ 20260428 10:00`) | — | 08-03 |
| 45분 | 약 5개월 (`~ 20260311 09:00`) | 9 | 08-04 |
| 60분 | 약 6.5개월 (`~ 20260121 15:00`) | — | 08-03 |

행 수가 고정이라 **커버리지는 스코프에 비례**한다. 넓은 스코프일수록 콜당 효율이 좋다.
지수 `ka20005`([스펙](2026-07-29-kiwoom-index-minute-tr-spec.md))와 동일한 8종 집합이다 —
**분봉 TR 이 1분봉만 준다는 통념은 사실이 아니다.**

> **검증 방법 주의**: 행 수 900 은 파라미터가 해석됐다는 증거가 **아니다**. 같은 TR 에서
> `strt_dt` 는 무시되고도 기준선과 동일한 900행 정상 응답을 냈다(§1). 증거는 응답 내용의
> 구조 변화뿐이라 `cntr_tm` 의 **간격 분포**를 셌다: `tic_scope=10` 은 10분 간격이 848건으로
> 압도적이고 봉 시각이 `09:00`/`09:10`/`09:20` 격자에 정렬된다.

#### 하루 격자 — 45분만 마감과 어긋난다

```
10분  09:00 … 15:00, 15:10, 15:30   39봉   ← 15:20 없음
15분  09:00 … 15:00, 15:15, 15:30   27봉
45분  09:00 … 13:30, 14:15, 15:00    9봉   ← 15:30 없음
```

- **10·15분**: `15:20` 봉이 없다. 15:20~15:30 은 종가 단일가 호가접수 구간이라 체결이 없고,
  `15:30` 이 종가 단일가 체결봉으로 따로 붙는다.
- **45분**: 정규장 390분 ÷ 45 = 8.67 로 나눠떨어지지 않는다. 마지막이 `15:00` 봉이고
  **종가 단일가 봉이 별도로 없다** — 10·15분과 하루 마지막 봉의 의미가 다르다.
- **빈 봉을 채워 주지 않는다.** 10분봉 간격 분포의 `20분` 24건은 체결 없는 구간의 스킵이고,
  `1050분` 18건은 거래일 경계(15:30→익일 09:00 = 17.5h), `3930분` 은 주말이다. 균일 격자를
  가정하는 코드는 여기서 깨진다.

### 5. 수정주가 — `upd_stkpc_tp`

삼성전자 2018-05-04 액면분할(50:1)을 리트머스로 썼다:

```
upd_stkpc_tp=0 → 20180427 종가 2,650,000원   (원주가)
upd_stkpc_tp=1 → 20180427 종가    53,000원   (수정주가)
                 2,650,000 ÷ 50 = 53,000 ✓
```

**1 = 수정주가, 0 = 원주가.** `screener_backfill.py:257,272` 가 요구하는 **2벌**(수정주가/원주가)에 정확히 대응한다 — KIS `FHKST03010100` 의 `adjust` 플래그 대응물이 확보됐다.

### 6. venue — 종목코드 접미

```
stk_cd=005930      → 900행  ~ 20260730 09:33
stk_cd=005930_NX   → 900행  ~ 20260731 08:12   (NXT 시간외 시작 시각이 보인다)
stk_cd=005930_AL   → 900행  ~ 20260731 08:13
```

`kis_venue.py` 의 `_KIS_DIV`(`J`/`NX`/`UN` wire 인코딩)에 대응하는 것은 **종목코드 접미**다. 지도 fog 의 "venue 라우팅의 키움 대응물" 항목이 이것으로 해소된다.

`_NX` 응답이 08:12 부터 시작하는 것은 NXT 시간외 세션과 부합한다. `_AL` 의 정확한 시맨틱(통합 병합 규칙)은 이 티켓 범위 밖 — ADR-0118/#681 이 이미 다룬 축이다.

## ADR-0120 을 다시 읽는다

ADR-0120 은 세 성질이 곱해져 O(D²) 가 된다고 했다. 실측 대조:

| ADR-0120 의 근거 | 실측 |
|---|---|
| ① **랜덤 액세스 불가** — 시작 날짜 파라미터 없음 | ❌ **사실 아님** — `base_dt` 작동 |
| ② 직렬 강제 + 1 req/s | ⚠️ 절반만 — 커서 직렬은 맞지만 `base_dt` 로 **날짜별 병렬이 가능**하고, 1 req/s 는 벤더 한계가 아니다 |
| ③ 순회분 폐기 | ✅ 우리 구현 문제이고 여전히 유효 — 다만 ①이 무너지면 순회 자체가 사라진다 |

**ADR-0120 의 결정(키움 walk-back 제거)이 당시에 틀렸다는 뜻은 아니다.** 당시 구현이 `base_dt` 를 쓰지 않았고, KIS 라는 검증된 대안이 있었다. 다만 **"키움은 랜덤 액세스가 안 된다" 가 벤더의 성질로 일반화되어 남은 것**이 문제였다 — 그것은 `ka10080` 을 그렇게 **호출한 방식**의 성질이었다.

### [#1012](https://github.com/Soochol/hoga-ops/issues/1012) 에 미치는 영향

티켓 #1012 의 첫 질문은 *"커서 재사용 계층을 지을 것인가 — 지으면 이 지도 최대 단일 덩어리"* 였다. **그 질문이 대체로 사라진다.** `base_dt` 로 재진입할 수 있으면 커서를 프로세스 간에 보존할 이유가 없다.

남는 설계 질문은 훨씬 작다:
- 날짜 → `base_dt` 매핑과 900행 페이지의 경계 처리(목표 날짜가 페이지 끝에 걸치는 경우)
- 분봉 1년 보유 밖 구간의 표시 정책(`kis_api` 존치본과의 이음매)
- 순회분 전량 적재(ADR-0120 원인 ③ — 여전히 유효한 개선)

## 미측정 · 리스크 — 정직하게 남긴다

- **`base_dt` 가 공식 문서화된 파라미터인지 미확인.** 우리가 참조한 공개 카탈로그에 없었고 ADR-0120 도 "없다" 고 기록했다. 실측으로 작동을 확인했지만, **문서화되지 않은 동작이면 벤더가 예고 없이 바꿀 수 있다.** [#1012](https://github.com/Soochol/hoga-ops/issues/1012) 착수 전에 키움 공식 API 문서에서 확인할 것 — 설계 전체가 이 파라미터 위에 서기 때문이다.
- **종목 1개(005930)만 측정.** 보유 기간·페이지 크기가 종목마다 다를 가능성은 배제하지 못했다. 특히 신규 상장·거래정지 종목.
- **유량 상한 미탐색.** 3.3 req/s 에서 에러가 없었을 뿐이다(→ [#1015](https://github.com/Soochol/hoga-ops/issues/1015)).
- **커서 cross-process 유효성 미검증.** `base_dt` 가 되면 설계상 불필요해져 우선순위가 떨어졌다.
- ~~1분 외 스코프의 커서·`base_dt` 규칙 미검증~~ → **`tic_scope=10` 에서 실측 성립**
  (2026-08-05, 005930): `base_dt=20260721` 페이지의 최古 날짜 20260617 이 13:40부터로
  **앞이 잘려** 오고(11봉), `base_dt=20260617` 재지정 시 09:00부터 **온전한 39봉**이
  온다(잘린 11봉은 그 부분집합). [커서 검증 문서](2026-08-03-kiwoom-minute-ka10080-cursor-verified.md)
  의 규칙("최古 날짜만 잘렸을 수 있고, 재지정으로 온전 재수신")이 1분 외 스코프에도
  적용된다. 나머지 스코프(3/5/15/30)는 여전히 미실측이나 두 극단이 같은 규칙이다.
- **`_AL` 병합 시맨틱** · **일봉 venue 접미** 미검증.
- 분봉 보유 바닥이 **롤링인지 고정인지** 미확인 — 1년 롤링으로 보이지만 재측정으로만 확증된다.
