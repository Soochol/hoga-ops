# 미국 개별 종목 키움 REST 분봉: 실조회와 앱 연결

검증일: 2026-10-19 KST (실조회 2026-10-18 15:21–15:33 UTC, 미국 휴장 중).

## 확인 결과

키움 REST `usa06011`로 미국 개별 종목의 **1·3·5·10·15·30·60분봉이 실제 반환**된다.
각 주기를 공급자에게 직접 요청한다. 앱에서 1분봉을 재집계하지 않는다.
NASDAQ NVDA/AAPL, NYSE KO/BRKb/AHT_pd, AMEX AAAA를 확인했다.
실조회는 기존 캐시 토큰만 사용한 독립 프로세스에서 수행했다. 토큰 발급·폐기,
WS 연결, 주문 전송을 하지 않았고 개발/E2E 서버에는 자격증명을 주입하지 않았다.

공식 근거:

- [키움 공식 REST 명세](https://github.com/Kiwoom-Securities/Kiwoom-REST-API/blob/main/kiwoom/_data/kiwoom_api_spec.json): `usa06011`, `POST /api/us/chart`, 요청·응답 필드.
- [한투 공식 해외주식 분봉 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/overseas_stock/inquire_time_itemchartprice/inquire_time_itemchartprice.py): 시각 교차 검증에만 사용했다. 제품의 미국 개별 종목 분봉은 키움만 사용한다.
- [키움 공식 저장소 시간/세션 관련 질문](https://github.com/Kiwoom-Securities/Kiwoom-REST-API/issues/5): 조사 시점에 공급자가 시간대·전체 세션 범위를 명확히 답변하지 않았다. 아래 시간 해석은 실제 가격 대조에 근거한 결과다.

## 요청 및 실제 응답

```json
{"stex_tp":"ND","stk_cd":"NVDA","strt_dt":"20261018","tic_scope":"1","upd_stkpc_tp":"0","exrt_appl_tp":"0"}
```

실제 호출의 날짜별 body와 응답은 아래 JSON 증거에 보존했다. 거래소는
NASDAQ=`ND`, NYSE=`NY`, AMEX=`NA`다. 티커 대소문자와 밑줄을 보존해야 한다.
`BRKb`, `AHT_pd`가 실제 성공했다. 잘못된 거래소에 넣은 SPY/UAMY는 1903 오류를 반환했다.
AMEX 마스터 1,991개 중 실제 등록된 AAAA로 재확인했으며 정상 반환했다.
따라서 임의의 티커/거래소 조합으로 전체 시장의 지원 여부를 판단하면 안 된다.

100봉씩 `cont-yn`/`next-key`를 사용해 연속 조회가 된다. 새 앱 어댑터
`UsMarketApi.stock_minutes → UsStockMinuteService → KiwoomRestClient`로 아래를 재조회했다.
모든 조합이 **8페이지, 800봉, 정상, more_available=true**였다.
공통 REST 호출 예산이 추가된 최신 main을 반영한 뒤에도 12개 결과의 캔들 SHA256이 동일했다.

**800봉은 앱의 요청/메모리 제한이며 공급자의 보관 한도가 아니다.** 별도 날짜 요청으로
NVDA 2026-06-01의 1분봉도 확인했다. 2026-01-09의 60분봉은 정상 빈 응답이었다.
이 두 표본으로 정확한 보관 시작일이나 최대 조회 연수를 단정할 수 없다.
이번 범위에서는 화면의 이전 날짜 이동/자동 백필을 추가하지 않았다.

## 시각, 장외, 지연 여부

`cntr_tm`의 뉴욕 현지 시각 해석을 검증했다. NVDA·AAPL 각각 한투와 겹치는
60개 분에서 OHLC와 거래량이 모두 일치했다. 예를 들어 키움 `20261016185900`과
한투 `xymd=20261016,xhms=185900,kymd=20261017,khms=075900`이 일치했다.
한투의 최신 봉은 19:59, 키움은 18:59였지만 중복 구간의 가격/거래량이 같은 분에
정확히 일치하므로 단순히 키움 시각을 한 시간 밀어서는 안 된다.

장외 야간 시각 `20261015261000`도 실제 반환됐다. 이를 뉴욕 2026-10-16 02:10으로
날짜를 넘긴 뒤 DST를 적용한다. `bus_dt=20261015`는 공급자 영업일로 별도 유지한다.
소스의 영업일이 뉴욕 달력 날짜와 항상 같다는 가정은 하지 않는다.
파서는 24–47시의 한 번 날짜 넘김을 지원하고 48시 이상·잘못된 날짜/분/초·
DST 전환으로 존재하지 않는 현지 시각을 거부한다. 겨울/여름 UTC 변환도 단위 테스트했다.
`upd_stkpc_tp` 응답에 `1f`가 들어온다. 명세에서 의미가 명확하지 않아 숫자로 파싱하거나
수정주가의 증거로 쓰지 않는다. 요청은 수정 전 가격(`0`), USD(`0`)로 고정한다.

장외 데이터가 포함된 사실은 확인했으나 전체 세션의 계약상 범위는 확인하지 못했다.
휴장 중 표본이므로 **실시간 여부와 고정 지연 시간은 미확인**이다.
화면에도 지연 여부 미확인, 장외 포함, 마지막 봉 변경 가능을 표시한다.
차트 축은 기존 앱 기준 KST, 제공 범위 표기는 뉴욕이다.

## 앱 구현

- 새 typed GET `/api/live/us-stock-minute-candles?exchange=NASDAQ&symbol=NVDA&timeframe=1m`.
  7개 분 주기만 허용하며 티커를 검증한다. 기존 일/주/월봉 경로는 유지한다.
- 페이지마다 기존 capacity scheduler와 공유 REST 예산을 통과한다.
  요청 12초, 최대 8페이지/800봉, 메모리 캐시 64개, 동시 동일 요청 합류,
  TTL/화면 폴링 60초, 실패 재시도 30초로 제한한다. 취소된 HTTP 대기자가 공동 조회를 취소하지 않는다.
- 거래소·정확한 티커·주기별 격리, LRU, 연속키 반복/정체·잘못된 row·충돌 시각 검사,
  종료 시 진행 중 작업 취소를 적용했다. 디스크/WS/다른 벤더 fallback을 추가하지 않았다.
- 갱신 실패 시 마지막 정상 데이터를 보존하고 stale을 표시한다. 첫 부분 조회는 partial,
  정상 빈 결과는 분봉 없음, 무자격/우회는 각 상태로 표시한다.
- URL·검색·그룹·핀·저장된 주기를 연결했다. 해외 종목에 국내 호가/체결 WS를 구독하지 않는다.
  현재 미국 종목 capability에 맞춰 거래량/대금/호가 패널은 계속 비활성이다.
  공급자가 반환한 거래량은 백엔드 wire에 보존한다.
- 실제 800봉을 브라우저에 넣는 과정에서 근접한 야간 영업일 경계가 다음 세션의
  pre-open으로 오인돼 일부 봉이 빠지는 문제를 발견했다. 실제 세션을 우선 분류하고,
  봉 간격이 다음 세션 시작에 닿을 때 inclusive 끝 경계를 겹치지 않게 제한했다.

실제 외부 호출 검증과 브라우저 검증은 분리했다. 브라우저 E2E는 위 실조회 응답을
고정해 사용하고 HTTP polling/stale/주기 선택/새로고침/화면 페인트/800봉 보존/국내
API·WS 차단을 검사한다. 실제 키움 서버를 E2E 서버에 연결했다고 주장하지 않는다.
KST 자정 경계 테스트는 실제 가격을 사용하되 타임스탬프를 경계 표본으로 재배치한 합성 테스트다.
최종 전체 단위/API 검사·타입·빌드·관련 E2E 결과는 검증 기록에 저장한다.

## 최신 main 통합 검사에서 확인한 회귀 수정

전체 백엔드 검사에서 신규 거래 v2 라우트의 응답 모델 누락과, 공통 REST admission
추가 후 진단 테스트의 실제/가상 시계 혼용으로 발생한 실패를 확인했다. v2 라우트에
기존 모델과 전체 상태/보유종목/명령 상태 모델을 선언하고 프론트 타입 미러 및 필드
스냅샷을 함께 추가했다. HTTP 회귀 테스트로 전체/주문/잔고 상태를 정확히 구분하고,
보유종목·동적 영수증·부분 취소의 키 생략까지 보존됨을 확인했다. 진단 테스트는
admission과 측정에 같은 가상 시계를 사용하도록 수정했다. 실제 주문 전송이나 벤더
주문 처리 로직은 바꾸지 않았다. 이 수정은 미국 분봉의 공급자 선택과 독립적이다.

프론트에 추가된 거래 타입은 TypeScript transpile 출력이 수정 전과 byte-identical함을
확인했다. 전체 Vitest 결과는 재사용하고, 새 타입 검사와 거래 관련 단위/E2E 검사를
추가 실행한다. 상세 재사용 근거와 지문은 최종 검증 JSON에 기록한다.
