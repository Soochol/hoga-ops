# 공통 bin 집계 및 정확한 cutoff 인덱스

분포와 POC는 동일한 (가격범위, bin 수, 세션 하한/유효 상한)의 원시 집계를 공유한다. 내부 결과에 각 bin의 수량·최초·마지막 시각을 보존한다. 분포의 raw 최상단 bin은 그대로 내보내고 POC만 마지막 bin에 합친 뒤 낮은 bin 우선으로 동률을 선택하므로 기존 값과 일치한다.

과거일 cutoff는 bin별 정확한 체결 시각과 누적 수량을 이진 탐색한다. 분 단위 근사가 없어 임의 millisecond까지 포함하는 기존 계약을 유지한다. Polars의 Int128 누적 후 int64 범위를 확인하고 압축 배열에 저장한다. 인덱스가 50만 (bin, time) 행을 초과하거나 int64 누적량을 넘으면 기존 직접 집계를 사용한다.

QueryEngine마다 LRU를 두며 보존 payload 상한 32MiB, 최대 64항목이다. 파일의 경로·device/inode·size·mtime_ns·ctime_ns와 전체 숫자 조건으로 키를 나눈다. 동일 key 동시 요청은 한 번만 생성하고 예외 후 재시도가 가능하다. 오늘과 cache=None은 직접 조회를 유지한다. 디스크에 cutoff별 파일을 추가하지 않는다. 키/컨테이너 및 DuckDB/Polars의 생성 중 메모리는 payload 상한과 별도다.

## 실데이터 측정

기준은 main 7669334e3의 테이블 함수다. 분포+POC는 워밍업 후 5회 중앙값이며 매번 새 공통 캐시를 사용한다. cutoff는 09:00부터 10분 간격 36개 위치에 0/1/537ms 오프셋을 더한 108회 조회의 합계다. 모든 cutoff와 두 집계의 필드를 원본과 대조했다. 아래는 순수 테이블 조회로 HTTP/JSON/렌더링 시간은 제외한다.

초기 인덱스 생성은 단일 직접 조회보다 느릴 수 있다. 반복 스크럽에서 비용을 회수하는 변경이며 첫 조회까지 모두 빨라진다는 뜻은 아니다. API의 실제 사용자 스크럽 빈도는 측정하지 않았고, 위 108회는 통제된 workload다.

인접 JSON과 하네스를 보존했다. 재현하려면 `git show 7669334e3:hoga/tables/trades.py > /tmp/indicator-trades-before.py` 후 하네스를 `PYTHONPATH=.`와 프로젝트 Python으로 실행한다. 원본 parquet가 필요하며 서버 자격증명이나 사용자 서버는 사용하지 않는다.
