# Live 주봉·월봉 과거 조회 비용과 키움 직접 조회 실측

- 조사일은 2026-11-05다. 코드 기준은 `f809c8d0f7dc5ad6c8e7a15eb9bb3cbfd0c48465`다.
- 대상은 국내 주식 Live의 과거 추가 로딩과 키움 주·월봉 직접 조회다.
- 이 기록은 조사 결과다. 제품 경로, API 계약, 캐시 정책은 변경하지 않았다.
- 수치 원자료 요약, 반복별 값, 대표 응답 행과 캡처 해시는 [evidence.json](evidence.json)에 있다.

## 현재 주봉은 더 긴 일봉 이력을 요청한다

D, W, M은 같은 `/api/live/past-daily-candles`를 사용한다. 프런트가 일봉을 주·월 단위로 집계한다. 과거 추가 로딩의 표시 목표는 약 50봉이며, 날짜 예산은 D 50평일, W 250평일, M 1,050평일이다. 기본 초기 범위도 D 350캘린더일, W 1,750캘린더일, M 7,350캘린더일로 다르다. [범위 계산](../../../frontend/src/live/liveDateTime.ts), [캘린더 집계 선택](../../../frontend/src/live/useLiveBundle.ts)

서버는 캐시에 없는 구간을 오늘의 수정주가 기준으로 조회한다. 각 walk는 빈 연속조회 키로 시작해 최근 페이지부터 목표 시작일 이전까지 순차 조회한다. 따라서 과거를 확장할 때 이미 읽었던 최근 페이지를 다시 받을 수 있다. 프런트는 확장된 전체 기간을 요청하고 완성된 응답을 기다린다. 이 구조는 주봉의 더 긴 원본 범위를 대기로 바꿀 수 있다. 실제 사용자 지연에서의 비중을 확정한 것은 아니다. [수정 기준일](../../../hoga/live/live_daily_candle_backfill.py), [일봉 어댑터](../../../hoga/live/kiwoom_daily_candles.py), [연속조회](../../../hoga/live/kiwoom_rest.py), [전체 범위 요청](../../../frontend/src/api/livePastDailyCandles.ts)

크게 팬하면 D와 W 모두 정해진 fill 예산만큼 후속 요청을 순차 실행했다. 서로 다른 날짜 범위의 연속 요청 자체는 중복 fetch의 증거가 아니다. `CONTEXT.md`의 Live Edge 항목에 있는 minute-only settle loop 설명은 조사 기준 코드와 맞지 않는다. 이 기록에서는 현 [백필 effect](../../../frontend/src/live/useViewportBackfill.ts)를 기준으로 삼았다.

## 키움은 주봉과 월봉을 직접 제공한다

공식 [주봉 ka10082](https://openapi.kiwoom.com/m/guide/apiguide/07/ka10082)와 [월봉 ka10083](https://openapi.kiwoom.com/m/guide/apiguide/07/ka10083)은 `POST /api/dostk/chart`를 사용한다. 필수 본문은 `stk_cd`, `base_dt`, `upd_stkpc_tp`이며 연속조회는 `cont-yn`, `next-key`로 이어간다. 수정주가는 `1`, 원주가는 `0`이다. 문서에는 KRX 기본 코드, NXT `_NX`, SOR `_AL`이 명시된다.

별도 정규장 주봉 `ka11082`, 월봉 `ka11083`도 있지만 이번 대조에는 섞지 않았다. 현재 제품의 표준 일봉 `ka10081`과 표준 주·월봉을 비교했다. 조사 기준 TR 등록부에는 국내 주식 `ka10082/83`이 없고 지수 `ka20007/8`만 별도로 등록되어 있다.

## 같은 요청 기간의 호출량이 줄었다

사용자가 지정한 로컬 환경에서 기존 유효 토큰을 재사용했다. 토큰 발급·갱신, WS, 주문, 서버 재시작은 하지 않았다. 기준일은 `20261105`, 종목은 삼성전자 `005930`, 거래소는 KRX, 수정주가는 `1`이다.

주봉 비교 시작일은 `20210204`, 월봉은 `20020912`다. 현 초기 이력에 첫 과거 스텝을 추가한 범위다. 각 방식 5회를 일봉, 직접 조회 순서로 교차 실행했다. 매 walk는 빈 연속조회 키로 시작했다. 같은 HTTP 연결 풀을 사용했고 제품 캐시는 통과하지 않았다. 한 번에 요청 하나, 요청 시작 간격 1초로 제한했다.

다음 수치는 5회 모두 같았다. 같은 것은 요청 날짜 범위다. 페이지의 초과 반환 행도 집계했으므로 실제 반환 집합은 다르다. 바이트는 압축 해제된 응답 본문 크기다.

| 대상 | 일봉을 받아 집계 | 직접 조회 |
|---|---:|---:|
| 주봉 구간 호출 | 3회 | 2회 |
| 주봉 구간 받은 행 | 1,800행 | 600행 |
| 주봉 구간 본문 | 415,082바이트 | 143,031바이트 |
| 월봉 구간 호출 | 10회 | 2회 |
| 월봉 구간 받은 행 | 6,000행 | 480행 |
| 월봉 구간 본문 | 1,376,817바이트 | 113,274바이트 |

첫 페이지의 실제 반환량은 일봉 600행, 주봉 300행, 월봉 240행이었다. 모든 종목이나 향후 API 용량을 보장하는 상수로 해석하지 않는다.

페이지별 HTTP 응답 시간을 더한 중앙값과 최소·최대는 다음과 같다. 시험용 1초 페이싱과 JSON 파싱 이후 처리는 제외했다. 제품 스케줄러, 캐시, 차트 렌더 시간도 포함하지 않는다.

| 대상 | 일봉을 받아 집계 | 직접 조회 |
|---|---:|---:|
| 주봉 HTTP 합계 | 344ms [266, 798] | 231ms [93, 443] |
| 월봉 HTTP 합계 | 1,232ms [702, 2,468] | 120ms [74, 168] |

주봉 시간 범위는 겹치므로 일관된 속도 향상 배수를 정하지 않았다. 월봉은 이 표본의 직접 벤더 경로에서 시간 합계도 작았다. 수집기의 전체 시간은 의도한 페이싱이 지배한다. 이 결과를 Live가 몇 배 빨라진다는 값으로 바꾸지 않는다.

## 가격은 일치했지만 모든 값이 같지는 않았다

현재 Python `parse_row`로 일봉을 정규화하고, 실제 프런트 `aggregateCalendar`를 메모리 번들로 실행해 기준값을 만들었다. 독립 구현을 제품의 정답으로 쓰지 않았다. Decimal과 정수로 원문을 읽고 JavaScript 안전 정수 범위를 검사했다. 부분 경계와 현재 진행 기간은 별도로 기록하고 제외했다.

| 수정주가 표본 | 완성 기간 | OHLC | 거래량 |
|---|---:|---|---|
| 삼성전자 KRX, 2017년 이후 | 512주·118월 | 전부 일치 | 전부 일치 |
| 삼성전자 NXT, 최근 구간 | 13주·3월 | 전부 일치 | 전부 일치 |
| 삼성전자 통합, 최근 구간 | 13주·3월 | 전부 일치 | 전부 일치 |
| 카카오 KRX, 2017년 이후 | 512주·118월 | 전부 일치 | 94주·32월에서 차이 |

카카오 수정 거래량에서 직접 조회 값과 일봉 합계의 차이는 주봉 -1~+2주, 월봉 -2~+3주였다. 원주가 `0`으로 같은 구간을 다시 조회하면 512주·118월의 OHLC와 거래량이 모두 일치했다. 차이가 수정 모드와 연관된다는 관측은 지지된다. 정수화 시점이나 반올림 때문이라는 설명은 추론이며 벤더 내부 계산식을 확인한 것은 아니다.

조회량을 측정한 첫 반복 응답도 별도로 대조했다. 주봉 범위의 완성 299주와 월봉 범위의 완성 289월에서 삼성전자 OHLC와 거래량이 모두 일치했다. 월봉 완료 기간은 2002년 10월부터 2026년 10월까지다. 앞 표와 중복되는 관측이므로 표본 수를 합치지 않는다.

거래대금은 모든 비교 기간에서 정확히 같지 않았다. 일봉은 백만원 정밀도 값을 원으로 환산하고, 직접 주·월봉은 원 단위 값이다. 관측 차이는 각 기간의 일봉 개수에 100만원을 곱한 범위 안이었다. 이 범위를 허용오차로 사용해 일치 판정을 만들지 않았다. 정밀도 차이와 양립하는 결과이며 정확한 반올림 규칙은 미확인이다. 기존 일봉의 `×1,000,000` 변환을 직접 주·월봉에 재사용해서는 안 된다.

커밋된 KRX 달력이 완전히 덮는 범위에서는 두 종목 각각 499주·115월의 일봉 날짜가 기대 거래일과 일치했다. 달력 보장 범위는 2007-01-02부터 2026-08-03까지다. 최근 구간, NXT와 통합의 완전성 증거로 확장하지 않았다.

## 전환에는 데이터 계약 정리가 필요하다

동일 기준일·수정주가 요청값으로 비교했을 때 직접 주·월봉의 호출 수와 응답량이 줄었다. 특히 긴 월봉에 유리한 후보다. 두 API의 수정 기준 의미가 항상 같은지, 일봉 캐시가 따뜻할 때도 이득인지까지 확인한 결과는 아니다.

제품 반영에는 다음 조건이 남는다.

- 주기·거래소·수정 기준별 캐시와 기간 coverage를 구분한다.
- 원 단위 거래대금 파서와 수정 거래량 의미를 정한다.
- 봉 대표 날짜, 현재 진행 봉의 실시간 갱신과 과거 시점의 미래 데이터 차단을 검증한다.
- D로 전환할 때의 일봉 캐시 재사용 효과를 비교한다.
- [ADR-0048](../../adr/0048-live-daily-direct-backfill.md)의 일봉 공유 결정을 재검토한다. [ADR-0139](../../adr/0139-candle-resolution-axis-source-cost.md)는 소스 비용 판단 근거이며 기존 분봉 실측을 이번 주·월봉의 성능 근거로 쓰지 않는다.

조회량 감소와 수치 관측은 확인됐지만, 확인되지 않은 달력·수정 기준·날짜 규약 때문에 비교 도구는 전면 동등 판정을 거부했다. 이는 제품을 같은 계약으로 바로 교체해도 된다는 판정과 다르다.

## 증거 보관 범위

실제 차트 조회는 본 실행 107회, 원주가 대조 8회, 최초 확인 3회로 총 118회였고 HTTP·벤더 오류는 없었다. 격리 비교 도구의 양성·의도적 불일치·누락·커서 오류 등 자기 검증 22개가 통과했다.

원본 전체 캡처와 진단 도구는 조사 세션의 로컬 산출물로 보존했다. 저장소에는 요약, 5회별 측정값, 원본 캡처 해시와 대표 응답 행을 남긴다. 대표 행은 금액 단위 차이와 카카오 수정·원 거래량 차이를 재계산할 수 있다. 모든 기간의 전수 재검산에는 전체 원본 캡처가 필요하다. 인증 헤더, 토큰, 계정 식별자, 로컬 파일 경로는 이 증거 파일에 포함하지 않았다.
