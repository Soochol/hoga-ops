# 장전 시간외 종가매매(08:30–08:40) 호가 조사 — 2026-08-19

`/live` 10호가 창이 **장전 08:30–08:40 에 통째로 "호가 데이터 없음"** 이라는 보고에서
출발했다. 그 구간의 매도/매수 잔량이 화면에 나와야 한다는 요구다.

2026-08-14 문서(`2026-08-14-kiwoom-after-hours-orderbook-sources.md`)가 **장후**
(15:30 이후)를 다뤘다면 이 문서는 그 **아침 거울**이다. 결론이 대칭이 아니라는 것이
이 조사의 요점이다: 장후는 "총잔량만 뜬다"인데 **장전은 "아무것도 안 뜬다"** 이고,
그 차이는 벤더가 아니라 **우리 프론트의 폴백 설계**에서 나온다.

## 결론

1. **데이터는 정상적으로 도착하고 있다.** 08:30:00–08:40:00 에 키움 `0E`(주식시간외호가)
   가 KRX venue 로 흐르고, 매도·매수 총잔량 두 개를 싣는다. 백엔드 링 버퍼 →
   `/api/live/series.after_hours` → 프론트 venue 필터 → `latestAfterHoursTotals` 까지
   **전 구간 무결**하다.
2. **그런데 화면에는 한 글자도 못 뜬다.** 총잔량 스트립이 `snapshot`(10단 사다리)
   **존재를 전제로** 렌더되는데, 아침에는 그날 `0D` 가 아직 한 번도 오지 않아
   `snapshot === null` 이고 `BookPanel.tsx:129` 가 그보다 먼저 리턴한다.
3. **10단 사다리 자체는 이 구간에 원리적으로 없다.** 장전 시간외 종가매매는 전일종가
   **단일 가격** 거래라 사다리라는 개념이 없다 — 15:40–16:00 과 같다. 표현 가능한
   실체는 실측된 `0E` 총잔량 두 개뿐이다.

## 1. 실측 (2026-08-19 08:33–08:42, 사용자 dev 서버 :8000)

관측 방법은 2026-08-14 문서와 같다 — 표시 링 버퍼(`/api/live/series`)를 12–15초 주기로
GET. **대조군을 같은 폴링에 태웠다**: KRX-only 2종목 + NXT 상장 1종목.

### 1.1 `0E` 는 08:30:00 에 시작해 08:40:00 에 정확히 멎는다

| 종목 | `0E` 프레임 | 구간 | 매도총잔량 추이 | 매수총잔량 |
|---|---|---|---|---|
| 069500 KODEX200 (KRX-only) | 119 | **08:30:00 ~ 08:40:00** | 4,786 → 22,367 (단조 증가) | **0 내내** |
| 006360 GS건설 (KRX-only) | 28 | **08:30:00 ~ 08:40:00** | 13,770 → 13,755 | **0 내내** |
| 005930 삼성전자 (NXT 상장) | 194 | 08:30:00 ~ | 4,786 → 24,870 | **0 내내** |

08:40:00 이후 08:42:14 까지 7회 연속 폴링에서 프레임 수·마지막 값이 **고정**됐다
(069500: 119건 / 08:40:00 / 22,367). 창이 닫힌 것이지 폴링이 멈춘 것이 아니다 —
같은 폴링의 다른 축은 계속 움직였다.

⚠ **매수총잔량이 세 종목 모두 0** 이다. 장전 시간외 종가매매는 **전일종가** 고정가
거래이므로 그 가격에 사겠다는 대기가 없는 것은 있을 수 있는 상태이지만, 세 종목이
전부 0 인 것은 "FID 135 를 이 구간에 벤더가 안 채운다" 와 구별되지 않는다.
**미해결 — §5 참조.**

### 1.2 같은 구간 `0D` 사다리는 0 건이다

| 종목 | `0D` 스냅샷 | venue 분포 |
|---|---|---|
| 069500 (KRX-only) | **0 건** | — |
| 006360 (KRX-only) | **0 건** | — |
| 005930 (NXT 상장) | 360 건(캡 포화) | **`NXT`·`UN` 만** — KRX 프레임 0 건 |

NXT 상장 종목조차 **KRX venue 0D 는 하나도 없다**. 360 건은 NXT 프리마켓
(08:00–08:50 접속매매)의 호가다. 즉 거래소 선택이 `KRX` 인 사용자는 종목 종류와
무관하게 장전 내내 빈 화면을 본다.

`last_ob` 서버 폴백도 **KRX·NXT·UN 세 venue 전부 `null`** 이었다(069500).

### 1.3 체결은 일어나는데 호가 축만 죽어 있다

006360 은 **08:33:19 에 체결 3 건**이 있었다(venue=KRX). 2026-08-14 문서가 장후에서
관측한 "0B 는 재개되는데 0D 는 죽어 있다" 와 정확히 같은 형태다.

### 1.4 부수 확인

- `expected`(0H 예상체결)는 이 구간 **0 건**이다(세 종목 모두).
- WS 연결 창은 `08:00–20:00`(`session_gate.ws_connection_window`)이라 구독은 살아
  있다. `0E`·`0B` 수신이 그 증거다 — **0D 부재는 구독 결손이 아니라 벤더 침묵이다.**
- 2026-08-14 문서가 남긴 미해결("0E 가 오는데 0D 가 안 오면 벤더가 0D 를 그 구간에
  안 준다가 확정된다")의 **판별 조건이 아침 구간에서 충족됐다.**

## 2. 시장 구조 — 아침의 세 구간

| 구간 | 제도 | 가격 | 호가 사다리 |
|---|---|---|---|
| 08:30–08:40 | **장전 시간외 종가매매** | 전일종가 단일가 | **없음** — 제도상 |
| 08:30–09:00 | 장 시작 동시호가(시가 단일가) | 호가 접수 | 10단이 존재해야 하는 구간 |
| 09:00–15:30 | 정규장 접속매매 | — | 10단 (`0D`) |

08:30–08:40 은 **두 제도가 겹치는** 구간이다. `0E` 가 커버하는 것은 첫째 줄이고,
둘째 줄(장 시작 동시호가)의 10단은 별개 축이다 — §5 미해결.

## 3. 왜 화면이 비는가 — 코드 경로

```
live.afterHours (0E, KRX 태그)  ──→ latestAfterHoursTotals()  → { ask: 22367, bid: 0 }   ✅ 정상
live.ob         (0D, KRX 태그)  ──→ latestOrderbookSnapshot()  → null                     (0D 0건)
                                        │
                     resolveOrderbookCardSnapshot({ inactiveSnapshot: null })  → null
                                        │
                     singlePriceSnapshot (ka10087, 16:00–18:00 전용) → null
                                        │
                            snapshot = null
                                        │
        BookPanel.tsx:129  if (snapshot === null) return <PanelState>호가 데이터 없음</PanelState>
                                        │
                            ✂ 여기서 끊긴다 — TotalQtyStrip 에 도달하지 못한다
```

`TotalQtyStrip` 은 시그니처가 `snapshot: OrderbookSnapshot`(**non-null**)이고, 시간외
총잔량을 `afterHoursTotals?.ask ?? snapshot.tot_ask` 로 **덧씌우는** 방식이다. 즉
시간외 총잔량 표시가 사다리 스냅샷 존재에 **구조적으로 종속**돼 있다.

### 왜 장후에는 이 설계가 작동했는가

15:40–16:00 에는 **그날 15:30 까지 쌓인 `0D` 사다리가 버퍼·래치에 남아 있다.**
그래서 `snapshot !== null` 이고, 스트립이 렌더되며, 주석대로 "사다리는 15:30 값 그대로
두고 스트립만 살아 움직인다" 가 성립한다.

**그 전제는 시간 방향에 의존한다.** 아침에는 그날의 선행 사다리가 원리적으로 존재할
수 없다(어제 값을 오늘 아침 화면에 남기는 것은 폴백으로도 옳지 않다). 폴백 세 겹
— 버퍼 / `bufferFallbackSnapshot` / 서버 `last_ob` — 이 **전부 `0D` 파생**이라
아침에는 셋이 동시에 비고, 그 순간 시간외 총잔량도 같이 사라진다.

## 4. 그래서 이것은 데이터 결손이 아니라 표시 설계 결손이다

- 백엔드 수정 필요 없음 — 파서·게이트·버퍼·라우트 전부 정상.
- 프론트 어댑터 수정 필요 없음 — `latestAfterHoursTotals` 가 값을 정확히 뽑는다.
- **필요한 것은 `snapshot === null` 이어도 시간외 총잔량을 렌더할 경로 하나다.**

## 5. 미해결 (다음 거래일 08:30 이전에는 재측정 불가)

1. **장 시작 동시호가(08:30–09:00)의 10단 사다리** — 벤더가 이 구간에 `0D` 를 아예
   안 주는지, 09:00 정각부터 주는지. 판별식은 **오늘 첫 KRX `0D` 프레임의 시각**이다.
   (§6 에 관측 결과 기록)
2. **매수총잔량(FID 135)이 이 구간에 항상 0 인가** — 세 종목 전부 0 이었다. 판별하려면
   장후 15:40–16:00 의 같은 필드가 non-zero 로 오는지 대조해야 한다. 장전 매수 대기가
   실제로 없는 것과 벤더가 안 채우는 것은 값만 봐서는 구별되지 않는다.
3. `0E` 가 정규장(09:00–15:30)에도 0 아닌 값으로 오는지 — `_parse_after_hours` docstring
   이 남긴 숙제. 오늘 09:00 이후 관측으로 일부 답할 수 있다.

## 6. 08:50 경계 — KRX `0D` 는 09:00 이 아니라 **08:50 에 시작한다**

| 종목 | KRX `0D` 첫 검출 | 그때 예상체결가 | `0H` |
|---|---|---|---|
| 069500 | **08:50:03**(6건) | 105,000 | 1건 |
| 006360 | **08:50:00**(2건) | 32,950 | 1건 |
| 005930 | **08:50:03**(14건) | 250,000 | 18건 |

08:49:5x 폴링까지 0 건이었다가 08:50 폴링에서 한꺼번에 나타났다. 예상체결가가 **함께**
등장하므로 이것은 장 시작 동시호가(시가 단일가)의 호가 접수 신호다.

**08:50 은 NXT 프리마켓 종료 시각과 정확히 일치한다.** `session_gate` 의 NXT 창 주석
("08:50–09:00:30 은 KRX 단일가 동안 NXT 가 거래정지")과 정합한다. 즉 아침의 실제
구조는 이렇다:

| 구간 | KRX | NXT |
|---|---|---|
| 08:00–08:30 | 침묵 | 프리마켓 접속매매(`0D` 흐름) |
| 08:30–08:40 | **`0E` 총잔량만**(장전 시간외 종가매매) | 프리마켓 계속 |
| 08:40–08:50 | 침묵 | 프리마켓 계속 |
| 08:50–09:00 | **`0D` 10단 + 예상체결**(시가 단일가) | 거래정지 |

⚠ 시분할 구독은 **폐지됐다**(ADR-0140 §2 — 세 venue 동시 구독). 따라서 08:50 경계는
우리 구독 스케줄이 아니라 벤더·제도 쪽이다. 다만 `session_gate._PREOPEN_AUCTION_MIN`
은 `[08:30, 09:00)` 으로 잡혀 있어 실측(08:50 시작)보다 20분 넓다 — 예상체결 게이트는
`값>0` 을 AND 로 걸므로 **오늘 기준 무해**하지만, 창의 근거가 실측과 다르다는 것은
기록해 둔다.

## 7. 살아 있는 사다리 위에 멎은 `0E` 가 덮인다 (별개 결함, 같은 날 발견)

08:53 실측(005930, 통합):

| | 값 | 프레임 시각 |
|---|---|---|
| 사다리(`0D`) 총잔량 | 13,938 | **08:53:59**(실시간) |
| 스트립이 그리던 값(`0E`) | 23,870 / 0 + "시간외" 라벨 | **08:40:00**(멎음) |

`latestAfterHoursTotals` 에 시계 게이트가 없었던 것은 의도였지만(장후엔 `0E` 가 유일
신호라 창을 좁히면 진짜 신호가 죽는다), 그 설계는 **"사다리는 멈춰 있다"** 를 암묵
전제로 깔고 있었다. NXT 프리마켓처럼 **사다리가 살아 있는** 구간에서는 전제가 깨지고
두 시장의 값이 한 패널에 섞인다.

`0E` 는 `KRX` 뿐 아니라 **`UN` 태그로도 온다** — `_parse_after_hours` docstring 이
"`_NX`/`_AL` 구독 코드에 0E 가 실제로 오는지는 **미실측**" 이라 적어 둔 항목이 이
관측으로 풀렸다(`_AL`=UN 은 **온다**, `_NX` 는 여전히 미관측). 그래서 venue 필터가
이 혼입을 걸러 주지 못한다.

**해결**: 덧씌우기 판정을 **프레임 t_ms** 로 한다 — `0E` 가 사다리보다 1분 이상 앞설
때만 이긴다. 벽시계 게이트를 쓰지 않는 이유는 그것이 창을 잘못 좁혀 진짜 신호를
죽이는 쪽으로 실패하기 때문이다. 여유(1분)는 정밀도가 아니라 **안정성**을 산다:
두 스트림이 둘 다 살아 있는 프리마켓에서 라벨이 깜빡이는 것을 막는다.
