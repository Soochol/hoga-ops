# 지투지바이오 주말 마지막 호가 REST 실조회

2026-10-24 토요일 10:15 KST, 사용자 요청으로 지투지바이오(`456160`)를 조회했다.
실행 중인 서비스의 유효한 디스크 토큰을 메모리에서만 재사용했다. 새 토큰 발급·갱신,
WS 연결, 주문, 서버 재시작은 하지 않았고 토큰 파일의 내용이 그대로임을 확인했다.
개발 서버에 실자격증명을 설정하지 않았다.

`POST /api/dostk/mrkcond`, `api-id: ka10004`, 본문 `stk_cd`에 KRX는 `456160`,
NXT는 `456160_NX`, 통합은 `456160_AL`을 보냈다. 세 요청 모두 HTTP 200,
`return_code=0`이며 매도·매수 10단 가격과 잔량을 반환했다.

| 시장 | 매도 1호가 / 잔량 | 매수 1호가 / 잔량 | 총 매도 / 매수 잔량 |
|---|---:|---:|---:|
| KRX | 49,600원 / 43주 | 49,500원 / 1주 | 2,033 / 1,759주 |
| NXT | 49,550원 / 325주 | 49,500원 / 3주 | 1,560 / 1,690주 |
| 통합 | 49,550원 / 325주 | 49,500원 / 4주 | 2,978 / 3,449주 |

`bid_req_base_tm`은 모두 `200000`이다. **이 응답에는 거래일이 없다.**
조회일이나 가장 최근 달력 거래일을 조합해 실제 호가 발생 epoch를 만들지 않는다.
응답의 시각은 `20:00:00`, 거래일은 미제공으로 표시한다. KRX 결과도 정규장 마감
호가라고 부르지 않는다. 이번 실측은 이 종목·이 시각의 제공 여부를 입증하며,
모든 종목·주말의 제공이나 데이터가 확정 종가 시점이라는 보장은 아니다.

인증정보 없이 보존한 세 응답은
[실응답 픽스처](../../tests/fixtures/kiwoom_rest/orderbook_weekend_456160.json)에 있다.

## 적용

- `/api/live/last-orderbook`은 기존 REST 거버너·계정 풀을 통과한다. 같은 종목/시장은
  진행 중 조회와 60초 결과 캐시를 공유한다. 실패·저장 실패는 수동 재시도를 허용한다.
- 유효한 가격이 있는 사다리만 `last_rest_orderbook/{Code}-{venue}.json`에 원자 저장한다.
  빈 응답·초기화·조회 실패는 마지막 정상 사다리를 덮지 않고, 재시작 후에도 복원한다.
  조회 실패와 저장 실패는 응답에서 각각 보존한다.
- 호가주문창은 표시 가능한 기존 호가가 없을 때만 이 REST 경로를 사용한다. 기존
  WS 호가가 도착하면 즉시 우선하며 REST 사다리는 실시간 이력이나 주문 신선도에
  넣지 않는다. 출처·시장·호가 시각·거래일 미제공을 표시하고 신규 주문은 차단한다.
- 호가가 없으면 상세정보를 본문에 계속 표시한다. 넓은 창은 옆에, 좁은 창은 아래에
  놓는다. 공급자가 주지 않은 상세 필드는 대시를 유지한다.
- ADR-0167의 기존 LATEST 만료는 유지한다. 만료된 WS 값을 실시간으로 재승격하지
  않고, 날짜 없는 REST/저장 사다리를 명시적 열람 전용으로 허용하는 예외다.
