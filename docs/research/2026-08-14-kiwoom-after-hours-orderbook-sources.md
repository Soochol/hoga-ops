# 시간외 호가 소스 조사 — KRX-only 종목의 15:30 이후 (2026-08-14)

/ live 10호가 창에서 **NXT 미상장(KRX-only) 종목만** 15:30 에 호가가 얼어붙는 증상에서
출발했다. NXT 상장 종목은 같은 시각 NXT·UN venue 로 호가가 계속 흐르므로 그 비대칭이
"우리가 뭔가 안 받고 있다" 처럼 보인다.

결론부터: **10단 사다리는 시간외에 원리적으로 불가능하다.** 벤더가 주지 않고, 시장
구조상 존재하지도 않는 구간이 있다. 받을 수 있는 것은 (a) WS 총잔량 2개, (b) REST
시간외 단일가 **5단** 호가다.

## 1. 실측 — 무엇이 언제 끊기는가

사용자 dev 서버(:8000)의 **표시 링 버퍼**(`/api/live/series`)를 GET 으로 세 번 떴다.
디스크가 아니라 링 버퍼를 본 이유: 저장 게이트가 KRX 를 15:30 에 닫으므로
(`session_gate.venue_capture_windows`) **디스크에 없다는 것은 벤더 침묵의 증거가 아니다**.
표시 경로는 무게이트라(`stream.on_tick`, "표시 경로는 §11에 따라 무게이트") 벤더가 보내면
링 버퍼에는 남는다.

| 종목 | 호가 0D 마지막 | 체결 0B 구간 |
|---|---|---|
| 006360 GS건설 (KRX-only) | **15:30:25** | 15:40:00 ~ **15:59:38** |
| 069500 KODEX200 (KRX-only) | **15:30:22** | 15:40:00 ~ **15:59:58** |
| 005930 삼성전자 (NXT 상장) | NXT·UN 계속 | NXT·UN 계속 |

세 시점(15:51 · 16:00 · 16:12)에서 위 경계가 움직이지 않았다. 읽히는 사실:

- **0D 는 15:30 에 끊긴다.** 15:40~16:00 시간외 종가매매 중에도 호가 축은 죽어 있다.
- **0B 는 15:40:00 에 정확히 재개**되고 전량이 당일 종가 단일가로 체결된다
  (GS건설 35,350 원 고정). 시간외 종가매매의 정의 그대로다.
- **16:00 이후에는 0B 도 끊긴다.** 즉 현재 구독(`0B`/`0D`/`0F`/`0w`)으로는 시간외
  단일가 구간(16:00~18:00)에 **신호가 0개**다.
- NXT 상장 종목이 15:30 이후에도 멀쩡한 것은 그 시장의 애프터마켓이 20:00 까지
  접속매매를 하기 때문이고, KRX-only 종목에는 해당 사항이 없다.

### 네 번째 프로브(16:37)와 **표시 링의 관측 한계**

16:37:57 에 다시 뜨니 KRX-only 두 종목은 OB·TRADE **양쪽 다 0건**이 됐다. 이건 새로운
침묵이 아니라 **버퍼가 비워진 것**이다 — 표시 링은 시간 기반 eviction 이고 보존창이
15분이다(`buffer.DEFAULT_RETENTION_MS = 900_000`). 마지막 KRX 틱(15:59:58)이 37분 전이라
창 밖으로 밀려났다.

**그래서 이 방법에는 관측 한계가 있다: 표시 링 GET 은 "지금부터 15분 전까지" 만
답한다.** 16:37 관측이 실제로 말하는 것은 "16:22~16:37 사이에 아무것도 오지 않았다"
이고, 그 창에는 16:30 단일가 체결 주기가 포함된다. 같은 시각 삼성전자(NXT)는 OB·TRADE
모두 정상 수신 중이었으므로 **서버·버퍼·구독이 살아 있다는 대조군이 성립**한다.

⚠ 그럼에도 16:00 이후 침묵이 **벤더 침묵인지 그날 그 종목의 체결 부재인지**는
여전히 못 가른다. 호가(0D)는 체결과 무관하게 접수만 있어도 흘러야 하므로 침묵 쪽
근거가 더 강하지만, 확정하려면 0E 를 구독한 상태에서 같은 창을 관측해야 한다 —
0E 가 오는데 0D 가 안 오면 "벤더가 0D 를 그 구간에 안 준다" 가 확정된다.

## 2. 시장 구조 — 세 구간은 서로 다른 제도다

| 구간 | 제도 | 호가 사다리 |
|---|---|---|
| 09:00–15:30 | 정규장 접속매매 | 10단 (0D) |
| 15:40–16:00 | 장후 시간외 **종가**매매 | **없음** — 당일 종가 단일 가격에 시간우선 체결 |
| 16:00–18:00 | 시간외 **단일가**매매 | 5단 (REST 전용, 아래) |

15:40~16:00 에 사다리가 없는 것은 벤더의 누락이 아니라 **제도가 그렇다.** 가격이
하나로 고정돼 있으니 단계가 성립하지 않는다. 그 구간에서 의미 있는 호가 정보는
"얼마나 쌓여 있는가"(총잔량)뿐이다.

가격이 움직이는 것은 16:00~18:00 시간외 단일가 쪽이고, 여기엔 실제 호가가 접수된다.

## 3. 벤더가 주는 것 — 소스 3종

키움 공식 문서(`Kiwoom-Securities/Kiwoom-REST-API` → `kiwoom_docs/실시간시세.md` ·
`시세.md`) 기준.

### 3.1 WS `0E` 주식시간외호가 — 총잔량 2개

```
21   호가시간 HHMMSS
131  시간외매도호가총잔량      132  직전대비
135  시간외매수호가총잔량      136  직전대비
```

**이게 전부다.** 0D 의 41~50(매도호가 1~10)·61~70(잔량) 에 해당하는 단계별 FID 가
존재하지 않는다. 실시간 타입 18종 중 시간외 관련은 이 하나뿐이다.

### 3.2 REST `ka10087` 시간외단일가요청 — **5단** 호가

요청은 `stk_cd` 하나(**max 6자 — venue 접미가 없다**. 시간외 단일가가 KRX 전용
제도라는 wire 레벨 증거다).

```
ovt_sigpric_sel_bid_[1-5]       시간외 단일가 매도호가
ovt_sigpric_sel_bid_qty_[1-5]   수량
ovt_sigpric_sel_bid_jub_pre_[1-5]
ovt_sigpric_buy_bid_[1-5]       매수호가 (동일 3종)
bid_req_base_tm                 호가시각
ovt_sigpric_cur_prc / _pred_pre / _flu_rt / _acc_trde_qty
```

**시간외 단일가 구간을 채울 수 있는 유일한 소스**이고, 상한이 **5단**이다.

### 3.3 REST `ka10004` 주식호가요청 — 10단 + 시간외 총잔량

정규장 10단 전체(`sel_1th`~`sel_10th`·`buy_*`, 가격·잔량·직전대비)에 더해
`ovt_sel_req`/`ovt_buy_req`(+`_pre`) 로 **시간외 총잔량**을 함께 준다.
`stk_cd` 는 venue 접미를 받는다(`039490` / `039490_NX` / `039490_AL`).

시간외에 10단 필드가 채워지는지는 **미실측**(§6).

## 4. 그래서 10호가 창에 무엇을 띄울 수 있나

| 구간 | 사다리 | 총잔량 | 체결 |
|---|---|---|---|
| 15:40–16:00 | ❌ 제도상 없음 | ✅ WS `0E` | ✅ 이미 수신 중(0B) |
| 16:00–18:00 | ⚠ **5단**, REST `ka10087` 뿐 | ✅ WS `0E` | ❌ 현재 수신 0 |

즉 "10호가 창을 시간외에도 10단으로" 는 **달성 불가능한 목표**다. 최대치는
16:00~18:00 에 위 5행/아래 5행이 차는 것이고, 15:40~16:00 은 총잔량 두 개가 전부다.

## 5. 구현 선택지

### 5.1 총잔량만 (구현 완료 — 이 브랜치)

`0E` 를 `DEFAULT_TYPES` 에 추가. 슬롯 비용 0(키움 한도는 종목 단위, 타입 무관).
표시 전용으로 나르고 저장은 하지 않는다(0w PROGRAM 과 같은 부류). BookPanel 하단
총잔량 스트립이 시간외 값으로 갱신되며 "시간외" 라벨이 붙는다 — 위 사다리는 15:30
정규장 마지막 값 그대로라 **"사다리 합 ≠ 총잔량" 이 정상**이고, 라벨이 그 불일치를
설명하는 유일한 장치다.

### 5.2 시간외 단일가 5단 (구현 완료 — 이 브랜치)

`ka10087` REST 온디맨드. WS 로는 불가능하다.

- **골격은 ka10001(`kiwoom_stock_info`) 미러다** — 동기 httpx + `to_thread`,
  single-flight, 실패 무캐시. 다른 점은 캐시 축뿐: 저쪽은 KST 날짜(고정값),
  이쪽은 **3초 TTL**(변동값).
- **게이트는 fetcher 가 아니라 라우트가 든다.** `session_gate.
  is_after_hours_single_price_window`(16:00–18:00, 주말만 배제) — 창 밖이면
  **벤더를 아예 치지 않고** 200 + `active:false` 를 준다. 프론트 폴링 실수 하나가
  장중 유량을 태우는 것을 막는 방어선이 백엔드에 있어야 한다.
  거래일 판정은 얹지 않았다(캘린더 = 동기 KIS HTTP 재도입, `_quote_phase` 선례).
- **대상**: 화면에 떠 있는 종목만 — 프론트 훅이 선택 종목 하나를 5초 주기로 폴링하고,
  스팟 커서 중에는 아예 끈다. 백엔드 TTL 이 동시 요청을 접으므로 창 하나가 곧
  벤더 콜 하나가 되지도 않는다. (유량은 애초에 제약이 아니다: 종목당 1콜,
  `(앱키,TR)` 5 req/s × 5계정 = 25 req/s → 291종목 전량도 ~12초.)
- **표시**: **10단 격자 유지, 중앙 쪽 5행만 채움**(사용자 결정 2026-08-14).
  5단짜리 스냅샷을 10칸으로 zero-pad 하면 BookPanel 격자 로직을 손대지 않고
  그 동작이 나온다 — 바깥 5행은 정규장에서 짧은 book 이 오는 경로와 같게 빈다.
  "시간외 단일가" 라벨이 그 빈 행을 설명한다(결손이 아니라 **없는 단계**).
- **`active` 가 판별 필드**다. 창 밖이거나 전 단계가 0(그 종목에 시간외 주문 없음)이면
  `false` 이고, 소비자는 **정규장 스냅샷을 유지**한다 — 빈 호가창으로 갈아끼우면
  화면이 오히려 나빠진다. 그 판정을 프론트가 다시 하지 않도록 백엔드가 접는다.
- **총잔량은 `ovt_sigpric_*` 쌍**을 읽는다(§3.2 의 세 쌍 함정). 테스트가 나머지 두
  쌍의 값을 fixture 에 넣어 두고 "그걸 집으면 실패" 를 고정한다 — red-check 으로
  확인했다(정규장 쌍으로 바꾸니 그 테스트만 빨개짐).

## 6. 미실측 — 다음에 확인할 것

1. **`ka10087` 이 실제로 값을 주는가.** 2026-08-14 16:20 시점에 디스크 토큰 캐시가
   전부 만료(최신 8/5)라 REST 를 칠 수 없었다. 새 토큰을 발급하면 사용자 dev 서버의
   토큰이 죽으므로(#1088) 실측을 포기했다. **거래일 16:00–18:00 에 dev 서버를 통해
   확인할 것.**
2. **`ka10004` 가 시간외에 10단을 채우는가.** 채운다면 §4 의 결론이 바뀐다.
3. **`0E` 가 정규장에도 흐르는가.** 흐른다면 값 게이트만으로 부족하고 시계 창이
   필요하다(예상체결 FID 23/24 가 NXT 에서 겪은 함정과 동형).
4. **`0E` 가 `_NX`/`_AL` 구독 코드에도 오는가.** 파서는 접미로 venue 를 태그하지만
   수신 자체가 미확인이다.
5. **WS `0H`(주식예상체결)가 16:00–18:00 단일가 사이클에 예상체결가를 흘리는가.**
   보조 후보일 뿐 사다리는 어차피 REST 뿐이라 결론은 바뀌지 않는다.
6. **`0E` 기능 자체의 실검증.** dev 서버는 main 코드라 `0E` 를 구독하지 않고,
   워크트리에서 자격증명 백엔드를 띄우는 것은 금지다(ADR-0134). 살아 있는 0E 프레임
   확인은 거래일 15:40~18:00 에 이 브랜치로 dev 서버를 재시작하거나 머지 후 다음
   세션 관측으로만 가능하다.
