# 키움 순위 TR 4종 스펙 실측 — ka10027 / ka10023 / ka10030 / ka10032

**작성:** 2026-07-22 · **티켓:** #819 (지도 #818) · **성격:** research (AFK)

## 2026-10-14 연속조회 실측 및 구현 갱신

기존의 "1차 미사용"은 초기 구현 당시의 결정이다. 현재는 우측 순위 패널에서
100위씩 더 펼치며, 매 갱신마다 처음부터 펼친 범위를 다시 조회한다.

실계정 REST, 전체 시장(`mrkt_tp=000`), KRX(`stex_tp=1`), 현재 구현의 요청 body로 확인했다.
`scripts/probe_kiwoom_rest_tr.py`를 사용하고 요청 간격은 1.5초로 두었다.

| 탭 | TR | 첫 페이지 | 다음 페이지 | 다음 조회 가능 |
|---|---|---:|---:|---|
| 거래대금 | ka10032 | 100 | 100 (101~200위), 세 번째 100 (201~300위) | 세 번째도 Y + 키 있음 |
| 등락률 상승 | ka10027 | 200 | 200 | 두 번째도 Y + 키 있음 |
| 등락률 하락 | ka10027 | 200 | 200 | 두 번째도 Y + 키 있음 |
| 거래량 급증 | ka10023 | 200 | 200 | 두 번째도 Y + 키 있음 |
| 거래량 | ka10030 | 100 | 100 | 두 번째도 Y + 키 있음 |
| 프로그램 순매수 (코스피) | ka90003 | 15 | 15씩 5페이지, 75위까지 확인 | 다섯 번째도 Y + 키 있음 |
| 기관 순매수 | ka10065 / orgn_tp=9999 | 100 | 없음 | N, 키 없음 |
| 외국인 순매수 | ka10065 / orgn_tp=9000 | 100 | 없음 | N, 키 없음 |

등락률·급증은 두 페이지 사이 1~2개 종목이 중복됐다. 장중 순위는 고정 스냅샷이
아니므로 파싱 후 종목코드로 중복을 제거한다. 조회 범위(`queried_count`)는 ETF 제외와
중복 제거 전이며, 화면에 표시하는 개수와 구분한다. 마지막 응답에 연속조회가 없더라도
200행 중 요청 범위 밖 행이 남으면 `has_more=true`를 반환한다.

`limit` 기본값은 일반 순위 100, 프로그램 50, 최대값은 5,000이다.
일반 순위는 최대 100페이지, 프로그램은 페이지당 15행이므로 최대 400페이지로 제한한다.
각 페이지는 공용 REST 거버너를 거쳐 호출한다. 누락·반복 커서와 페이지 한도 초과는
완료로 가장하지 않고 오류로 반환하며, 실패한 부분 결과는 캐시에 넣지 않는다.
프로그램은 기본 50위에서 100위씩 더 펼치며, 전체 시장은 시장별 요청 범위를
순매수 금액으로 병합한 상위 범위를 반환한다. 양수 순매수가 끝나면 커서가 이어져도
조회 종료로 처리한다. 프로그램의 queried_count는 이 병합 후, ETF 제외 전 순위 범위다.
기관·외국인은 실응답에 추가 조회가 없어 기존 상위 100을 유지한다.

키움의 [공식 거래대금 예제](https://github.com/Kiwoom-Securities/Kiwoom-REST-API/blob/main/examples/국내주식/순위정보/get_domestic_trading_value_top.py)도 `cont-yn`과 `next-key`를 통한 연속조회를 사용한다.

## 백엔드 정규화 규약 (#820 입력)

- **숫자는 부호 접두 문자열로 온다**: `flu_rt`, `pred_pre`, `cur_prc` 등이 `"+29.97"`, `"-18.32"`,
  `"--500"`(하한 특수), 콤마 포함(`"71,200"`) 형태. .NET 래퍼 `KiwoomNormalizerConverter`가
  `--`/`+`/`-` 접두와 콤마를 벗겨 파싱한다. 백엔드 `parse_*`도 동일 처리 필요:
  선행 `+`/`-`/`--` 부호 정규화 + 콤마 제거 후 `float`/`int` 변환. (기존 `kiwoom_frames` 파싱 관례 참고)
- **행 축약**: 프론트는 `stk_cd`/`stk_nm`/`cur_prc`/`flu_rt` 4개만 쓴다(기준값 열 제거, 그릴링 결정).
  백엔드 응답 모델 `RankingRow`는 이 4개 + (선택) `rank`로 축약해 페이로드를 줄인다.
- **kind → (api-id, sort_tp, 래퍼키) 매핑**:

  | kind | api-id | 정렬 파라미터 | 응답 래퍼 키 |
  |---|---|---|---|
  | `change` | ka10027 | `sort_tp`=1(상승)/3(하락) | `pred_pre_flu_rt_upper` |
  | `surge` | ka10023 | `sort_tp`=2(급증률) | `trde_qty_sdnin` |
  | `volume` | ka10030 | `sort_tp`=1(거래량) | `tdy_trde_qty_upper` |
  | `value` | ka10032 | (없음) | `trde_prica_upper` |

## 검증 필요 항목 (#820에서 실콜로 확정)

1. **`mrkt_tp` 문자열 포맷** — `"000"/"001"/"101"`(zero-pad) vs `"0"/"1"/"101"`. 공식 문서는 zero-pad,
   .NET enum은 정수. → **zero-pad로 보내고 실응답 확인.**
2. **응답 숫자 표기** — `flu_rt`가 `"+29.97"`인지 `"29.97"`인지, `cur_prc` 콤마 유무. → 파서 방어적으로.
3. **장외 응답** — 마감/휴장일 호출 시 직전 거래일 순위를 주는지(그릴링 결정 9의 "열 때 1회 조회" 전제).
   → 거래일 캘린더 게이트(KIS chk-holiday)로 폴링은 막되, 1회 조회 응답은 이 동작에 의존.
4. **응답 행 수** — 1회 응답 종목 수(≈100 추정). 스크롤 리스트 높이 설계 입력.

## WebSocket 대안 없음 (재확인)

키움 WS 실시간 19종에 시장 전체 순위 푸시 타입은 없다. 순위 4종은 REST 폴링이 유일 경로
(그릴링 질문 "ws는 없지?" 확정). 조건검색 실시간(ka10173)은 정렬 리스트가 아니라 편입/이탈
이벤트라 성격이 다르며 이번 범위 밖.
