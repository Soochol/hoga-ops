# 지표 성능 개선 후속 범위 판단

> 아래는 최초 조사 시점의 판단이다. 이후 사용자 승인으로 [실행 계획](../plans/2026-09-07-indicator-followups.md)을 수립해 공통 집계·정확한 cutoff 인덱스(PR #1757), 히트맵 1분 캐시 파생을 구현했다. 선택 소스 응답은 [측정과 판단](2026-09-07-depth-reaggregate-performance.md)에 따라 기존 세 소스를 유지한다.

2026-09-07 조사와 구현의 마무리 판단이다. 최초 조사의 숫자는 개선 전 스냅샷이며 현재 성능을 뜻하지 않는다. 최대벽/총잔량 이후 히트맵 표시 범위, 프로그램 순매수, 일반·일봉 MA, POC 폴백 및 작은 서버 중복 계산을 순서대로 개선했다. 거래량·호가비·외국인·기관·거래원은 기존 증분/캐시가 이미 있어 추가 변경 우선순위를 낮게 유지한다.

## 큰 설계 후보는 이번 구현에서 제외

### 커서 컷오프 매물대 prefix

`useVolumeDistributionCutoffProfile.ts`는 화면 요청을 봉 경계로 맞추지만, `build_volume_distribution_slice`의 공개 계약은 임의 Unix millisecond까지 포함한다(`+1` 후 exclusive upper bound). 매 분 누적량만 저장하면 그 분의 00.000초 체결 포함 여부부터 기존 결과와 달라진다. 정확한 구현에는 누적 완료 분과 현재 분의 세부 체결/시각 인덱스가 함께 필요하다. 동시호가/마감 경계와 last_trade_ms도 보존해야 한다.

현재 완료일의 일반 분포는 디스크 캐시가 있으며 cutoff 비용은 원시 세 샘플에서 약 2.5~49.6ms였다. prefix 캐시의 추가 부담은 분×가격 bin 수×가격범위/소스/종목/날짜 키 수에 비례한다. 예컨대 390분×100 bin×8바이트만으로 한 격자에 312,000바이트이며 시각·부분 분 인덱스·객체 overhead는 별도다(실측 메모리가 아닌 최소 수량 배열 산식). 실제 스크럽 빈도·동시 종목 수·캐시 회수 정책을 아직 측정하지 않았으므로 순이익이 입증된 개선으로 취급하지 않는다. 먼저 반복 스크럽 workload와 메모리 상한을 정하고 exact cutoff 동등성을 측정해야 한다.

### 분포와 POC의 공통 집계

일반 분포는 희소 `(bin_idx, qty)`와 전체 마지막 시각, POC는 clamp한 bin의 최초 시각·낮은 bin 우선 동률 규칙을 사용한다. 분포의 최상단 가격은 일단 bins 인덱스로 나갔다가 확장 단계에서 마지막 bin에 합쳐지는 반면 POC는 SQL에서 미리 clamp한다. 현재 분포 wire를 POC로 바로 전환하면 필요한 최초 시각이 없고 경계 합산도 달라질 수 있다.

공통 내부 집계에 최초·마지막 시각과 정본 bin 경계를 정의하면 원시 동시 조회를 줄일 여지는 있다. 다만 두 결과가 각자 완료일 캐시를 사용하므로 이득은 주로 양쪽 캐시가 모두 없는 첫 조회/백필이다. 원시 합산 비용 수치만으로 실제 전체 조회 이득을 보장할 수 없다. 공통 cache key/version·무효화와 두 소비자의 경계 동등성을 먼저 설계하는 후속 항목으로 남긴다.

### 히트맵 선택 소스 응답과 1분 캐시 파생

현재 세 소스(close/최대 총잔량 순간/가격별 최대)를 함께 유지해 사용자 토글이 즉시 바뀐다. 선택 소스 응답은 작은 API 추가만으로 끝나지 않고 토글 재조회·프리패치·레전드·캐시 키까지 영향을 준다. 실제 소스 전환 빈도와 네트워크 병목 측정 없이 기존 기능을 바꾸지 않는다.

1분→coarse의 가격별 max와 마지막 대표 행은 결합할 수 있고, 최대 총잔량도 20레벨 합으로 복원할 수 있다. 그러나 SQL `arg_max(rep, total)`은 total 동률 때 정본 대표 행을 명시하지 않는다. 1분 대표의 재집계와 직접 coarse 집계가 같은 행을 보장하려면 동률 규칙과 캐시 버전 변경이 필요하다. 따라서 이번에는 해당 계산식을 건드리지 않고, 결과 동등성이 입증된 존재 조회 개선만 적용했다.

위 항목은 미구현이며 완료된 것으로 계산하지 않는다. 이 문서는 추가 최적화의 부재가 아니라, 다음 구현이 먼저 충족해야 할 정확성·비용 조건을 기록한다.
