# 프로젝트 공탐지수 통합 페이지

프로젝트 상단 메뉴 **공탐지수**, 경로 `/breadth`. 독립 HTML 미리보기가 아닌 앱의
지연 로딩 React 라우트이며 기존 테마·우측 레일·고정 앱 셸을 사용한다.
기본 그래프 아래 네 영역을 세로로 표시하고 섹션 이동/기본 그래프 복귀 링크를 제공한다.

- 추이와 확산: 기존 42개 ETF의 5/20일 개선 수 추이를 유지하고, 477개 고유 종목의
  이평선 상회 개수(0–3) 증가·감소·동일과 시계열을 추가했다. ETF 확산과 종목 확산은 구분한다.
- ETF 비교: 현재 계산 가능한 42개(패시브 38·액티브 4), 전체 선택/해제와 선택 저장.
  3개 이하는 겹치고 4개 이상은 개별 그래프. 연속 개선·최근 5일 개선 횟수·5/20일 변화.
- 시장 스트레스: 대표 시장 ETF 두 개의 252일 고점 대비 하락률/20일 실현 변동성.
- 변화의 원인: 5/20거래일 종목별 기여, 이평선별 진입/이탈/기여, 검색·방향 필터.

## 고정 자료와 제한

종가 **2026-10-29**, 수정 기준일 및 편입 구성 기준일 **2026-10-30**.
`frontend/public/market-breadth/snapshot.json`을 같은 출처에서 읽는다. 운영 API 자동
갱신·새 증권사 수집·운영 서버 배포는 포함하지 않았다. 화면에도 이를 표시한다.
새 REST 라우트는 없으며 파일의 생산자 계약은 `frontend/src/breadth/report.ts`에 있다.
스키마·정렬·기여도 합계 검증 실패 시 오류와 재시도를 표시하며 점수로 대체하지 않는다.

현재 42개 ETF의 편입 관계 836건은 중복 제거 시 정확히 기존 **477종목**이다.
액티브 81개 전체/총 119개 ETF 집합의 896종목과 혼동하지 않는다. 대기 61개와
상장 이력 부족 16개는 목록에 사유와 함께 표시하지만 계산에는 넣지 않는다.
전체 477종목의 유효 과거 구간은 당일 포함 24일, 비교 표본은 23일이다.
350종목 장기 고정 집합의 과거 위치는 별도 카드이며 원점수의 백분위로 사용하지 않는다.
현재 편입 구성의 소급 분석이므로 당시 편입 구성의 성과 백테스트는 아니다.

## 수식

`above = close × period > sum(last period confirmed closes)`를 유리수로 비교한다.
같은 가격은 비상회, 필요 거래일이 하나라도 없으면 계산 불가다.
한 종목의 개선/악화는 두 시점의 상회 개수 차이 부호로 결정한다.
서로 다른 이평선의 진입·이탈이 상쇄되면 ‘개수 동일’에 포함하고 별도 개수를 제공한다.

`stock contribution = (above_count_now − above_count_before) × 100 / (477 × 3)`.
종목별 합계/이평선별 합계는 전체 원점수 변화와 정확히 일치한다. 표시만 반올림한다.
5일: 개선 49·악화 61·동일 367, 점수 변화 −1.0482180293501049.
20일: 개선 52·악화 236·동일 189(상쇄 5), 점수 변화 −23.200559049615652.

연속 개선은 실제 거래일 원점수의 엄격한 연속 상승 횟수다. 보합은 연속을 끊고,
직전 쌍이 결측이면 판정 불가다. 상승 도중 관측 경계/결측을 만나면 ‘최소 N일’이다.
최근 5일 개선 횟수에는 연속된 6개 원점수가 필요하며 부족하면 판정 불가다.
ETF 원점수의 부동소수 오차는 기존 계산과 같은 `1e-7` 허용차로 보합을 처리한다.
지속성은 회복 확률/수익률/매수 신호가 아니다.

## 재현

저장소 루트에서 (네트워크 및 운영 데이터 쓰기 없음):

```sh
PYTHONPATH=. uv run python docs/research/2026-10-30-etf-insights-page/build_page.py
```

입력 지문과 출력 SHA256은 `validation.json`에 보존한다.
`hoga/market_breadth_insights.py`는 순수 계산 모듈이며 고정 일자/477 같은 범위를 강제하지
않는다. 빌더가 이번 연구의 집합과 기존 원점수·현재 477×3 판정 일치를 검사한다.

검증 명령과 코드/기준 SHA, 도구 버전, 검사 입력 지문은 `verification-record.json` 참조.
