# 프로젝트 ETF 탐색 페이지

상단 메뉴 **ETF 탐색**, 실제 앱 경로 `/etfs`. 승인한 미리보기를 React 라우트로 옮겼다.
기존 앱 셸·우측 레일·테마 토큰을 사용하고 라우트와 구성 자료를 지연 로딩한다.

## 조회와 비교

- 패시브 38개·액티브 81개, 총 119개 ETF와 고유 국내 주식 896개·편입 관계 4,937건.
- ETF 이름/코드·구성종목 검색, 운용 방식/운용사 필터, 페이지 이동.
- 입력이 종목명/코드와 정확히 같으면 해당 종목만 찾는다. `삼성전자`는 46개 ETF,
  `삼성전자우`는 별도 종목이다. 부분 이름 검색도 지원한다.
- ETF별 운용사/비교지수/원본 대조 상태, 상위 5개 집중 비중·상위 10개 비중 그래프,
  전체 구성종목 표·이평선 상태, 종목명/코드 검색 및 비중/이름/포함 ETF 수 정렬.
- 종목 역검색: 원래 공시 비중 내림차순으로 해당 종목을 담은 ETF를 펼치고,
  각 ETF 상세로 이동한다. 삼성전자는 46개 중 액티브 43개다.
- 2–4개 ETF를 비교에 담으면 최대 6개 조합별 중복 비중과 공통/각 ETF에만 있는 종목을 본다.
- ETF 선택·필터·비교 대상·조합·비교 범위는 버전이 있는 별도 localStorage 키에 보존한다.
  잘못된 코드/중복/범위 초과는 걸러내고 명시적 ‘비교 비우기’는 새로고침 후에도 유지한다.
- 로딩/빈 검색/자료 실패·재시도 상태를 제공하며 불량 자료를 점수 0으로 바꾸지 않는다.

## 수식과 자료 범위

공시 비중을 소수 둘째 자리까지 정확히 보존하도록 정수 basis point(1bp = 0.01%)로 저장한다.
상위 종목 합계·중복 계산은 정수이며 화면에서만 백분율로 표시한다.
`중복 비중 = Σ 공통 종목별 min(A의 공시 비중, B의 공시 비중)`.
예: SOL 코리아메가테크액티브 ↔ KODEX 반도체는 공통 3종목, **37.20%**.
직접 국내 주식의 합계가 100% 미만이어도 100%로 재정규화하지 않는다.
공시 비중이 0인 미세 편입도 종목 존재 자체는 유지한다. 미편입은 ‘—’로 구분한다.
다른 ETF·파생상품·기타 자산은 겹침 계산에서 제외한다. 별도 자산에는 원래 이름과
공시된 양/음 부호를 유지한다(MIDAS 코스피액티브에 −0.20%·−0.38% 파생상품 존재).

구성 **2026-10-30**, 검증 가격 **2026-10-29**의 고정 자료다. 전체 상장 ETF가 아닌
조사한 후보 집합이다. `frontend/public/etf-explorer/snapshot.json`을 같은 출처에서 읽으며,
자동 API 갱신·운영 수집·운영 서버 재시작은 포함하지 않는다. 화면에도 기준일과 갱신 상태를 표시한다.

공탐 원점수는 준비된 42개에만 제공하고, 확정 입력 검증 대기 61개·상장 이력 부족 16개도
구성 조회·비교는 제공한다. 이평선 판정은 기존 확정 477종목 자료만 사용하며 나머지는
미검증으로 둔다. 동점은 ‘동일’, 엄격한 `종가 > SMA`만 ‘상회’다. 기존 공탐 원점수의
477종목 분모·같은 가중치 계산은 바꾸지 않았다.

패시브 38개·액티브 9개는 운용사 원본 대조 완료이고 나머지 액티브는 공통 API 구성 기준이다.
공시된 편입 비중의 중복은 수익률 상관계수·포트폴리오 성과·투자 추천이 아니다.

## 재현과 검증

```sh
.venv/bin/python docs/research/2026-10-30-etf-explorer/build_snapshot.py
```

빌더는 동결 조사 자료 세 개를 읽고 명시적인 종목 집합·편입 건수·날짜·비중 정밀도를 검증한다.
입력·출력 SHA256은 `validation.json`, 실행 검증·입력 지문은 `verification-record.json` 참조.
새 REST API는 없으며 정적 생산자 계약과 런타임 검사·검색/역검색/중복 산식은
`frontend/src/etfExplorer/model.ts`에 있다.
