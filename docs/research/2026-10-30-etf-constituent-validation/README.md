# ETF 편입 종목 확정과 일봉 준비 상태

선정 ETF 38개의 최신 구성 바스켓을 운용사 원본과 전수 대조했다. 편입 주식 757행의 종목 Code와 CU 수량이 모두 일치했고, 현금 38행의 수량도 일치했다. ETF 간 중복을 제거한 국내 주식 집합은 **477종목**이다. 구성 기준일은 2026년 10월 30일이며, 일봉 점검은 당시 완료된 **10월 29일**까지로 제한했다.

477종목 모두 최근 125거래일의 원주가·기존 수정주가 파일에 유효한 OHLC 행이 있다. 물리적인 백필 부족 종목은 없다. 그러나 프로젝트의 공급자 확정 수정주가 계약으로 보면 470종목의 과거 구간 검증이 남아 있고, 나머지 7종목도 10월 23일까지만 확인돼 있다. 다음 단계는 기존 데이터를 전부 다시 채우는 작업보다 **공급자 관측 확인과 수정 기준일 정렬**이다.

## 운용사 원본 대조

| 운용사 | ETF 수 | 주식 등록 행 | 전체 행 | 결과 |
|---|---:|---:|---:|---|
| KODEX | 17 | 344 | 361 | 주식 Code·CU 수량 일치 |
| TIGER | 9 | 219 | 228 | 주식 Code·CU 수량 일치 |
| SOL | 2 | 33 | 35 | 주식 Code·CU 수량 일치 |
| PLUS | 3 | 35 | 38 | 주식 Code·CU 수량 일치 |
| HANARO | 5 | 71 | 76 | 주식 Code·CU 수량 일치 |
| RISE | 2 | 55 | 57 | 주식 Code·CU 수량 일치 |
| 합계 | 38 | 757 | 795 | 전부 일치 |

ETF별 정확한 건수와 차이 목록은 [issuer-comparison.json](issuer-comparison.json)에 저장했다. 대조 대상은 이전 조사에서 보존한 공통 API 응답과 이번 운용사 원본이다. 원본 조회 URL·시각·해시는 [issuer-source-manifest.json](issuer-source-manifest.json)에 있다.

운용사 경로는 다음과 같다.

- KODEX: [상품 직접 JSON](https://m.samsungfund.com/api/v1/kodex/product/2ETF07.do)의 `pdf`. 기계장비·에너지화학·바이오는 JSON 목록이 30행으로 잘려 있어 [전체 구성 XLS](https://m.samsungfund.com/excel_pdf.do?fId=2ETF63&gijunYMD=20261030)로 보완했다. 선언 건수와 실제 행 수를 대조했다.
- TIGER: [운용사 구성 표](https://investments.miraeasset.com/tigeretf/ko/product/search/detail/pdf.ajax?ksdFund=KR7143860005)에 연결된 `pdfListAjax.ajax`. `listCnt=100`으로 요청하고 `data-tot-cnt`와 실제 행 수를 대조했다. ETF Code로 계산한 ISIN 체크 디지트를 사용하며 선행 0·영문을 보존했다.
- SOL: [직접 JSON](https://www.soletf.com/api/fund/pdfList?fund_cd=210980&work_dt=20261030)의 ETF Code와 `WORK_DT`를 확인했다.
- PLUS: [직접 JSON](https://www.plusetf.co.kr/api/v1/product/pdf/list?n=006192&page=0&d=20261030&pageSize=100)의 `totalElements`, `last`, 행별 `wkdate`를 확인했다.
- HANARO: [직접 구성 표](https://www.hanaroetf.com/api/v1/fund/24A384532ECE491A/get-fund-holdings-list?baseDate=20261030)의 전체 숨김 행까지 읽고 선언 건수와 대조했다. 상품 UID는 운용사 상품명 검색에서 연결했다.
- RISE: [공식 영문 상품 페이지](https://eng.riseetf.co.kr/prod/finderDetail/44A7)의 날짜와 전체 구성 표를 읽었다. 영문 사이트에서 TLS 검증을 정상 수행했다. 국문 주소의 인증서 오류는 별개로 남아 있다.

KODEX·SOL·PLUS·RISE 24개는 응답에 기준일이 나온다. HANARO·TIGER 14개는 구성 표 자체에 기준일 필드가 없으므로 10월 30일을 지정한 요청과 날짜 선택 표본 검사를 근거로 구분했다. 같은 날의 종목·수량 일치는 확인했지만 과거 전 기간 조회가 보장된다는 의미는 아니다.

날짜 선택에는 주의가 필요하다. HANARO는 `baseDate=20261029`와 `2026-10-29`가 같은 이전 바스켓을 반환했지만 점을 넣은 `2026.10.29`는 최신 바스켓과 같았다. 이번 대조는 `YYYYMMDD` 요청을 사용했다. TIGER도 이전 날짜 요청은 바스켓이 달라졌지만 미래 날짜 요청에는 최신 목록을 반환했다. 이를 기록한 [날짜 검사](issuer-date-checks.json) 때문에 요청 날짜만 믿고 과거 구성 이력을 적재해서는 안 된다.

`PDF`는 Portfolio Deposit File인 CU 기준 자산 구성 바스켓이다. 펀드 전체 실보유 수량을 인증한 결과로 해석하지 않는다. 이번 전수 일치는 종목 식별자·CU 수량에 관한 것이다. 공급자 간 비중 분모·정밀도 차이는 이전 조사와 같으며, 비중을 100%로 재정규화하지 않았다. 음수 현금도 원본 그대로 유지했다.

## 종목 집합

| 구분 | 수 |
|---|---:|
| ETF별 주식 등록 행 | 757 |
| 중복 제거한 주식 | 477 |
| KOSPI | 258 |
| KOSDAQ | 219 |
| 제외한 현금 행 | 38 |
| 종목 마스터 미연결 | 0 |
| ETF·ETN으로 분류된 편입 증권 | 0 |

[universe.json](universe.json)이 이번 기준일의 확정 편입 집합이다. 477개 전부 기존 키움 종목 마스터의 `security_type=stock`, `market=KOSPI/KOSDAQ`와 연결됐고, ISIN 내부 Code와 단축 Code도 일치했다. 마스터는 주식의 보통주·우선주 세부 유형까지 제공하지 않으므로 그보다 강한 자산 유형 인증을 주장하지 않는다.

[memberships.json](memberships.json)은 757개 등록 행과 업종·테마 연결, 원본 비중·CU 수량·기준일을 보존한다. 전체 시장 합집합 지표에서는 같은 종목을 한 번만 센다. 개별 ETF 지표에서는 해당 ETF의 편입 관계를 쓴다. 여러 ETF에 들어 있다는 이유로 전체 지표에서 여러 표를 주지 않는다. [excluded-assets.json](excluded-assets.json)에는 현금 38행을 따로 남겼다.

이 집합은 10월 30일의 현재 편입 집합이다. 이전 날짜의 백테스트에 그대로 적용하면 생존·편입 선택 편향이 생긴다. 역사적 구성 이력은 별도 수집해야 한다.

## 일봉 부족과 검증 미완료

| 평가 기준 | 20일 충족 | 60일 충족 | 120일 충족 | 125일 충족 |
|---|---:|---:|---:|---:|
| 10월 29일까지 기존 원주가 파일 | 477 | 477 | 477 | 477 |
| 10월 29일까지 기존 수정주가 파일 | 477 | 477 | 477 | 477 |
| 10월 23일까지 공급자 확정 수정주가 | 7 | 7 | 7 | 7 |
| 10월 29일까지 공급자 확정 수정주가 | 0 | 0 | 0 | 0 |

최근 120거래일과 추가 5거래일을 구분해서 검사했다. MA120만 계산하려면 120일이면 되고, MA120을 5거래일 전과 비교하려면 125일이 필요하다. 행 수만 세지 않고 저장된 거래일 달력의 날짜별 존재, 중복, 유효한 양수 OHLC, 고가·저가 관계를 검사했다. 원주가·기존 수정주가 모두 이 구간의 중복·유효하지 않은 OHLC는 없었다. 가격 보간이나 거래량 0 행의 삭제는 하지 않았다.

현재 스냅샷의 달력은 10월 23일에 끝나고 수정 기준일은 10월 24일이다. 거래일 달력 오버레이에는 10월 26·27·28·29일이 있지만 아직 해당 검증 스냅샷에는 반영되지 않았다. 기존 parquet의 행이 있다는 사실만으로 공급자 확정 관측으로 승격할 수 없다. 이는 [ADR 0057의 확정 관측 계약](../../adr/0057-screener-kis-authoritative-factor-store.md)을 따른다.

| 작업 묶음 | 종목 수 | 필요한 확인 |
|---|---:|---|
| 과거 구간 확인 | 470 | 최근 125거래일의 공급자 확정 수정 OHLC와 실제 관측 기준일 |
| 기존 확인 구간 연장 | 7 | 10월 26~29일 4거래일 및 공통 수정 기준일 재정렬 |
| 물리적 누락 백필 | 0 | 현재 조사 범위에서는 없음 |

기존 확인 구간이 있는 7종목은 CJ대한통운 `000120`, 삼양식품 `003230`, 태광산업 `003240`, 삼성전자 `005930`, 한화에어로스페이스 `012450`, 아난티 `025980`, 레드캡투어 `038390`이다. 이 7개도 예전 수정 기준일 가격에 새 날짜만 붙여 완료 처리해서는 안 된다. 복구 시 공급자가 확인해 주는 공통 수정 기준일과 실제 관측 계약을 기록해야 한다.

실행 대상은 [confirmation-worklist.json](confirmation-worklist.json)에 470개와 7개로 나눴다. [daily-coverage.json](daily-coverage.json)은 477개별 기간 충족 수와 부족 날짜를 담는다. 반복되는 날짜 배열은 최상위 `date_sets`에 한 번 저장했고, 각 기간의 `missing_or_invalid_dates_ref`로 참조한다. 빈 배열 참조는 부족 날짜가 없다는 뜻이다.

거래량 0은 별도 주의 항목이다. 조사한 130거래일 안에 가온전선은 2일, 현대사료는 130일, 트리니티항공은 15일 있었다. [현재 공개 거래 상태](security-observations.json)에서는 현대사료가 거래정지이고 나머지 두 종목은 거래 가능이었다. 이는 과거 모든 날짜의 거래 상태 인증은 아니다. 현대사료를 편입 집합에서 지우거나 거래량 0을 누락으로 바꾸지 않았다. 지표 구현에서는 정지 종목의 계산 대상 포함 정책과 전체 편입 수·판정 가능 수·제외 사유를 함께 표시해야 한다.

## 검증과 재현

원본과 파생 산출물을 보존했으며 운영 데이터·서버·정기 수집기는 변경하지 않았다. 로컬 일봉·마스터·달력은 읽는 동안 파일 해시가 변하지 않았음을 확인했다. 공급자 가격 확인은 기존 `screener_series_values.load_series`의 읽기 경로를 사용했다. 원주가 수량의 분쟁으로 독립 확인된 수정주가까지 탈락시키지 않았다.

- `issuer-responses/`: 운용사 JSON·HTML·전체 구성 Excel 및 조회 메타데이터. KODEX 상품 JSON은 구성 바스켓과 상품 정보만 보존한 투영본이며 원응답 해시를 따로 남겼다.
- `daily-evidence/`: 읽기 전용으로 추출한 두 가격 파일, 확정 수정주가, 종목 마스터, 거래일 달력, 고정 스냅샷 및 입력 해시. 운영 경로를 다시 읽지 않고 재검사할 수 있다.
- `compare_issuers.py`: 원본에서 다시 Code·CU 수량을 대조한다. 전체 XLS 3개를 읽는 데 `xlrd==2.0.2`가 필요하다. 저장소 의존성은 바꾸지 않았다.
- `audit_daily.py`: 기본 실행은 저장한 증거만으로 종목 집합·부족 목록을 재생성한다. `--capture`는 기존 증거 디렉터리가 있으면 읽기 시작 전에 거부한다.
- `fetch_issuers.py --output-dir <새 경로>`: 공개 원본 URL 41개를 새 연구 폴더에만 조회한다. 기존 경로에는 쓰지 않는다. 최신 전용 API는 나중에 호출하면 날짜가 달라질 수 있다.
- `validation.json`: 대조·집계·재현 검사 결과와 입력 및 출력 해시, 실행 환경.

다음 구현은 위 작업 목록의 공급자 확정 관측을 확보한 뒤, 20·60·120일선 위에 있는 종목 비율과 판정 가능 비율을 함께 계산하는 순서가 적절하다. 현재 행 수 충족만으로 공탐 점수를 공개하지 않는다.
