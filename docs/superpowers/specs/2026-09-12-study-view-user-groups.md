# 저장뷰 사용자 그룹 — UI/UX 검토안

2026-09-12. 상태: 사용자 승인 후 구현 완료. 운영 데이터는 직접 수정하지 않았으며, 구버전 목록은 새 코드의 최초 읽기에서 전환한다.

## 요청과 핵심 정책

현재 종목별 자동 분류를 사용자가 만드는 그룹으로 바꾼다. 저장 단위는 종목 자체가 아니라 **종목 + 봉 단위 + 저장 기간을 가진 독립 저장뷰**다. 같은 그룹에 서로 다른 종목, 같은 종목의 여러 기간을 함께 담을 수 있다. 기존 저장뷰 목록은 초기화해도 된다는 사용자 허용이 있다.

권장 세부 정책:

- 그룹은 한 단계만 제공하고, 각 저장뷰는 하나의 그룹에 속한다. 그룹은 빈 상태로도 유지한다.
- 매번 저장할 때 새 ID를 만든다. 코드·이름·기간으로 기존 항목을 자동 덮어쓰거나 합치지 않는다. 완전히 같은 기간도 별도 메모를 위해 저장 가능하다.
- 그룹 간 이동은 저장뷰 ID와 기간을 유지한다. 동일 종목이 목적지에 있어도 이동을 허용한다.
- 그룹명은 공백을 제거한 빈 문자열을 금지하고, 앞뒤 공백 제거 후 대소문자 구분 없이 같은 이름은 중복 생성하지 않는다. 저장뷰 이름은 중복 가능하다.
- 관심종목 그룹 및 차트 연결 그룹과는 독립된 저장뷰 전용 그룹이다.

## 현재 구현에서 달라져야 할 부분

- `studyViewTree.ts`는 Code로 그룹을 만들며 그룹은 저장되지 않는다. `CONTEXT.md`의 “UI-only tree / no folders” 정의를 변경해야 한다.
- `StudyViewsDrawer.tsx`는 종목명을 그룹 헤더에서만 보여주고 행에는 이름과 날짜를 표시한다. 다른 종목이 섞이면 행에 종목명이 반드시 필요하다.
- 현재 드래그 목적지 검사와 순서 상태가 같은 Code 안으로 제한되어 있다. 사용자 그룹 ID 기준으로 전환해야 한다.
- `StudyViewSaveDialog.tsx`에는 그룹 선택이 없고 이름 입력이 필수다. `studySaveCommand.ts`는 라이브 저장의 기본 이름을 빈 값으로 만든다.
- `LiveStudyViewSaveButton.tsx`는 버튼을 누른 창의 저장 명령을 먼저 확정한다. 다이얼로그를 여는 동안 차트가 바뀌어도 저장 대상이 바뀌지 않는 이 성질은 유지한다.
- ADR-0157의 `/live`에서 기간을 여는 동작, ADR-0144의 KRX 기준, 현재 지표로 재분석하는 계약과는 충돌하지 않는다. 이번 변경은 목록 분류 정책을 대체한다.

## 패널

화면 명칭은 기존 제품의 `저장뷰`를 유지한다. 헤더 오른쪽에 `+ 그룹`, 아래에 검색과 전체 접기, 다음 줄에 다중 선택과 정렬을 둔다. 기존 280px 패널 폭과 디자인 토큰을 유지한다.

그룹 헤더: `돌파 복기 · 3개` + 펼치기/접기 + 메뉴. 개수는 고유 종목 수가 아닌 저장뷰 수다. 검색 중에는 `검색 2 / 전체 3`처럼 구분한다.

행 정보 우선순위:

1. 종목명 · 사용자 지정 저장뷰 이름. 긴 이름은 줄임표 처리하고 포커스/툴팁에 전체 이름과 코드를 제공한다.
2. 봉 단위 · 저장 기간. 일/주/월봉은 날짜, 분봉은 KST 시각까지 표시한다. 좁은 폭에서는 기간을 줄바꿈하며 종료 시각을 잘라 숨기지 않는다. 연도가 달라지면 양쪽 연도를 표시한다.
3. 메모가 있을 때 첫 줄 미리보기.

예시:

```text
저장뷰                         + 그룹
그룹·종목·저장뷰 검색            접기
다중 선택                       이름 ↕

▾ 돌파 복기 · 3개                   ⋯
  삼성전자 · 장초 돌파               ⋯
  1분봉 · 2026-09-10 09:00–10:30
  거래량 동반 여부 확인

  SK하이닉스 · 전고점 재돌파          ⋯
  일봉 · 2026-08-03–09-10

  삼성전자 · 오후 재진입             ⋯
  1분봉 · 2026-09-10 13:00–14:30

▾ 눌림목 복기 · 0개                  ⋯
  캔들차트의 저장 버튼으로 추가
```

행 클릭은 해당 종목과 저장 기간을 연다. 그룹 헤더 클릭은 접기만 수행한다. 그룹을 선택했다고 여러 종목 차트를 한 번에 열지 않는다.

검색은 그룹명·종목명·코드·저장뷰 이름·메모를 포함한다. 그룹명 일치는 그룹 전체, 항목 일치는 해당 행만 표시한다. 검색을 해제하면 이전 접힘과 스크롤을 복원한다. 필터 및 이름 정렬 중 드래그 재정렬은 기존 정책대로 제한하되 메뉴의 그룹 이동은 가능하다.

## 캔들차트 → 저장

`저장` 클릭 → 하나의 다이얼로그 → 그룹 선택 또는 새 그룹명 입력 → `저장`.

다이얼로그 순서:

1. 제목 `저장뷰 저장`
2. 고정 대상 요약: 종목명·코드, 봉 단위, KST 저장 시작/종료 시각, KRX 기준
3. 필수 `저장 그룹`: 검색 가능한 선택 목록과 `+ 새 그룹`
4. 새 그룹 모드이면 같은 위치에 `새 그룹 이름` 입력, `기존 그룹 선택`으로 복귀 가능
5. 선택 `이름`: 비워두면 종목·봉 단위·기간으로 자동 생성. placeholder에 예시 제공
6. 선택 `메모`
7. 기존 빠진 기간 수집 옵션과 예상량
8. `취소` / 기존 그룹이면 `저장`, 새 그룹이면 `그룹 만들고 저장`

그룹이 전혀 없으면 처음부터 새 그룹 입력을 표시한다. 그룹이 있으면 마지막 저장에 성공한 그룹을 기본 선택한다. 그 그룹이 삭제되었거나 처음 방문이면 선택 안내를 보여주고 필수 선택으로 둔다. 마지막 그룹은 저장 성공 이후에만 갱신한다.

새 그룹 생성과 저장은 하나의 작업으로 완료한다. 취소하거나 저장이 실패하면 빈 그룹만 남지 않는다. 이미 같은 그룹명이 존재하면 해당 그룹을 선택할 수 있게 안내한다. 패널의 `+ 그룹`은 독립적인 빈 그룹 생성 기능이다.

저장 성공: `돌파 복기에 저장했습니다` + `목록에서 보기`. 차트의 현재 상태를 불필요하게 이동하지 않는다. `목록에서 보기`를 누르면 검색을 해제하고 목적 그룹을 펼쳐 새 항목을 노출한다.

오류 시 다이얼로그·입력값·저장 대상을 유지하고 재시도한다. 제출 중에는 중복 클릭을 막는다. 그룹 목록 조회 실패는 “그룹 없음”으로 처리하지 않고 재시도를 제공한다. 선택 그룹이 다른 탭에서 삭제되면 그룹 재선택을 안내한다. 저장 성공 후 수집만 실패한 경우에는 저장 성공과 수집 재시도를 구분한다.

키보드: 열기 버튼으로 포커스 복귀, 다이얼로그 포커스 제한, Esc 취소, 명확한 필드 라벨, 오류 읽기 지원. 한글 조합 중 Enter는 제출하지 않고 메모 Enter는 줄바꿈한다.

## 그룹과 항목 관리

- 그룹 메뉴: 이름 변경, 그룹 삭제. 비어 있으면 즉시 삭제, 항목이 있으면 그룹명과 저장뷰 개수를 밝힌 확인창에서 `그룹과 저장뷰 삭제`를 제공한다.
- 행 메뉴: 열기, 새 탭에서 열기, 이름 변경, 메모 수정, 그룹 이동, 삭제.
- 다중 선택: 그룹 이동 / 선택 삭제. 드래그는 보조 경로로 제공하고 메뉴만으로도 이동 가능하게 한다.
- 그룹 간 드래그는 헤더와 빈 그룹에도 놓을 수 있게 하고, 목적 그룹을 강조한다. 그룹 내에서는 순서 변경이다. 패널 밖 드롭은 취소한다.
- 항목 삭제 후 마지막 행이 사라져도 그룹은 남는다. 기존 항목 삭제 실행 취소와 순서 복원 동작을 유지한다.

## 저장 구조와 초기화 경계

구현 시 `groups: [{id, name}]`, 각 저장뷰의 `group_id`를 영속화한다. 그룹 및 저장뷰 수정은 기존 저장소 락과 원자적 쓰기로 함께 처리한다. 조회·생성·이동·삭제의 API 모델과 TypeScript 미러를 함께 변경한다. 그룹 순서와 항목 순서의 식별자는 Code가 아닌 group ID / save ID다.

구버전 저장 파일의 목록은 명시적인 버전 전환에서 한 번만 초기화한다. 알 수 없는 버전이나 손상 파일을 임의로 빈 목록으로 덮어쓰지 않는다. 항목 스키마 버전과 파일 포맷 버전은 별도로 관리한다. 저장뷰의 옛 접힘·수동 순서·최근 그룹 상태도 정리하고, 삭제된 뷰 딥링크는 찾을 수 없다는 안내를 제공한다.

초기화 허용 범위는 기존 저장뷰 목록이다. 원본 캔들·수집 데이터, 관심종목, 히트맵, 차트 레이아웃과 지표 설정은 대상이 아니다. 운영 목록을 직접 삭제하는 명령은 실행하지 않았다.

## 구현 완료 판정

- 서로 다른 두 종목과 같은 종목의 다른 두 기간을 한 그룹에 저장하고 새로고침 후 다시 연다.
- 동일 날짜의 서로 다른 분봉 구간을 목록만으로 구분하고 각 시작/종료 범위가 복원된다.
- 그룹 없는 상태에서 생성·저장, 취소, 실패·재시도, 중복 그룹명, 선택 그룹 삭제 경합을 검증한다.
- 빈 그룹 유지, 그룹 간 이동, 다중 이동, 그룹 이름 검색, 접힘 복원, 그룹 삭제 대상 개수를 검증한다.
- 구버전 목록은 한 번만 비워지고 다음 실행에서는 새 저장뷰가 유지된다. 원본 시장 데이터는 유지된다.
- 280px 패널에서 긴 종목명·메모·연도 경계·분봉 시각과 키보드 접근을 검증한다.

검증: 백엔드 전체 테스트와 변경 경로 재검증, 프론트엔드 전체 단위 테스트, 타입검사, 빌드, 기존 E2E 120개 및 실제 저장 API를 사용하는 그룹 생성·동일 기간 재저장·이동·새로고침 E2E를 수행했다. 저장 다이얼로그와 280px 패널의 스크린샷도 확인했다. 행 메뉴는 포인터 접근을 보장하도록 항상 클릭 가능하게 표시한다.
