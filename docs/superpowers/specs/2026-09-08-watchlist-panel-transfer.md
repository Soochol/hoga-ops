# 관심종목 패널 이동 UX

사용자 승인 범위: 우측 패널의 종목·그룹 이동 핸들, 정확한 삽입 위치, 목적지 안내,
이동 결과와 되돌리기, 접힌 그룹 자동 펼침, 가장자리 스크롤, 정렬 중 그룹 이동,
다중 선택 이동, Delete로 현재 그룹 소속 제외.

## 사용자 동작

- 종목·그룹 이름 왼쪽의 ⠿ 핸들에서 드래그를 시작한다. 행 클릭은 차트를 연다.
- 기본 정렬에서는 대상 행의 위·아래 절반으로 삽입 위치를 고른다. 메모도 위치 기준이다.
  그룹 헤더와 빈 그룹에 놓으면 끝에 넣는다.
- 드래그 목적지는 패널 하단에 고정 표시한다. 패널 바깥 드롭은 취소하며,
  단일 종목의 기존 차트 드롭은 유지한다. 여러 종목은 차트에 일괄 적용하지 않는다.
- 등락률 정렬 상태에서는 그룹 간 이동만 허용한다. 대상 그룹의 기존 저장 순서를
  보존하고 새 코드를 끝에 추가한 뒤 화면의 정렬 기준에 맞춰 표시한다.
- 접힌 그룹 위에 600ms 머무르면 일시적으로 펼친다. 드래그 종료·취소 후에는
  저장된 접힘 상태로 돌아간다.
- 스크롤 영역의 위·아래 48px 안에서는 가장자리에 가까울수록 속도를 높인다.
  최대 650px/s이며 패널 밖에서는 멈춘다. 드래그가 끝나면 타이머·RAF를 해제한다.
- `여러 종목 선택`으로 체크박스를 켠다. 선택한 행의 핸들을 잡으면 선택된 소속을
  화면 순서대로 묶어 이동한다. 선택하지 않은 행의 핸들은 해당 한 행만 옮긴다.
  대상에 이미 있는 코드는 합치고 목적지 안내에 중복 개수를 표시한다.
  선택하지 않은 다른 그룹의 같은 코드 소속은 보존한다.
- 포커스된 종목 행의 Delete는 해당 그룹의 소속만 해제한다. 입력칸·행 안 버튼의
  Delete와 Backspace는 이 동작을 실행하지 않는다.

## 저장 계약

`PUT /api/watchlist/items/transaction`은 `changes` 배열을 받는다. 각 원소는
`folder_id`, `before`, `after`이며 두 목록은 `WatchlistItemRef`(코드 또는 메모 id)다.
프런트 `planTransfer`가 전체 순서의 변경을 만들고 `useWatchlistTransfer`가 저장·결과를 소유한다.

서버는 하나의 잠금 안에서 모든 `before`를 최신 폴더 순서와 비교하고 한 번만 저장한다.
폴더 중복, 항목 중복·유실·신규 생성, 메모의 다른 그룹 이동은 거절한다. 메모 내용과
종목 메타데이터는 서버의 기존 모델을 보존한다. 영향받지 않는 그룹은 건드리지 않는다.
조건 불일치는 409, 사라진 그룹은 404다. 일부 폴더만 성공하는 저장 경로는 없다.

성공 후 결과 문구와 `되돌리기`를 표시한다. 되돌리기는 직전 성공한 이동의 before/after를
바꿔 같은 API로 보낸다. 그 사이 대상 폴더가 바뀌었으면 409로 거절하여 후속 편집을 보존한다.
오류 시 최신 목록을 다시 조회하고 실패를 안내한다. 저장 중 중복 드래그·되돌리기를 막는다.
되돌리기 기록은 현재 패널이 마운트된 동안만 유지된다. 새 이동을 시작하거나 안내를 닫으면
이전 기록을 지운다. 배포 시 프런트와 백엔드를 함께 반영해야 한다.

## 검증 범위

- Python API 테스트: 다중 이동·중복 합침·역변경, 메모·메타데이터 보존, 충돌 시 무변경.
- Vitest: 순서 계산, 선택하지 않은 소속 보존, 정렬 대상의 저장 순서 보존, 패널 이벤트 연결.
- Playwright: 실제 포인터로 행·헤더·빈 그룹·메모 위치 이동, 다중 선택·중복·되돌리기,
  자동 펼침 취소, 정렬 그룹 이동, 외부 드롭 취소, 자동 스크롤, 실패 안내, Delete 범위.
