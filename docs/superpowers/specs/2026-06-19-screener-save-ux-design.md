# Screener 저장/조회 UX 개선

## Summary

`/screener`의 저장 UX를 리스트 행 아이콘 중심에서 상단 작업바 중심으로 옮긴다. 사용자는 조건을 편집하는 위치에서 현재 조건검색 이름, 수정 여부, 저장 액션, 조회 액션을 한 번에 확인하고 실행할 수 있어야 한다.

## UX Decisions

- 상단 작업바는 현재 조건검색 이름, `수정됨`, `다시 조회 필요`, `저장`, `다른 이름으로 저장`, `조회`를 표시한다.
- 기존 저장본을 불러온 상태에서 `저장`은 현재 빌더 조건과 사전필터로 해당 저장본을 덮어쓴다.
- 저장본이 없는 상태에서 `저장`은 이름 입력 모달을 열고 새 조건검색을 만든다.
- `다른 이름으로 저장`은 저장본 로드 여부와 무관하게 현재 빌더 상태를 새 저장본으로 만든다.
- 조건 또는 사전필터가 마지막 조회 이후 바뀌면 결과 영역에 `조건 변경됨 · 다시 조회 필요`를 표시한다.
- 조건 카드에는 `복제`만 추가한다. 비활성화 토글은 이번 범위에서 제외한다.
- 조건 추가 메뉴는 `가격`, `거래대금`, `신고가/거래량`, `이동평균`, `등락률` 카테고리로 묶는다.
- 저장 목록은 검색과 `⋯` 메뉴를 제공한다. 행 클릭은 불러오기만 수행한다.
- 저장 목록 행 메뉴는 `이름변경`, `복제`, `삭제`를 제공한다. 기존 숨은 덮어쓰기 아이콘은 제거한다.

## State And Data Flow

- 기존 저장 API를 유지한다: 새 저장은 `createSave`, 덮어쓰기는 `updateSave`, 삭제는 `deleteSave`.
- 저장 목록 `복제`는 선택한 저장본의 `conditions`와 `universe`를 그대로 사용하고, 이름은 `<원본 이름> 복사`로 생성한다.
- 프론트엔드는 마지막 성공 조회의 `{ conditions, universe }` 스냅샷을 보관하고 현재 빌더 상태와 비교해 stale 결과를 표시한다.
- 조건 복제는 원본 `type`과 `params`를 깊은 복사하고 새 `id`를 부여한다.

## Acceptance Criteria

- 저장된 조건을 불러온 뒤 조건이나 사전필터를 수정하면 상단 작업바와 저장 목록에 `수정됨`이 표시된다.
- 상단 `저장`은 기존 저장본에서는 `updateSave`, 새 조건에서는 이름 입력 후 `createSave`를 호출한다.
- `다른 이름으로 저장`은 항상 `createSave`를 호출한다.
- 조건 변경 후 조회 전에는 결과 영역에 `조건 변경됨 · 다시 조회 필요`가 표시되고, 조회 성공 후 사라진다.
- 조건 `복제`를 누르면 같은 조건이 새 id로 추가된다.
- 조건 추가 메뉴는 카테고리 헤더와 기존 조건 항목을 함께 표시한다.
- 저장 목록 검색은 이름 기준으로 필터링한다.
- 저장 목록 `⋯` 메뉴의 이름변경, 복제, 삭제는 행 불러오기와 충돌하지 않는다.
