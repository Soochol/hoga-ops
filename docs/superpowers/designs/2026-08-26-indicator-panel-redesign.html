보조지표 패널 리디자인

두 개의 목록(내 지표 ↔ 카탈로그)을 오가던 패널을 고정 순서의 단일 리스트로 합치고, 지표마다 생김새와 그려질 위치를 동시에 말하는 글리프를 부여한다. 아직 추가하지 않은 지표는 설정 폼 대신 미리보기 카드로 답하고, 검색을 신설하며, 파괴적 초기화는 ⋯ 메뉴로 물러난다. 확정된 결정은 전부 그대로다 — 이 제안은 그 결정들 안에서의 재설계다.

현행 패널의 네 가지 마찰

1모드 플립이 전체 그림을 가린다

「내 지표」와 「카탈로그」가 서로를 완전히 대체한다. 15개 중 무엇이 켜져 있는지 한 화면에서 볼 수 없고, 추가 한 번에 목록 전체가 갈아엎어진다. 「내 지표」 모드에서는 그룹 구조도 사라진다.

2텍스트 행만으로는 지표를 못 그려본다

「호가벽 급증」이 선인지 마커인지, 캔들 위에 겹치는지 하단 패널을 차지하는지 이름만으로 유추해야 한다. 추가해 보기 전까지 차트에 무슨 일이 생길지 모른다.

3존재하지 않는 지표의 설정 폼이 열린다

카탈로그에서 라벨을 누르면(미리보기 의도) 우측에 추가되지 않은 지표의 편집 가능한 설정 폼이 그대로 뜬다. 미리보기와 편집이 같은 화면이라 "지금 이걸 만지면 무슨 일이 나는가"가 불분명하다.

4검색이 없고, 파괴적 액션이 상석에 있다

15개 항목에 검색이 없다. 반면 가장 위험한 「현재 봉 초기화」는 nav 하단에 상시 노출되어 매일 쓰는 목록의 높이(실측 903px 요구)를 잡아먹는다.

분봉 초기화?

메뉴 열림 → 항목 클릭 → 같은 자리 인라인 확인. 현행과 같은 보호 수준을 유지하면서 nav 하단 상시 푸터 2행(모드 전환 + 초기화)을 없앤다.

1검색은 그룹을 보존한다. 일치 행만 남되 소속 그룹 헤더는 유지 — "어느 계열의 지표인가"가 결과에서도 읽힌다. 강조는 tint 배경 + 600 무게(색 규율 안). 일치가 없으면 "일치하는 지표 없음" 빈 상태 한 줄.
2키보드 흐름. 열림 → 검색 포커스 → ↑↓ 이동 → Enter = 선택(미리보기) → Esc(검색 지우기 → 패널 닫기 순). 추가는 어디서든 명시적이다 — 행의 ＋ 또는 미리보기의 [차트에 추가]. Enter 를 추가에 걸지 않는 이유는 어휘 결정과 같다: 보기 전에 차트가 바뀌면 안 된다. 전역 focus-visible 규칙 그대로.
3초기화의 새 자리. ⋯ 메뉴 안으로 — 빈도가 낮고 파괴적인 액션이 매일 쓰는 목록의 상석을 차지하지 않는다. 보호 수준(인라인 2단 확인)은 그대로다.

2열 머리 = 방향 마스터. 종전의 「매도 최대벽 표시」 토글이 열 머리로 승격 — 스코프가 위치로 보인다. 스펙: 두 열을 모두 끄면 존재 삭제와 동일하다(현행 의미 그대로) — 행이 미추가로 돌아가고 이 화면은 미리보기 카드로 전환된다. 전환 직전 확인은 두지 않되, 이 경로에도 undo 토스트를 배선한다 — 현행 토스트는 레전드 칩 ✕ 경로에만 걸려 있으므로 배선은 스펙 요구사항이다.
3셀 = 계열×방향의 최소 제어. 스위치·색·표시 개수가 셀 안에, 선택(tint)하면 그 셀의 세부가 아래 존에 열린다. 종전 구조는 전부 펼치면 3계열×7행=21행이라 아코디언이 필수였다 — 매트릭스+존은 5행 + 세부 7행으로 같은 정보를 상시 화면 안에 둔다.
4깔때기 = 작동 중인 후보 필터 수. 중립(fg-dim)이면 "필터가 있지만 벽이 그려지는 중", warn 이면 켜져 있는데 지금 0개 — "벽이 왜 안 보이나"의 답이 접힌 메뉴 속이 아니라 셀 위에 뜬다. 종전의 「끈 개수」 뱃지는 폐지하고 역할을 깔때기+리드아웃이 승계한다.
5공용의 위치 문법 완성. 방향 공용(캔들 수평선·봉 내 최대)은 매트릭스 푸터 행 — 열 아래 정렬이 "방향별 값"을, 전역(강도 pane)은 매트릭스 밖 배지 행이 "하나뿐"을 말한다. 「분봉 내 최댓값 기준」(intraMax)을 계열별로 내리지 않는 이유도 유지된다(미도달 계열엔 무효 스위치가 된다).
6표시 개수 리드아웃. "지금 1개 표시 · 2개 필터로 숨김" — 렌더 경로와 같은 셀렉터에서 세므로 새 데이터가 필요 없다. 0개일 때 warn 톤. 필터 기본값(현재 4종 모두 ON) 재검토는 별도 결정으로 남긴다 — 2026-08-26 조사가 근거다.

수치와 경계 조건

높이 수지 — 스크롤이 사라진다

단일 리스트는 푸터 2행(모드 전환 + 초기화)을 없애고 검색 1행을 더한다.

현행: nav 16항목 903px + 푸터 ≈100px ≈ 1,003px
제안: 검색 44 + 그룹헤더 4×28 + 행 15×34 + 패딩 ≈ 682px (−32%)
→ 카드 h-[min(960px,86vh)] 기준, 세로 ~800px 화면부터 nav 무스크롤.

그래도 부족해지면 결정 로그가 지정한 탈출구는 그룹 접기다(2026-08-21 재검토 트리거) — 이 구조는 그룹 헤더가 이미 있으므로 접기를 바로 얹을 수 있다.

행이 움직이지 않는다는 계약

2모드 분리의 원래 근거는 "켜고 끌 때 행이 두 섹션 사이를 오가면 방금 조준한 항목이 커서 밑에서 움직인다"였다. 단일 리스트는 정렬을 상태와 무관하게 고정해 같은 문제를 구조로 해소한다 — 추가/삭제 시 바뀌는 것은 행 내부의 상태뿐, 위치는 불변. 모션도 같은 계약을 따른다: 디테일 전환 150ms ease-out 페이드, 색 점 등장 150ms, hover 80ms. 리스트 reflow 애니메이션은 없다.

능력(capability) 필터는 그대로 탄다

이 목업은 주식 종목 창(전 지표 노출) 기준이다. 실제로는 현행과 같은 필터가 단일 리스트에도 적용된다 — 지수 창은 10호가·프로그램 그룹 자체가 사라지고, 투자자 순매수가 없는 종목은 거래원 그룹의 해당 행이 빠지며, hiddenCategories(워크스페이스가 안 그리는 지표)도 동일하게 제외된다. 빈 그룹은 헤더째 숨긴다.

바뀌지 않는 것

  • 저장 모델 — 창×봉 버킷, 즉시 적용. 스코프 칩(삼성전자 · 분봉)과 툴팁 문구 유지.
  • 삭제 undo 토스트 — 행 ✕ 의 배선은 현행 그대로.
  • ModalShell·workspacePanel.ts 상수 — 폭 760 · nav 240 · 높이 계약과 설정 패널과의 동기화 테스트(IndicatorPanel.test.tsx) 유지.
  • 각 지표의 세부 설정 컴포넌트 — 폼 문법(열 헤더 그리드·섹션 라벨)만 공통 프리미티브로 감싼다. 로직 변경 없음.

이후로 미루는 것

pane 미니맵(차트의 오버레이·하단 패널 스택을 도식으로 보여주고 칩 클릭으로 설정 이동) — 이번 판의 시그니처는 글리프 하나로 제한한다. 글리프의 레전드 칩 재사용도 별도 판으로: 패널↔레전드↔차트가 같은 글리프·색으로 이어지면 세 표면의 동일성이 완성되지만, 레전드는 이 패널과 다른 밀도 제약을 갖는다(차트 위 반투명 surface). 먼저 패널에서 글리프를 검증한 뒤 옮긴다.

정적 목업 — 상호작용(hover 제외)은 명세 텍스트로만 담았다. 토큰 실값은 frontend/src/styles/tokens.css 에서 옮겼으며 새 색·새 자간·임의 px 타이포는 없다. 승인 시 이 파일이 DESIGN.md 결정 로그의 1차 사료가 된다.
