# 전체 최대벽 pane의 누적 최대값 이력 복원

작성일: 2026-09-21
상태: 구현 완료

## 목표와 완료 조건

당일 최대벽 지표의 전체 최대벽 계열도 누적 계단 모드에서 **해당 날짜 최초 유효 관측부터 그 시점까지의 최대 잔량**을 표시한다. 매도·매수 모두 적용한다.

예시: 09:00 1만 주 → 10:00 3만 주 → 14:00 10만 주라면 세 구간을 모두 표시한다. 오후 최종 최대값을 오전으로 소급하지 않는다. 관측 전에는 값이 없고 날짜가 바뀌면 누적값을 초기화한다. 기존 계단 모드의 MA 필터가 켜져 있으면 필터를 통과한 후보 기준이라는 규칙을 유지한다.

## 확인한 원인

- `frontend/src/live/usePeakWallRender.ts`: 체결벽 계단은 기록 이력과 최종 순위 후보를 합치지만 전체 최대벽 계단은 최종 순위 후보만 받는다.
- `frontend/src/live/peakWallSegments.ts`의 `toAllWallPeakInputs`: 전체벽 스칼라·순위만 옮기고 이력은 공급하지 않는다. 과거 날짜는 최대벽 한 개만 남을 수 있다.
- `frontend/src/chart/peakWallSteps.ts`: 첫 후보 발생 전에는 점을 만들지 않는다. 따라서 입력 이력이 누락되면 최종 최대벽 발생 시점부터 선이 생긴다.
- 체결벽에는 과거 계산, 서버 당일 상태, 프론트 seed·live 병합 및 접속 중 누적 경로가 이미 있다. 전체벽에도 이 경로를 연결해야 한다.

## 구현 순서

### 1. 사용자 증상을 재현하는 회귀 테스트

최종 상위 벽은 오후에만 있고 오전의 작은 기록은 순위 밖인 날짜를 만든다. 실제 pane 입력 생성과 계단 계산을 연결해 오전 값이 사라지는 실패를 먼저 확인한다. 같은 가격에서 잔량이 여러 번 커지는 사례도 포함해 가격별 중복 제거로 이력이 사라지는 것을 잡는다.

### 2. 과거 전체벽 이력 생성과 API 전달

- `hoga/tables/snapshots.py`: 가격별 중복 제거 전 rep·cont 프레임에서 터치 여부와 무관한 기록 갱신 이력을 만든다. 기존 기록 계산을 공통화하되 체결 여부 필터를 명시한다.
- 제안 필드: `all_record_peaks`, `all_record_max_peaks`. 매도·매수 결과 모델, `hoga/api/models.py`, `hoga/api/bundle.py`, 프론트 API 타입에 함께 연결한다.
- 시간순·잔량 순증가, 동률 최초 도달 유지 규칙을 고정한다. 같은 시각의 여러 호가 단계는 결정적으로 처리한다.
- 기존 기록 함수의 앞 128개 제한을 그대로 적용하지 않는다. 기록이 128회를 넘는 날에도 중간 계단과 최종값을 보존하는지 검증하고, 반환 크기를 측정한다. 원본 전체 후보 대신 최대값 갱신 지점만 전달한다.
- 과거 payload에서 전체 순위 배열을 제거하는 최적화가 새 이력을 제거하지 않도록 한다.
- 1분 캐시에서 굵은 분봉을 파생하는 경로에 새 필드를 보존한다. 기존 체결벽 이력과 동일하게 1분 이력을 표시 봉에 접는 규약을 따른다.
- 과거 지표 캐시 버전을 올려 이력 없는 기존 캐시를 재계산한다. 광범위한 선제 재생성은 별도 작업으로 두고 정상 조회 갱신 경로를 검증한다.

### 3. 당일 서버 상태와 복구 경로

- `hoga/live/ask_peak_state.py`: 전체벽 후보를 관측할 때 최종 순위와 별도로 기록 이력을 유지하고 live payload에 포함한다.
- 늦게 도착한 관측, 동일 데이터 재수신, JSONL 재생본 병합에서도 시간순 누적 최대값이 유지되게 한다.
- 재시작 후 `merge_from`이 top-3만 복구하지 않고 오전 이력도 복구하는지 검증한다.

### 4. 프론트 병합과 pane 연결

- `peakWallRecordSeries.ts`, `useDayAskPeaks.ts`, `useDayBidPeaks.ts`: 전체벽의 range seed·live 이력과 접속 이후 관측을 병합한다. 체결벽 이력 병합의 공통 로직을 재사용하고 계열별 상태는 분리한다.
- 종목·거래일·venue 등 기존 누적기 초기화 조건을 동일하게 적용한다. 재접속, 늦은 seed 응답, 과거 데이터 추가 로드 때 이력이 사라지거나 다른 날짜와 섞이지 않게 한다.
- 가격 조정 경로(`scaleRangeBundlePrices.ts`)와 wire 필드 검증 목록에도 새 필드를 반영한다.
- `toAllWallPeakInputs`에서 새 이력을 계단 빌더로 전달한다. `stepHistory` 경로가 이력을 사용하게 하되 캔들 수평선의 표시 개수와 최종 순위 의미는 유지한다.
- 기존 봉별 모드와 미도달 계열 계산은 유지한다. 전체벽 pane이 참여하지 않는 경우 불필요한 계단 계산을 추가하지 않는다.
- “전체벽은 pane에 참여하지 않는다”, “이력이 없어 top-3로 근사한다” 등 현재 코드와 어긋난 주석을 갱신한다.

### 5. 검증

핵심 사례:

- 오전 최초 관측 → 여러 번 기록 갱신 → 오후 최종 최대값.
- 같은 가격의 잔량 증가, 동률, 같은 시각의 복수 단계, 역순 도착.
- 128회를 넘는 기록 갱신에서 중간 구간과 최종값 보존.
- 매도·매수, rep·cont, 1분·굵은 분봉, 날짜 경계, 빈 날짜.
- 필터 해제 상태에서 최초 관측부터 표시, MA 필터 활성 상태에서 기존 후보 필터 규약 유지.
- 과거 캐시 갱신, 오늘 seed+live 병합, 재접속·서버 재시작 복원.
- 최종 pane 값과 동일 필터 조건의 전체 최대벽 값 일치.
- 체결벽·봉별 모드·캔들 오버레이 회귀 없음.

먼저 관련 pytest/Vitest를 실행하고, 구현 완료 후 저장소의 필수 검증을 수행한다: Ruff, wallclock 제외 전체 pytest, 프론트 typecheck·Vitest·Vite build·Playwright. 브라우저에서는 동일 날짜의 과거 구간과 당일 구간을 확인하며, 사용자 서버와 설정을 보존한다.

## 범위와 주의점

이 작업은 전체 최대벽의 **누적 계단 입력 누락**을 고친다. UI 설정을 추가하거나 최대벽 정의를 변경하지 않는다. 최초 관측 이전을 0 또는 최종 최대값으로 채우지 않는다. 날짜 경계에서 선을 끊는 기존 렌더러의 투명 연결 처리 때문에 첫 점의 시각과 실제 보이는 선의 시작 사이에 한 봉 차이가 있을 수 있으므로 입력 누락과 구분해 검증한다.

구현 결과: `all_record_peaks`/`all_record_max_peaks`를 과거 계산, 캐시, REST 모델,
장중 상태, 재시작 병합, 프론트 seed·live·접속 이후 누적 경로에 연결했다. 전체 최대벽
계단은 최종 top-3 밖의 오전 기록도 보존한다.
