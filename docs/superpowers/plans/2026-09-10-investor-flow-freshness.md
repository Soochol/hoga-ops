# 투자자 수급 수신 신선도 개선 계획

작성일: 2026-09-10 · 상태: 구현 및 격리 검증 완료 · 실서버 적용/장중 관찰은 미실시

## 목표

`/market` 투자자 수급에서 사용자가 현재 수신 여부, 마지막 정상 수신 시각, 수집되지 않은 구간을 구분할 수 있게 한다. 현물·파생 각각의 수집 시간 동안 서버 수집과 화면 갱신을 모두 10초 주기로 운영한다. 파일 변경 감지 기반 캐시와 수신 상태 측정을 함께 적용한다(사용자 동의: 2026-09-10).

## 조사에서 확인한 사실

- 2026-09-10 15:33~15:35 KST, 두 API 모두 HTTP 200. 현물 표본 간격 중앙값 30.1초, 파생 30.4초. 파생 금액 변화와 화면 표본 수 자동 증가를 확인했다.
- 현물은 키움 `ka10051`, 파생은 KIS `FHPTJ04030000`을 서버에서 수집한다. 화면 API는 저장된 표본을 읽는다.
- 서버 수집 시간은 현물 08:00–16:30, 파생 09:00–15:45다. 프론트 공통 게이트는 09:00–15:30분까지 30초, 그 밖에는 60초를 사용한다.
- 오늘 첫 저장 표본은 약 09:20이었다. 코스피에는 15:21:37–15:30:19의 저장 표본 공백이 있다. 서버 지연·실패·재시작·동일 응답 생략 중 어느 원인인지는 현재 자료로 확정하지 못했다.
- 동일 응답은 저장하지 않는다. 따라서 마지막 저장 시각과 마지막 정상 수신 시각은 다르다. `sample_count / expected_count`는 정상 수신율이 아니다.
- 실행 서버는 `/home/dev/code/hoga-ops`에서 동작하며, 조사한 핵심 파일은 현재 워크트리와 동일했다.

## 구현 순서

### 0. 10초 주기에 앞서 반복 파싱 비용을 줄인다

대상: `hoga/api/market_routes.py`, 현물·파생 store의 읽기 경로 및 관련 테스트.

- 현재 두 API는 매 요청마다 하루치 JSONL을 전량 읽고 파싱한다. 10초 수집·조회로 표본과 요청이 각각 늘면 같은 시각 기준 파싱 작업량은 약 9배까지 증가할 수 있다. 동일 값 생략에 따라 실제 증가는 달라지므로 측정한다.
- 데이터 경로·날짜·파일 식별자(inode)·크기·나노초 수정 시각으로 변경을 감지하고, 변경이 없으면 파싱된 표본을 재사용한다. 같은 파일에 대한 동시 요청은 한 번의 파싱으로 합친다.
- 원자적 파일 교체, truncate, 날짜 전환, 미완성 마지막 줄과 읽는 도중 append를 처리한다. 파싱 전후 파일 상태가 다르면 결과를 최신 캐시로 확정하지 않는다. 캐시는 최근 날짜로 제한하고 공유 배열을 응답 생성 중 수정하지 않는다.
- 값 표본 캐시와 신선도 상태 캐시는 분리한다. 값이 같아 파일이 그대로여도 정상 수신 시각과 지연 여부는 갱신되어야 한다.
- 확정 파일 변경과 파생 단위 판정도 응답에 반영한다. 전체 응답을 원본 JSONL 변경 여부 하나만으로 캐싱하지 않는다.
- 10초마다 파일이 실제로 바뀌는 경우 단순 캐시만으로 파싱 증가를 해소하지 못한다. 아래 성능 기준을 넘으면 append 이후 추가 바이트만 읽는 증분 파싱을 적용한다. 재작성·truncate 시에는 전량 재구축한다.

완료 기준: 동일 파일 반복 요청은 추가 파싱 0회, 변경 후 첫 응답은 최신 표본을 포함하고, 동시 요청은 파싱을 중복 수행하지 않는다.

### 1. 정상 수신과 값 변경을 분리해서 기록한다

대상: `hoga/live/investor_flow_collector.py`, `deriv_flow_collector.py`, 각 store/runtime, `hoga/api/scheduler.py`.

- 현물은 시장별, 파생은 상품별로 `last_attempt_at_ms`, `last_success_at_ms`, `last_written_at_ms`, 연속 실패 횟수와 안전한 오류 분류를 기록한다.
- `last_success_at_ms`는 대상 시장·상품의 필수 데이터 검증까지 성공한 뒤 갱신한다. HTTP 200이어도 필요한 행이 없거나 파싱에 실패하면 정상 수신으로 세지 않는다.
- 동일 값 수신도 정상 성공 시각을 갱신한다. 한 시장만 성공했을 때 다른 시장의 실패가 가려지지 않게 한다.
- 현물·파생 fetch가 예외를 `None`으로 접지 않고 호출 경계까지 전달한다. 수집기가 시장/상품별로 예외를 분류하고 다음 대상을 계속 수집한다. 확정 수렴 호출부는 실패한 날짜를 다음 실행으로 미룬다.
- 원본 값 JSONL의 중복 생략은 유지한다. 별도의 작은 상태 파일을 수집 사이클당 원자적으로 갱신하고, 날짜·수집 실행 식별자를 포함한다. 읽기 서버와 수집 소유 프로세스가 달라도 같은 상태를 보게 한다.
- 재시작 시 과거 상태를 현재 실행의 성공으로 오인하지 않는다. 프로세스 내 생존 판정은 기존 태스크 핸들을 사용하며, 파일에 남은 `running=true`를 생존 근거로 쓰지 않는다.
- 오류 로그에는 시장/상품·분류·시각만 담는다. 인증정보와 원시 요청 헤더를 노출하지 않는다.

완료 기준: 값이 10분간 같아도 정상 수신 상태를 유지하고, 코스닥만 실패하면 코스닥만 지연으로 판정한다.

### 2. API가 수집 일정과 신선도를 제공한다

대상: `hoga/api/market_routes.py`, `hoga/live/session_gate.py` 및 수집 상태 모듈.

기존 응답에 하위 호환 필드를 추가한다.

| 위치 | 추가 정보 | 의미 |
|---|---|---|
| 응답 공통 | `server_now_ms`, `collection_expected`, `poll_interval_ms`, `stale_after_ms` | 서버 시각·거래일 달력·수집 창을 기준으로 판정 |
| 시장/상품별 | `last_success_at_ms`, `last_written_at_ms`, `consecutive_failures`, `error_kind` | 정상 수신과 실제 저장을 분리 |
| 시장/상품별 | `status` | `waiting`, `receiving`, `delayed`, `closed`, `unavailable`, `unknown` |

- 수집 창과 거래일 여부는 기존 서버 게이트를 재사용한다. 벤더 조회는 기존 수집기만 수행한다.
- 기본 지연 임계는 10초 수집의 3주기인 30초로 제안한다. 실제 요청·거버너 대기 시간을 측정해 오탐 여부를 검증한다. 서버 정책 상수 하나에서 응답과 판정에 함께 사용한다.
- 수집 예정 시간 안에서 마지막 정상 수신 후 30초 초과면 `delayed`. 첫 성공 전에는 개장/수집 시작 후 같은 유예를 적용한다.
- 미설정은 `unavailable`, 수집 시간 밖은 `closed`로 구분한다. 과거 오류 이력은 보존하되 장 종료 자체를 장애로 표시하지 않는다.
- 이전 날짜 표본이나 확정점 추가를 오늘의 정상 장중 수신으로 세지 않는다. `confirmed`와 신선도는 독립 상태다.
- 구버전 파일에 신선도 정보가 없으면 `unknown`을 반환한다. 저장 시각을 정상 수신 시각으로 대신 채우지 않는다.
- 재시작·날짜 전환·비소유 읽기 서버에서 상태가 어떻게 보이는지 API 테스트로 고정한다.

완료 기준: 동일 값 정상 수신, 단일 시장 실패, 미설정, 장 종료, 이전 날짜 상태를 응답에서 구별한다.

### 3. 수급 전용 폴링과 상태 표시를 적용한다

대상: `frontend/src/api/market.ts`, `frontend/src/market/InvestorFlowCard.tsx`, 필요시 공용 표시 컴포넌트.

- 수급 두 훅은 응답의 `collection_expected`와 `poll_interval_ms`를 사용한다. 수집 중에는 10초, 수집 시간 밖에는 60초 하트비트를 유지한다.
- 최초 응답 전이나 API 오류 시에도 타이머가 사라지지 않게 한다. 구버전 응답에는 기존 정책으로 폴백한다.
- 수집 시간 밖에서 페이지를 열어 둔 경우 개장 후 첫 하트비트, 최대 60초 이내에 수집 중 정책으로 전환한다.
- 탭 복귀 시 수급 쿼리가 오래되었으면 즉시 갱신한다. 전역 쿼리 정책 변경 대신 두 수급 훅에 한정한다.
- 선택된 시장·상품에 `정상 수신 · 15:34:00`, `수신 지연 · 마지막 정상 수신 15:31:20`, `수집 종료`를 표시한다. 기존 디자인 토큰을 사용하고 색상만으로 구분하지 않는다.
- 화면 API 요청 실패는 벤더 수신 지연과 구별하여 `서버 연결 확인 필요`로 표시하고 마지막 값은 유지한다. 최초 요청 실패를 ‘오늘 표본 없음’으로 숨기지 않는다.
- 응답이 끊겨도 마지막 성공 응답의 ‘정상’ 표시가 고정되지 않게 로컬 경과 시간을 반영한다. 서버 시각에 응답 이후 단조 증가 경과 시간을 더해 클라이언트 시계 오차 영향을 줄인다.

완료 기준: 08시 현물 및 15:31 이후 현물·파생이 수집 시간 동안 10초 갱신을 유지하고, 실패 시 기존 값과 오류 상태를 함께 보여준다.

서버 주기 변경 시 함께 처리할 사항:

- 현물·파생 `POLL_INTERVAL_S`를 10초로 변경한다. 프론트 `staleTime`도 새 폴링 주기에 맞추어 설정한다.
- 현재 루프는 한 사이클 완료 후 sleep하므로 실제 간격은 10초 + 작업 시간이다. 사이클 소요 시간과 거버너 대기 시간을 계측하고, 시작 간격을 맞출 경우 단조 증가 시계를 사용한다. 느린 사이클을 겹쳐 실행하거나 누락된 사이클을 몰아서 호출하지 않는다.
- 파생 7상품은 순차 요청한다. 각 상품의 실제 응답 수신 시각을 기록해 뒤쪽 상품에 사이클 시작 시각을 잘못 붙이지 않는다.
- 정상 일정에서 현물은 분당 약 4→12콜, 파생은 14→42콜이다. 기존 호출 제한기를 그대로 거치고 다른 기능과 함께 동작할 때 대기·제한 오류가 늘어나는지 확인한다.
- 기존 저장 표본의 공백 판정에 새 10초 상수를 소급 적용하지 않는다. 수집 실행/주기 변경 이력에 적용 시각을 남겨 구간별로 해석하고, 이력이 없는 과거 구간은 원인 불명으로 유지한다. 장중 주기 변경이 가능한지도 테스트한다.

### 4. 표본 수와 공백을 오해 없이 표시한다

대상: `hoga/live/investor_flow_store.py`, `deriv_flow_store.py`, `frontend/src/market/InvestorFlowCard.tsx`, `marketBits.tsx`.

- 카드의 `표본 713/1020`은 `저장 표본 713개`로 바꾼다. 기존 분모는 하루 전체 예정 슬롯이며 중복 생략도 있어 수신율처럼 표시하지 않는다.
- 상세 설명에 첫 저장 시각과 마지막 저장 시각을 제공한다. 개장 이후 첫 표본까지는 `저장 이력 없음`으로 표시하며 장애 원인을 추정하지 않는다.
- 기존 `gap_ranges`는 `저장 표본 공백`으로 설명한다. 이를 통신 실패 구간으로 이름 붙이지 않는다.
- 새 수집 상태 기록에는 실패/복구·수집 실행 시작 이벤트도 남겨 이후 발생한 확인 가능한 미수신 구간을 구분한다. 동일 값 수신 중에는 미수신 이벤트를 만들지 않는다.
- 확인된 미수신 구간은 차트 선을 끊거나 기존 토큰의 구간 표시로 드러낸다. 과거 원인 불명 공백은 상세에 시각과 ‘원인 확인 불가’를 표시한다.
- 과거 장중 공백을 보간해서 실측값처럼 만들지 않는다. 누적값 수집 재개와 장중 경로 복구는 구분한다.

완료 기준: 동일 값 생략을 장애나 수신율 저하로 표현하지 않으며, 확인된 미수신 구간을 연속 관측처럼 그리지 않는다.

## 검증 계획

기존 테스트에 회귀 시나리오를 추가한다. 실제 자격증명이 없는 격리 환경에서 실행한다.

- 백엔드 수집기: 동일 응답 반복, 한 시장/상품 실패, 빈 필수 행, 실패 후 복구, 저장 실패, 재시작, 날짜 변경.
- API: 상태 파일 없음/손상, 과거 상태 파일, 수집 소유권 분리, 30초 임계 경계, 확정점이 신선도를 덮지 않는 경우.
- 프론트 가짜 시계: 현물 07:59→08:00, 파생 08:59→09:00, 15:30→15:31, 파생 15:45, 현물 16:30, 주말·휴장일, 탭 복귀.
- UI: 정상/지연/연결 오류/미설정/종료, 오류 시 마지막 값 유지, 선택 상품 전환, 동일 값 장기 수신.
- 기존 `tests/test_investor_flow_collector.py`, `tests/test_investor_flow_store.py`, `tests/test_market_routes.py` 및 파생 관련 테스트 실행. 프론트 `market.test.ts`, `InvestorFlowCard.test.tsx`, `marketBits.test.tsx` 실행 후 타입 검사·린트.
- E2E: 정상→API 오류→복구와 표본 자동 증가를 격리 서버에서 확인한다. 이후 가동 중인 실서버에는 읽기 전용으로 3~5분 확인하고 정상 수신 시각 증가와 화면 반영을 대조한다. 사용자 서버를 재시작하지 않는다.
- 10초 수집 + 10초 화면 폴링에서 원천 값 변화의 화면 반영은 위상에 따라 약 20초와 요청 시간이 걸릴 수 있다. 이를 기준으로 측정하며 증권사 자체 지연까지 보장하지 않는다.

### 성능·운영 검증

- 동일 머신에서 하루치 30초 표본과 최대 3배 크기의 10초 표본 fixture로 응답 p50/p95, 파싱 횟수, CPU, 메모리, 이벤트 루프 지연, 응답 바이트를 비교한다. 브라우저 1개와 동시 5개 조건을 포함한다.
- 초기 합격 목표: 10초 조건의 API p95가 1초 미만이고, 30초 기준 대비 이벤트 루프 지연·제한 오류가 유의하게 악화되지 않을 것. 값이 안 바뀌는 요청의 재파싱은 0회일 것. 목표 미달이면 증분 파싱을 적용한 뒤 다시 측정한다.
- 실제 장중 적용 후 최소 30분 동안 수집 사이클 p95, 상품별 성공 간격, 호출 제한 오류, 공유 요청 대기 시간을 기록한다. 3~5분 화면 확인은 기능 점검이며 장중 안정성 검증을 대체하지 않는다.
- 실제 데이터가 매 요청마다 바뀌는 비율도 기록한다. 증권사 자체 갱신 빈도 때문에 10초 수집의 실효성이 낮을 수 있다.
- 호출 제한·다른 기능 대기·서버 응답 지연이 악화되면 서버 주기를 30초로 복구한다. 프론트는 API의 주기를 따라 복귀하며 신선도 표시와 캐시는 유지한다. 적용 중 사용자 서버의 재시작이 필요하면 별도 배포 단계에서 처리한다.

## 구현 결과 (2026-09-10)

- 기본 수집 주기를 10초로 변경하고 사이클 시작 간격에서 처리 시간을 차감한다. 느린 사이클을 중첩 실행하지 않으며 사이클 소요 시간을 상태 응답에 제공한다.
- 원본 JSONL은 변경 감지·최대 4파일 캐시를 공유한다. 새 인스턴스/동시 읽기도 합치며 미완성 꼬리·교체·truncate·읽기 중 append를 처리한다. 캐시된 모델은 읽기 전용으로 취급한다.
- 수신 상태는 `<investor-flow 또는 deriv-flow>/receipts/YYYYMMDD.json`에 원자적으로 저장한다. 시장/상품별 수신·저장 시각, 실패/복구 구간, 실행/주기 이력을 제공한다. 상태 파일 쓰기 실패도 원본 수집을 중단시키지 않는다.
- API에 `collection`을 추가했다. 기존 원본과 확정점은 정상 수신 시각의 근거로 사용하지 않는다. 구버전 데이터는 `unknown`으로 표시한다.
- 화면은 서버 일정·주기를 따르며 10초 갱신, 마지막 정상 수신 시각, 연결 오류와 수신 지연을 표시한다. 소형 상태 컴포넌트만 경과 시간을 갱신하므로 전체 차트를 매초 다시 그리지 않는다.
- 저장 표본 수의 분모를 제거하고 첫/마지막 저장 및 공백을 펼쳐 볼 수 있게 했다. 확인된 실패/복구 구간에서는 선을 연결하지 않는다.
- 표본마다 수집 주기를 남긴다. 주기 정보가 없는 과거 표본은 기존 30초 기준을 유지해 10초 전환으로 과거 공백 판정이 달라지지 않게 했다.
