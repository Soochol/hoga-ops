# 8종목 원본 충돌·수량 이력과 497종목 확대 검토

2026-10-24 KST. 기존 10종목 시범 복구의 격리된 8종목을 조사했다.
이번 작업은 검토다. 497종목 수집 실행, 원본 정정 승인, 운영 수량 증거 import,
저장 조건 변경은 수행하지 않았다. 기존 서버를 통한 분봉 조회는 캐시를 보충할 수 있다.

## 판단

**수정주가라는 개념 하나의 문제가 아니다. 기존 역산으로 만든 원본과 수집 중간 시점의
일봉이 섞여 있었다.** 가격·수량 기준을 분리한 방향은 유지해야 한다.

- 충돌 618개 종목·날짜 중 컬러레이 **476개는 기존 역산 방식으로 정확히 재현**했다.
  448개는 반올림 손실, 28개는 병합 후 구간에 잘못 적용된 5배 계수다.
- 동화약품의 기존 6월 2일 일봉은 **09:00~09:01 두 분봉을 합친 OHLCV와 전체 일치**한다.
- 다른 표본 6개도 기존 일봉이 정규장 또는 장후 특정 시점까지의 분봉 누적 OHLCV와
  전체 일치한다. 새 관측 종가는 조회한 8개 최근 표본 모두 마지막 분봉 가격과 일치한다.
  이 가운데 7개는 15:30 정규장 종가와 다르다.
- 남은 **142개 종목·날짜 전체**를 개별 확정 시각까지 복원한 것은 아니다. 특히 삼성전자와
  동화약품 9월 21일은 분봉 전체 거래량과 새 일봉 거래량도 일치하지 않는다.
  수량 변환만으로 설명하거나, 차이를 모두 애프터 거래량이라고 단정하면 안 된다.

**497종목으로 관측 수집은 확대할 수 있다. 정상 복구·조건 전환 완료로 처리하는 것은
아직 이르다.** 먼저 세션·확정 시각 계약과 정정 후보의 별도 판정 경로를 준비해야 한다.
단순 허용오차 확대, 기존 원본 덮어쓰기, 가격계수로 거래량 재구성은 사용하지 않는다.

### 동화약품 장중 값

6월 2일 09:00 분봉은 거래량 5,943, 09:01 분봉은 4,011이다. 합계 **9,954**,
시가 5,520 / 고가 5,520 / 저가 5,460 / 종가 5,460으로 보존 일봉과 전부 일치한다.
새 일봉은 고가 5,560 / 저가 5,410 / 종가 5,470 / 거래량 122,980이다.
기존 8/20·8/23 원본 백업에도 동일한 장중 값이 남아 있어 이번 복구가 만든 차이가 아니다.
장중 오늘 일봉 저장 차단은 이후 커밋 `7e3762007`에 추가됐다.

### 컬러레이 역산

448일(2024-01-02~2026-05-14)의 기존 거래량은 전부
`round(새 원본 거래량 / 5) × 5`로 재현된다. 차이는 ±1~2주다.
예를 들어 새 원본 118,678주는 기존 118,680주로 저장되어 있다.
정수로 반올림된 수정량에서 실제 원본량을 역산하면 잃은 나머지를 되찾을 수 없다.

28일(2026-06-11~2026-08-03)은 모든 OHLC가 새 원본의 1/5, 거래량이 정확히 5배다.
6/11 기존 종가 368원·257,685주와 새 원본 1,840원·51,537주가 대표적이다.
기존 `factors.parquet`도 이 날짜들에 5와 1을 번갈아 갖고 있으며, 기존 adjusted 값은
재곱셈으로 올바르게 보이는 경우가 있다. 원본 오류가 파생 가격에서 숨는 구조다.

관련 구형 코드 `hoga/api/screener_history_backfill.py`의 `unadjust`는 수정 OHLC를
계수로 나누고 수정 거래량에 계수를 곱한다. 모듈 문서에도 결손 구간 내 수량 사건을
모르는 상태에서 재구성한 raw가 역사적으로 부정확할 수 있다고 명시되어 있다.
이번 476일은 그 한계를 실데이터에서 재현한 결과다. 최초 writer의 실행 로그까지
확보한 것은 아니므로 실행 프로세스·개별 수신 시각을 확정했다고 표현하지 않는다.

나머지 8일(8/19~9/21)은 해당 식으로 설명되지 않는다. 병합의 정상적인 결과라고 묶지 않는다.
날짜·필드별 값은 [컬러레이 분류](coloray-classification.json)에 보존했다.

## 497종목 확대의 구체적 범위

| 항목 | 확인 수치 |
|---|---:|
| 기존 저장 조건의 날짜 누락 대상 | 497종목 |
| 당시 필요 구간의 누락 | 290,054개 종목·날짜 |
| 그중 시범 관측을 받은 종목 | 6종목, 모두 관련 창 충돌 격리 상태 |
| 시범 수집으로 별도 v2에 확보한 필요 날짜 | 3,096개 |
| 추가 관측을 받지 않은 대상 | **491종목** |
| 여전히 날짜 관측이 필요한 수 | **286,958개** |
| 기존 원본 OHLC에 소수점이 있는 대상 | **43종목, 12,689행** |

소수점은 필요 구간 안의 기존 원본에서 확인한 **역산 의심 신호**다. 43종목 전체가
잘못되었다거나 나머지 454종목이 정상이라는 판정이 아니다. 정수로 반올림된 역산은
이 점검으로 검출되지 않는다. 43종목 목록과 497종목별 상태는
[확대 대상 검토표](expansion-targets.json)에 있다.

497종목의 기존 실패 분류는 거래량 불일치 454, 공급자 불량 행 31, 가격 불일치 6,
기존 파생 변경 위험 6이다. 불량이 현재 필요한 날짜 밖이라면 해당 사실만으로
현재 창을 막지 않는다. 새 관측을 받기 전 성공 종목 수·행 수·호출 수를 확정하지 않는다.

497는 기존 **날짜 누락 집합**이다. 날짜가 원래 충분한 종목도 새 가격 관측이나 수량
이력이 필요할 수 있다. 따라서 497종목 수집 완료를 저장 조건 전체 유니버스의 검증
완료로 표현하지 않는다. 삼성전자·신라섬유는 이 497종목 밖의 대조군이다.

   공급자 기준일을 기록한다. 현재 공급자 일봉 종가를 15:30 정규장 종가라고 가정하지 않는다.
   확정 시각 전의 관측은 중간본으로 남기고 이후 관측과 구별한다. 기존 16시 가드와
   22시 스케줄러는 서로 다른 역할이며 수동·부팅 경로도 동일 계약을 따라야 한다.
2. **충돌 후보의 별도 판정**: 보존 원본·새 관측·사유·근거·영향 구간을 연결하는
   판정 기록을 추가한다. 기존 parquet는 보존하고 v2의 명시적으로 승인된 버전만 선택한다.
   역산 재현 476일도 반올림 허용오차로 통과시키지 않는다. 나머지 142일은 날짜별
   세션·확정 시점·공급자 정정의 분류가 더 필요하다.
3. **단계 수집**: 역산 의심 43종목에는 이미 수집한 컬러레이가 포함되므로 신규 대상은
   42종목이다. 이 중 일부와 가격 불일치·불량 행·변경 위험 사례를 골라 20~30종목으로
   먼저 검증하고 나머지로 넓힌다. 기존 서버 소유
   수집기·background 제한·체크포인트·개별 격리를 유지한다. 같은 기준일이면 시범 6종목의
   관측을 재사용할 수 있지만, 기준일이 바뀌면 수정 OHLC는 새 버전으로 확보해야 한다.
   현재 복구기는 다른 계획의 완료 항목을 자동 skip하지 않으므로 대상 목록에서 명시적으로
   제외하거나 재사용 기능을 먼저 추가한다.
4. **수량 이력**: 명시된 배정비율·정정 후 일정·검증 구간으로 인증한다. 무상·분할·병합,
   현금배당, 자기주식 소각, CB/BW·유상증자·정체성 변경을 구분한다. 미지원 사건을
   지나는 `share_adjusted` 창은 보류한다. `raw`로 자동 폴백하지 않는다.
5. **동일 조건 비교**: 기존 저장 7개·제외 설정의 해시와 기존 결과를 보존하고 새 결과는
   가격 기준 차이, 날짜 보충, 단위 보정, 충돌·미확인으로 설명한다. 같은 유니버스·시각·
   기준일을 고정해 실행을 저장하고 replay한다. 결과 없는 미확인을 '조건 불충족'으로
   합치지 않는다. 충돌 없는 가격만의 창과 raw/수량 보정 창의 준비 상태를 분리한다.

현재 [승인 설계](../../plans/2026-10-24-screener-adjustment-bases.md)는 CB·유상·합병의
자동 연결을 보류한다. 이번 검토에서 그 정책을 완화하거나 새 승인으로 간주하지 않았다.
