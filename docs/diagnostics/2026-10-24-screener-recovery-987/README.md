## 권고 실행 순서와 완료 조건

1. **대상 고정**: [종목별 계획](recovery-targets.json)의 `saved_window_gap` 497종목과
   저장 조건별 필요 구간을 1차 원본 복구 대상으로 고정한다. 나머지는
   `other_calendar_gap` 244종목, `prefix_review_only` 246종목으로 구분한다.
   ETF 포함 조건을 새로 사용할 때는 위 2종목의 16일씩 누락을 우선순위에 올린다.
2. **운영 실행 수단 준비**: 기존 수동 갱신 버튼은 `legacy_v1` 검증·공개 경로 그대로다.
   v2 과거 준비는 기존 서버의 클라이언트·페이지별 background 거버너를 재사용한다.
   현재 공개 유니버스 API는 임의 코드 목록을 받지 않으므로, 497종목만 실행하려면
   고정 코드 목록·요청 범위·체크포인트를 받는 서버 소유 운영 실행 경로를 먼저 마련한다.
   대상 지정을 위해 운영 관심종목·히트맵·로스터를 바꾸지 않는다.
3. **표본 검증**: 거래량 불일치·가격 불일치·불량 행·보존 충돌을 포함한 소규모 배치로
   시작한다. 기존 값 해시와 기존 정책의 결과를 고정하고 새 관측의 누락·충돌·불량 날짜를
   비교한다. 불량이나 충돌이 발견된 종목은 격리하고 나머지는 계속 진행한다.
4. **필요 구간 수집**: 같은 `adjusted_as_of`를 고정한 실행에서 원주가와 공급자 수정
   OHLC를 v2에 별도 보관한다. 현재 구현은 호출 시점의 날짜를 기준일로 정하므로 날짜가
   바뀌면 그 배치를 중단하고 새 기준일 배치로 재준비해야 한다. 기존 parquet·factor·
   저장 조건·제외 파일은 보존한다. 원본 부족 497종목과 별개로, 새 가격 기준으로 조건을
   평가하려는 대상 전체에는 해당 구간의 새 수정 OHLC가 필요하다.
5. **신고거래량 기준 확정**: 실제 거래량은 사용자가 명시한 새 조건 사본에만 `raw`로
   적용한다. `share_adjusted`는 독립적으로 검증한 주식 수 변환과 검증 구간이 있어야 한다.
   공급자 가격 조정률·빈 이벤트 목록을 수량 완전성 증거로 사용하지 않는다. 증거가
   없으면 관측 수집이 끝나도 수량 보정 판정은 미확인으로 남긴다.
6. **완료 판정과 보고 분리**: 요청 구간별 원본·가격·수량 증거·원본 충돌 상태를 따로
   기록한다. 기존/새 결과 차이는 정책 차이·누락 해소·충돌·미확인으로 설명하고 확정
   일봉 실행을 보존한다. 이전 `refresh_report.json`의 실패 987을 임의로 0으로 바꾸지
   않는다. 새 준비 완료와 기존 호환 갱신의 결과는 각각 보고한다.

전체 배치를 멈춰야 하는 조건은 원본 보존 해시 변화, 기준일 혼합, 취소, 공유 스케줄러의
지속적인 인증·레이트 제한 장애다. 원본 값 충돌이나 증거 부족은 개별 종목 격리 사유다.
수집 성공만으로 새 조건의 정상 판정 완료를 선언하지 않는다.
