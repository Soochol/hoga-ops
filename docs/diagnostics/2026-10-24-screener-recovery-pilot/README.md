# 스크리너 복구 실행 기능과 10종목 시범 복구

2026-10-24 KST. [987종목 검토](../2026-10-24-screener-recovery-987/README.md)의 후속 작업이다.
**복구 실행 기능을 구현하고 실제 운영 서버에서 10종목 수집을 수행했다.**
기존 parquet·계수·저장 조건·발생 제외·이전 갱신 보고는 보존했으며, 새 자료는
`screener/series_v2/`에만 저장했다. 497종목 전체 수집은 실행하지 않았다.

## 실행 기능

- 종목 목록·종목별 시작/종료일·수정 기준일·조회 시각·비교 요청·원본 해시·코드 지문을
  불변 계획으로 보존한다. 계획 파일 변경·다른 코드 버전의 재개를 거부한다.
- `POST /api/screener/recovery/{plan_id}/run`은 요청 연결과 독립된 서버 소유 작업을
  시작한다. 같은 실행 중 요청은 합류하고 다른 복구/기존 수집 작업과의 시작 충돌은 거부한다.
- 기존 키움 REST 클라이언트·페이지별 background 거버너를 사용한다. 별도 WS·인증 서버를
  만들지 않는다. 독립 실행 모드는 기본 체크아웃·운영 서버 중지·기존 유효 토큰을 요구한다.
- 수집 응답을 불변 객체에 먼저 저장하고 종목별 체크포인트를 남긴다. 재개는 완료/격리된
  관측을 다시 받지 않고, 공개 전에 중단됐다면 보관 응답으로 재시도한다. 개별 실패만 재시도한다.
- 취소·KST 기준일 변경·기존 입력 변경·더 새로운 가격 기준일 공개·지속 인증/유량 오류는
  전체 실행을 중단한다. 파일 공개와 체크포인트 쓰기는 취소 시에도 완료를 기다린다.
- 필요한 날짜의 원본 충돌·불량·가격 부족을 종목별로 격리한다. 수량 이력 확인은 관측 수집
  성공과 별도다. 수량 자료 없이 `share_adjusted`를 실제량이나 1배로 대체하지 않는다.
- 비교 명령은 운영 경로 밖의 새 복사본에서만 실행한다. 그 복사본의 로스터만 시범 종목으로
  한정하고, 저장 조건의 ETF 제외·관심종목/히트맵 스코프는 그대로 적용한다.

구현: `hoga/api/screener_recovery{,_api,_provider,_compare,_cli}.py`.
API 요청·응답은 Pydantic 모델과 `frontend/src/api/screenerRecovery.ts`로 미러했다.
별도 화면 버튼은 추가하지 않았다.

## 실제 수집 결과

수정 기준일은 **2026-10-24**, 수집 종료일은 **2026-10-23**으로 고정했다.

ETF는 확인된 상장일부터 수집했다. 계획은 [pilot-spec.json](pilot-spec.json)에 있다.

10종목 모두 요청 구간의 원본 날짜와 수정 OHLC 날짜는 확보했다. 공급자 파서가 이
요청 구간에서 보고한 불량 행은 0개다. 원본 추가 수는 기존 parquet에 새로 쓴 행 수가
아니라 **v2에서 추가로 확보한 유효 원본 날짜 수**다.

ETF 2종목은 요청 구간 전체를 원본 충돌 없이 준비했다. 나머지 8종목에는 보존 원본과
새 관측이 다른 날짜가 있어 전체 구간 준비 상태를 `quarantined`로 기록했다.
기존 값을 덮어쓰거나 새 관측을 정정으로 자동 승인하지 않았다. 모든 618개 충돌 날짜에
거래량 차이가 있고 일부에는 OHLC 차이도 있다. 출처·venue 차이인지 공급자 정정인지는
아직 확정하지 않았다. 날짜·필드·양쪽 값은 [conflict-review.json](conflict-review.json)에 있다.

격리는 필요한 비교 창에만 적용된다. 충돌이 없는 **최신 20거래일 실제량 조회는 10종목
모두 판정 가능한 상태**였다. 반면 독립 수량 이력은 10종목 모두 미확인이므로 수량 보정
신고거래량은 준비 완료라고 하지 않는다.

실행 후 같은 계획을 실제 API로 재개했을 때 작업 결과와 공개 스냅샷이 동일했다.
완료·격리된 10개 관측을 다시 공개하거나 교체하지 않았다. 이후 체크포인트 취소 처리와
CLI 도움말을 정리한 최종 코드의 지문은 수집 당시 지문과 별도 기록했다. 버전이 달라진
기존 계획의 재실행은 의도적으로 거부하며, 새 실행에는 새 계획을 만든다.

## 기존·신규 결과 비교

고정 조회 시각 `2026-10-24T16:30:00+09:00`. 기존 저장 조건 **7개**와 ETF를 포함하는
최신 20일 진단 조건 **2개**를 비교했다. 운영 로스터와 저장 조건은 수정하지 않았다.

- **기존 정책 결과 9/9가 비교 전후 동일**했다. 결과 행뿐 아니라 상태·경고·이력 커버리지와
  기준 시각을 함께 비교했다.
- 신규 `raw`·`share_adjusted` 결과 **18개를 보존하고 18/18 재실행 일치**를 확인했다.
  재실행 자료는 비교 복사본에 있으며, 운영 서버의 실행 보존 목록으로 옮기지 않았다.
- 장기 신고가(최근 400봉, 800봉 비교)의 시범 범위 결과는 기존 **2종목**에서 신규
  **4종목**으로 늘었다. 태광산업·대림제지가 추가됐다. 두 종목은 기존에 2024년부터
  683일만 보유했으나, 필요한 수정 OHLC 1,199일을 직접 확보해 더 긴 비교가 가능해졌다.
  원본 거래량 충돌을 무시한 결과가 아니라 가격 자료로 평가하는 조건의 변화다.
- 최신 20일 신고가 진단은 기존·신규 모두 `0113P0` 1종목으로 같았다.
- 최신 20일 실제량 진단은 기존·신규 모두 매치 0개였고, 신규 실제량의 불충분 종목도
  0개였다. 같은 조건의 수량 보정 결과는 **매치 0개·수량 이력 미확인 10종목**이므로
  정상 미충족과 구별한다.
- 장기 거래량 조건에는 원본 충돌 구간이 남아 있다. 비교 창이 충분한 과거 발생은 반환될
  수 있지만, 불충분 사유가 함께 있는 종목 전체를 정상 판정 완료로 집계하지 않는다.

[comparison.json](comparison.json)은 요청·기존 전후 응답·신규 응답·종목별 선택 여부와
미확인 사유·실행 보존 ID를 포함한다. `raw`/`share_adjusted`는 비교용 요청 사본에만 적용했으며
기존 조건을 실제량으로 바꾸거나 신규 저장 조건을 자동 생성하지 않았다.

## 보존 및 검증

[verification.json](verification.json)에 명령·입력 지문·환경·로그 해시를 기록했다.
[pilot-summary.json](pilot-summary.json)은 실제 HTTP 응답·상태·보존 결과 요약이다.

- 원주가·수정주가·계수·로스터·상태·기존 이력 자료·기존/신규 저장·제외 파일·이전 갱신
  보고서의 존재 여부와 내용 해시를 실행 전후 확인했다. 기존 저장 조건 7개는 그대로다.
- 운영 토큰 캐시 6개도 전후 동일했다. 시범 실행이 새 인증 토큰을 발급하지 않았음을
  파일 보존으로 확인했다. 키/토큰 값은 진단 산출물에 넣지 않았다.
- 기본 체크아웃의 기존 사용자 수정 파일 9개도 설치 전후 내용이 같았다.
- 최종 관련 백엔드 검사 **826개 통과**, Ruff 위반 0개. 타입 검사(앱·단위·E2E)와 Vite
  빌드 통과. 빌드의 기존 700 kB 청크 경고는 남아 있다.
- 실제 HTTP 상태 응답과 Pydantic 직렬화의 키·값이 일치했다. 프론트 enum을 임시로
  어긋나게 한 음성 대조에서 wire 검사가 실패했고, 복원 후 통과했다.

## 운영 명령

계획 작성은 인증·수집을 하지 않는다. JSON 형식은 시범 사양을 참고하되 새 실행의
기준일·조회 시각·대상 구간을 다시 정한다. 이전 날짜·다른 코드 버전의 계획은 재사용하지 않는다.

```bash
python -m hoga.api.screener_recovery_cli plan \
  --data-dir /운영/데이터 --input 복구사양.json --output 계획ID.json

# 기본 실행은 이미 실행 중인 운영 API에 요청한다.
python -m hoga.api.screener_recovery_cli run \
  --data-dir /운영/데이터 --plan-id <계획ID> --server-url http://127.0.0.1:8000
python -m hoga.api.screener_recovery_cli status --data-dir /운영/데이터 --plan-id <계획ID>
python -m hoga.api.screener_recovery_cli cancel --data-dir /운영/데이터 --plan-id <계획ID>
python -m hoga.api.screener_recovery_cli resume --data-dir /운영/데이터 --plan-id <계획ID>

python -m hoga.api.screener_recovery_cli compare \
  --data-dir /운영/데이터 --plan-id <계획ID> \
  --comparison-dir /새로운/별도/비교경로 --output 비교결과.json
```

원격 수집 응답과 작업 체크포인트는 운영 `screener/series_v2/`에 남아 있다. 비교용 전체
복사본 경로와 스냅샷·실행 ID는 비교 결과에 기록했다. 실제 관측 수집은 완료됐지만,
**8종목의 원본 충돌 승인과 10종목의 독립 수량 이력 검증은 완료 범위가 아니다.**
497종목 확대 전에 이 출처/venue와 수량 증거 문제를 검토해야 한다. 이전 수동 갱신
보고서의 `실패 987`은 역사적 결과로 보존했으므로 이 시범 실행만으로 0이 되지 않는다.
