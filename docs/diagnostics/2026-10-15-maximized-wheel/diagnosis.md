# 두산에너빌리티 분봉 최대화 후 휠 좌우 이동 조사

2026-10-15 KST · 제품 기준 `289d46c7893e150a0e7791d47d28ee0e4d52689b`

## 결론

두산에너빌리티(034020) 3분봉의 **과거 구간**에서 일반 휠을 반대로 돌릴 때 오른쪽 기준 캔들이 좌우로 움직이는 현상을 재현했다. 최대화 자체의 별도 휠 핸들러 문제가 아니라, 과거 구간에서 픽셀 앵커를 사용하지 않는 기존 정책이 넓은 화면에서 더 크게 드러나는 경우다.

최신 캔들이 화면에 들어온 경우에는 같은 테스트에서 좌표가 유지됐다. 이 조사로 최신 구간의 다른 조건까지 모두 문제가 없다고 단정하지 않는다. 사용자의 원래 휠 입력을 직접 녹화한 결과도 아니다.

## 재현 조건과 측정

실행 중인 로컬 서버에서 다음 **읽기 요청**으로 얻은 공개 시세를 `034020-3m.json`에 보존했다. 이후 브라우저 테스트는 이 응답을 모킹하며 백엔드나 벤더에 연결하지 않는다.

```text
GET /api/live/past-candles?code=034020&from=20261005&to=20261015&bucket_ms=180000&venue=KRX
```

실제 `/live`의 `ChartWindow`, `LiveChartRoot`, windowed 어댑터, production 휠 훅을 사용했다. 대상 창은 workspace의 창 id로 찾고 `window.__liveCharts.get(id)`로 측정한다. 최대화 버튼과 같은 `toggleMaximize(id)` 액션으로 일반→최대화→복원을 실행했다. 사용자의 열린 탭 배치·설정은 수정하지 않았다.

일반 휠 `deltaY=-120`, `+120`을 5회 왕복했다. 최신 구간과, 마지막 캔들보다 200칸 앞에서 끝나는 과거 구간을 비교했다. 각 배율의 최초 위치는 명시적으로 같게 설정했으므로 아래 수치는 최대화 전후 같은 봉 수에서의 비교다. 최대화 클릭 직후의 자연스러운 재배치량을 버그 이동량에 포함하지 않았다.

viewport 2766×1100, DPR 1 결과(CSS px):

| 논리 span (`봉 수 - 1`) | 일반 창 plot 폭 1702 | 최대화 plot 폭 2630 |
| --- | ---: | ---: |
| 과거 420 | 0.258px | 0.398px |
| 과거 100 | 1.074px | 1.660px |
| 과거 10 | 9.864px | 15.242px |
| 과거 3 | 27.125px | 41.915px |
| 최신 구간, 위 배율 전부 | 0.01px 미만 | 0.01px 미만 |

휠 왕복마다 확대 쪽으로 이동했다가 원위치로 돌아온다. 누적 팬이 아니라 방향을 바꿀 때 반복되는 위치 오차다. 각 시퀀스에서 plot 폭과 가격축 폭은 변하지 않았으므로, 이번 재현은 가격축 폭 변동으로 설명되지 않는다. 복원 후에는 원래 창 크기의 이동량으로 돌아왔다.

## 계산상 원인과 대조 실험

라이브러리에서 논리 인덱스 `a`의 캔들 중심은 다음과 같다.

```text
x = width - 1 - (to - a + 0.5) * width / (to - from + 1)
```

과거 화면의 오른쪽 끝이 정수 `a=to`라면 `x = width - 1 - 0.5 * barSpacing`이다. `to`만 고정하고 휠로 봉 간격을 바꾸면 캔들 중심은 **봉 간격 변화량의 절반**만큼 이동한다. 같은 봉 수에서는 `barSpacing`이 plot 폭에 비례하므로 최대화가 이동을 증폭한다. 표의 수치는 이 식의 예측과 일치했다.

같은 차트·데이터·가격축을 두고, 진단 코드에서만 과거 기준 캔들 중심을 앵커로 삼는 수식을 적용해 비교했다. 제품 코드의 수정 없이 원인 분기를 분리하는 대조 실험이다. **최대 이동이 41.915px에서 2.1e-11px 이하로 감소**했다. 1400px·2766px viewport, DPR 1·1.35에서 동일한 결과였다.

## 수정 방향

일반 휠의 과거 구간에도 화면 오른쪽에서 보던 실제 캔들의 픽셀 앵커를 적용하는 방향이다. 최신 캔들을 화면으로 끌어오는 동작으로 바꾸면 안 된다. 공유 시간축에 캔들 없는 지표 포인트가 있을 수 있으므로, 단순 `floor(to)`가 항상 실제 캔들이라고 가정하지 말고 오른쪽 실제 캔들을 구해야 한다.

이는 기존의 **과거 `to` 숫자 고정** 계약을 **과거 기준 캔들 중심 고정**으로 바꾸는 정책 수정이다. 위 단위 테스트와 관련 wheel 설계 문서도 함께 갱신해야 한다. 일반/최대화/복원, 정수·소수 우단, 희소 지표 시간축, native/windowed, 줌 양 끝 한계, 연속 입력, 백필, Ctrl/Cmd·Shift·Alt를 함께 검증한다.

위 내용은 제품 수정 전 조사 기록이다. 이후 구현과 검증은 아래 기록을 따른다.

## 구현 및 수정 후 검증

2026-10-15 KST에 `useWheelInteractions`와 계산 헬퍼를 수정했다. 과거 구간의 오른쪽
실제 캔들을 공유 시간축 인덱스로 찾아 픽셀 앵커로 전달한다. `drawnCandleIndex`의
기존 캐시를 재사용하고 정렬된 캔들을 이진 탐색하므로 매 휠마다 전체 이력을 순회하지 않는다.

연속 휠에서 새 캔들이 작은 우측 여백에 들어와도 기존 앵커를 유지한다. native 차트의
다음 프레임 전 연속 입력은 이전에 그려진 범위를 다시 읽을 수 있으므로 마지막 입력
범위와 요청 범위를 모두 구분해 같은 앵커를 유지한다. 팬·외부 범위 변경·창 폭·축 세대가
바뀌면 현재 화면에서 다시 고른다. 실제 캔들이 없는 화면은 기존 숫자 `to` 고정을 유지한다.
데이터 시작점의 native 최소 노출 한계도 줌 계산에 반영했다.

- 관련 Vitest 4개 파일 **246개 통과**.
- native/windowed, 최신/과거, Ctrl/Shift, 프레임 전 burst, 줌 한계, Virtual Axis prepend,
  실제 `LiveChartRoot` 백필을 검증하는 E2E **56개 통과**.
- 실제 라이브러리의 지표 전용 시간축 칸 대조 E2E **2개 통과**.
- 두산에너빌리티 fixture로 일반→최대화→복원, DPR 1/1.35, 폭 1400/2766을 확인한
  E2E **4개 통과**. 기존 최대 41.915px 이동이 **2.1e-11px 이하**로 감소했다.
- 전체 TypeScript 검사, ESLint 오류 검사와 production build를 수행한다. 최종 통과 상태와
  명령·기준 SHA·입력 지문은 `fixed-verification.json`에 기록한다.
- 기존 build의 700KB 초과 청크 경고와 mocked 화면의 ResizeObserver loop 경고는 남아 있다.

수정 후 측정은 `fixed-*.json`, 수정 전 측정은 `measurement-*.json`이다. 진단 명령은
기본적으로 수정 후 좌표 고정을 검사하며, `HOGA_WHEEL_BASELINE=1`은 수정 전 코드에서
실행할 때 기존 오차를 검사하는 모드다.
