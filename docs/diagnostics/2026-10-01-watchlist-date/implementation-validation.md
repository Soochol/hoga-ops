# 날짜 위치 보존 구현 검증

2026-10-01 KST, 현재 작업 트리 기준. 기존 분봉 렌더링 최적화에 위치 보존을 추가했다. 실제 벤더 응답 대신 순서와 지연을 제어한 API 픽스처를 사용했으며, 브라우저에는 실제 차트 라이브러리를 띄웠다.

## 구현

- 렌더링 어댑터가 이전 시간 격자와 그 격자를 만든 Virtual Axis 변환을 함께 보관한다. 새 격자 반영 직전에 현재 화면의 기준 시각을 실제 ms로 읽고 새 축으로 다시 찾아 범위를 옮긴다. 변경된 축을 통해 옛 데이터를 읽지 않는다.
- 최신 캔들이 화면에 있으면 마지막 실제 캔들과 기존 우측 여백을 유지한다. 과거 화면은 보던 시각과 표시 폭을 유지한다. 오늘 시드 이후 과거 추가, 지표만 바뀐 합집합, 왼쪽 트림, 실시간 새 봉을 동일한 반영 절차로 처리한다.
- 라이브러리가 다음 프레임에 적용할 범위도 보관해, 한 프레임 전에 데이터 배치가 연속으로 들어와도 마지막으로 요청한 위치를 승계한다. 드래그 중 반영은 현재 포인터에서 계속 이동하도록 기준 범위를 함께 바꾼다.
- 일반 백필 재투영은 이 어댑터에 중복 적용하지 않는다. 소스 교체와 명시적 복원은 기존 상위 정책을 유지한다. 대부분 빈공간인 화면의 기존 재투영 자격 판정도 유지한다.
- 최신 복귀 애니메이션의 시작과 목적지 역시 격자 변경에 맞춰 다시 투영하며, 명시적 팬은 애니메이션을 취소한다. 범위 알림은 화면 반영 후 예약해 중간 범위의 동기화·조회 발행을 줄인다.

## 검증 결과

| 검증 | 최종 결과 |
| --- | --- |
| 앱·단위·E2E TypeScript 검사 | 통과 |
| 전체 Vitest | 600 파일, 7,695 테스트 통과 |
| 제품 빌드 | 통과, 기존 큰 번들 경고 있음 |
| 관심종목 1분봉 선택 → 오늘 시드 → 과거 추가 | 5회 통과 |
| 관심종목 15분봉 선택 → 오늘 시드 → 과거 추가 | 5회 통과 |
| 새로고침 → 초기화 → 일봉의 분봉으로 → 응답 대기 중 드래그 → 응답 후 계속 드래그 → 점프 해제 | 5회 통과 |
| 긴 이력: 캐시 내 드래그·백필·값 일치·창별 캐시 이동·수동 Y축 팬 | 5회 통과 |

관심종목 테스트는 분봉 범위를 수동으로 재배치하지 않는다. 데이터 마지막 봉과 화면 우단 봉이 동일하고 최신 봉 x 좌표 오차가 1 CSS px 미만이며, 표시 폭과 봉 간격이 유지됨을 단언한다. 점프 테스트는 09-29 기준일의 데이터 우단과 칩이 좌측 확장 뒤에도 유지되는지 확인한다. 분할 조회는 기준일보다 이른 날짜에서 끝날 수 있지만 기준일보다 미래를 요청하지 않는다.

드래그는 화면을 이동하는 기존 동작이다. 드래그 자체로 화면의 우측 날짜가 바뀔 수 있으며, 손을 놓거나 데이터를 추가하는 것만으로 추가 이동하지 않아야 한다. 이 검증은 우측을 고정하는 새로운 제스처를 도입하지 않는다.

반복 검증 과정에서 두 계측 문제를 수정했다. 포인터 이벤트 직후 native draw 전에 x 좌표를 읽던 비교는 두 프레임 뒤 측정으로 바꿨다. 기존 긴 이력 테스트는 합집합 재매핑 중에도 논리 번호가 같아야 한다고 단언했는데, 같은 날짜의 번호는 바뀔 수 있으므로 동일한 봉을 식별해 실제 포인터 픽셀 이동량과 비교하도록 바꿨다. 이 변경 후 5회 전부 통과했다. 날짜 앵커·백필 후 위치·배율의 단언을 완화하지 않았다.

최종 제품 해시와 단계별 결과는 [검증 JSON](implementation-validation.json), 반복 성공 로그는 [신규 시나리오](new-scenarios-repeat.log)와 [긴 이력](deep-history-repeat.log)에 있다. 핵심 20회는 같은 제품 코드로 실행한 두 실행의 합계다. 전체 E2E는 성능 개선과 합친 별도 작업 공간에서 최종 검증 중이다.

사용자 개발 서버 5173·8000은 유지했다. 테스트는 별도 포트 20581·21581, 빈 벤더 자격증명, 별도 데이터·dist·Vite 캐시를 사용했고 종료 후 임시 설정을 정리했다. [Playwright 설정](viewport-e2e.config.ts.txt)과 [Vite 설정](viewport-e2e-vite.config.ts.txt)을 진단 자료로 보관했다.

원본 데이터와 전체 지표 계산을 유지하는 성능 최적화도 유지한다. 이 위치 보존 변경에 대한 별도의 성능 수치 계측은 수행하지 않았으며, 실제 벤더 데이터 가용성을 검증한 결과도 아니다.
