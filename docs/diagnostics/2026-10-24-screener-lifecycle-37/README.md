## 구현과 운영 반영

- `screener_daily_lifecycle.py`에서 검토된 종료일·사유·확인 시각·출처를 별도 불변 객체에 저장한다.
  등록 시 원문 해시와 종목코드 연결을 검증하고, 기존 출처와 종료일 충돌·검토 객체 변조는 거부한다.
  기존 `history_evidence.json`을 수정하지 않고 수집 범위에만 근거를 겹쳐 적용한다.
- 공급자 요청 전에 종료 확인 종목을 건너뛴다. 이번 37종목과 기존 출처가 있던 51종목으로
  정기 요청 제외 대상은 총 88종목이다. 과거 미확인 일봉은 `retired_history_unavailable`로 남기고
  매일 반복 재시도 대상에서만 제외한다. 잠정·충돌·기존 승인 정정은 삭제하거나 해제하지 않는다.
- 활성 종목의 미제공·처리 실패·저장 대기는 기존 재시도 예산(하루 2회, 최소 30분)을 유지한다.
  새 거래일과 재확인할 활성 관측이 없으면 종료 종목의 과거 누락만으로 주말 전체 재시도를 하지 않는다.
  추가 공급자 폴링·KRX 자동 조회·차트 폴링은 추가하지 않았다.
- 운영 반영은 기존 uvicorn reload/Vite HMR을 사용했다. 별도 브로커 클라이언트나 자격증명 복사,
  사용자 서버의 수동 종료·재시작은 하지 않았다. 진행 표시에도 종료 확인 수와 미제공 재시도 수를 추가했다.
- 현재 원장 재분류는 기존 원본 응답만 재사용했다. 실제 관측 시각 22:31:30.972795, 당일 시도 2회,
  공급자 사용량·관측 원장·확정 이력은 유지했다. 새 브로커 원본 응답은 0개다.

## 데이터·결과 비교

`operation.json`은 실제 운영 상태, `comparison.json`은 복제 데이터의 독립 검증이다.
실제 운영 상태는 처리 오류 0, 미확인 2, 재시도 가능한 미확인 0, 종료 확인 88이다.
출처로 설명되는 범위 밖 날짜는 264개에서 443개로 재분류됐고, 기존 값과 일치한 관측은 21,571개다.
잠정·새 확정·새 충돌은 모두 0이다. 원래 존재하던 별도 복구 충돌 12건을 해결했다는 의미는 아니다.

- 원주가·수정주가·계수·수량 근거·종목 목록·저장 조건 등 보호 대상 8개 파일과 미존재 3경로,
  복구 계획·작업 파일 9개의 해시를 확인했다. 기존 관측 원본 전부와 원장 entries·attempts·confirmed_through도 동일하다.
- 현재 v2 스냅샷 `ab727fe060b27e9b8b188c2153e201178c8088ab8ba89803f1cbf5b6d841cc2c`는 동일하다.
  원래 v2 스냅샷 `5c4fb9b34ab6898a2e9f5aae78d0394c1bd78e9443e40e155bdae764d4d6cc3b`와
  baseline·observations·quantity·corrections도 보존됐다.
- 기존 저장 검색 7개의 결과를 고정 시각에서 비교했다. 실제 HTTP v2 원수량 신고거래량·주식 수
  조정 신고거래량·가격 조건 3개도 반영 전후 비교하고 새 실행의 정확 재실행과 옛 실행 GET을 확인했다.
  코드 지문이 바뀐 옛 실행을 현재 코드의 정확 재실행으로 인증하지 않는다.
- 복제 데이터에서 정기 수집 분기를 강제 실행해 4,404종목 중 종료 88종목을 제외한 4,316종목만
  fetch 콜백을 호출했다. 기존 타임스탬프의 저장 응답만 반환했으며 네트워크 요청은 0회다.
  일요일(직전 거래일 동일)은 실행 불필요, 월요일(새 거래일)은 실행 필요임을 검증했다.
  이 강제 실행은 운영에서 세 번째 수집을 실행했다는 의미가 아니다. 실제 `skipped_codes`는
  이번 재분류 시 0이며, 다음 실제 정기 실행에서 집계된다.

## 검증 입력과 재현

최신 main의 복기노트 변경까지 병합한 소스·테스트·의존성·설정·도구 버전과 head/base SHA는
`verification-inputs.json`에 기록한다. 이전 main에서의 통과 결과와 구분해 변경된 범위를 최종 입력으로 재검증한다.

- 백엔드: `.venv/bin/ruff check .`, `.venv/bin/pytest -q -m 'not wallclock'`.
- 프론트: `npm run typecheck`, `npx vitest run`, `npx vite build`.
- 종료 판정 미래 시각·미래 폐지일, 검토 철회 후 재활성화, 원문·검토 객체 변조, 종료일 충돌,
  활성 미제공 재시도 유지, 당일 예산 보존, 기존 격리 유지에 대한 회귀 검증을 포함한다.
- UI는 기존 상태 문자열만 확장했으며 레이아웃·입력 동작은 변경하지 않았다.
