# 스크리너 거래일 중복과 조건 평가 조사

## 확인된 원인

2026-10-20 자정 이후 사용자 저장 조건 `장단기 신고거래 + 4d 신고가`를 같은 API에
`eod`와 `intraday`로 조회했다. 확정 조회는 23종목이고 삼성전자를 제외했지만,
장중 조회는 55종목이며 삼성전자의 가격일·4일 신고가 발생일을 10/20으로 반환했다.
이 숫자는 당시 조회 결과이며 나머지 차이 전부를 같은 오류라고 판정한 것은 아니다.

확정 일봉에서 삼성전자 고가는 10/14 241,500원, 10/15 221,500원,
10/16 222,500원, 10/19 224,000원이다. 10/19는 후보 포함 3봉 신고가다.
키움 복수시세에는 거래일이 없는데 기존 overlay는 조회한 달력 날짜를 붙였다.
전날 OHLCV를 10/20 봉으로 복제하자 비교 4봉이 10/20·19·16·15로 밀려
10/14의 더 높은 고가가 빠지는 것을 SQL에 같은 데이터를 넣어 재현했다.

원주가·수정주가 parquet는 수정하지 않았다. 문제의 봉은 조회 중에만 생성됐다.
수정 후 같은 저장 코퍼스와 조건을 읽기 전용으로 실행했으며, 장전의 `eod`와
`intraday`가 모두 동일한 23종목을 반환하고 삼성전자를 제외하는 것을 확인했다.
이 확인은 장전 게이트에서 벤더 접근 없이 끝났으며 사용자 서버를 재기동하지 않았다.

## 조건별 영향과 조치

| 범위 | 조사 결과 | 조치 |
|---|---|---|
| 신고가·신고거래량·기간내 변형 | 중복 봉이 비교/발생 창을 밀거나 동률 신고를 생성할 수 있음 | 실제 장 시작 전에는 새 일봉 생성 금지 |
| 이동평균·신고가 대비 고가 | 중복 봉으로 이평/최고가 비교 창이 바뀜 | 같은 overlay 진입부에서 차단 |
| 등락률 | 전날 종가를 새 봉으로 복사하면 전일 대비가 0%가 됨 | 같은 진입부에서 차단 |
| 거래대금·기간내 거래대금·현재가 범위 | 전날 값을 새 날짜의 충족 기록/가격으로 표시할 수 있음 | 같은 진입부에서 차단 |
| D/W/M 봉 조건의 시세 누락 | SQL은 EOD로 대체하지만 봉 평가기는 빈 오늘을 요구해 종목을 탈락시킴. 부분 누락에서도 재현 | 누락 종목만 확정 기준으로 평가 |
| 거래일 달력 갱신 | 기존 6시간 주기만으로는 장 시작 후에도 오늘이 미확인으로 남을 수 있음 | 장 시작에 재확인하고 장중 미확인 상태만 1분 간격 갱신, 확인 후 기본 간격 복귀 |
| 분봉 조건 | 벤더 봉에 실제 거래 시각이 있어 날짜 복제 경로와 독립 | 일봉 대체가 분봉 시각을 바꾸지 않는 회귀 테스트 |
| 매도·매수 총잔량 신고/기간내 신고·기준시각 돌파 | 별도의 날짜별 캡처/승격 파일을 사용하며 시세 OHLCV overlay 미사용 | 기존 회귀 테스트 포함, 같은 날짜 복제 결함은 발견하지 못함 |
| 날짜 범위·발생 제외·AND/OR | 별도 날짜 제한과 발생 키/종목 집합 조합 경로 | 기존 회귀 테스트 포함, 이번 조사에서 추가 결함은 발견하지 못함 |

## 검증

- 신규 테스트를 기존 구현에 실행해 일봉 조건 10건과 주·월봉 부분 시세 누락 18건,
  총 28건이 실패하는 것을 확인했다.
- 장전·휴장일·주말·달력 미확인·자정 캐시·09:00 경계·KST/UTC·월요일 장전·
  부분 시세 누락·분봉 혼합을 고정 시각/가짜 공급자와 격리된 데이터로 검증한다.
- 달력 갱신은 08:59:30 → 09:00 → 09:01의 최초 거래일 확인 뒤 6시간 간격으로
  돌아가는 것을 실제 태스크에 가짜 시계와 대기 함수를 주입해 검증한다.
- 전체 스크리너 API 테스트, 거래일 달력, REST wire 계약과 관련 프론트 테스트를 실행한다.
  정확한 최종 명령·대상·SHA·입력 지문·결과는 해당 PR 검증 기록을 기준으로 한다.
