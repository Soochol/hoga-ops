# 최대벽 소량 입력 비용 보완

## 결정

직전 후보 가지치기 개선에서 추가 그룹 집계는 작은 프레임의 정렬 절감보다 비쌌다.
세 후보 함수에 4,096행 기준을 두고, 그 미만은 PR #1925의 전체 정렬 경로를 그대로
사용한다. 이상은 최대 잔량 후보만 남기는 직전 개선을 유지한다. 이 값은 실측한
보수적 전환점이며 모든 데이터·하드웨어의 최적값이라는 뜻은 아니다.
행 수는 기존 DataFrame 메타데이터로 확인하며 별도 스캔하지 않는다. 체결 후보는
원본 행 수를 사용해 필터 결과를 미리 materialize하는 추가 비용을 피한다.
스레드 수, 실행시간, 처리 건수, 출력 행 수의 제한이 아니다.

## 후보 비교

실제 Stock-Date 5개에서 동일한 SQL 결과 프레임을 공유하고 실행 순서를 교대했다.
출력 비교는 ask/bid 모든 필드와 대표 행 목록의 순서를 포함한다.

- `prototypes.json`: 각 4회. 직전 개선 대비 분당 체결 극값 공유의 CPU 절감은
  1.3%, 기록 정렬 공유는 0.4%였다. 소량 표본에서 후퇴도 있어 채택하지 않았다.
  가격별 가지치기를 전부 제거하고 봉별만 유지하면 CPU가 2.3% 늘어 채택하지 않았다.
- `small-frame-prototypes.json`: 각 8회. 직전 개선 CPU 합계 73,187ms에서
  4,096행 기준은 70,843ms(-3.2%), 16,384행 기준은 71,340ms(-2.5%)였다.
  완료 시간은 각각 약 2.2%, 2.3% 감소했다. 출력 불일치는 없었다.
- 추가로 지정했던 267260/20260218, 005490/20260212는 저장된 데이터가 없어 제외했다.
  실제 측정 대상은 아래 다섯 개이며, 표본을 추가했다고 주장하지 않는다.

## 최종 구현 재검증

기준: 병합된 PR #1925, commit `6fc7109c`.
기존 후보 가지치기와 이번 소량 입력 분기를 합친 결과다.
Polars 기본 32스레드를 유지했다. 진단 프로세스의 DuckDB는 양쪽 모두 4스레드이며
사용자 서버 설정을 바꾸지 않았다. 실제 Stock-Date 5개 × 8회, 실행 순서 교대.
벤치마크와 자체 테스트는 동시에 실행하지 않았다.

| 측정 범위 | 이전 | 최종 | 감소율 |
|---|---:|---:|---:|
| 집계 CPU | 66,583ms | 59,790ms | 10.2% |
| 집계 완료 시간 | 5,699ms | 5,235ms | 8.2% |
| SQL 포함 CPU | 77,388ms | 70,733ms | 8.6% |
| SQL 포함 완료 시간 | 10,328ms | 10,086ms | 2.3% |

| Code / 날짜 | SQL 포함 CPU 감소율 |
|---|---:|
| 373220 / 20260219 | 3.1% |
| 267260 / 20260219 | -4.9% |
| 005490 / 20260213 | 4.0% |
| 005930 / 20260921 | 13.0% |
| 000660 / 20260921 | 14.3% |

소량 데이터의 손해를 완전히 없앤 것은 아니다. 267260 표본은 아직 약 4.9%의 CPU
증가가 남는다. 이 한 표본에 맞춘 추가 임계값은 도입하지 않았다. 전체 표본을 합친
CPU 절감과 모든 결과의 동일성을 근거로 이번 분기를 채택했다.

정확성은 동일한 SQL 프레임 40쌍에서 검증했다. 별도 SQL 실행은 기존 동률 입력
순서가 변할 수 있어 정확성 오라클로 사용하지 않고 성능 측정에만 사용했다.
실행 중인 다른 앱을 통제하지 않은 로컬 측정이다. CPU 시간 절감은 전력이나
노트북 온도 감소율과 같지 않으며, 서버 반영 후 일일 작업 관측은 아직 하지 않았다.

## 코드 및 재현

- `hoga/tables/snapshots.py`: 세 후보 선택 함수의 작은 입력 분기.
- `tests/test_peak_candidate_pruning.py`: 12개 시드 × 세 함수 × 1,500/4,095/4,096/4,097행.
  빈 입력 및 4,096행 모두 미체결인 경우도 기존 전체 정렬 결과와 대조한다.
- `probe_sharing.py`, `probe_small_frames.py`: 실험 후보 비교. 직전 함수 사본은
  `pruning_baseline.py`에 동결해 최종 코드로 실행해도 실험 기준을 유지한다.
- `benchmark.py`: 최종 코드와 병합 기준 비교. 기본 모드는 정확성 및 집계 비용,
  `--full`은 SQL 포함 비용. 스크립트 머리말의 기준 파일 준비 절차를 따른다.

검증 완료: Ruff 및 diff 공백 검사 통과. 전체 백엔드 5,565 통과, 2 건너뜀,
wallclock 13개 제외, 기존 경고 35개(145.47초).
현재 작업 워크트리의 변경이며 main 병합 및 사용자 서버 반영은 하지 않았다.
