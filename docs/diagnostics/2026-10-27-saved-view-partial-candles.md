# 저장뷰 분봉 부분 공백 보충

## 확인한 원인

우리로 `046970/20261016`의 hogaplay 캔들 파일은 500행으로 11:22~20:00만 갖고 있다.
메타는 `collection_complete=true`, `is_partial=false`여서 캔들 소스 선택에서는 이
파일이 선택된다. 이 날짜는 `missing_dates=[]`여서 기존 저장뷰 보충 대상도 아니다.
500행 제한의 수집기 추가 조회는 이미 수정됐지만 이 과거 파일은 복구되지 않았다.
실제 열린 저장뷰의 10/16 오후 봉은 확인했으며, 하루 전체가 안 보이는 현상은 재현하지
못했다. 오전 누락은 디스크 파일과 서버 응답 양쪽에서 확인했다.

## 변경

- 로컬 캔들 시각과 날짜별 세션 경계로 선행·내부·후행 공백의 조회 후보를 만든다.
- 기존 순차 조회·예산·캐시·KRX·과거일·수정계수 검증을 사용한다.
- 보충 응답을 표시 주기로 접은 뒤 디스크에 없는 버킷만 추가한다. 기존 OHLCV와
  방향별 거래량은 보존하며 공급자에 없는 분의 가격·거래량을 생성하지 않는다.
- 거래량 0인 공급자 원본 봉도 유지한다. 응답이 없음을 무체결로 단정하지 않는다.
- 같은 날 부분 보충은 저장뷰 칩으로 알리고 기존 호가 지표는 보존한다. 호가 지표를
  소급 생성하지 않는다. HogaPlay 전용 모드와 국내 일반 실시간 경로는 유지한다.
- 과거 하루짜리 저장뷰도 실제 오늘을 기준으로 보충한다. 최초 저장 구간 배치는
  보충 후 한 번 적용하며 이후 조회가 이미 완료한 배치의 표식을 초기화하지 않는다.

## 실데이터 확인

기존 운영 서버 `127.0.0.1:8000`의 같은 Code·날짜·KRX·1분 응답을 읽어 새 병합
함수에 넣었다. 새로운 자격증명 프로세스나 WS 구독은 만들지 않았다.

| 항목 | 결과 |
| --- | --- |
| 디스크 봉 | 500 |
| 키움 REST 봉 | 620 |
| 수정계수 | 1.0 |
| 추가 봉 | 141 |
| 병합 봉 | 641 |
| 09:00 이상 10:00 미만 | 09:02~09:59의 58봉 |
| 기존 500봉 OHLCV·방향별 거래량 | 전부 동일 |
| 병합 시각 중복 | 없음 |

공급자가 09:00·09:01 봉을 반환하지 않아 생성하지 않았다. 실제 무체결인지 여부는
확인하지 않았다. 이 검증은 조회·메모리 병합이며 운영 Parquet를 수정하지 않았다.
코드는 이 작업 워크트리에서 검증했고 운영 체크아웃·서버는 변경하지 않았다.
