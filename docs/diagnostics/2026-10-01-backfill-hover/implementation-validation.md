# Live 과거봉 백필 성능 개선 검증

2026-10-01 작업 트리의 구현을 검증했다. 제품 변경은 `frontend/src/chart/windowedChart.ts`의 표시 구간 어댑터와 병합·좌표·세션 계산 최적화다. 상세 설계와 적용 범위는 [구현 계획](../../plans/2026-10-01-live-backfill-interaction-performance.md)에 기록했다.

## 차트의 동작과 부작용 검사

신규 브라우저 테스트는 120일 분봉을 실제 lightweight-charts에 넣고 다음을 확인한다.

- 표시 구간의 경계를 넘는 마우스 드래그를 5회 반복해 이동량이 봉 간격과 일치하는지 검사한다.
- 과거봉 응답을 지연시킨 채 드래그하고, 응답 후 같은 봉의 위치 오차가 1 CSS px 미만이며 봉 간격과 가시 폭이 유지되는지 검사한다.
- 전체 데이터는 3만 점 이상 유지하면서 실제 라이브러리 입력은 2천 점 미만인지 검사한다.
- 실제 라이브러리의 OHLC와 MA가 전체 원본의 값과 일치하는지 검사한다.
- 캐시 구간 왕복과 최신 봉 복귀에서 추가 과거봉 API 요청이 없는지 검사한다.
- 수동 Y축 팬의 가격 범위 이동, 다른 창에서 아직 표시하지 않은 캐시 시각으로 점프를 검사한다.
- 브라우저 실행 중 페이지 오류가 없는지 검사한다.

어댑터 단위 테스트는 희소 선의 실제 경계 이웃점과 값, 합집합 시간 인덱스, 전체 최신 값 조회, 화면 밖 라이브 업데이트의 원본 불변성, primitive·크로스헤어 시리즈 식별, 제거 시 예약 작업 취소, 전체 렌더링 복귀도 검사한다. 기존 프로젝트의 계산 테스트를 함께 통과했다. 모든 지표 조합과 모든 하드웨어에서 같은 성능을 보장하는 검증은 아니다.

## 성능 측정과 남은 제약

프로덕션 빌드, Chrome, 1800×1000, CPU 감속 없음, 기본 4 MA, 툴팁 OFF, 동일 지연 응답 조건으로 측정했다. 계측은 어댑터의 예약 호출이 아니라 실제 라이브러리 `series.setData()` 호출을 측정한다.

| 120일 이력에 10일 추가, 1창 | 변경 전 2회 | 최종 구현 3회 |
| --- | --- | --- |
| 최대 프레임 간격 | 383.3–433.4ms | 50.1–66.7ms |
| 실제 시리즈 교체 총 시간 | 215.8–255.4ms | 3.6–4.7ms |
| 응답 주변 긴 작업 | 원시 자료 참조 | 62–72ms |

전체 35,814 슬롯을 보관하면서 라이브러리는 약 555 슬롯을 그렸다. 원시 자료는 `results.json`, `after.json`, `after-calendar.json`, 비교표는 `implementation-comparison.json`이다. 16조건 비교와 최종 3회 측정은 단위 테스트·E2E와 동시에 실행하지 않았다.

최대 프레임 간격은 직접 마우스 입력 지연 또는 INP가 아니다. 전체 원본에서 수행하는 수치 계산과 투영은 여전히 남아 있으므로 50ms 목표를 모든 반복에서 충족하지 못했고, 완전한 무끊김으로 표현하지 않는다. Worker와 화면 주변만 투영하는 계산 엔진은 이번 구현에 포함하지 않았다.

일반 종목 분봉의 마우스 환경에 적용한다. 터치 가능 기기, 초봉·일주월·지수는 기존 렌더링 경로를 유지한다. 작은 이력, 큰 줌아웃, native 최신값 라벨·가격선, custom series도 전체 렌더링으로 돌아간다. 희소 선의 실제 이웃점이 멀면 표시 구간이 넓어질 수 있다. 따라서 모든 구성에서 라이브러리 입력량이 동일하다는 보장은 없다.

## 전체 E2E 실패 10개

첫 전체 실행과 최종 전체 실행에서 같은 10개가 실패했다. 테스트 오류와 현재 UI, 변경하지 않은 소스의 HEAD를 대조해 아래 계약 불일치를 확인했다. 변경 전 전체 E2E를 별도로 실행해 얻은 기준 결과는 아니다. 이번 성능 변경의 테스트를 통과시키기 위해 이 선택자나 기대값을 수정하지 않았다.

## PR 준비 중 기존 UI 테스트 정리

실패한 테스트의 전제를 현재 제품 결정과 대조했다. [PR #1859](https://github.com/Soochol/hoga-ops/pull/1859)는 종목별 발생 건수 버튼과 펼치기 영역을 의도적으로 제거했다. 따라서 해당 버튼을 복원하거나 테스트를 건너뛰지 않고, 현재 지원되는 사용자 동작을 검증하도록 바꿨다.

- 과거 일봉 수집과 자동 재조회는 그대로 검증하고, 거래량·거래대금의 날짜별 근거는 실제 CSV 다운로드로 검사한다.
- 스크리너 제외 테스트는 현재 남아 있는 기존 제외 기록의 복원 UI를 사용한다. 저장 실패 시 기록 유지, 자동 재조회, 300종목 가상화, AND 종목의 복귀, 검색·선택 유지, CSV 발생 건, 새로고침 후 복원 상태를 검사한다. 제거된 발생 상세 영역에서 신규 제외하는 경로는 더 이상 E2E의 전제가 아니다.
- 좁은 스크리너 패널에서는 종목당 한 행·낮은 행 높이·발생 상세 없음과 기존 제외 기록 복원의 사용 가능성을 검사한다.
- 관심종목 메뉴는 실제 v3 폴더 소속을 가진 fixture로 전체 관심 해제와 그룹 추가를 검사한다. 메뉴를 한 번 더 여는 옛 단계와 유효하지 않은 `folder_id: null` fixture를 제거했다. 다중 폴더 소속 유지도 확인한다.
- 저장뷰 드래그 안내는 현재 짧은 날짜 표시를 기대하며 이동 대상·방향·순서·되돌리기 검증은 유지한다.

개별 실행에서 수정 항목은 통과했다. PR에 통합할 최종 차트 위치 보존 코드와 전체 E2E의 결과는 이후 검증 기록으로 갱신한다.

## PR 통합 최종 검증

과거의 UI 계약 불일치 10개를 현재 지원 동작에 맞게 갱신했고, 별도 날짜 위치 보존 작업을 함께 통합했다. 첫 통합 전체 실행은 144개 통과·4개 실패였다. 긴 이력 테스트는 날짜가 같은 봉의 실제 픽셀 이동을 검증하도록 수정했다. 나머지 도형 확대 후 hover 및 정규장 전환 실패는 어댑터가 native draw 전에 요청 범위를 외부 getter에 보고하던 차이였다. 외부 getter는 실제 그려진 범위를 읽고, 내부 연속 배치만 요청 범위를 승계하도록 고쳤다. 기존 실패 테스트의 단언은 유지했다.

| 최종 검사 | 결과 |
| --- | --- |
| 전체 TypeScript | 통과 |
| 전체 Vitest | 600 파일, 7,696 테스트 통과 |
| Vite 제품 빌드 | 통과, 기존 큰 번들 경고 유지 |
| 전체 Playwright | 148개 전부 통과 (4.1분) |
| 차트 핵심 10시나리오 × 3회 | 30회 전부 통과 (1.7분) |
| 변경 파일 공백 검사 | 통과 |

전체 Playwright는 작업 트리 전용 20124·21124, 빈 벤더 자격증명, 새 데이터·dist 경로에서 실행했다. 사용자 개발 서버 5173·8000을 재시작하지 않았다. 핵심 반복은 도형 3분/일봉, 정규장 1/3/5/10분봉, 긴 이력 및 날짜 보존 3시나리오다. 실패를 건너뛰거나 retry로 숨기지 않았다. 날짜 보존의 별도 검증은 [관련 기록](../2026-10-01-watchlist-date/implementation-validation.md)에 있다.

위 성능 수치는 날짜 보존 및 applied getter 통합 전 측정이다. 통합 후 최대 프레임 간격 50ms 목표와 남은 계산 비용은 별도 후속 측정으로 확인한다.
