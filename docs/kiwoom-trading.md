# 토스·키움 호가주문

호가주문 창의 **주문 계좌**에서 증권사와 실전/모의 계좌를 선택한다. 토스의 기존
신규·정정·취소·전체 취소는 같은 명령 엔진을 사용하며 구 API도 유지한다.
키움은 국내 현금 지정가 신규 주문, 잔량 전체 정정·취소, 계좌 미체결·이력·잔고를 지원한다.
화면의 시세 거래소와 주문 거래소는 독립적이다. 정정·취소는 원주문에 저장된 거래소를 따른다.

호가주문 창의 개별·가격별 드래그 취소는 요청을 보낸 주문만 즉시 잠근다. 다른 가격의
주문은 응답을 기다리지 않고 이어서 취소할 수 있다. 접수한 주문은 결과 동기화까지
중복 취소·정정을 막으며, 결과가 불명확하면 같은 요청 ID로 재확인한다. 여러 취소의
실패 알림은 주문별로 보존한다. 신규 주문·전체 취소·계좌 변경의 기존 보호는 유지한다.
토스는 서로 다른 주문의 취소를 병행하고, 키움은 서버에서 같은 계좌·종목의 요청을
순서대로 처리한다.

## 인증과 기본 동작

- 실전: 기존 `KIWOOM_APP_KEY` / `KIWOOM_APP_SECRET`, 두 번째부터 `_2`, `_3` 순서.
- 모의: 별도의 `KIWOOM_MOCK_APP_KEY` / `KIWOOM_MOCK_APP_SECRET`, 같은 번호 규칙.
- 실전 `api.kiwoom.com`, 모의 `mockapi.kiwoom.com`으로 고정한다. 모의 키가 없으면 실전으로 대체하지 않는다.
- 기존 런타임 토큰 소유자를 공유한다. 모의 토큰 캐시는 별도 파일과 환경 태그를 사용한다.
- `ka00001`로 확인한 실제 계좌를 불투명한 `account_ref`에 영속 연결한다.
  같은 인증 별칭이 다른 실제 계좌를 가리키면 주문을 차단한다.

키움 인증 정보가 설정되고 실제 계좌가 확인되면 주문을 사용할 수 있다.
실전은 KRX/NXT/SOR, 모의는 KRX를 지원한다. 별도 활성화 설정이나 수용 검증 파일은
필요하지 않으며, 기존 `trading/kiwoom-acceptance.json`은 더 이상 읽지 않는다.
키움 계좌를 선택한 뒤 주문 거래소를 선택해 사용한다. 토스 주문은 기존 동작을 유지한다.
변경된 코드를 적용하려면 백엔드를 재시작하고 프런트엔드를 새로 빌드·배포한다.

현재 자동 검증은 가짜 HTTP/WS 응답으로 수행했으며 실계좌 주문은 보내지 않았다.
실제 키움 서버에서의 주문·체결·정정·취소 동작은 사용자가 직접 확인해야 한다.
중복 전송 방지, 계좌·환경 확인, 주문 가능 수량 확인, 결과 불명확 시 재전송 금지는 유지한다.

## API와 영속 기록

### 차트의 내 매매 표시

차트 설정에서 `매매내역 표시`를 켠 후 상단 `매매 계좌`에서 조회 계좌를 선택한다.
국내 종목 일봉·분봉의 체결 가격에 B/S만 표시하며 클릭하면 해당 봉의 개별 체결 목록을 연다.
계좌 변경·OFF에는 이전 마커가 사라지고, 같은 창의 마지막 계좌는 종목·봉 전환·재접속 후에도 유지된다.
주문창의 주문 계좌와는 독립된 조회 선택이다.

`GET /api/trading/v2/executions?account_ref=…&code=…&date=YYYYMMDD&venue=KRX`는
계좌를 확인한 뒤 키움 `kt00009`의 `cntr_no`, `cntr_tm`, `cntr_uv`, `cntr_qty`를 읽는다.
다음 페이지는 응답의 `next_cursor`를 같은 계좌·종목·날짜·시장으로 보낸다. 서명 커서는 프로세스
수명 동안 유효하며 서버 재시작으로 만료되면 `다시 조회`로 처음부터 받는다. 타임스탬프는 UTC epoch ms,
가격·수량은 원본 정밀도를 보존하는 문자열이다. 가격 보정용 `raw_close`는 같은 날짜·시장의
키움 원주가 일봉(`ka10081`, `upd_stkpc_tp=0`) 종가이며 실제 체결 가격을 바꾸지 않는다.
과거 일봉 좌표는 화면의 종가/이 원주가 종가를 사용해 차트 자체의 수정 기준에 맞춘다.

화면에 보이는 거래일만 최근부터 페이지별로 조회하며 당일만 15초 갱신한다. 요청당 벤더 체결
한 페이지이고 자동 조회는 128페이지에서 멈춰 `더 조회`로 이어간다. 서버는 같은 조회를 묶고
당일 5초·과거 5분 캐시를 최대 256개 유지한다. 확인된 체결은 `trading/executions.sqlite3`에
계좌·종목·날짜·체결 ID별로 저장한다. 조회 중·조회 실패·미지원과 정상 빈 조회는 별개다.
증권사가 제공하지 않는 과거 이력의 완전성이나 앱이 확인하지 않은 체결의 복원을 보장하지 않는다.

프런트의 과거 페이지 캐시는 서버 캐시와 별개로 탭 메모리에 유지한다(2026-10-29).
계좌·종목·가격 시장·날짜·커서별로 공유하며 완료된 빈 날짜도 다시 조회하지 않는다.
겹치는 기간으로 이동하거나 이전 기간·봉 주기·계좌로 돌아올 때는 미조회 페이지만 최근 날짜부터
하나씩 받는다. 이동으로 취소된 페이지나 실패 페이지는 완료로 취급하지 않고 받은 페이지 뒤에서
이어간다. 자동 조회는 해당 범위에서 새로 받는 128페이지 뒤에 멈추며 `더 조회`로 재개한다.
서버 재시작으로 커서가 만료되면 `다시 조회`에서 해당 날짜의 첫 페이지를 갱신해 새 커서를 얻는다.
오늘이 보이는 동안만 15초 갱신하며 과거 캐시는 새로고침하면 다시 채운다.

토스는 [공식 OpenAPI](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)의
`OrderExecution`에 주문별 평균가와 최종 체결 시간이 있다. 사용자 승인(2026-10-28)으로
토스 계좌는 이 가격·시각에 주문당 B/S 하나를 표시하며 상세에 **주문 평균가 기준**을 명시한다.
응답 행의 `basis`는 키움 `execution`, 토스 `order_average`다. 토스의 소수점 평균가를 보존하며
키움과 같은 날짜·시장의 원주가 종가와 기존 시세 거버너를 사용해 과거 일봉 좌표를 맞춘다.
체결 시장은 API에 없으므로 `미확인`으로 표시한다.

토스 `GET /api/v1/orders`의 OPEN과 CLOSED(100건씩)를 읽는다. 부분 체결 후 취소·정정된
주문도 체결 수량이 있으면 포함하며, 수량 0인 주문은 제외한다. 날짜 필터는 주문 생성일 기준이므로
원본을 주문일로 제한하지 않고 마지막 체결일로 분류한다. 원본 주문 페이지는 계좌·종목별로
공유해 여러 거래일·시장 창의 중복 조회를 줄이며 자동 128페이지 뒤의 명시적 추가 조회를 유지한다.
토스 요약은 변할 수 있어 개별 체결 보존소에 저장하지 않고 같은 주문 ID를 갱신한다.
평균가·마지막 체결 시각이 없으면 주문 가격·접수 시각으로 대체하지 않는다.
[공식 FAQ](https://openapi.tossinvest.com/openapi-docs/faq.md)는 분할 체결의 주문별 합산과
일부 미지원 호가 유형의 조회 제외를 명시한다. 과거 개별 체결 전체를 복원하는 기능은 아니다.
키움 필드·경로의 근거는 [공식 사양의 고정 버전](https://raw.githubusercontent.com/Kiwoom-Securities/Kiwoom-REST-API/953e5dbff123f437ab4d11a78a95191a685eb51f/kiwoom/_data/kiwoom_api_spec.json)의
`계좌별주문체결현황요청(kt00009)`와 `주식일봉차트조회요청(ka10081)`이다.

### 주문 API

새 계약은 `/api/trading/v2`다. `/accounts`, `/state`, `/account-orders`, `/holdings`는 조회다.
`POST /orders`, `/orders/{order_ref}/modify`, `/orders/{order_ref}/cancel`, `/cancel-all`은
`X-Hoga-Order: 1`, `account_ref`, `command_id`, `code`가 필요하다. 신규에는 `route`도 필요하다.
명령 상태 조회는 `GET /commands/{command_id}?account_ref=...`다.

`account_ref`는 계좌, `order_ref`는 영업일을 포함한 주문, `operation_ref`는 정정·취소 접수다.
키움의 7자리 번호는 앞자리 0을 보존한다. 전일 주문 참조로 당일의 같은 번호를 변경할 수 없다.
화면은 키움의 명시적 잔여수량을 사용하고 불명확한 체결수량·여력은 `null`로 유지한다.
동일 종목의 현금 잔고 행은 합산하고 신용 잔고와 거래소별 중복 잔고를 합치지 않는다.

명령은 기존 `trading/commands.sqlite3` 저널을 공유한다. 전송 전 `prepared → sending`을
커밋하고 쓰기는 한 번만 시도한다. 응답 유실·잘못된 접수·전송 후 기록 실패는 `unknown`으로
남긴다. 재시작·동일 명령 재조회·대기자 취소가 재주문을 만들지 않는다. 수동 확인은 시각을
남기고 차단만 해제하며 원요청을 재전송하지 않는다. 계좌·주문 참조는 별도 `accounts.sqlite3`에 보관한다.

키움 `00`/`04`는 기존 시세 WebSocket 소유자를 공유하되 별도 큐와 수집기 제어 채널을 사용한다.
큐 초과는 연결을 종료하고 REST 대조를 유도한다. 이벤트는 계좌를 검증해 조회를 무효화하며,
불완전한 이벤트만으로 최종 체결을 추정하지 않는다. REST는 연결 계좌를 고정하고 기존 시세와
공유하는 호출 예산을 적용한다. 주문 대기 만료와 전송 후 타임아웃은 구별한다.

## 외부 주문 없는 재현 검증

```sh
python scripts/run_kiwoom_trading_validation.py -q
cd frontend
npm run typecheck
npm run test -- --run --maxWorkers=3 src/api/trading.test.tsx src/api/tradingOrderEvents.test.ts src/live/workspace/OrderWindow.test.tsx src/live/workspace/AccountTradingPanel.test.tsx src/live/workspace/useOrderQuantity.test.ts src/live/workspace/orderReceiptSound.test.ts src/state/orderWindowSettings.test.ts
npx playwright test live-orders.spec.ts --reporter=line
```

Python 검증기는 인증 환경변수·`.env` 재로딩을 차단하고 프로세스의 외부 TCP 연결을 금지한다.
WebSocket 검증용 루프백은 허용한다. OS 전체 방화벽은 아니다. 브라우저 주문 테스트는 HTTP/WS
가짜 응답을 사용하며, Playwright 서버도 실전·모의 인증정보를 비워 시작한다.
워크트리에서 독립 실행할 때는 빈 `.env`로 메인 체크아웃 설정 상속을 막는다.

## 내 체결내역

호가주문 계좌 줄의 **내 체결** 버튼은 선택 계좌에 연결된 독립 작업 창을 연다.
토스·키움 계좌 전환을 따라가며, 시세 KRX/NXT/통합 선택과 관계없이 해당 계좌의
당일 체결을 조회한다. 여러 호가주문창의 연결은 서로 독립적이다. 원래 창을 닫으면
마지막 계좌를 유지하며, 계좌 연결이 사라지면 다른 계좌로 자동 대체하지 않는다.

표는 상태 열 없이 주문별 체결수량·체결가·체결금액을 보여준다. 부분체결 후 잔량을
취소한 주문의 체결분도 포함하며, 같은 주문의 누계를 중복 합산하지 않는다. 토스는
평균체결가, 키움은 `kt00007`의 명시적 체결단가를 사용한다. 미제공 체결시각·금액은
빈칸이며 주문시각·확인시각을 체결시각으로 바꾸거나 SOR를 실제 체결 시장으로
단정하지 않는다. 종목 버튼의 상세에서 주문번호·주문수량·주문시각·가격 기준을 본다.

조회는 `GET /api/trading/v2/execution-history`이며 `account_ref`, `date`, 선택적
`next_key`를 받는다. 연속조회 키는 계좌·날짜에 묶이며 조회 권한은 매번 검증한다.
토스는 초기 CLOSED 페이지와 진행 중 OPEN 부분체결을 함께 읽고, 키움은 계좌에
고정된 게이트웨이로 전체 거래소의 이력을 조회한다. 최신 페이지만 주기·주문 이벤트로
갱신하며 이전 페이지는 더 보기로 읽는다. 화면을 스크롤하는 동안 새 체결·갱신은
안내로 모아 표시하고, 다시 연결되면 조회로 대조한다. 체결내역 조회는 주문 명령을
전송하지 않는다.
