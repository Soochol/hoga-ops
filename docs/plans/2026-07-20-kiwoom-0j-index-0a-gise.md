# 키움 0J(업종지수)·0A(주식기세) 도입 플랜 — 잔존 KIS 폴링 축소

- 날짜: 2026-07-20
- 선행: [0F/0w 실시간 전환 플랜](2026-07-20-kiwoom-0f-0w-realtime.md) 완주(PR-F 시리즈
  main 머지). 이 플랜은 그 후속 — 2026-07-20 KIS 잔존 기능 조사에서 "실질 개선
  후보"로 판정된 2건만 다룬다.
- 관련: ADR-0118(브로커 특화 절단선 — 이 플랜은 절단선을 옮기지 않고 push 영역을
  넓힌다), [키움 REST/WS 카탈로그 조사](https://github.com/younghwan91/kiwoom-rest-api).

## 배경 — 왜 이 2건만인가

2026-07-20 조사 결론: 남은 KIS 기능 9종 중 배치(일봉·스크리너 EOD)는 키움 REST
유량(~1/s)이 구조적 병목이라 이관하면 퇴보, 휴장일은 키움에 API 자체가 없다.
실질 개선은 **폴링을 push 로 바꿀 수 있는 곳**뿐이다:

| | 현재 (KIS) | 목표 (키움 WS) | 이득 |
|---|---|---|---|
| 0J | 지수 현재가 30s 폴(FHPUP02100000, TTL 20s) | 업종지수 push | 하단 시장지표 바 실시간화 + 지수당 ~180콜/hr 소멸 |
| 0A | 리스트 시세 10s 폴이 무체결 종목 커버 | 주식기세 push | 무체결 종목(실측 7%)도 틱 경로로 — 폴 의존 추가 축소 |

0J 는 확실한 개선이라 본선, 0A 는 **수신량 게이트 통과 시에만** 진행하는 조건부다.

## 미확정 사실 (P1 채록이 확정할 것)

0F/0w 때와 동일한 규율 — **추정으로 파서를 쓰지 않는다.**

1. **0J FID 구조** — 지수 현재가·전일대비·등락률·시각 FID 번호와 스케일(지수는
   소수점 — 0B 의 int 파싱 재사용 불가 가능성).
2. **업종코드 체계** — 대표지수 5종(KOSPI·KOSDAQ·KOSPI200·KOSDAQ150·KRX100,
   `index_registry`)의 키움 업종코드 매핑(001=종합 추정 등). KRX100 이 키움에
   있는지도 미확정 — 없으면 그 지수만 KIS 폴 잔존.
3. **슬롯·그룹 회계** — 업종지수 구독이 연결당 200종목 한도에 포함되는지,
   종목 REG(grp_no=1)와 분리된 grp_no 가 필요한지. 현 ws_client 는 grp_no="1"
   고정 + item×type 곱집합 REG 라 **지수 코드를 종목 타입(0B/0D/0F/0w)과 같은
   REG 에 넣으면 무의미한 조합이 등록된다** — 별도 REG 경로가 필요할 것.
4. **0A 프레임 빈도** — 기세는 호가 유발이라 0D(실측 245/s@235종목)급일 수 있다.
   235종목 0A 추가 시 총 수신량과 백엔드 파싱 여유 실측.
5. **0A FID** — 현재가·전일대비(11)·OHLC(16/17/18)가 0B 와 동형인지.
6. 장외(애프터마켓·주말) 발화 여부 — 0J 가 장외에도 오면 하단바 장외 표시 정책
   재확인.

## 단계

의존성: P1 → P2(0J), P1 → 게이트 → P4(0A). P3 는 P2 검증 후 선택.

### P1 — 실채록 (정규장 30분, 유휴 앱키)

T2 채록(2026-07-20 0F/0w)과 동일 절차 — 유휴 키(`KIWOOM_APP_KEY_3`)로 운영 conn
무간섭 채록:

- 0J: 업종코드 후보(001·101·201·상응 코드들) × type 0J REG → ACK rc·FID 전수·
  발화 빈도. 0U(업종등락)도 같은 세션에서 관찰만(도입 판단은 별도).
- 0A: 표본 5종목(대형 2 + 저유동 3 — 무체결 종목 커버가 목적이므로 저유동 중심)
  × type 0A → FID 전수·**종목당 프레임/분**·0B 와의 중복 수신 여부.
- 산출물: `docs/research/` 채록 문서 + `tests/fixtures/kiwoom_t2/` 골든 프레임
  추가. FID 확정표(시계열 검산 — 0w 방법론 재사용: 산식 스캔·단조성·교차검증).

### P2 — 0J 지수 래치 (본선)

**소비자 무변경 seam** — 프로그램매매 latch 패턴 재사용:

1. `kiwoom_ws_client` — 지수 REG 경로 추가(별도 grp_no, P1 확정 반영). 구독
   대상은 대표지수 매핑 상수(신규 `kiwoom_fields.py` 또는 index_registry 확장).
2. `kiwoom_frames._parse_index` — 0J → 신규 kind(`SnapshotKind.INDEX` 류).
   stream.on_tick 입구에서 지수 래치로 라우팅·return (PROGRAM 과 동형 —
   표시 버퍼·저장 미진입).
3. `/index-quotes` 핸들러 — **래치 우선, KIS 폴백**: 래치에 신선한 값(예: 60s
   이내)이 있으면 KIS fetch 생략. `IndexQuoteSnapshot` shape 로 변환해 반환
   → 프론트·TTL·single-flight 전부 무변경. 래치 miss(키움 다운·미매핑 지수)면
   기존 KIS 경로 그대로 — 폴백이 구조적으로 남는다(quotes 오버레이와 동일 원칙).
4. 프론트 폴 주기(30s)는 1단계에서 유지 — 신선도는 서버 래치가 이미 push 수준.

게이트(장중 스모크): 래치 hit 률·KIS 지수 콜 감소 확인, 값이 KIS 와 일치
(등락률 부호 정규화 포함 — KIS 는 하락=음수 정규화가 이미 있다).

### P3 — 0J 프론트 실시간 push (선택 후속)

P2 검증 후: `/api/ws` 에 지수 채널을 실어 하단바를 진짜 틱 갱신으로. 프론트
변경이 들어가므로 별도 PR. P2 만으로 폴 주기(30s) 신선도가 이미 확보되면
스킵 가능 — 그때 판단.

### P4 — 0A 주식기세 (조건부)

**진행 게이트**: P1 실측에서 `(0A 추가 수신량)`이 현 총 수신 대비 +50% 이하이고
백엔드 파싱 여유가 확인될 때만. 초과 시 **드롭**하고 quotes 10s 폴 잔존을
수용한다(폴은 이미 폴백 역할로 안정적 — 무리해서 옮길 이유 없음).

진행 시:
1. `DEFAULT_TYPES` 에 "0A" 추가.
2. `_parse_gise` — 0B 와 동형이면 TRADE payload 재사용하되 **trades 는 빈 배열**
   (기세는 체결이 아니다 — 체결량·매물대 오염 금지), 최상위 `prev_close`·
   `day_*`·기세가만. 프론트 `tradeSample` 이 trades 빈 배열 + 기세가를 읽도록
   확장.
3. 저장 경로 미진입(표시 전용) — stream 라우팅 가드 테스트.

## 리스크

| 리스크 | 완화 |
|---|---|
| 0J FID 스케일 오판(지수 소수점) | P1 채록 + KIS 값 교차검증 후 파서 |
| 업종 REG 가 종목 슬롯을 잠식 | P1 에서 subscribed_count 회계 실측, 잠식 시 전용 conn 검토 |
| KRX100 등 키움 미제공 지수 | 래치 miss → KIS 폴백이 자동 흡수(P2 설계에 내장) |
| 0A 수신량 폭주 | P4 진행 게이트(+50% 상한)로 사전 차단 — 미달 시 드롭이 기본 |
| 0A 기세가가 체결 경로 오염 | trades 빈 배열 원칙 + 저장 미진입 가드 테스트 |
| 유휴 키 채록이 운영 킥 | T2 절차 재사용(키 3 번, 상호 킥 없음 실증됨) |

## 하지 않는 것

- 일봉·스크리너 EOD 배치의 키움 이관 — 키움 REST ~1/s 로는 퇴보(조사 확정).
- 휴장일 조회 대체 — 키움에 API 없음, KIS 잔존 필수.
- 심볼 마스터 이관 — KIS 쪽이 무인증 정적 파일이라 더 가벼움.
- quotes 10s 폴 제거 — baseline·미구독(>300)·graceful 폴백 역할 존속(기존 결정).
- 지수 일봉/분봉 백필 이관 — 가능하나 실익 없음(저빈도 read-through).
