# 기간내 신고거래량의 분·일·주·월봉 파라미터

사용자 승인: 2026-10-19. `new_high_vol` 하나에 주기와 진행 중 봉 포함 여부를
저장하고, 해당 주기의 캔들 개수로 최근 N봉 / M봉 신고를 판정한다.

## 계약과 판정

- 최근 방식: `{lookback, period, timeframe, include_open_bar}`. 주기는
  `1m/3m/5m/10m/15m/30m/60m/D/W/M`. 누락된 새 필드는 D/true로 복원한다.
- 기본 D/true는 기존 SQL·저장 조건·발생 제외 키를 유지한다. 당일 신고거래량 등
  다른 조건의 의미는 바꾸지 않는다. 차트에서 선택한 주기와 독립적이다.
- 후보 봉을 포함한 M봉 최대와 동률 이상인 양의 거래량을 기록하면 발생이다.
  후보마다 그 시점의 비교 창을 사용한다. 진행 중 제외는 N봉을 선택하기 전에 적용한다.
- 완전한 최근 N봉 평가에는 N+M-1봉이 필요하다. 이력이 부족해도 완전한 비교 창에서
  확인한 발생은 반환하고, 전체 기간 미확인을 `bar_coverage`에 남긴다.
- 새 날짜 방식: `{mode:'date_range', start_date, end_date, timeframe,
  include_open_bar, record_period:{unit:'bars',value:M}}`. 봉 시작 날짜로 범위를
  선택하고 분봉 요청은 종료일 15:30 KST까지, D/W/M은 종료일의 일봉까지 사용한다. 중간 주/월에서 끝나면
  그 종료 시점까지의 진행 중 집계이며 완료봉만 선택했으면 제외한다.
- 기존 일봉 날짜 조건의 년/거래일 비교·과거 일봉 보충 수집은 유지한다. 새 봉수
  조건을 기존 일봉 수집 작업으로 보내지 않는다.

## 데이터와 장중 갱신

- D/W/M은 기존 보정 일봉 거래량을 사용한다. W는 ISO 주, M은 달력 월이며
  실제 거래일 달력을 기준으로 합산한다. 첫 실제 거래일을 표시 앵커로 삼는다.
  달력·일봉 결손은 0으로 정상화하지 않는다. 달력이 모르는 과거/꼬리 기간도 미확인이다.
- 장중 W/M에는 기존 키움 일봉 OHLCV overlay의 당일 거래량을 **교체**하여 반영한다.
  이미 누적인 거래량에 overlay를 더하지 않는다. 전일 확정에서는 오늘 행을 제외한다.
- 분봉은 기존 키움 `ka10080` 어댑터의 원본 거래량·타임스탬프를 사용한다. KRX
  정규장 09:00~15:30 범위이며 주기별 원본 분봉끼리 비교한다. NXT·통합·KRX 애프터를
  포함한 분봉 검색은 이번 범위가 아니다. 일봉 보정계수를 분봉 거래량에 곱하지 않는다.
- 날짜 경계가 잘린 가장 오래된 응답 날짜는 다음 `base_dt`에서 확보한다. malformed
  OHLCV가 있는 페이지는 정상 0거래량으로 취급하지 않는다.
- 장중 반영은 요청 시점 REST 스냅샷이다. 드로어의 기존 모니터링(기본 관심·히트맵
  15초 / 전 시장 30초)을 재사용한다. 매 체결 즉시 판정하는 WS 감지기는 추가하지 않았다.
- 페이지마다 기존 키움 background 거버너를 사용한다. 종목당 최대 8페이지, 한 조회의
  신규 평가 배치는 최대 64종목·동시 4개·대기 포함 20초다. 넓은 유니버스의 다음 조회는
  다음 배치를 선택하며, 신선한 캐시만 추가로 사용한다. 전체 시장 동시 평가·탐지 지연을
  보장하지 않는다. 요청 범위 초과와 실패는 `bar_coverage`에 남기고 화면에 표시한다.
- 캐시는 메모리 전용, TTL 15초, 최대 512항목/250,000봉이다. 서버 재시작 시 재조회한다.
  ADR-0095의 분봉 memory-only 정책을 유지한다. 미완료 조회는 single-flight로 공유한다.

## 발생·제외·화면

- 발생은 기존 날짜와 함께 `bar_start_ms`와 `bar_match`를 반환한다. 근거는 주기,
  거래량, 해당 비교 창 최대, 창 시작 시각, 진행 중 여부, 조회 시각이다.
- 제외 키는 조건 의미·종목·발생일에 봉 시작 시각을 추가한다. 같은 날 다른 분봉의
  발생을 보존하고, 제외를 AND/종목 결과 상한 전에 적용한다. 기존 날짜 제외도 유지한다.
- 분/일/주/월 선택, 분봉 간격, N/M 봉수, 진행 중 포함을 편집·저장·복원한다.
  발생 상세와 CSV에 봉 식별·근거를 보존한다. 기간 방식 전환에서도 진행 중 설정을 유지한다.

## 검증

검증은 이 워크트리의 격리된 Python/Node 의존성과 무자격 E2E에서 수행했다.
사용자 서버 5173/8000과 운영 데이터는 변경하지 않았다. 실시세 및 공급자 지연·보유 범위의
운영 검증은 수행하지 않았다. E2E는 20332/21332, `/tmp/hoga-e2e-data-332`를 사용한다.

최종 기준 HEAD/main: `fbda4e4b859d3efb59048410d31523aa40c0157a`.
초기 `0b85b9e639d808e75b4d5497916b8fc9f31da087`에서 시작했고, 검증 중 합쳐진
테마 변경 두 건을 fast-forward로 반영했다. 백엔드 실행 코드 변경은 없으며 프론트
타입·전체 테스트·빌드·관련 브라우저 검증을 새 기준에서 수행한다. 아래 기록은
미커밋 변경을 포함한다.

- 신규 단위/API: 주·월 실제 집계, 일봉 기본값 호환, 동률/0/부족 이력, 진행 중 도달,
  완료봉 선택, 날짜 끝 이후 데이터 차단, 달력 꼬리 부족, 당일 누적 교체, 종목·봉별 제외,
  SQL AND/상한 전 제외, 분봉 원본 주기/캐시/예산 회전/잘못된 거래량을 확인한다.
- HTTP 응답에서 실제 Pydantic 직렬화와 봉별 제외 저장·복원을 확인한다.
- wire enum 가드는 별도 임시 프론트 사본에서 W를 지워 실패함을 확인했다.
  저장소 소스에 의도적 불일치를 남기지 않았다.
- 브라우저: 주기·봉수·완료봉 선택 → 저장 → 새로고침 → 조회 → CSV 근거를 검증하고,
  넓은 화면/768px 화면 스크린샷을 확인했다. 기존 날짜 수집·발생 제외 E2E도 확인한다.
