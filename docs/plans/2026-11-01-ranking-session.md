# 순위 기준일과 휴장일 조건검색

## 후속 변경 — 저장 기록 없는 휴장일 순위 검색

2026-11-01 사용자 추가 승인. 아래 최초 구현의 “기록이 없으면 스크리너 평가 불가”를
확장한다. 저장 기록을 우선하며, 없거나 범위가 부족하면 우측 패널과 같은 fetcher의
`allow_last_available=True`로 공급자 마지막 순위를 읽는다. 달력 미확인 평일에는 허용하지
않고, REST 중지·연결 누락·응답 실패는 명시적 오류로 유지한다.

`provider` 순위의 거래일·관측 시각은 null이고 `fetched_at_ms`는 실제 수신 시각이다.
수신 시각을 금요일 관측으로 바꾸거나 날짜별 이력에 저장하지 않는다. 조건 계산에는 별도의
내부 `evaluation_at_ms`를 두고 최근 거래일 23:59:59.999 KST까지의 완료 자료를 쓴다.
저장본과 공급자 응답이 섞여도 다른 조건은 이 완료일 기준이며 같은 관측 시각을 약속하지
않는다. 저장 순위만 있는 검색은 아래 기존 관측 시각 상한을 유지한다.

순위별 근거 3개 모델에 `basis`를 추가해 각각의 출처와 실제 시각을 보존한다. 전체 응답은
공급자 순위가 하나라도 있으면 `rank_basis.source=provider`로 날짜 미확인과 다른 조건의
완료일을 안내한다. 메인·우측 패널과 근거 상세에서 동일하게 표시하며 기관/외국인의
거래소 미지정, 상승/하락 방향, 원래 시장 순위와 기존 AND/OR·범위 필터를 유지한다.

기존/분리 계산과 자동 일봉 준비에 같은 과거 계산 상한을 적용하고 오늘 overlay·실시간
분봉 누적값을 사용하지 않는다. 누락 기준일을 이전 봉으로 대체하지 않으며 일봉·분봉
부족은 기존 coverage로 표시한다. 호가 조건과 정확 재실행 보존 제한은 유지한다.
증권사 마지막 순위는 60초 캐시를 공유하고 최대 90초 수신 나이(요청 여유 포함)를 검증한다.

검증은 7종·두 계산 정책·세 거래소, 장전/휴장/달력 미확인, 저장/공급자 혼합,
AND/OR, 금요일 완료 일봉·분봉과 누락, HTTP 근거·일봉 자동 준비·UI를 포함한다.

## 최초 구현

2026-11-01 사용자 승인 개선안 구현. 10/30까지만 있는 달력으로 11/1을 조회할 때,
우측 순위는 미확인을 허용해 날짜 없는 키움 응답을 표시했고 스크리너는 조회를 거절했다.
두 기능의 날짜 판정과 관측 기록을 통일한다.

## 동작과 보존

- `ranking_session.resolve`가 장중·장외·장전·휴장·달력 미확인을 판정한다.
  주말은 달력 밖이어도 휴장이다. 직전 거래일을 찾다가 미확인 평일을 만나면 중단한다.
  기존 KRX 정규장·시행일별 시간외 세션과 NXT/통합의 시간 창을 따른다.
- 거래일 개장 이후의 성공한 순위 조회를
  `<data_dir>/rankings/YYYY-MM-DD/{종류}-{시장}-{방향}-{거래소}-{범위}.json`에 원자 저장한다.
  원래 순위·ETF 제외 전 목록·실제 관측 시각·조회 범위·더보기 여부를 보존한다.
  기관·외국인은 순위의 거래소 미지정과 시세 거래소를 구별한다.
- 저장은 현재 조회에 부수되며 새 폴링·별도 토큰·배경 전 종목 수집을 추가하지 않는다.
  저장 실패 시 현재 조회는 유지하고 휴장일 재사용 불가를 안내한다.
- 휴장·장전에는 정확한 최근 거래일·종류·시장·방향·거래소의 충분한 범위 기록을 읽는다.
  충분한 큰 범위는 작은 범위에 재사용하되 원래 순위를 유지한다. 기록의 관측 시각은
  재조회·서버 재시작 후에도 그대로이며, 복원한 기록을 새 관측으로 다시 저장하지 않는다.
  오래된 날짜로 임의 후퇴하거나 날짜 없는 휴장일 응답을 날짜가 확인된 기록으로 승격하지 않는다.
- wire의 `basis`/`rank_basis`가 세션·출처·거래일·관측 시각·안내를 전달한다.
  순위 기록이 없거나 부족한 스크리너 조회는 HTTP 409와 원인을 반환한다.
  우측 순위는 기준 미확인 상태를 표시하며, 범위 확장 실패 시 이전 성공 목록을 유지한다.

## 조건 평가

- 순위 판정을 일봉 전체 이력 로딩 전에 수행한다. 날짜·기록 부재를 알아내기 위해
  전 시장 v2 관측 자료를 먼저 읽지 않는다.
- 순위는 시장에서 원래 매겨진 순위를 유지한다. AND/OR 조합식에서 순위만으로 탈락이
  확정된 종목의 분봉·일봉 조회만 생략하며, OR의 다른 조건은 전체 후보로 취급한다.
- 저장 순위는 같은 거래일의 실제 관측 시각으로 분봉 조회를 고정한다. 여러 종류의 순위는
  각 근거의 시각을 보존하고 가장 이른 시각을 다른 조건의 상한으로 쓴다.
  과거 조회에는 오늘 실시간 누적값·일봉 overlay를 섞지 않는다.
- 과거 시각의 진행 중 분봉은 확정 분봉의 최종 수량으로 복원하지 않는다. 해당 비교 창을
  판정 보류한다. 기준일 분봉이 없을 때 전 거래일 마지막 봉으로 대체하지 않는다.
- 공급자 전체 세션 일봉의 확정 시각(22시) 전 순위와 확정 일봉의 조합·과거 호가 조건·
  순위 이후 종료일 조건은 명시적으로
  거절한다. 허용된 일봉 조회는 순위 기준일 이후 행을 사용하지 않는다.
- 기존 분봉 조회 예산(한 회 64종목)·동시성·거버너·상한을 유지하며 부족분을 표시한다.
  과거 분봉 캐시는 관측 상한까지 포함해 키를 나누고 5분 동안 재사용한다.
- 화면은 완전 평가의 미충족과 일부/전체 데이터 부족을 구분한다. 가격의 현재 시세 보기와
  조건 평가 기준은 기존처럼 별개이며, 각 행의 가격 기준일과 순위 근거를 유지한다.

## 검증과 적용

날짜 경계·미확인 평일·주말·장전·재시작 복원·범위/거래소 격리·손상 기록·실제 빈 순위,
legacy/v2 순위+분봉 결합·미래 진행 봉 값 차단·누락 기준일·HTTP/화면 상태를 검사한다.
검증 결과와 입력 지문은 같은 디렉터리의 `2026-11-01-ranking-session-validation.json`에 기록한다.

실자격증명과 운영 데이터는 사용하지 않는다. 기존 기록이 없는 날짜는 이번 변경만으로
검색 가능해지지 않는다. 실행 중인 사용자 서버와 앱의 재시작·배포는 이 코드 검증과 별개다.
