# 스크리너 발생 건 제외 구현 계획

## 목표와 계약

조건 × 종목 × 실제 발생일 단위로 제외한다. 다른 날짜와 다른 의미의 조건에는 전파하지 않는다. 같은 의미의 조건에서는 저장본·미저장 조회·우측 패널 모두 같은 제외 기록을 사용한다. 제외는 원본 일봉이나 조건 설정을 변경하지 않으며 복원 가능하다.

- 서버가 조건별 실제 발생일 목록을 반환한다. 가격 기준일이나 조회 실행일로 추측하지 않는다.
- 기간 조건은 충족하는 날짜를 모두 평가한다. 제외된 발생일을 제거한 뒤 조건별 존재 여부와 기존 AND를 평가하고, 마지막에 결과 상한을 적용한다.
- 기존 `history_matches`의 최신 근거 계약은 유지하고 별도 `occurrences`에 전체 날짜를 담는다.
- 조건 키는 서버에서 타입과 정규화한 판정 파라미터로 만든다. 임의 leaf ID·이름·순서·검색 범위는 포함하지 않는다. 임계값과 비교 기준 기간이 바뀌면 다른 키다. 동일 날짜의 장중·확정 결과는 같은 발생 건이다.
- 기간 검색과 당일 검색의 타입 구분(ADR-0055)은 유지한다. 검색 범위 제외는 키 정규화에만 적용한다.
- 제외 목록은 `<data_dir>/screener/exclusions.json`의 버전 파일에 원자적으로 저장한다. `GET /api/screener/exclusions`로 목록을 조회하고, `PUT /api/screener/exclusions`에 `condition`, `code`, `date`, `stock_name`을 보내 제외한다. `DELETE /api/screener/exclusions/{id}`로 개별 복원한다. 추가·복원은 멱등이며 전체 목록 덮어쓰기 충돌을 피한다.

## 구현 순서

1. wire 모델, 조건 키, 제외 저장소와 API 구현.
2. SQL·날짜 범위·총잔량 평가에서 발생일 보존 및 제외 후 AND/상한 처리.
3. 결과 행에 발생 건 펼치기와 개별 제외 제공. 상단 제외 목록, 개별 복원과 되돌리기, 저장 오류 표시.
4. 재조회·새로고침·페이지/우측 패널 공유, 결과 캐시·CSV와 연결. 제외 후 서버 재조회는 실행 당시 요청을 사용한다.
5. 의미 있는 회귀 테스트와 필수 로컬 검증, 별도 테스트 환경의 UI 확인.

## UI

기존 결과표와 관심종목 하트를 유지한다. `발생 N건`을 펼치면 조건 이름·날짜·`이 발생 건 제외`가 나온다. 제외 목록은 결과가 0종목이어도 접근 가능하다. 저장 중 중복 조작을 막고 실패하면 성공으로 표시하지 않는다. 행 액션은 차트 이동·드래그를 실행하지 않는다. 종목 선택 체크박스는 CSV 용도로 유지하며 일괄 제외는 이번 범위에서 제외한다.

## UI 변경: 발생 건별 평면 목록

사용자 요청에 따라 종목별 펼치기를 제거했다. 같은 종목이라도 조건·날짜마다 독립된 행으로
표시하고 행의 제외 버튼을 사용한다. 발생일·충족 조건·당시 수치를 현재 시세와 구분한다.
선택, CSV, React 및 가상화 키는 발생 건 단위이며 시세 구독은 종목 단위를 유지한다.
여러 AND 조건 중 마지막 발생 건을 제외할 때 다른 행도 결과에서 빠지는 영향을 먼저 안내한다.
서버의 제외/복원과 AND·종목 상한 계약은 유지한다. 과거 조건 근거는 발생 건마다 내려준다.
