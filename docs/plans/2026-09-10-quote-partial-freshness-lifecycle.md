# 시세 부분 성공, 지수 관측 시각, 조회 작업 수명

## 구현 범위

1. `LiveQuoteFetcher`에서 청크별 실패를 격리한다. 성공 종목은 사용하고 실패 종목만 마지막 성공 시세에 stale 사유를 붙인다. 종가 표본이 아닌 마감 폴백은 기존 `pre_close_sample`을 유지하면서 warnings에 실패 분류를 보존한다. 이전 값도 없는 종목은 `/quotes`의 `missing_codes`로 명시한다. 정상 응답에서 빠진 종목도 같은 방식으로 처리한다.
2. 지수 WS 가격의 HHMMSS를 서버 수신 날짜(KST)에 결합해 관측 시각을 전달한다. 가격이 없는 등락 종목 수 틱은 가격 시각을 갱신하지 않는다. 서버에서 역순 가격 틱을 무시하고, 브라우저의 공유 지수 캐시는 WS·REST를 같은 관측 시각으로 비교한다. 하단 바는 90초 이상 지난 시세의 나이와 기준 시각을 표시한다.
3. HTTP 응답 제한시간 뒤의 캐시 채우기 작업을 fetcher가 강한 참조로 보관한다. 완료 콜백이 예외를 회수하고 기록하며 앱 종료 시 cancel+await한 뒤 벤더 런타임을 내린다. 기준가 일괄 워밍과 조회는 같은 resolver를 사용한다.

## 유지하는 계약과 한계

- 청크별 페이싱·우선순위·중복 병합은 기존 용량 스케줄러가 맡는다. 원시 `fetch_multi_price`의 다른 소비자에는 부분 결과를 정상 완결 데이터처럼 넘기지 않는다. 이번 부분 성공 정책의 주체는 LiveQuoteFetcher다.
- 1초 HTTP 제한시간과 배경 캐시 채우기는 유지한다. 모든 청크가 완료될 때 결과를 조립하며, 스트리밍 응답으로 바꾸지 않는다.
- 지수 WS에는 거래일이 없어 수신 날짜를 사용한다. 비정상 HHMMSS는 수신 시각으로 대체하며, REST의 마감 센티넬도 기존 수신 시각 대체 계약을 유지한다. 이 경우 거래소 관측 시각의 엄밀한 순서를 보장하지 않는다.
- `missing_codes`는 API 누락 정보다. 신규 종목 행을 가격 0으로 만들지 않는다. 종목 목록의 새로운 경고 UI는 이번 범위에 포함하지 않는다.
- 시세 나이는 장마감·휴장일에도 사실인 중립적 정보다. 오래됐다는 이유만으로 연결 장애를 선언하지 않는다.
- 사용자 운영 서버 배포·재시작은 하지 않는다.

## 검증

청크 부분 실패의 실제 HTTP 직렬화, 실패 캐시 폴백, 대기자 취소 후 작업 유지 및 종료 회수, 분리된 작업의 예외 회수, 지수 틱 역순과 가격 없는 틱, REST 진행 중 WS 갱신, 오래된 지수 표시를 회귀 검사한다. 전체 백엔드·프런트 타입 검사·Vitest·빌드·Playwright 결과는 PR에 기록한다.
