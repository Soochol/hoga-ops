# 키움 휴장 구독 경고 개선 계획

작성일: 2026-10-03 KST

휴장 중인 키움 수집 세션에서 `registration_incomplete` 경고가 반복되는 문제를 고친다. 연결에 사용하는 거래일·시간 게이트를 복구 작업과 경고 판단에도 적용하고, 장중에는 등록 미완 상태를 계속 관측하면서 중복 로그를 제한한다. 아래 계획에 따른 구현과 로컬 검증을 작업 트리에서 완료했다. 운영 배포와 재기동은 수행하지 않았다.

## 확인된 원인과 증거

2026-10-03 18시대 운영 수집 프로세스 PID `870557`과 포트 8000의 `/api/live/status`를 조사했다. 운영 체크아웃과 조사 작업 트리의 커밋은 모두 `c9f1c10269db8476c91988d4b4d0bdc3eab8ec39`였다.

| 관측 항목 | 확인 결과 |
| --- | --- |
| 날짜 | 토요일이므로 `CollectorWorker.day_allowed()`가 False |
| 수집 프로세스 | alive와 ready가 True이며 storage_errors는 빈 목록 |
| 연결 | 설정 계정 6개 모두 connected=False, connection_generation=0 |
| 등록 | 계정별 expected는 130, 130, 130, 130, 129, 87이며 acked는 모두 0 |
| 기대 구독 수 | 총 736건이며 venue별 등록을 포함함 |
| 저장 대상 종목 | 328개이며 구독 건수와 다른 단위 |
| 수집 상태 | capture_reason=closed, registration_incomplete=True |
| 로그 | 30초마다 동일 경고 8줄이 반복됨 |

원문 로그는 `/home/dev/.local/share/hoga-ops/logs/hoga.log`에서 확인했다. 이 PID의 조사 당시 기록에는 등록 경고 외에 GC 프로브 설치 로그만 있었고, 연결 실패나 등록 거부 기록은 없었다. 연결 게이트가 닫혀 실제 연결 시도에 들어가지 않은 상태와 일치한다. 이 판단을 다른 날짜의 장중 ACK 실패 원인으로 확대하지 않는다.

현재 경로는 다음과 같다.

1. `hoga/live/collector_worker.py`가 거래일과 연결 시계로 `gate_fn`을 구성한다. 토요일에는 False다.
2. `hoga/live/kiwoom_ws_client.py`의 `run()`은 닫힌 게이트에서 접속을 시작하지 않고 대기한다. 기대 구독 목록은 남아 있으므로 ACK가 없는 전체 목록이 `sub_missing()`에 잡힌다.
3. `hoga/live/kiwoom_session.py`의 `watchdog_pass()`는 게이트 확인 없이 계정별 재구독 작업을 예약한다. `resubscribe_missing()`은 실제 소켓이 없으면 0을 반환한다.
4. 워치독이 등록 검사를 두 번 호출하고, 6개 계정의 작업 종료에서도 전체 등록 검사를 호출한다. 각 검사에서 경고가 출력되어 한 패스에 8줄이 발생한다.

실제 manager와 WS client에 닫힌 게이트, 가짜 token 콜백, 6개 계정의 736개 KRX 전용 구독을 주입한 오프라인 실행에서도 token 호출 0회, 연결 세대 모두 0, missing=736, 경고 8회를 재현했다. 이 재현은 공급사 접속 없이 경고 경로를 확인한 것이며 운영 종목의 venue 구성을 그대로 재현한 것은 아니다.

## 목표 동작

| 상태 | 복구 작업 | 등록 경고와 상태 표시 |
| --- | --- | --- |
| 연결 게이트 닫힘 | 새 표적 재구독을 예약하지 않음 | 등록 미완 경고를 출력하지 않고 휴장 상태로 표시 |
| 연결 게이트 열림과 접속 대기 | 기존 WS 연결·backoff 동작 유지 | 등록 미완 진단을 유지하며 반복 경고를 제한 |
| 연결 게이트 열림과 일부 ACK 미확인 | 기존 계정별 표적 재구독 유지 | 계정 목록과 missing 수를 담은 경고 출력 |
| 전체 등록 완료 | 불필요한 재구독 작업을 생성하지 않음 | 미완 상태 해제, 경고한 장애의 복구를 INFO로 한 번 기록 |
| 휴장 후 연결 창 재개 | 최신 저장·표시 구독 목록으로 기존 연결·정합화 재개 | 실제 연결과 ACK가 확인되기 전에는 ready로 표시하지 않음 |

연결 창은 기존 거래일·08:00–20:00 KST 정책을 따른다. 정규장 09:00–15:30 시계나 마지막 틱 시각을 대신 사용하지 않는다. 휴장 중에도 저장 멤버십, 표시 참조, 유예 만료 처리, 종료와 flush는 유지한다.

## 구현 순서

### 1 연결 게이트 판단을 매니저에서 공유

대상: `hoga/live/kiwoom_session.py`, `hoga/live/collector_worker.py`, `hoga/live/storage_runtime.py`.

- 기존 `gate_fn`을 재사용한다. 주말·공휴일·연결 시간 판단을 새로 복제하지 않는다. 프로세스 방식과 인프로세스 방식 모두 같은 manager 동작을 사용한다.
- 매니저에 최근 연결 허용 판정과 관측 시각을 보관한다. `gate_fn`이 있는 초기 상태는 미판정, 명시적 False는 닫힘, True는 열림으로 구분한다. `gate_fn=None`은 기존처럼 항상 허용한다.
- `sync()`와 `watchdog_pass()`의 비동기 진입점에서 판정을 갱신한다. 인프로세스 게이트는 캘린더 조회로 블로킹할 수 있으므로 `asyncio.to_thread()`를 사용하고 매니저 lock 바깥에서 평가한다. 평가 후 현재 연결 목록을 lock 안에서 다시 읽는다.
- `status()`와 구독 작업의 `finally`에서는 저장된 판정만 읽는다. 동기 상태 조회나 작업 종료에서 캘린더 I/O를 실행하지 않는다.
- 게이트 평가 예외를 False나 정상 상태로 바꾸지 않는다. 저장된 판정은 미판정으로 무효화하고 기존 실패 감독 경로에 예외를 남긴 뒤, 다음 패스가 다시 평가하게 한다. 미판정은 휴장이나 등록 완료의 근거로 사용하지 않는다.

### 2 휴장 중 복구 예약과 경고를 중단

대상: `hoga/live/kiwoom_session.py`.

- `watchdog_pass()`를 장부 유지와 연결 복구로 구분한다. 표시 유예 만료와 참조·소유 정리는 계속하고, 명시적으로 게이트가 닫혔으면 새 연결 재빌드와 표적 재구독 예약을 건너뛴다.
- `_resubscribe_missing_locked()`는 missing이 없는 계정과 현재 미연결 계정에는 작업을 만들지 않는다. 미연결 계정의 최신 기대 구독은 기존 WS `run()`의 재연결·초기 등록 경로가 처리한다.
- 이전 패스가 예약한 retry도 실행 직전에 최근 게이트와 연결 상태를 확인한다. 닫힘으로 전환되었다면 retry만 건너뛴다. 이미 송신 중인 작업은 일괄 취소하지 않고 기존 소유자에게 정리를 맡긴다.
- 저장·표시 멤버십 변경과 최신 desired 구독 목록은 계속 보존한다. 휴장 중 pending 상태를 잃지 않고, 연결 창이 열리면 기존 정합화 경로가 최신 목록을 적용하게 한다.
- 게이트가 열려 있는데 connected=False인 계정을 휴장으로 처리하지 않는다. 접속 실패·backoff·kick cooldown과 기존 오류 기록을 유지한다.
- 현재 주석의 “연결이 없으면 `_conns`가 비어 있다”는 가정과 “재구독 뒤에는 ACK가 이미 반영된다”는 설명을 수정한다. 연결 객체의 존재와 실제 소켓 연결, 비동기 작업 예약과 ACK 완료를 구분한다.

### 3 상태 갱신과 로그 출력을 분리

대상: `hoga/live/kiwoom_session.py`.

- 등록 상태 계산은 구독 작업 종료에도 즉시 수행한다. 이 계산에서 로그를 출력하지 않는다.
- 전체 계정에 대한 등록 경고 출력은 워치독 패스당 한 지점으로 모은다. ACK 대기 완료를 위해 워치독을 블로킹하지 않는다. 출력한 missing 수는 그 시점의 스냅샷이다.
- 제안 기본 정책은 최초 관측 시 WARNING 한 번, 미완이 지속되면 단조 시계 기준 최소 60초 간격의 WARNING 한 번이다. 계정 목록이나 missing 수가 바뀌어도 같은 제한을 적용해 배치별 진행이 로그 폭주를 만들지 않게 한다.
- WARNING으로 보고한 미완이 전체 등록 완료로 해소되면 INFO 한 번을 기록한다. 게이트 닫힘은 등록 복구로 기록하지 않고 해당 경고 주기를 종료한다. 다음 연결 창의 장애는 새 주기로 판단한다.
- 회복·휴장·stop에서 경고 제한 상태를 초기화한다. 재시작 후 첫 실제 장애가 이전 상태에 가려지지 않게 한다.
- 로그 문구는 확인된 행동에 맞춘다. 예를 들어 “구독 등록 미완”과 missing 수를 기록하되, 미연결 계정에도 무조건 “재구독 재시도 중”이라고 쓰지 않는다. 필요하면 retry 예약 계정과 접속 대기 계정을 구분해 기록한다.

### 4 상태 API와 휴장 표시를 일치시킴

대상: `hoga/live/kiwoom_session.py`, `hoga/live/lifecycle.py`, 관련 상태 타입과 테스트.

- manager 상태에 최근 게이트 판정과 관측 시각을 추가한다. 초기 미판정과 명시적 닫힘을 구분하는 필드로 설계하고, process collector의 기존 상태 전달 경로를 사용한다.
- `registration_incomplete`는 운영상 등록이 필요한데 미완인 상태를 나타내게 한다. 명시적 닫힘에서는 False로 내리되 `sub_expected`, `sub_acked`, `ready_codes`, `registration_ready` 등 실제 진단 값은 그대로 유지한다. 게이트가 미판정이면 현재의 실제 미완 계산을 보존한다.
- `lifecycle.get_status()`는 manager가 명시적으로 닫힘을 보고하면 `capture_reason=closed`로 판정한다. 아직 게이트를 평가하지 않았거나 해당 필드가 없는 기존 테스트·대체 구현에서는 기존 시계 판정을 fallback으로 유지한다.
- `capture_healthy`는 휴장 상태에서 False이며, 게이트가 열렸다는 이유만으로 True가 되지 않는다. 기존 연결·collector 준비·ACK 조건을 계속 확인한다.
- 프론트의 추가 상태 필드 타입을 맞추고 기존 `closed` 표시를 재사용한다. 새로운 배너나 상태 종류를 추가하지 않는다.

## 검증 계획

테스트는 가짜 게이트, 가짜 소켓, event와 주입 가능한 단조 시계를 사용한다. 공급사 접속과 실제 30초·60초 대기는 필요 없다.

| 시나리오 | 검증할 결과 |
| --- | --- |
| 토요일 6계정 736개 구독 | 여러 watchdog 패스에서 표적 retry와 등록 WARNING이 0회, 실제 ready는 False |
| 평일 공휴일과 연결 창 밖 | 동일 게이트 판정을 사용하는 두 런타임 모두 휴장 처리 |
| 닫힘에서 열림으로 전환 | 재시작 없이 최신 desired 적용, ACK 이전에는 미완, ACK 완료 후 ready |
| 열림에서 닫힘으로 전환 | 새 retry 중단, 경고 중단, 저장·표시 장부와 종료·flush 유지 |
| 열린 상태의 일부 ACK 미확인 | 연결된 해당 계정에만 retry, 다른 계정의 구독과 표시 처리를 막지 않음 |
| 열린 상태의 접속 실패 | 휴장으로 오판하지 않고 기존 backoff와 오류 관측 유지 |
| 6개 구독 작업 동시 종료 | 같은 패스의 등록 WARNING 최대 1회, 상태 갱신은 지연되지 않음 |
| missing 수가 계속 바뀜 | 60초 제한 안에서 추가 WARNING 없음, 다음 출력에는 최신 수 반영 |
| 복구 후 재발과 stop 후 시작 | INFO 복구 1회, 새 장애의 최초 WARNING 정상 출력, 제한 상태 잔류 없음 |
| 게이트 블로킹과 평가 예외 | manager lock과 동기 status를 막지 않으며 예외가 휴장·정상으로 변환되지 않음 |
| 초기 미판정과 gate_fn=None | 초기 상태를 정상으로 위장하지 않고 기존 게이트 없는 테스트 동작 유지 |
| 상태 API | 닫힘에서 reason=closed, 미완 진단 수치는 유지, ACK 없이 healthy나 ready로 승격하지 않음 |

주요 테스트 파일은 `tests/unit/live/test_kiwoom_session.py`, `test_kiwoom_ws_client.py`, `test_collector_process.py`, `test_lifecycle_kiwoom.py`다. 게이트와 인프로세스 배선은 같은 디렉터리의 `test_session_gate.py` 및 `test_storage_runtime.py`를 확장한다. 기존 `test_kiwoom_control_isolation.py`와 `test_kiwoom_session_retirement.py`도 실행해 복구·종료 회귀를 확인한다.

구현 후 변경 파일의 lint와 위 관련 backend 테스트를 실행한다. 프론트 타입을 변경하면 프로젝트의 기존 타입 검사도 수행한다. 불필요한 전체 E2E 실행은 추가하지 않는다.

## 완료 기준과 운영 확인

1. 오프라인 736건 재현에서 휴장 등록 WARNING과 신규 표적 retry가 모두 0회여야 한다.
2. 열린 상태의 실제 미완은 상태 API에 남고 첫 워치독 관측에서 경고되어야 한다. 동일 장애는 최소 60초 간격으로만 반복 출력한다.
3. 휴장 이후 연결 창 재개와 장중 ACK 실패 복구를 관련 테스트가 통과해야 한다. 계정별 격리, kick cooldown, 최신 desired 보존, flush 동작이 유지되어야 한다.
4. 운영 적용 후 현재와 같은 휴장 상태에서 최소 3회 워치독 주기 동안 불필요한 경고가 없어야 한다. 프로세스 생존과 `capture_reason=closed`, 실제 ACK 미확인 값도 함께 확인한다.
5. 다음 실제 연결 창에서 연결·등록 준비 상태를 확인한다. 휴장 로그가 사라진 것만으로 장중 수집 안정성까지 검증했다고 보고하지 않는다.

한 PR에서 게이트 적용, 로그 집약, 상태 정합성과 회귀 테스트를 함께 구현한다. 운영 적용 시점은 구현·검증 뒤 정하며, 이 계획 작성에는 배포나 재기동이 포함되지 않는다. 문제가 생기면 해당 PR을 되돌릴 수 있도록 변경 범위를 제한한다. 이 수정은 기존 접속 시간, ACK timeout, 큐 용량, 공급사 등록 형식과 세션 종료 정책을 변경하지 않는다.
