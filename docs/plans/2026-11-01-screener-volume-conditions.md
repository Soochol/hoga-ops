# 거래량 범위·거래량 비교·평균 대비 거래량

사용자 승인안대로 세 조건의 최신/기간내 변형 6개를 추가했다. 기존 신고거래량의
평가·저장·실시간 감시 범위는 유지한다.

## 판정과 계약

- `volume_range`: 후보 기준 `offset`봉 전 거래량의 하한·상한을 양끝 포함으로 판정한다.
  최소 한쪽이 필요하고 0도 유효하다. 기본은 0봉 전·10만 주 이상이다.
- `volume_compare`: 독립적인 `left_offset/right_offset`의 거래량을
  `gt/gte/lt/lte/eq`로 비교한다. 기본은 0봉 전 > 1봉 전이다. 충족 상태를 각각 기록하며
  순간적인 교차 조건은 아니다.
- `volume_ratio`: 대상 거래량 / 대상 봉 직전 N봉 평균 ×100이다. 평균에 대상 봉은
  들어가지 않는다. 100%=같음, 200%=두 배다. 이상/이하/범위를 지원하며 기본은
  0봉 전·직전 20봉 평균의 200% 이상이다. 평균 0은 판정 불가다.
- 위치는 0~1,000, 평균 기간·검색 봉수는 1~1,000이다. 임계 주수는 JS에서도 정확한
  0~9,007,199,254,740,991 정수, 비율은 유한한 비음수다. 소수 주수는 입력하지 않는다.
- 각 `_period`는 최근 N봉 또는 날짜 범위 안의 후보를 평가하며 기본 최근 20봉이다.
  기간 합계가 아니라 개별 봉 판정이다. 날짜는 후보 봉 시작일이며 시작일 전 비교
  이력을 읽고 종료일 뒤 값은 집계하지 않는다. 부족·손상 구간은 압축하지 않는다.
  확인된 발생을 보존하며 평가 불가 구간은 커버리지에 남긴다.
- 분·일·주·월봉의 기존 준비 경로를 사용한다. legacy는 기존 보정 일봉 수량,
  v2는 실제 수량 또는 독립 검증된 주식 수 단위 환산을 사용한다. 각 후보 시점의
  동일 단위로 환산하며 `Fraction`으로 평균과 임계값까지 정확히 비교한다. 가격 보정
  자료가 수량 근거를 대신하지 않는다. 분봉은 실제 수량이며 가격계수를 읽지 않는다.
- 진행 중 봉은 그 시점 누적량이고 시간 비례 환산은 하지 않는다. 기존 완료봉 전용
  API 옵션은 유지한다. 새 조건을 기존 신고거래량 전용 실시간 모니터로 보내지 않는다.

`bar_volume_condition_match`는 대상·비교 수량, 평균, 비율, 계산 기간과 시작/끝,
대상 시각·수량 기준·진행 상태·조회 시각을 보존한다. 수량은 정수/분수 문자열이며
프론트에서도 큰 정수를 Number로 변환하지 않는다. 비율의 부동소수 값은 표시용이고
판정은 정확한 분수값으로 수행한다. Python/TS 모델과 enum/필드 계약 가드를 함께
추가했다. 복구 대조는 조회 시각만 정규화하고 수량 변화는 계속 감지한다.

편집기는 기존 카드·수량 기준 선택을 사용한다. 기간내 날짜 전환 때 주기·대상·관계·
임계값을 보존하고, 범위의 상한/하한은 한쪽만 입력할 수 있다. 페이지·드로어의
`거래량 발생 N건`으로 계산 근거를 열고 한 봉씩 제외한다. 검색 봉수·날짜는 제외
키에서 빼며 실제 판정 설정과 수량 기준은 키에 포함한다.
