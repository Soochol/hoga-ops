# 스크리너 복구: 세션·확정 관측·근거에 따른 정정

2026-10-24 사용자 요청으로 구현. 기존 원본·계수·저장 조건은 보존하며 v2의 선택만 바꾼다.
근거는 [8종목 충돌 조사](../diagnostics/2026-10-24-screener-conflict-review/README.md)와
[승인된 가격·수량 분리 설계](2026-10-24-screener-adjustment-bases.md)다.

## 세션과 확정의 계약

새 복구 계획의 기본 `confirmation_policy`는 `historical_recheck_v1`이다.
키움 `ka10081`의 KRX 일봉을 `provider_daily_all_sessions`로 명시한다. 이는 공급자가
보고한 하루 집계이며 분봉 합계와 모든 거래 유형이 일치한다는 보장은 아니다.
종가는 `provider_last_price`이고 **15:30 정규장 종가를 뜻하지 않는다**.
현재 일봉/신규 API를 정규장 전용 가격으로 다시 만들어 저장하지 않는다.

복구는 기준일 이전의 과거 거래일만 받는다. 각 거래일의 보수적인 확정 경계는 KST
22:00이며, 첫 수신 시작도 이 경계를 지나야 한다. 고정 수정 기준일로 원주가와 수정
가격을 두 번 독립 조회한다. 첫 수신 종료 후 최소 2초를 두고 재조회하며 페이지별
background 거버너 키에도 회차를 넣어 같은 조회에 합류하지 않는다.
두 표본의 OHLCV·금액·가격 이벤트·파싱 위반이 일치해야 확인된 관측이다.
양쪽 원 응답과 수신 시작·종료 시각을 불변 객체에 함께 보관한다.

이 확인은 **해당 시점에 안정된 공급자 과거 관측**이라는 뜻이다. 미래 공급자 정정이
없다는 보증이나 독립적인 주식 수 이력 인증이 아니다. 값이 다르면 `unstable`, 시점이
이르면 `too_early`, 근거가 없으면 `unverified`다. 수집 자료는 남기지만 판정에는 사용하지 않는다.

새 확인 계약을 가진 관측이 들어오면 manifest의 `daily_contract_required`가 유지된다.
후속 구형 수집 경로가 확인 자료 없는 값을 기록해도 현재 v2의 가격·수량 판정에 쓰지 않는다.
현재 재조회 범위 밖의 오래된 병합 행도 새 확인을 상속받지 않는다.
이전에 보존한 manifest는 원래 계약으로 계속 열 수 있다. 기존 `legacy_v1` 파일·일일
갱신의 16시 규칙·저장 조건의 계산 의미는 자동 전환하지 않는다.

새 결과의 `calculation`에는 `daily_session_scope`, `daily_confirmation_policy`,
`correction_revision`을 포함한다. 선택 대상의 관측 계약이 다르면 `mixed`로 구별한다.
새 확인 관측의 `basis_at_ms`는 해당 날짜의 정책 경계인 22:00이며, 실제 수신 시각은
관측 자료에 따로 있다. 표시상 확정 기준 시각을 실제 수신 시각으로 위장하지 않는다.

## 정정 선택의 기준

정정은 **기존 파일 변경이 아니라 특정 v2 버전에서 원주가 후보를 선택하는 판정 기록**이다.
스냅샷·baseline·관측 id·선택 후보 해시·날짜·기존 값·선택 값·근거 id·이유를 보존한다.
공급자 관측이 바뀌면 기존 판정을 재사용하지 않는다. 이전 판정과 원본은 남는다.

수량·가격이 조금 다르다는 허용오차, 최근 값 우선, 재조회 두 번 성공만으로 승인하지 않는다.
선택 후보는 새 확인 계약을 통과하고 정상 OHLCV여야 하며 다음 근거 중 하나를 만족해야 한다.

1. `legacy_reverse_rounding`: 별도로 검토·가져온 주식 수 사건의 비율·적용일과 기존 계수를
   대조한다. 사건 전 날짜에서 가격은 같고, 공급자 수정량을 정수 반올림한 뒤 기존 방식으로
   역산한 값이 보존 거래량과 정확히 같아야 한다. 선택하는 값은 공급자 원본이며 수량을
   역산해 새로 만드는 것이 아니다.
2. `legacy_reverse_basis`: 같은 독립 사건 근거와 기존 계수로, 사건 후 날짜의 모든 기존
   OHLC와 거래량이 잘못 적용된 역산 식과 정확히 일치해야 한다.
3. `intraday_prefix`: 같은 종목·날짜의 KRX 1분봉을 특정 시점까지 합친 **전체 OHLCV**가
   보존 일봉과 정확히 같아야 한다. 분봉 가격의 보정계수는 가격에만 역적용한다.
   거래량에는 곱하지 않는다. 선택 후보의 시가는 같고 고저·거래량이 전체 일자 범위의
   확장 조건을 만족해야 한다. 분봉 거래량 합계가 전체 공급자 일봉량과 같다고 요구하지 않는다.

주식 수 사건 자료는 운영자가 별도로 검토한 원문·URL·SHA-256과 비율을 명시적으로 import한다.
원문 해시를 확인하지만 외부 공시의 내용을 자동 이해·인증하는 수집기는 아니다.
특정 사건 증거를 전체 구간 `ShareEvidence`로 격상하지 않는다. CB/BW·제3자배정·소각
등 미지원 또는 분류 정책이 필요한 이력은 별도 검토 대상이다.

분봉 누적의 일치 시각은 값이 나타내는 시점이다. 당시 일봉의 실제 수신 로그가 없다면
정확한 수신 시각으로 확정하지 않는다. 근거가 없거나 식이 맞지 않으면 거부 사유를
보존하고 그 날짜는 계속 격리한다. 다른 날짜까지 자동 승인하지 않는다.

## 실행과 보존

기존 복구 CLI의 `plan/run/resume/status/cancel/compare`에 `review`를 추가했다.
실제 수집은 기존 서버의 클라이언트·거버너를 공유한다. 정정 검토는 네트워크와 자격증명이
필요 없는 운영 명령이며 수집이 끝난 계획에만 같은 파일 소유권 잠금 아래 적용한다.

```sh
python -m hoga.api.screener_recovery_cli plan --data-dir DATA --input pilot-spec.json
python -m hoga.api.screener_recovery_cli run --data-dir DATA --plan-id PLAN
python -m hoga.api.screener_recovery_cli review --data-dir DATA --plan-id PLAN --input correction-input.json
python -m hoga.api.screener_recovery_cli compare --data-dir DATA --plan-id PLAN --comparison-dir OUTSIDE_NEW_DIR
```

`review` 입력은 `evidence` 객체 목록과 `requests`(종목별 날짜·이유·evidence id·필요한 경우
분봉 종료 시각) 목록이다. 근거 id는 기존 불변 객체와 같은 JSON digest다.
일치하지 않는 증거·코드·날짜·원문·중복 날짜·변경된 스냅샷은 승인하지 않는다.
검토 시작·종료와 종목별 처리 전에 기존 파일 지문을 확인한다.
v2 writer는 같은 `.writer.lock`을 사용하지만 미완료 legacy 공개 journal을 복구하거나 쓰지 않는다.

복구 상태에는 `confirmation_state`, `resolved_conflict_dates`, `correction_id`를 추가했다.
`observed/complete`는 요청한 원본·가격 창의 준비 상태이며 수량 보정 인증 완료와 다르다.
`share_evidence_ready`는 별도다. 수량 근거가 없으면 `raw`로 자동 폴백하지 않는다.

## 비교·검증

운영 경로 밖 복사본에서만 로스터를 표본으로 좁히며 조건의 표현식·스코프는 유지한다.
정정은 원본 baseline id에 묶이므로 그 불변 baseline과 관측·이전 관측·판정·근거 객체를
동일 id로 복사한다. 기존 결과는 전후 같아야 한다. 새 결과는 `raw`, `share_adjusted`,
정정 전 `raw_unreviewed`를 구별해 보존하고 각각 정확 재실행한다.
재실행은 행·커버리지뿐 아니라 세션·수량·정정 등 계산 기준의 동일성도 확인한다.

검증에는 불안정 표본·잘못된 venue·짧은 재조회 간격·표본 변조·확인 범위 밖 행·
후속 구형 writer·원문 해시 불일치·틀린 수량 비율·분봉 가격 0.01 차이·1주 차이·
오래된 판정·동시 공개·기존 journal 보존·HTTP 직렬화·독립 복사본 replay를 포함한다.
실제 25종목 결과와 최종 검증 입력 지문은 해당 시범 복구 진단 자료에 기록한다.

기존 정책의 독립 실행 비교는 `scanned_at_ms`와 발생 근거의 `fetched_at_ms`처럼 실행 때마다
달라지는 시각만 제외한다. 원 응답에는 그 시각을 그대로 남긴다. 실제 전체 유니버스
검증에서 기존 볼린저 근거가 실행 시각을 기록하는 것을 확인했으며, 가격·거래량·금액·
발생일·평가 기준 시각·커버리지는 제외하지 않는다. 새 정책의 정확 replay는 이 정규화를
사용하지 않고 발생 근거의 시각까지 원 응답과 동일한지 검사한다.

## 검토 전용 계획 인계와 583개 운영 반영 (2026-10-24 후속 요청)

수집 당시와 검토 당시의 코드 지문이 다른 경우 옛 계획의 코드 가드는 그대로 유지한다.
새 `review-plan`은 중지된 원 계획·작업의 확인 관측을 현재 코드로 명시적으로 인계받는다.
원 계획·작업은 덮어쓰지 않으며, 대상 날짜·기준일·baseline·최초 비교 기준·수집 후보 id를
유지한다. 관측을 다시 수집하거나 공개하지 않으므로 이전 483개 판정의 관측 바인딩이 유지된다.

새 계획의 내부 `review_binding`은 원 계획 id, 원 작업의 불변 사본 id, 정정 입력의 불변 id,
검토 시작 snapshot id를 포함한다. 입력은 검토할 원 작업의 미해결 충돌 날짜만 허용한다.
모든 근거를 읽기만 하는 `prepare_review`로 먼저 검증하며, 하나라도 거부되거나 이전 승인
값이 바뀌면 계획 생성/반영 전체를 거부한다. 기존 검토 규칙의 수치 허용오차는 바꾸지 않는다.

```sh
python -m hoga.api.screener_recovery_cli review-plan --data-dir DATA --plan-id SOURCE_PLAN --input review-input.json
python -m hoga.api.screener_recovery_cli review --data-dir DATA --plan-id NEW_REVIEW_PLAN
python -m hoga.api.screener_recovery_cli status --data-dir DATA --plan-id NEW_REVIEW_PLAN
```

검토 전용 계획에 `run/resume` 또는 HTTP 수집 시작을 요청하면 거부한다. `review` 입력은
계획에 이미 고정되어 있으며, 명시적으로 다시 제공할 경우에도 같은 digest여야 한다.
계획 생성·반영은 기존 복구 owner lease와 기존 파일 해시·코드 버전 가드를 공유한다.

반영은 종목별 공개 대신 **검증된 전체 묶음을 한 번의 manifest CAS로 공개**한다.
가격/거래량 관측·수량 인증·종목 목록·달력 등은 그대로 두고 corrections와 parent만 바꾼다.
객체 쓰기 실패 또는 동시 snapshot 변경이면 기존 포인터가 유지된다. 새 review에는 계획 id와
요청 지문을 넣는다. 공개 직후 작업 파일 저장 전에 중단되더라도 재시도 시 해당 묶음 전체와
이전 snapshot의 관계를 재검증해 작업 상태만 복구한다. 다른 쓰기 위에 재공개하지 않는다.

4종목 운영 검증은 실제 서버에서 같은 과거 snapshot과 새 snapshot을 명시한 EOD 실행을
보존하고, 원거래량의 장기 평가 가능 여부·기존 저장 조건·수량 미확인 유지·정확 replay를
검사한다. 결과와 지문은 별도 583개 반영 진단 보고서에 기록한다.

## 사건 전 수정 기준이 원본에 들어간 경우 (535개 후속 반영)

`legacy_pre_event_adjusted_basis`는 기존 역산 정정과 별도 규칙이다. 사람의 검토로 비율을
확인한 결정 공시와 실제 거래 단위 적용일을 확인한 거래소 공시를 원문·SHA256으로 각각
고정한다. 법적 효력일·배정기준일·신주 상장 예정일을 거래 단위 적용일로 대신하지 않는다.
런타임은 고정한 근거의 체크섬·종목·적용일과 다음 수식을 검사하며 HTML 내용을 자동으로
해석해 공시 사실 자체를 인증하는 기능은 아니다.

- 대상은 확인 관측에 포함된 유효한 충돌 날짜이며 사건 이전이어야 한다.
- 사건은 공급자 수정 기준일 이내의 분할·병합·무상증자이고 수량 비율은 1이 아니어야 한다.
- 보존된 legacy 계수는 정확히 1이고 기존 원본의 **전체 OHLCV**가 공급자 수정 OHLCV와 같아야 한다.
- 독립 공시 비율 `r = 신주 / 구주`에 대해 모든 가격은 `기존 가격 = 확인 원가격 / r`,
  거래량은 `기존 수량 = round(확인 원수량 × r)`이어야 한다. 유리수로 계산하고 추가 허용오차는 없다.
- 이 조건을 만족한 날짜만 별도 v2 선택으로 공개한다. 전체 수량 이력 인증이나 다른 사건의
  자동 승인은 하지 않으며 `share_adjusted` 미확인은 그대로 유지한다.

정정은 검토 전용 계획의 사전 검증·이전 승인 보존·한 번의 manifest CAS·동일 계획 재시도
절차를 사용한다. 대신정보통신 317개와 레드캡투어 218개의 실제 적용·전후 비교·운영 검증은
[535개 후속 반영 자료](../diagnostics/2026-10-24-screener-review-535/README.md)에 보존한다.
