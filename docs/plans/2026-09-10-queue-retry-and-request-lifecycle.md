# 일일 등록 재시도·스캔 종료·큐 저장 상태

## 문제와 범위

일일 거래일 단계는 종목 등록 예외를 로그로 흡수하고 완료 마커를 남겨 당일 등록을
재시도하지 않았다. `/scan`은 요청 취소와 독립적으로 실행되는 작업의 마지막 독자가
떠난 뒤 발생한 예외를 회수하지 않았다. 큐 매니페스트 저장 실패는 로그에만 남았다.

## 구현

- 실패한 당일 등록을 `scheduler_pending_enqueues.json`에 체크포인트한다. 정상 응답
  (중복·실패 횟수 제한에 의한 차단 포함)은 제거한다. 완료 마커가 있어도 다음 60초
  틱에서 남은 종목만 `enqueue_items_core`로 재시도한다. 재시작 후에도 파일에서
  이어받으며, 지난 날짜는 만료한다. 스크리너·집계·캐시 예열은 반복하지 않는다.
- `/scan`과 패턴 검색은 라우터별 `ReadRequestCoalescer`를 사용한다. 한 독자가 떠나도
  다른 독자의 실행은 유지하고 마지막 독자가 떠나면 작업을 취소한다. 오류는 회수하고,
  라우터 lifespan 종료는 소유 작업을 취소하고 기다린다. 종료 이후 요청은 503이다.
- 매니페스트 저장 성공 여부를 큐 소유 모듈이 추적한다. 실패해도 인메모리 작업은
  계속하며, lifespan 소유 작업이 30초마다 실패 상태인 경우에만 최신 큐를 잠금 안에서
  다시 저장한다. 저장 성공 시 경고를 해제한다. 비소유 인스턴스는 쓰지 않는다.
- 큐 응답에 `persistence_degraded`, `last_persisted_at_ms`를 추가한다. 마지막 저장 시각은
  현재 서버 실행에서 성공한 시각이며, 아직 성공이 없으면 null이다. 실패/복구 전환만
  `capture_queue_persistence`로 푸시하고 프론트 캐시의 상태 필드만 갱신한다.
- 빈 큐에도 저장 경고를 표시하고 복구 시 제거한다. 별도 폴링은 추가하지 않는다.

ADR-0034의 큐 클라이언트 경계와 ADR-0019의 저장 실패 흡수 정책을 유지한다.

## 검증

실패 종목만 재시도, 당일 체크포인트 복원, 만료·정책 차단·취소, 일일 작업 중복 방지,
마지막 독자 취소 후 오류 회수, 라우터 종료, 저장 실패/복구 wire·push, 비소유 쓰기 방지,
프론트 상태 패치 및 브라우저 복구 흐름을 회귀 테스트로 확인한다. 필수 전체 검증은
백엔드 Ruff/pytest, 프론트 타입/Vitest/build와 Playwright E2E다.

최종 결과: Ruff 통과, 백엔드 5,026 passed / 2 skipped / wallclock 13 deselected,
프론트 타입 검사 및 Vitest 7,319 passed / 559 files, Vite build 통과(기존 큰 청크 경고),
Playwright 109 passed. REST 계약 가드는 의도적으로 필드를 누락한 음성 대조에서
실패함을 확인했고, SSE 새 이벤트도 계약 스냅샷에 등록했다.

## 한계

일일 등록 재시도 파일도 디스크 장애 시 기록하지 못할 수 있으며 로그로 알린다.
매니페스트 경고는 현재 실행의 저장 실패를 나타낸다. 재시작 전에 저장하지 못한
목록을 새 서버가 복구하거나 과거 실패를 추론하지는 않는다. 이미 실행 중인 동기
스캔/CPU 작업을 강제 중단하지는 않는다. 실제 벤더나 운영 서버 재시작은 검증 범위 밖이다.
