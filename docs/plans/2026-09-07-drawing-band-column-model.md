# 드로잉 빈 밴드 — 열(column) 모델로 통일 (#1759 · #1760 후속)

2026-09-07. #1760 이 「못 보는 것」으로 남긴 세 경우를 한 모델로 푼다.

## 남은 세 경우

| 경우 | 왜 납작해지는가 |
|---|---|
| ① 주말(today-segment 없음)에 그린 도형 | 밴드가 real ms 로 연장돼 「금 16:20」 같은 갭 시각으로 저장 → 월요일엔 밴드도 축 안도 아니라 갭 스냅이 금요일 마감 열에 붙인다 |
| ② 마지막 봉이 세션 마지막 rung 이 아닌 종목(15:19 로 끝남) | 사다리가 금요일의 빈 슬롯(15:20~15:30)을 먼저 세서 꼭짓점이 빈 슬롯 시각으로 저장 → 월요일엔 `nearestLoadedBarX` 가 15:19 열로 붙인다 |
| ③ 캘린더 축(D/W/M) | 사다리 경로가 캘린더를 제외해 ① 이 그대로 남고, 연장 단위가 달력일이라 토·일이 갭이다(+3 = 월요일 = 실제로는 +1 열) |

## 결정 — 「저장된 realMs 는 열 번호로 읽는다」

세 경우의 공통 뿌리는 **realMs 가 시각과 열을 동시에 뜻하는데 둘이 갈릴 때 시각을 택한
것**이다. 화면이 보여 준 것은 열이다. 그러니 축·번들이 바뀌어도 **열이 보존되도록**
realMs 를 해석한다.

### 열 번호 `columnOf(realMs)`

세션 사다리(#1760 의 `sessionLadder`: 세션당 `floor(len/bucket)+1` rung, 갭은 0) 위에서:

- **축 안** → 그 rung 의 번호(기존 `onAxisBar`).
- **세션 사이 갭·축 끝 너머**(직전 세그먼트 i 의 close 뒤) → `segEndBar(i) + (realMs − close_i) / bucket`.
  즉 **갭 시각은 「직전 마감 이후 N 열」이다.** 이것은 기존 real-ms 연장이 저장한 값의
  의미 그대로다(연장이 `close + N × bucket` 을 찍었다). 새로 정의한 게 아니라 **읽는
  쪽을 쓰는 쪽에 맞춘 것.**
- **캘린더** — 일 단위(bucket ≤ 1d, 즉 D): 갭 열 = 직전 세그먼트 날짜 이후 **평일 수**.
  주·월(7d/30d 명목): `round((realMs − close_i) / bucket)`.

### 역함수 `realAtColumn(col)`

- `col ≤ lastBar`(사다리 안) → 그 rung 의 실제 시각(기존 `rungReal`; 분수 열은 세션 안이면
  유지, 경계에 걸리면 가까운 rung).
- `col > lastBar`(사다리 밖) → **마지막 세그먼트의 close + (col − lastBar) × bucket** —
  갭 시각. D 는 마지막 날짜의 다음 평일 09:00.

### 마지막 봉의 기준 열 `baseColumn`

밴드의 「N 열 앞」은 어디서부터인가.

- 마지막 봉의 세션이 **끝났으면**(뒤에 세그먼트가 있거나 `close < now`) → 그 세션의
  **마지막 rung**. 남은 슬롯(15:20~15:30)은 영영 채워지지 않으므로 열이 아니다 → ②.
- **진행 중이면** → 마지막 봉의 rung(기존). 슬롯이 곧 봉으로 채워진다.

`now` 는 순수 기하 함수에 넣지 않는다. `futureBandFor` 가 `FutureBand.lastSessionComplete`
로 한 번 계산해 넘긴다. 테스트 픽스처의 리터럴 FutureBand 는 기본 `false`(진행 중) 라
기존 기대치가 그대로 성립한다.

### 치유(heal)

`realMsToCanvasX` 는 축 밖 realMs 를 만나면 먼저 `realAtColumn(columnOf(realMs))` 로
**같은 열의 실제 rung** 으로 바꿔 읽는다. 월요일 세그먼트가 생기면 「금 16:20」(= 마감
+50 열)은 월요일 50번째 rung 이 되고, 봉이 생기면 그 봉의 X 로 곧장 투영된다 → ①.
드래그 도메인(`toBar` = `columnOf`, `toReal` = `realAtColumn`)도 같은 셈이라 첫 드래그가
저장값을 실제 rung 으로 되쓴다(기존 translate 의 「왕복이 갭 좌초를 치유한다」 규약과
같은 방향). 저장 포맷은 바뀌지 않는다 — **읽는 규칙만** 바뀐다.

공휴일에도 맞는다: 월요일이 휴장이면 다음 세그먼트가 화요일이고, 「마감 +N 열」은
화요일의 N 번째 rung 이 된다. 사용자가 본 것은 열이므로 그게 정답이다. D 의 평일
근사는 라벨(날짜)만 틀리고 열은 맞는다.

### 이 PR 이 바꾸는 값

- 장외(세션 종료 뒤) 밴드 생성값: 15:19 로 끝나는 종목에서 `15:19 + N` → `close + N`(②).
  15:30 으로 끝나는 보통 종목은 값이 같다.
- 캘린더 밴드 생성값: D 는 다음 평일(주말 건너뜀), W/M 은 명목 그대로.
- 축 밖 realMs 의 렌더·드래그: 갭 스냅(직전 마감 열) → **같은 열의 실제 rung**.

## 여전히 못 보는 것

- 구 코드가 남긴 「완료된 세션의 꼬리 빈 슬롯」 값(② 종목에서 15:22 등)은 축 안이라
  치유 대상이 아니고 `nearestLoadedBarX` 가 이웃 봉에 붙인다. 드래그하면 낫는다.
- 측정자(measure)의 기간 표시는 `b.realMs − a.realMs` 그대로다 — 갭 시각을 포함하면
  「실제 경과」가 아니라 명목값이다. 별건.
- 공휴일이 낀 D 의 날짜 라벨은 평일 근사라 하루 어긋날 수 있다(열은 맞다).
