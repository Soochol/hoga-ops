# 시세 캐시 정합성과 조회 책임 개선

작성: 2026-09-10. 기준: main의 PR #1802 반영본.

## 범위와 순서

1. 재현된 시세 캐시 역행과 장마감 전체 재조회 문제를 수정한다.
2. 이번에 수정하는 시세 조회·캐시·phase 표시 책임을 라우트에서 독립 모듈로 옮긴다.
3. 동기 저장과 프론트 이력 계산은 먼저 비용을 측정하고, 병목 근거가 있을 때 별도 구조 변경으로 확장한다. 기존 검토에서 조건부로 제안한 부분이다.
4. 전체 로컬 검증, 최신 main 및 열린 PR 확인 후 PR을 생성·병합한다. 운영 서버 배포·재시작은 범위 밖이다.

## 재현과 수정

### 캐시 역행

중첩된 종목 목록을 서로 다른 요청으로 조회할 수 있다. 먼저 시작한 요청이 나중에 완료되면 이미 성공한 새 요청의 표본을 덮어썼다. 모의 입력에서 캐시 가격 200→100 역행을 확인했다.

- 성공 표본에 거래일과 요청 시작 순번을 함께 저장한다. 비교 단위는 `(venue, code)`다.
- 더 최근 거래일 또는 같은 거래일의 더 최근 성공 요청만 캐시를 갱신한다.
- 새 요청이 실패하거나 특정 종목을 반환하지 않았다면 이전 요청의 성공을 사용할 수 있다. 마지막 발행 순번만으로 모든 이전 결과를 버리지 않는다.
- 같은 거래일의 늦은 응답에는 이미 보유한 더 최근 성공 가격을 반환한다.
- **제약:** Quote에는 공급자 관측 시각이 없다. 시작 순번은 서버 요청 순서이며 거래소 이벤트 시각의 대체 보장이 아니다. 이번 수정은 서버 캐시의 역행을 막으며 브라우저 전체의 시계 정합성까지 보장하지 않는다.

### 장마감 부분 재조회

종가 표본 100종목이 이미 있어도 1종목이 빠지면 101종목을 두 청크로 재조회했다. 계산된 `refetch` 목록만 실제 호출에 넘기도록 수정했다. 재현 입력은 1종목·1콜로 줄고, 반환 순서와 기존 캐시 값은 유지한다.

### 모듈 분리

`live_quote_fetcher.py`가 시세 조회, 마지막 성공 캐시, phase 표시, 실패 폴백과 `LiveQuote` 응답 모델을 소유한다. `api.py`는 입력 해석·호출 의존성 조립·HTTP 응답을 담당한다. 기존 `api.LiveQuote`와 `api.LiveQuoteFetcher` 접근은 import로 호환되며 응답 필드/enum은 동일하다. 단위 테스트는 새 모듈을 직접 사용한다.

## 저장·이력 계산 측정과 범위 결정

외부 자격증명·벤더 호출 없이 작업트리의 로컬 환경에서 측정했다. 실사용 장중 부하나 전체 브라우저 렌더 trace는 아니다.

| 측정 | 입력 | 결과 |
|---|---|---|
| 시간외 JSON 저장: 기존 파일 읽기·한 종목 갱신·원자 교체, 20회 | 저장 종목 10개 | 중앙값 0.06ms, 최대 0.12ms |
| 동일 | 저장 종목 100개 | 중앙값 0.36ms, 최대 0.48ms |
| 동일 | 저장 종목 1,000개 | 중앙값 3.65ms, 최대 4.03ms |
| 이력 복사·3개 venue 필터: OB/체결 두 kind, 50회 | kind당 3,000행 | 중앙값 0.43ms, 표본 p95 0.55ms |
| 동일 | kind당 30,000행 | 중앙값 4.32ms, 표본 p95 4.65ms |
| 동일 | kind당 60,000행 | 중앙값 8.94ms, 표본 p95 10.11ms |

저장은 임시 디렉터리에 실제 `save_books`를 실행했고, 프론트 계산은 Node에서 실제 `LiveSnapshotBuffer.get`과 venue별 filter를 실행했다. 후자는 React commit·차트·paint를 포함하지 않으므로 브라우저 지연으로 보고하지 않는다. 행 payload는 합성 입력이고 실제 객체 크기와 다를 수 있다.

현재 사용자 환경의 병목이라는 증거가 충분하지 않아 **저장 작업자·묶음 쓰기와 프론트 증분 처리 전환은 이번 PR에서 적용하지 않는다.** 큰 입력에서 비용이 증가하는 위험은 남아 있다. 후속 조건은 실제 종목 수·동시 요청 수·디스크 지연을 포함한 이벤트 루프 지연 측정, 그리고 여러 창의 브라우저 trace에서 해당 작업이 의미 있는 비중으로 확인되는 것이다. 저장을 옮길 때는 단일 작성자·종료 flush·재시도와 원자 저장을 함께 설계해야 한다.

## 검증

- 변경 전 신규 테스트: 캐시 역행 3경우와 전체 재조회가 실패, 새 요청 실패 시 기존 성공 보존은 통과.
- 변경 후: 같은 날 요청 역전, 장마감 전환, 날짜 전환, 실패 시 폴백, venue/종목별 독립 비교, 100종목 캐시+1종목 보충, 반환 순서 검사.
- 기존 시세 조회·라우트 및 wire 계약 검사 통과. 전체 백엔드·프론트 타입 검사·Vitest·빌드 결과와 검증 커밋은 PR 본문에 기록한다.
- 프론트 소스·공개 응답 필드·enum을 변경하지 않아 이번 PR의 E2E 재실행 대상은 아니다.
