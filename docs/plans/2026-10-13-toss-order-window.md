# 호가 주문창 — 토스증권·로컬 모의 계좌

기본은 통합 호가로 체결하는 로컬 모의 계좌다. 화면 시세는 10호가창과 같은
KRX·NXT·통합 선택을 따르며, 토스 API 키 없이 사용할 수 있다.
현금·보유 수량 설정과 체결 규칙은 아래 「로컬 모의 계좌」 절을 참고한다.

공식 토스 계약 확인일: 2026-10-14.

- https://developers.tossinvest.com/llms.txt
- https://openapi.tossinvest.com/openapi-docs/latest/openapi.json
- https://openapi.tossinvest.com/openapi-docs/latest/asyncapi.json
- https://openapi.tossinvest.com/openapi-docs/faq.md

토스 실계좌 모드에서는 프로덕션 서버 `.env`에 `TOSSINVEST_CLIENT_ID`·`TOSSINVEST_CLIENT_SECRET`을 설정한다.
토스 WTS 설정 > Open API에서 발급하고 서버 외부 송신 IP를 허용한다. 개발·E2E는
실자격증명을 쓰지 않는다. 서버만 토큰을 보관하고 브라우저에는 계좌 식별값과
마스킹된 계좌 이름을 제공한다. 기존 네트워크 접근 모델(ADR-0134)을 따른다.

`/live` 창 추가 > 호가 주문으로 연다. 종목 고정·링크 그룹 규칙은 따르되 과거
차트 커서는 따르지 않는다. 잔량 유지형, 왼쪽 매도·오른쪽 매수 주문 영역,
제목·추가 기호·드래그 아이콘 없음, 24px 행을 유지한다. 빈 영역 클릭으로 즉시
신규 주문, 수량 클릭으로 개별 상세, 수량 드래그로 즉시 정정, 호가 밖 드롭으로
즉시 취소한다. 신규 주문 확인창과 즉시 주문 전환 체크박스는 표시하지 않는다.

호가·단별 잔량·총잔량·잔량 증감·시장 체결·체결강도·시세 요약·VI는 선택한
venue를 따른다. 세션별 호가·총잔량 처리와 체결 목록 변환은 10호가창과 공유한다.
주문창에 「시세 NXT · 주문 통합(SOR)」 또는 「시세 NXT · 모의 체결 통합」처럼
표시 기준과 실행 기준을 함께 표시한다. NXT 미상장 종목의 통합 선택은 KRX로
대체하며 이를 표시한다. 계좌의 미체결·체결 내역은 시세 venue로 필터링하지 않는다.
venue 변경 시 드래그·고정 호가·가격 미리보기·미제출 고액 확인을 초기화하고,
입력 수량과 계좌 주문 상태는 유지한다. 신규·정정은 선택한 시세의 최신 호가로
가능 여부를 판단하며, 클릭한 지정가를 기존 토스 요청에 전달한다. 거래소 지정
필드는 보내지 않고 실제 주문은 통합(SOR)으로 유지한다. 토스의 투자자지시
거래소 설정이 통합이 아니면 API가 `investor-exchange-not-integrated`로 거절한다.

매수·매도는 공통 주문 입력을 사용한다. 계좌 행의 「설정」에서 수량 / 금액 모드와
각 모드의 프리셋 3개를 변경한다. 기본 수량 프리셋은 10/50/100주, 금액 프리셋은
1/5/10백만원이다. 금액은 **백만원 단위의 양의 정수**로 입력한다(1백만원 = 100만원).
수량 모드는 현재가 × 수량으로 예상 금액을, 금액 모드는 금액 ÷ 현재가의 정수
부분으로 예상 수량을 표시한다. 호가에 포인터·키보드 포커스를 두면 해당 가격으로
계산하며, 금액 신규 주문은 **클릭한 지정가**로 수량을 내림 계산한다. 계산 결과가
1주 미만인 호가는 신규 주문 버튼을 비활성화한다. 수수료·세금은 포함하지 않는다.
드래그 정정은 금액으로 다시 계산하지 않고 최신 잔여 수량을 유지한다.
설정 팝업은 「적용」을 눌러야 반영되며 취소·Esc·바깥 클릭은 변경을 버린다.
모드와 각 프리셋은 창별 워크스페이스 설정으로 저장해 종목·계좌 전환과 새로고침
후에도 유지한다. 현재 선택한 프리셋을 수정하면 같은 슬롯의 새 값으로 갱신하고,
직접 입력한 값은 유지한다. 다른 주문창은 별도 설정을 사용한다. 새로고침 시 입력
값은 해당 모드의 첫 프리셋으로 시작한다. 방향 전환·매도 비율 버튼은 표시하지 않는다.
계좌 행 아래 설정 행에는 현재 종목의 매입수량(주) / 매입평단가(원) / 평가수익(원) /
매수 가능 금액(원)을
주문수량 입력의 왼쪽에 표시한다. 보유 정보와 주문 설정은 얇은 구분선으로 나누고,
라벨은 위, 값·입력·프리셋은 아래에 정렬한다. 좁은 창에서도 한 줄을 유지한다.
매입수량은 해당 계좌의 현재 전체 보유 수량, 매입평단가는 API의
평균 매입가를 원 단위로 올림하여 표시한다. 미보유 종목은 0주 / 평단가 대시 /
평가수익 0원으로 표시한다.
평가수익은 해당 계좌·현재 종목의 **전체 보유 수량 × (현재가 − API 원본 매입평단가)**로
계산한 뒤 원 단위로 올림한다. 화면에 올림 표시한 평단가를 계산에 사용하지 않으며,
API의 십진 문자열을 유지해 정수 경계에서 부동소수점 계산의 1원 오차를 방지한다.
평가손익 숫자를 더블클릭하면 금액과 수익률(%) 표시를 번갈아 전환한다. 수익률은
올림 전 평가손익을 원본 매입금액으로 나눈 비율이며, 십진 원가를 유지해 소수점
두 자리까지 반올림한다. 기본 표시는 금액이고, 같은 주문창의 종목·계좌를 바꿔도
선택한 표시 방식은 유지한다. Enter·Space로도 전환하며 보유·시세·원가가 없으면
대시를 표시하고 전환을 비활성화한다. 표시 전환은 주문 수량이나 주문 요청을 바꾸지 않는다.
미체결 매도로 예약된 수량도 포함하며 선택 호가·입력 주문 수량은 평가수익에 영향을
주지 않는다. 보유가 없으면 0원, 현재가·원본 평단가가 없거나 계좌 조회에 실패하면
대시를 표시한다.
매수 가능 금액은 계좌 API의 `buying_power`를 원 단위로 표시한다. 주문 수량으로
환산하지 않으며 조회 실패·유효하지 않은 값은 대시로 표시한다.
호가 안쪽 시세 상세는 기존 10호가창의 `BookSummary`를 공유한다. 항목·가격색·
시/고/저 칩·거래량 만 단위·거래대금 억/조 단위·어제보다 %·KRX종가·VI·250일
정보를 같은 방식으로 표시하고 계좌 잔고를 섞지 않는다.
10호가창과 주문창 모두 좁은 폭에서 열·통계·체결을 숨기는 축소 모드를 사용하지
않는다. 기존 열 배분을 유지하고 최소 폭 아래에서는 가로 스크롤을 제공한다.
주문창의 계좌·수량 설정도 같은 최소 폭을 유지해 축소 시 줄 배치가 바뀌지 않는다.
같은 가격의 개별 주문 선택과 호가 밖 주문을 지원한다. 상단 종목명·현재가, 하단
미체결 요약·방향별/종목 전체 취소 버튼·보유 정보·취소 안내·접수 상태·최근 주문
표시는 제거했다. 가격·잔량·설정은 기존 10호가/지표창의 데이터 글자 크기,
라벨·등락률은 보조 글자 크기를 사용한다. 총잔량은 10호가창의 같은 스트립을
공유하여 비율 바와 좌우 숫자만 표시한다. 전체 취소는 단축키로 사용할 수 있다. 요청 실패만 공용 토스트로
짧게 알리고 같은 요청 ID로 결과를 다시 확인할 수 있다. 토스 실계좌의 1억원 이상
주문은 API 필수 금액 확인만 짧게 표시하고 `confirmHighValueOrder=true`를 보낸다.
모의 주문은 금액에 관계없이 즉시 접수한다. 예상 주문 금액은 수수료·세금 전 계산이다.

주문창 안에 포커스가 있을 때 Ctrl+1/2/3은 현재 모드의 프리셋 1/2/3, Ctrl+↑/↓는 선택한
주문의 다음 화면 가격으로 정정, Ctrl+Delete는 선택 주문 취소,
Ctrl+Shift+Backspace는 현재 종목 전체 취소 확인이다. 입력칸 편집과 키 반복에서는
실행하지 않는다. Esc는 드래그·확인을 중단한다.

주문을 6px 이상 끌면 원래 주문은 반투명으로 남고, 커서를 따라 최신 잔여 수량만
표시하는 작은 칩이 뜬다. 방향·가격·설명은 표시하지 않는다. 정정 가능한 같은 방향
주문 영역은 테두리로 강조한다. 호가 밖에서는 칩이 취소 색상과 점선 테두리로
바뀐다. 놓기 전에는 요청하지 않으며 드롭·Esc·포인터 취소
후 미리보기와 강조를 제거한다. 미리보기는 호가의 클릭·드롭 판정을 가로채지 않는다.

## 토스 계약

REST 서버: `https://openapi.tossinvest.com`. OAuth2 Client Credentials Grant를
`POST /oauth2/token`에 form-urlencoded로 보내고, 계좌 요청은
`X-Tossinvest-Account: accountSeq` 헤더를 사용한다.

- 신규: `POST /api/v1/orders`, LIMIT·DAY, 가격·수량은 십진 문자열.
- 정정: `POST /api/v1/orders/{orderId}/modify`; 실행 직전 상세에서 최신 잔량을
  계산한다. 직접 편집한 수량은 사용자가 지정한 값으로 전송한다.
- 취소: `POST /api/v1/orders/{orderId}/cancel`, 빈 객체.
- 정정·취소는 새 주문 ID를 반환한다. HTTP 성공은 접수이며 완료가 아니다.
- 국내는 통합(SOR)만 지원하고 거래소 지정이 불가능하다. 동일 종목의 반대 방향
  미체결 주문이 있으면 가격이 겹치지 않아도 신규 주문을 거절한다.

백엔드에서 personal:order 채널에 accountSeq로 구독하고 표준 ping(60초)으로
연결을 유지한다. 주문 이벤트·재연결 시 REST를 재동기화한다. 브라우저 알림은
기존 `/api/ws`의 trading_changed 이벤트를 사용한다(ADR-0053). 조회 폴링은
연결 단절 구간을 보완한다. API 그룹별로 요청을 페이싱한다.

## 중복·불명확한 결과

`<data_dir>/trading/commands.sqlite3`에 전송 전 요청 내용과 고유 ID를 기록한다.
같은 ID/내용은 한 번만 전송하고 동일 응답을 반환한다. 다른 내용이면 거절한다.
생성에는 같은 ID를 clientOrderId로 전달한다. 토스 멱등성 유효 기간은 10분이므로
재시작·시간 경과 후 자동 재전송하지 않는다. 정정·취소도 자동 재전송하지 않는다.

전체 취소는 최초 요청의 대상 주문 ID를 먼저 영속한다. 같은 요청을 다시 확인해도
이후 생성된 새 주문을 대상에 추가하지 않는다. 건별 취소는 고정된 하위 요청 ID로
기록하므로 응답 누락·재시작 후에도 이미 접수한 취소를 중복 전송하지 않는다.

연결 단절·5xx·잘못된 주문 응답은 결과 불명확으로 보존하며 실패로 간주해 새로운
주문을 생성하지 않는다. 해당 계좌·종목의 신규 주문을 제한하므로 운영자가 토스
WTS 내역과 서버 명령 기록을 대조해야 한다. 실제 주문·체결 여부 확인 체크와
확인 완료 버튼으로 확인 기록을 남기면 신규 주문 제한을 해제한다. 원요청은 다시
전송하지 않는다. 취소 경로는 유지한다. 이미 체결·
종료·처리 중인 주문을 정정·취소하지 않는다.

호가 단위·상하한가·접수 시간·수수료를 포함한 최종 주문 가능 수량은 토스가
검증한다. 30초 이상 오래된 호가는 신규·정정을 제한하고 계좌 연결이 살아 있으면
취소는 유지한다. 현재 범위는 국내 현금 지정가이며 미국·신용·조건주문·시장가·
계좌 전체 포지션 청산은 제외한다. 호가 갱신 대기 안내 문구는 표시하지 않는다.
실주문 검증은 개발 자격증명 격리 관례상 하지 않는다.

## 로컬 모의 계좌

주문창의 기본 모드는 **로컬 모의 계좌**다. `/live` > 창 추가 > 호가 주문으로
열고, 같은 즉시 주문 영역·드래그·단축키를 사용한다. 「주문 모드」에서
토스 실계좌를 별도로 선택할 수 있다. 전환 시 개별 상세·드래그 상태는
초기화되며 계좌 조회 캐시도 모드별로 분리한다.

모의 계좌에는 토스 API 키가 필요 없다. 화면 시세는 선택 venue를 따르고,
체결은 기존 수집기의 **실시간 통합(UN) 호가**를 사용한다. NXT 미상장이 확인된
종목은 통합 조회와 동일하게 KRX 호가로 체결한다. NXT 거래 가능 여부가 불명확하거나
거래 가능한 종목은 통합 호가 부재를 KRX로 대체하지 않는다. 해당 종목의 실제
체결 기준 호가 공급은 필요하다. 과거 차트 커서·복기
데이터를 체결 입력으로 사용하지 않는다. 호가가 없거나 30초 이상 오래되면
신규·정정·모의 체결을 멈추고 취소는 계속 사용할 수 있다. 수집이 중단되거나 종목이
수집 대상에서 빠지면 새 호가가 들어올 때까지 미체결 주문을 유지한다.

초기 가상 현금은 **1억원**, 보유 수량은 0주다. 「모의 계좌 설정」에서 현금과
현재 종목의 초기 보유 수량·평균 매입가를 설정할 수 있다. 초기 보유 주식은 현금과
별도로 부여한다. 초기화 확인 체크 후 실행하면 **모든 종목**의 모의 주문·체결·
보유 내역을 지우고, 입력한 현금과 현재 종목의 보유 수량으로 시작한다. 실계좌에
영향을 주지 않는다. 초기화 전 요청 ID도 보존하므로 늦게 도착한 재시도가 주문을
되살리지 않는다.

체결 규칙:

- 국내 현금 지정가만 처리한다. 매수는 매도 호가가 지정가 이하일 때, 매도는
  매수 호가가 지정가 이상일 때 해당 호가 가격으로 체결한다.
- 여러 가격을 만나면 유리한 가격부터 순서대로 체결하며 평균 체결가를 계산한다.
  같은 모의 계좌의 주문끼리는 가격 우선·접수 순서로 표시 잔량을 공유한다.
- 표시 잔량을 사용한 뒤에는 동일 프레임·동일 잔량으로 다시 체결하지 않는다.
  이후 잔량의 증가분 또는 새 가격의 잔량만 추가로 사용할 수 있다. 감소분은
  가용 잔량에서도 차감한다. 소비한 잔량은 서버 재시작·계좌 초기화 뒤에도 유지한다.
- 백엔드는 1초마다 최신 호가 버퍼를 확인하며, 주문·조회 직전에도 체결을 반영한다.
  모든 중간 틱·거래소의 실제 대기 순번·동시호가 배분·수수료·세금·시장 충격을
  재현하지 않는다. 양방향 호가가 없거나 교차한 호가는 체결에 사용하지 않는다.
- 미체결 매수 금액은 종목 간에 공유하는 현금에서 예약하고, 미체결 매도 수량은
  보유 수량에서 예약한다. 취소·정정 시 예약을 해제/재계산하며 초과 주문을 거절한다.
  같은 종목의 반대 방향 미체결 주문 제한은 토스 주문창과 동일하게 적용한다.
- 부분 체결 후 드래그 정정은 **정정 직전의 잔량**만 새 주문으로 이동한다. 기존
  체결은 서버의 보유 수량과 주문 기록에 남는다. 한국시간 날짜가 바뀌면 이전 날짜의
  미체결 DAY 주문을 만료한다.

부분 체결을 연습하려면 최우선 매도 호가 잔량보다 큰 매수 수량을 입력하고 그
가격의 매수 영역을 클릭한다. 표시 잔량만 체결되고 나머지가 수량 칩으로 남는다.
매도는 초기 보유 수량을 설정한 뒤 최우선 매수 호가에서 같은 방법으로 연습한다.
잔여 수량을 다른 가격으로 끌어 즉시 정정하고, 보이는 호가 경계를 벗어난 곳에
놓으면 즉시 취소한다. Esc로 드래그를 중단할 수 있다. 현재 종목의 전체 미체결
주문 취소는 주문창에 포커스를 두고 Ctrl+Shift+Backspace로 실행한다.

모의 REST는 `/api/paper-trading/*`로 분리되어 실주문 경로 `/api/trading/*`와
섞이지 않는다. 가상 현금·보유·주문·명령 ID·소비 잔량을
`<data_dir>/trading/paper.sqlite3`에 원자적으로 저장한다. 모든 모의 변경은 계좌
단위로 직렬화하며 중복 요청은 저장된 결과를 반환한다. 전체 취소는 현재 모의
계좌·현재 종목·선택 방향 범위이고, 같은 명령 ID 재시도는 이후 주문을 취소하지 않는다.

자동 검증에서는 벤더 자격증명을 비운 채 테스트용 호가를 실제 `LiveBuffer`에
주입한다. 모의 브라우저 테스트는 실제 REST·기존 `/api/ws`·체결 엔진을 사용해
부분 체결·잔량 정정·드래그 아웃 취소·전체 취소를 검증하며 실계좌 API 요청이 0건임을
확인한다. 테스트 호가 주입 API는 `HOGA_ENABLE_TEST_ENDPOINTS=1`인 환경에서만
노출된다. 실제 시장 연결 검증이나 실주문을 수행한 결과와는 구분한다.
