# 스크리너 가격 조건의 분·일·주·월봉 확장

사용자 승인 범위: 신고가, 기간내 신고가, 신고거래량, 신고가 대비 고가, 이동평균.
거래대금·등락률·총잔량 조건은 후속 단계다. 기준 main은
`f54b3e2f0f653d2770830025ad67de7f82babc39`, 브랜치는 `codex/screener-price-timeframes`다.

## 계약

- 다섯 조건에 `timeframe`과 `include_open_bar`를 추가한다. 주기는
  1/3/5/10/15/30/60분 및 D/W/M, 기본값 D/true다. 기본 일봉은 기존 SQL을 유지한다.
- 조건마다 독립적인 주기를 저장한다. 기존 저장본·조건 제외 해시·검색 요청 키의
  생략된 기본값과 명시된 기본값을 동일하게 정규화한다.
- 최신 신고가/신고거래량은 최신 선택 봉 하나에 대해 평가한다. 기간내 신고가는 최근
  N봉에서 각 후보를 포함한 M봉 고가 최대를 비교한다. 동률 포함, 미래 봉 참조 금지.
- 진행 중 제외는 검색 N봉을 고르기 전에 적용한다. 이평 관계는 진행 중 종가가 움직이면
  충족·해제될 수 있다. 최근 한 번이라도 충족한 이평 이력 검색으로 바꾸지 않는다.
- 고가 근접도는 최신 봉의 고가를 기준으로 한다. 보유 이력만으로도 판정하는 기존
  정책을 유지하되 M봉 미확인은 커버리지로 알린다. 신고가와 이평은 풀윈도우 필요.
- 이평은 OHLC source의 최신 값과 같은 source의 SMA를 비교한다. 종가로 강제하지 않는다.

## 데이터와 비용

- 기존 봉 거래량 경로를 확장해 OHLC를 함께 보존하고 동일 요청의 분봉 캐시를 공유한다.
  주·월은 기존 수정 일봉과 실제 거래일 달력에서 O=first/H=max/L=min/C=last로 집계한다.
  당일 overlay는 일봉 행을 교체한다. 누적 거래량·가격을 중복 합산하지 않는다.
- 분봉은 `ka10080` 원주가(`upd_stkpc_tp=0`)를 유지한다. 페이지마다 바뀌는 base_dt에
  벤더 수정 옵션을 적용하면 척도가 갈릴 수 있어 해당 옵션으로 전환하지 않는다.
- 과거 분봉 가격은 기존 `kiwoom_adjust_factors`의 원/수정 일봉 한 쌍으로 계산한
  계수를 적용한다. 모든 페이지는 요청의 현재 KST 날짜라는 동일 기준일을 공유한다.
  가격 4필드만 스케일하며 원본 분봉 거래량과 공유 캐시는 변경하지 않는다.
- 계수는 종목·기준일별 single-flight 및 최대 512항목 메모리 캐시로 공유한다. 실패는
  정상 캐시로 고정하지 않으며 재조회할 수 있다. 조회 종료 후 남은 작업의 실패도 소비한다.
  계수가 없는 과거 구간을 원주가 그대로 비교하지 않는다.
- 기존 분봉 예산(64종목 회전 배치, 동시 4개, 대기·수정계수 포함 20초,
  종목별 분봉 8페이지), 15초 원본 캐시 및 부분 커버리지를 유지한다.
- KRX 정규장만 지원하며 NXT/시간외는 범위 밖이다. 장중 반영은 기존 15~30초
  REST 모니터링 스냅샷이며 전 시장 동시 틱 감지는 보장하지 않는다.

## 발생과 화면

- `bar_price_match`는 주기, 가격 source, 값, 비교값, 창 시작, 진행 상태, 조회 시각을
  응답에 추가한다. 기존 `bar_match`의 거래량 계약은 유지한다.
- 가격 발생도 KST 봉 시작 시각으로 구분·제외하며, 제외는 SQL AND와 결과 상한 전에 적용한다.
- 폼에 분/일/주/월·분봉 간격·봉수·진행 중 포함을 표시하고 술어의 다른 파라미터를 유지한다.
  CSV와 발생 상세에 가격 근거를 보존한다.
- 여러 조건을 추가하면 flex 자식 카드가 줄어 입력이 잘리는 문제를 스크린샷에서 발견했다.
  카드에 shrink-0를 적용해 높이를 보존하고 기존 목록 스크롤을 사용한다. 조건 카드는
  접근 가능한 group 이름을 제공하며 좁은 화면에서도 체크박스가 카드 안에 남는지 검증한다.

## 검증 기록

검증은 이 워크트리의 Python 3.14.7, Node 24.13.1, npm 11.8.0과 별도 의존성으로 수행한다.
E2E는 저장소의 빈 벤더 자격증명·Chrome·단일 워커·20332/21332 포트 및
`/tmp/hoga-e2e-data-332`를 사용한다. 사용자 5173/8000 서버는 변경하지 않는다.
실제 장중 공급자 API의 운영 검증은 이번 검증에 포함하지 않는다.

신규 검사: 기본값/제외 해시 호환, 모든 주기 API 왕복, 최신/기간 변형 일치, 동률,
미래 최고가 차단, OHLC source별 이평, 진행 중 충족·해제와 완료봉 이동,
고가/종가 구별, 부분 이력, NaN 후 창 복구, 주·월 OHLC 및 누락, 원본 조회·계수 쌍 공유,
계수 누락·실패 재시도, HTTP 혼합 주기 응답과 봉 제외, SQL 우회 방지, 일봉 술어 일치,
당일 OHLC 교체, 저장·새로고침·주기 독립성·CSV·좁은 화면 입력 잘림 회귀.

새 MaSource enum 가드는 임시 프론트 사본에서 low를 제거해 실제 실패함을 확인했다.
저장소 소스에 의도적 불일치를 남기지 않았다.
