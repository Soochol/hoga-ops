# 분봉 API 절감과 변경 종목 판정

2026-11-02 사용자 승인 순서: 공유 캐시 정리 → 전 대상 검색의 1분 자료 통합 →
변경 종목만 재평가. 기존 3·5·10분봉 WS 감시 위에 적용했다.

## 공유 원본

`minute_day_cache`는 data_dir·키움 raw 버전·거래소·종목·거래일을 키로 사용한다.
조회 시각마다 별도 영구 키를 만들지 않고, 원본 관측 cutoff와 취득 시각으로 읽기를
검증한다. 현재 관측 요청만 응답 중 전진할 수 있으며 과거 진행 봉은 미래 값으로
복원하지 않는다. 거래소·정규장/차트 전체 세션과 가격 보정의 경계를 보존한다.

- 검색·감시의 원본과 차트의 오늘 원본을 양방향 재사용한다. 차트의 장전·장외 원본을
  보존하면서 검색에는 KRX 정규장과 조회 상한 이내의 분만 전달한다.
- 장중 검색은 15초, 차트의 오늘 원본은 기존 60초 신선도를 따른다. 정규장 마감 후
  15초 이상 지난 정상 완료 자료는 다시 사용한다. 빈 자료는 완료 자료로 영구 봉인하지 않는다.
- 요청 동시 합류·취소 분리·보충 강제 무효화·지연 응답 차단을 적용한다. 오류 응답은
  정상 캐시로 승격하지 않고, REST 우회는 캐시만 읽는다.
- 고정 이진 행과 희소 부가 필드로 압축하고 96MiB/8,192항목 LRU 상한을 적용한다.
  2,808종목×391분의 정규장 원본은 예약치 약 55.1MiB다. 기존 감시의 64MiB 예약,
  종목/이력 admission 제한은 별개로 유지한다. 디스크나 외부 캐시 서버를 추가하지 않는다.
- 중복 시각은 기존 원본 조회와 같은 마지막 행 하나로 통일한다. 차트가 공유하는
  원본도 엄격하게 검증해 잘못된 행을 정상적인 무거래 공백으로 받아들이지 않는다.

## 전 대상 검색

서버 소유 당일 검색은 종목당 raw 1분 자료 한 번을 준비하고 3/5/10/15/30/60분을
파생한다. OHLC는 첫 시가·최고 고가·최저 저가·마지막 종가, 거래량은 합계이며
완료/진행 여부·품질·15:30 독립 종가 체결을 보존한다. 빈 봉을 만들지 않는다.
같은 배치의 조건들이 같은 관측 자료를 사용하고 legacy/v2 모두 같은 경로를 탄다.

한 거래일 자료만 사용하며 주말/휴장일·장전에는 마지막 거래일, 정규장 시작부터 당일로
전환한다. 부족 시 보류와 기존 AND/OR의 확정/미확인 판정은 유지한다.
다중일 과거 차트·기존 읽기 전용 역사 조회의
native timeframe 경로는 ADR-0139대로 유지한다. 일봉 시세·표시/정렬·다른 지표의
필요한 API 호출은 이 변경의 분봉 호출 절감 수에 포함하지 않는다.

## 변경 종목 판정

- 원본 상태 revision·봉 경계·준비/복구·연결 상태·선택 거래일로 버전을 만든다.
  상태가 같으면 분봉 병합과 거래량 판정·품질·알림 비교 결과를 재사용한다.
- 새 체결이 발생한 종목만 다시 판정한다. 새 체결이 없어도 분 종료·연결 단절·오류·
  거래일 변경은 버전을 갱신한다. lease 만료로 재생성된 이력은 독립 식별자를 쓴다.
- 같은 조건의 동시 결과 읽기는 판정을 공유한다. 발생 근거는 응답마다 깊은 복사해
  v2 조건 키/제외 처리로 다른 소비자 결과가 바뀌지 않는다.
- 판정 캐시는 4,096항목/16,000발생으로 제한한다. 다른 조건의 계산·표시 시세/순위의
  갱신 계약은 유지하며, 전 시장 WS 구독이나 무손실 수신을 새로 보장하지 않는다.
