# Live 과거 캔들 로딩 성능 개선 계획

작성일: 2026-10-01 KST
상태: 핵심 개선 구현 · 검증 결과와 잔여 제약은 아래 기록
조사 기준: `beef04d6e`

과거 캔들을 추가하는 동안 마우스와 크로스헤어가 끊기는 문제를 개선한다. 주요 변경은 전체 수신 데이터를 유지하면서 차트 라이브러리에 전달하는 구간을 화면 주변으로 제한하는 것이다. 먼저 데이터 범위와 좌표 계약을 분리하고, 작은 최적화와 제한된 렌더링을 각각 검증한 뒤 적용 범위를 넓힌다. 이 문서는 구현 순서, 부작용의 방지 방법, 완료 기준을 정한다.

## 확인한 원인과 측정 범위

프로덕션 React와 실제 lightweight-charts를 사용한 격리 측정에서 다음 결과를 얻었다. 1분봉, 차트 1개, 기본 이동평균선 4개, 툴팁 OFF, CPU 감속 없음 조건이다. 조건별 2회 측정했으며 숫자는 최대 화면 갱신 간격이다. 직접적인 입력 지연이나 INP 측정값은 아니다.

| 조건 | 최대 화면 갱신 간격 | 차트 데이터 교체 누적 시간 |
| --- | --- | --- |
| 33,147봉에서 추가 로딩 없이 호버 | 16.8ms | 교체 없음 |
| 8,763봉에서 과거 추가 후 11,049봉 | 99.9–116.6ms | 47.8–60.6ms |
| 33,147봉에서 과거 추가 후 35,814봉 | 383.3–433.4ms | 215.8–255.4ms |

지연은 응답을 기다리는 600ms 구간보다 응답 도착 후에 발생했다. 과거 추가로 세션 배열과 Virtual Axis가 바뀌고, 캔들·거래량·이동평균선 4개가 전체 데이터를 교체했다. 시간축 변경은 기존 날짜 눈금이 잘못 남는 버그를 막기 위한 현재 계약이다. 이를 단순히 고정하면 성능은 좋아질 수 있어도 날짜가 틀릴 위험이 있다.

`setData()`는 전체 데이터를 교체한다. `update(..., true)`는 기존 과거 포인트 수정용이며, 새로운 과거 봉의 삽입을 대체하는 것으로 가정하지 않는다. [lightweight-charts 공식 API](https://tradingview.github.io/lightweight-charts/docs/api/interfaces/ISeriesApi#setdata)

canonical 병합 캐시의 깊은 비교를 생략한 별도 실험에서는 캐시 발행 시간이 8.5–30.1ms에서 0–0.1ms로 줄었지만 큰 차트 작업은 남았다. 캐시 최적화만으로 해결된다고 판단하지 않는다.

증거: [측정 요약](../diagnostics/2026-10-01-backfill-hover/summary.json), [원시 측정](../diagnostics/2026-10-01-backfill-hover/results.json), [캐시 비교](../diagnostics/2026-10-01-backfill-hover/cache-ab.json), [재현 방법](../diagnostics/2026-10-01-backfill-hover/README.txt).

누적 이력은 fixture 초기 응답으로 구성했고, 이후 실제 `extendChartHistoricalRange`와 델타 응답 경로를 사용했다. 실제 드래그, 실시간 WS 부하, 사용자 지표 조합까지 재현한 결과는 아니다. 3창 측정도 첫 창만 과거를 확장했으므로 여러 창의 동시 백필 비용은 추가 측정한다.

## 유지할 동작

- 기존 봉의 OHLC, 거래량, 지표 수치, 경매 구간 처리, 날짜 눈금이 같아야 한다.
- 과거 추가와 표시 구간 교체 후에도 보던 시각, 줌, 봉 간격, 오른쪽 여백이 유지돼야 한다.
- 받은 전체 데이터와 조회 완료 범위는 계속 유지한다. 화면 주변 구간을 바꾸는 일만으로 API를 다시 호출하지 않는다.
- 기존 실시간 tail 갱신, 분봉별 수신 해상도, 백필 예산·클램프·오류 재시도 정책을 유지한다.
- 캔들·호가의 과거 추가 원자성과 사이드카의 독립 로딩을 유지한다.
- 전체 데이터를 읽는 프로그램·투자자 창, 저장뷰, 지표 계산에는 표시용으로 잘린 번들을 전달하지 않는다.

1차 적용은 일반 분봉 차트로 시작한다. 초봉·D/W/M·대표지수는 기존 경로를 유지하고, 일반 분봉 검증 이후 별도 판단한다. 일반 분봉 안에서도 지원하지 않는 지표 조합은 창 단위로 기존 경로를 사용한다. 이 예외에서 남는 버벅임은 해결 범위에 포함됐다고 보고하지 않는다.

## 데이터와 표시 구간 설계

현재 `RangeBundle`과 전체 Virtual Axis를 데이터의 정본으로 유지한다. 별도의 창별 표시 상태에는 표시할 실제 시각 범위, 데이터·축 버전, 앵커, 표시 시리즈의 시간 합집합에 대한 좌표 정보를 둔다. 표시 구간의 시작을 바꾼다는 이유로 전체 축의 원점을 다시 정하지 않는다. 전체 데이터가 변경되는 경우의 기존 축 재생성은 유지한다.

처음에는 보이는 범위에 좌우 약 한 화면의 여유를 더한 구간을 후보로 삼는다. 이는 조정 가능한 초기값이다. 가시 구간을 잘라내는 고정 봉 수 상한을 두지 않는다. 예를 들어 실제 가시 봉이 150개라면 주변 여유를 포함한 약 450개를 차트에 전달하는 형태를 실험한다. 실제 개수는 보조 시리즈의 시각과 경계 처리에 따라 달라진다.

여유 안에서의 팬과 일반 호버는 표시 구간을 바꾸지 않는다. 뷰포트가 여유 구간의 안쪽 경계를 넘을 때만 새 구간을 준비한다. 갱신은 프레임 단위로 합치고, 자체 데이터 교체·뷰포트 복원에서 나온 범위 이벤트를 사용자 팬과 구분해 재귀 갱신을 막는다.

표시 상태와 수신 범위는 두 개의 별도 사실이다. `logical.from < 0`은 이제 화면에 올린 구간의 경계를 넘었다는 뜻일 수 있으므로 그것만으로 백필하지 않는다. 실제 시각과 수신 완료 범위로 다음 동작을 결정한다.

| 상황 | 동작 |
| --- | --- |
| 화면에 아직 안 올렸지만 전체 캐시에 데이터가 있음 | 캐시에서 표시 구간만 이동 |
| 캔들은 있으나 호가·사이드카 커버리지가 부족함 | 기존 지표 coverage gap 정책 적용 |
| 실제 수신 범위를 넘어 과거 데이터가 필요함 | 기존 백필 예산·클램프로 요청 |
| 거래가 없어서 빈 구간의 조회가 이미 완료됨 | 데이터 유무만 보고 반복 요청하지 않음 |

캔들뿐 아니라 lightweight-charts에 들어가는 모든 시계열을 같은 표시 구간 계약으로 제한한다. 전체 이력을 가진 보조 시리즈나 whitespace 시리즈가 남으면 공유 시간축이 계속 커진다. 희소 선에는 경계 직전·직후의 필요한 이웃점을 보존하고, 이를 좌표 합집합에 포함한다. line, histogram, whitespace, 누적값 시리즈 각각에 경계 정책을 선언한다.

라이브러리 logical index와 전체 캔들 배열 index가 같다고 가정하지 않는다. 보조지표가 시간축에 추가 시각을 넣을 수 있기 때문이다. 실제 시각을 기준으로 좌표를 변환하고, 차트가 보유한 합집합 인덱스로 착석한다. 표시 범위 바깥으로 드래그하거나 동기화 대상이 이동하는 경우에는 `getVisibleRange()`의 끝점 클램프만 사용하지 않고 전체 데이터 탐색과 논리범위의 초과분을 함께 처리한다.

## 구현 순서와 산출물

### 첫 단계 재현 테스트와 좌표 계약 분리

기존 진단 하네스에 실제 과거 드래그, 이미 받은 구간 왕복, 빠른 방향 전환, 3창 동시 백필을 추가한다. 로딩 대기와 반영 구간을 나눠 기록하고, 화면의 실제 봉·시각·지표값·API 호출 횟수를 확인한다. CPU profile은 프레임 성능 측정과 별도 실행한다.

`useViewportBackfill`, `viewportAnchor`, `useRangeSync`, 드로잉 좌표에서 전체 데이터 개수와 차트에 있는 봉 개수를 분리한다. 툴팁·범례에서 사용하는 커서 해석도 실제 시각 기준으로 확인한다. 이 단계에서는 전체 데이터를 계속 그려 기존 동작과 비교할 수 있게 한다.

주요 파일: `src/live/useViewportBackfill.ts`, `src/live/viewportAnchor.ts`, `src/live/useRangeSync.ts`, `src/chart/drawing/chartCoordinates.ts`, `src/live/CandleTooltip.tsx`, `src/live/PaneLegendOverlay.tsx`, `src/chart/drawnCandleIndex.ts`.

완료 조건은 기능 동등성, 캐시 안 팬에서 추가 요청 0회, 실제 조회 끝과 표시 끝을 구분하는 결정적 테스트 통과다.

### 두 번째 단계 병합과 캐시 발행 비용 감소

`mergePastCandleResponses`의 Map 생성·전체 정렬을 정렬된 두 배열의 병합으로 대체한다. 다음 응답이 같은 시각을 덮어쓰는 기존 규칙, 과거 가격 정정, 경고·세션·수정계수 병합을 유지한다. 입력이 정렬돼 있다는 조건을 검증하고, 조건이 깨질 때는 기존 안전 경로를 사용한다.

canonical 병합본에 한해 이미 보존한 불변 참조를 다시 깊게 비교할 필요가 있는지 확인한다. 안전성이 증명되면 해당 키의 structural sharing을 조정한다. 전역 쿼리 설정은 바꾸지 않는다. 병합 결과가 한 번만 적용되는 `createDeltaResponseMerger` 계약도 유지한다.

주요 파일: `src/api/livePastCandles.ts`, `src/api/deltaResponseMerger.ts`, `src/main.tsx`의 해당 쿼리 기본값.

이 단계는 보조 개선이다. 이후 측정에서 목표를 충족하지 못하면 다음 단계까지 진행한다. 캐시 비교만 줄인 결과를 전체 해결로 발표하지 않는다.

### 세 번째 단계 화면 주변 구간 렌더링 구현

순수 범위 선택 함수와 창별 구간 조정 훅을 추가한다. 후보 파일은 `src/chart/renderWindow.ts`와 `src/live/useChartRenderWindow.ts`다. 원본 전체 번들, 표시 번들, 표시 좌표 상태를 구분해 `LiveChartRoot`에서 각 소비처에 올바르게 전달한다.

캔들·거래량·현재봉 SMA·일봉 MA를 먼저 지원한다. 캔들·거래량은 범위를 선택한 뒤 좌표를 투영한다. 전체를 투영한 뒤 자르는 방식으로 비용을 다시 만들지 않는다. SMA는 1차 구현에서 기존 전체 원본과 계산 순서를 유지해 값 배열을 만들고, 화면 주변 값만 좌표에 투영한다. 값 계산과 좌표 계산을 분리해 구간 이동만으로 SMA 수치를 다시 계산하지 않도록 한다.

SMA를 화면 왼쪽부터 새로 계산하는 방식은 기본안에서 제외한다. 시작부 결측과 부동소수점 합산 순서가 달라질 수 있다. 일봉 MA도 원래 일봉 lookback과 당일 종가 프록시를 유지하고, 분봉으로 펼치는 점만 제한한다. 누적 거래량·체결강도는 기존 누적값을 사용해 표시 구간 시작에서 0으로 리셋하지 않는다.

시리즈 구간과 축 버전을 같은 커밋에서 적용하고, 실제 시각 앵커·폭·여백으로 화면을 복원한다. 서로 다른 축 버전의 캔들과 MA가 한 프레임에 섞이지 않게 한다. 라이브러리 내부 필드를 직접 고치거나 모든 시리즈를 한 번에 바꾸는 비공개 API에 의존하지 않는다.

주요 파일: `src/live/LiveChartRoot.tsx`, `src/chart/RangeSeriesPane.tsx`, `src/chart/projectors/candle.ts`, `src/chart/projectors/volume.ts`, `src/chart/projectors/maProjection.ts`, `src/live/indicators/MovingAverageOverlay.tsx`, `src/live/indicators/DailyMovingAverageOverlay.tsx`.

작은 차트에서는 기존 경로를 유지할 수 있지만 전환 임계값에는 여유를 둬 팬·줌 때 모드가 반복 전환되지 않도록 한다. 우선 내부 개발 플래그에서 검증하며 사용자 설정 항목은 추가하지 않는다.

### 네 번째 단계 보조지표와 연동 기능 통합

호가비·체결강도·프로그램·투자자 등 활성 시계열의 표시 범위를 같은 계약에 통합한다. 각 pane의 `bundleKind`와 오늘 데이터 소스를 유지한다. 고저 라벨·최대벽·매물대·히트맵·드로잉은 전체 데이터에서 의미를 계산하되 필요한 가시 후보만 투영한다. 현재가·최신 봉 판정은 화면용 배열의 마지막 점으로 대체하지 않는다.

그룹별 크로스헤어·기간·줌 동기화, 다른 종목 동기화, 저장뷰 복원, 기간 점프, 현재로 돌아가기, 창 리사이즈를 검증한다. 동기화 목적지가 캐시에는 있지만 표시 구간 밖이면 표시 구간을 먼저 준비한다. 표시 구간 밖을 실제 데이터 결손으로 알리지 않는다.

필요한 지표 조합을 모두 지원하고 기능·성능 기준을 통과한 일반 분봉 창에 기본 적용한다. 미지원 조합은 기존 경로를 쓰며 적용 범위를 명시한다.

### 다섯 번째 단계 잔여 계산 비용 평가

앞 단계 후에도 원본 병합·지표값 계산에서 50ms 이상의 동기 작업이 남으면 해당 계산을 나누거나 Worker로 옮기는 후속을 설계한다. Worker는 데이터 복사 비용, 최신 버전 취소, 메모리 중복, 창 간 공유를 별도 측정해야 한다. 차트의 `setData()` 자체는 화면 스레드에 남기 때문에 Worker만 도입하는 것으로 완료하지 않는다.

`startTransition`은 React 상태 업데이트의 우선순위 도구다. 그 안의 동기 계산이나 차트 API 호출을 자동으로 나눠 실행하는 해결책으로 사용하지 않는다. [React 공식 문서](https://react.dev/reference/react/startTransition)

| 화면이 좌우로 튐 또는 줌 변화 | 표시 구간 교체로 차트 logical index가 바뀜 | 실제 시각 앵커·bar span·여백을 저장하고 새 합집합 인덱스로 복원. 고정 봉의 픽셀 이동과 봉 간격 비교 |
| 이미 받은 과거를 반복 요청 | 표시 구간의 왼쪽 끝을 전체 데이터 끝으로 오인 | 캐시에서 구간 이동과 실제 백필을 별도로 판정. 캐시 내 왕복 요청 0회와 빈 응답의 종료 확인 |
| 이평선과 누적 지표 값 변화 | 잘린 입력으로 지표 계산을 다시 시작 | 전체 원본의 계산 의미·순서 유지. 긴 period, 모든 source, 소수값, 정정 응답을 기존 결과와 대조 |
| 선 끊김 또는 가격축 범위 변화 | 희소 선의 경계 이웃점·autoscale 입력 누락 | 이웃점 및 whitespace 의미 보존. 같은 뷰포트에서 가시 가격 범위와 경계 픽셀 비교 |
| 툴팁 또는 십자선이 다른 봉을 가리킴 | 로컬 차트 index를 전체 캔들 index로 사용 | 실제 시각을 통한 해석. 인접 봉·결측·희소 보조지표 시각 합집합 케이스 검사 |
| 저장뷰·점프·현재로 돌아가기 오동작 | 목적지가 차트에는 없지만 캐시에 존재 | 구간 준비 후 착석. 전체 최신 봉과 표시 마지막 봉을 분리. 신규 저장과 기존 저장 데이터 모두 확인 |
| 이동 중 순간 빈 화면 또는 새 팬 버벅임 | 빠른 드래그가 표시 여유를 소진하거나 매 이벤트가 setData를 호출 | 여유·전환 임계값으로 교체 횟수 제한. 캐시 구간 이동 성능도 별도 측정. 급격한 줌아웃은 한 번에 현재 가시 범위를 포함 |
| 캔들·MA·호가가 일시적으로 어긋남 | 다른 축·데이터 버전이 순차 반영됨 | 같은 버전으로 교체하고 앵커 복원. 오래된 준비 결과는 적용 전에 폐기 |
| 라이브 틱이 화면을 최신으로 끌고 감 | 표시 배열의 오른쪽 끝을 전체 최신으로 오인 | 전체 최신 시각과 실제 live-edge 상태 유지. 과거를 보는 중 WS 업데이트로 위치 불변 |
| 메모리 증가 또는 GC 정지 | 전체 이력에 표시·계산 캐시를 여러 세대 보관 | 창별 최신 표시 상태와 제한된 값 캐시만 보관. 종목·봉·지표 변경과 창 닫힘에서 정리. 기존 쿼리 축출 정책 유지 |
| 여러 창 중 하나만 회귀 | 창별 지표·종목·축 버전을 잘못 공유 | 표시 상태는 창별 소유. 공유 가능한 원본과 창별 설정 캐시를 분리하고 동시 백필 검증 |

핵심 위험은 좌표와 데이터 의미가 틀리면서도 화면이 그럴듯하게 보이는 회귀다. 따라서 스크린샷만으로 판단하지 않고 실제 시각, 가격, 지표값, API 요청 횟수와 함께 검증한다.

## 검증과 완료 기준

성능 목표는 구현 후 검증할 제안값이다. 현 측정으로 달성이 확정된 수치가 아니다.

| 구분 | 완료 기준 |
| --- | --- |
| 기준 성능 | 기존 120일 1분봉·4 MA·차트 1개 조건에서 응답 반영 주변의 최대 프레임 간격 50ms 이하를 목표로 반복 측정. 연속 100ms 이상 정지는 없어야 함 |
| 입력 반응 | 반영 구간과 캐시 내 팬에서 마우스 이벤트 처리부터 해당 프레임까지 별도 측정. 자동화 호출 왕복 시간과 INP를 혼동하지 않음 |
| 확장 성능 | 30일·120일·250일 이력, 1·3창, 1·5·30분봉, 일반·넓은 줌 비교. 고정 가시 범위에서 차트 입력량이 전체 이력에 비례해 증가하지 않는지 확인 |
| 정확도 | 같은 뷰포트의 봉·지표 수치·날짜·가격축·라벨이 기준 구현과 동등. 계산 순서 변경이 필요하면 허용 오차와 표시 동등성을 먼저 정의 |
| 화면 유지 | 정지한 상태의 구간 교체에서 기준 봉의 좌표 이동 1 CSS px 이내를 목표로 검증. 팬 중에는 사용자 이동분을 제외하고 비교 |
| 조회 | 캐시 안 이동 시 추가 요청 0회. 실제 데이터 끝을 넘으면 기존 예산만큼 요청하며 바닥·휴일·빈 응답에서 종료 |
| 수명 관리 | 종목 왕복·봉 변경·지표 추가삭제·창 열고 닫기를 반복해 이전 표시 상태가 무한히 누적되지 않는지 확인 |

큰 줌아웃에서 실제 가시 점이 증가하면 작업량도 늘어난다. 모든 확대율·모든 하드웨어에서 일정한 프레임 시간을 보장한다고 표현하지 않는다. 성능 기준을 넘는 구성은 전체 이력 수, 가시 점 수, 지표 수와 함께 남기고 개선 또는 명시적인 미지원 처리 후 적용한다. 봉 해상도를 몰래 낮추거나 보이는 데이터를 잘라 목표를 맞추지 않는다.

회귀 테스트는 순수 범위 선택·좌표 변환·병합의 단위 테스트, 데이터 준비와 표시 갱신의 컴포넌트 테스트, 실제 차트에서 드래그·백필·동기화·저장뷰를 검증하는 Playwright 테스트로 구성한다. 타이밍 기준은 흔들리기 쉬운 단위 테스트에 넣지 않고 격리 성능 하네스에서 별도로 반복한다.

프론트 구현의 최종 확인은 저장소 지침대로 `npm run typecheck`, 전체 Vitest, Vite build, 전체 Playwright를 수행한다. 성능 측정은 이 검사들과 동시에 실행하지 않는다. 사용자 서버 5173·8000과 화면 설정을 보존하고 별도 포트·fixture를 사용한다.

## 기존 결정과의 관계 및 되돌리기

ADR-0054의 공개 HorzScaleBehavior 확장점을 유지하고 내부 필드를 수정하지 않는다. ADR-0139의 소스별 수신 해상도, ADR-0103의 온디맨드 정책, ADR-0073의 독립 일봉 MA 경로, ADR-0157의 저장뷰를 live 창에서 여는 동작을 유지한다.

현재 구현의 전체 축 원점·날짜 눈금 갱신 계약은 유지한다. 새 표시 범위는 전체 축의 의미를 바꾸지 않는다. 기존 왼쪽 팬의 logical index 기반 트리거와 전체 데이터 렌더링 가정은 변경하므로 구현 전에 소비처 목록과 불변식을 문서화한다. 새로운 ADR 번호는 실제 구현 시 열린 PR까지 확인해 배정한다.

기능 단계를 독립 변경으로 구성한다. 표시 범위 적용을 끄면 기존 전체 렌더링 경로로 복귀할 수 있도록 하고, 변경 전후에 전체 캐시·저장된 뷰·지표 설정의 형식은 유지한다. 전환 시에는 현재 실제 시각 앵커를 복원한다. 불변식 위반으로 기존 경로에 복귀한 경우 진단 로그를 남겨 성능 개선 성공으로 오인하지 않도록 한다.

두 번째 단계의 작은 최적화는 기능 검증 후 독립 적용할 수 있다. 세 번째와 네 번째 단계는 좌표·백필·지표 정확도 검증을 함께 통과한 구성부터 적용한다. 계획 작성 당시에는 제품 코드를 변경하지 않았으며, 이후 실제 적용 결과는 아래에 기록한다.


## 실제 구현과 검증 결과

2026-10-01 작업 트리에 구현했다. 기존 소비처마다 다른 인덱스를 새로 도입하는 대신 `src/chart/windowedChart.ts`의 public API 어댑터에서 전체 합집합 인덱스와 라이브러리 내부 표시 인덱스를 변환한다. 애플리케이션의 전체 데이터·Virtual Axis·SMA 계산 순서는 유지하고, 실제 라이브러리 시리즈만 공통 표시 구간으로 제한한다. 이 방식은 위 제안의 파일 구성을 대체한다.

- 정렬된 과거봉은 선형 병합한다. 중복 시 새 응답이 이기며, 비정렬·중복 입력은 기존 정규화로 돌아간다. 재적용된 동일 봉·세션·수정계수는 참조를 유지한다.
- canonical 병합본에만 structural sharing을 생략한다. 청크 쿼리와 다른 API 쿼리의 기본값, 캐시 수명은 유지한다.
- 각 React 커밋의 시리즈 쓰기를 모아 뷰포트 복원 전에 반영한다. 표시 구간은 화면 양쪽 약 한 화면과 최소 200 슬롯의 여유를 갖고, 경계 접근 때만 옮긴다. 선의 실제 이웃점을 공통 구간에 포함한다.
- full-history `timeToIndex`·`dataByIndex`·범위·좌표 변환, 크로스헤어의 시리즈 키, primitive 부착을 어댑터가 처리한다. 전체 최신 봉과 캐시 경계는 표시 구간 끝점으로 대체하지 않는다.
- 마우스 팬은 전체 이력 좌표에서 처리해 구간 교체로 드래그 시작점이 어긋나지 않게 한다. 수동 Y축 팬, 시간축 초기화, 라이브 복귀 애니메이션을 유지한다. 구간 이벤트는 백필 복원 후 발행하도록 예약한다.
- 캔들·거래량·MA·툴팁의 캔들 좌표 분류를 공유한다. POC 세션 끝점은 이진 탐색으로 찾는다. KST 날짜 캐시는 1개 항목만 유지하고 마감 동시호가의 세션 마감 시각은 날짜당 한 번 계산한다.

**적용 범위와 제약:** 일반 종목 분봉의 마우스 환경에 적용한다. 4,000 슬롯 이하, 전체가 보이는 큰 줌 범위, native 최신값 라벨/가격선 또는 custom series 옵션은 전체 렌더링을 유지한다. 터치 가능 기기는 기존 경로를 유지한다. 희소 선의 이웃점이 멀면 표시 구간이 더 넓어질 수 있다. 초봉·일주월·지수에는 이 어댑터를 적용하지 않는다.

**수치 계산/투영에 관한 계획 변경:** 최초 적용은 전체 투영 배열을 유지하고 라이브러리 전달 직전에 자른다. 전체 원본에서의 SMA 일치와 범례/드로잉 계약을 우선 보존했다. 화면 주변만 투영하는 별도 계산 엔진과 Worker는 이번 변경에 포함하지 않았다. 따라서 전체 원본 계산·투영 비용은 남으며, 최대 프레임 간격 50ms 목표를 모든 측정에서 충족하지는 못했다.

프로덕션 빌드, CPU 감속 없음, 기본 4 MA, 툴팁 OFF의 동일 격리 측정:

| 조건 | 변경 전 최대 프레임 간격 | 구현 후 최대 프레임 간격 | 구현 후 실제 라이브러리 데이터 교체 |
| --- | --- | --- | --- |
| 1창, 30일 이력 + 10일 | 99.9–116.6ms | 33.4–50.0ms | 4.6–5.0ms |
| 1창, 120일 이력 + 10일 | 383.3–433.4ms | 66.6ms | 3.5–4.8ms |
| 3창, 120일 이력, 첫 창만 확장 | 기존 원시 결과 참조 | 66.6ms | 3.1–3.4ms |
| 백필 없는 1창 호버 | 16.8ms | 16.8ms | 교체 없음 |

달력 계산 최적화까지 포함한 최종 120일 조건 3회에서는 최대 프레임 간격 50.1–66.7ms, 긴 작업 62–72ms, 라이브러리 교체 3.6–4.7ms였다. 최종 자료는 `after-calendar.json`, 전체 16조건 비교는 `after.json`과 `implementation-comparison.json`이다. 약 35,814 슬롯의 전체 데이터는 유지하고 실제 표시 구간은 약 555 슬롯이었다. 최대 프레임 간격은 직접 입력 지연/INP가 아니며, 무끊김을 보장하는 결과는 아니다.

검증은 전체 TypeScript 검사, 단위 테스트 7,689개, 프로덕션 빌드가 통과했다. 실제 브라우저 회귀 테스트는 120일 이력에서 표시 구간을 넘는 연속 드래그, 응답 대기 중 이동, 응답 후 봉 위치 오차 1px 미만·배율 유지, 기존 봉/MA 값 일치, 캐시 내 추가 과거봉 요청 0회, 최신 봉 복귀, 수동 Y축 팬, 다른 창의 미표시 캐시 시각으로 이동을 검증한다. 전체 E2E의 최종 결과와 기존 UI 선택자 불일치는 진단 폴더의 `implementation-validation.md`에 기록한다.

## 머지 이후 후속

PR #1917을 머지·pull한 뒤 커서 인덱스의 두 해시맵을 정렬 숫자 키 조회로 바꾸고 MA가 동일 좌표 격자를 사용하도록 개선했다. 최종 120일 조건 5회는 툴팁 OFF 50.0–66.6ms, ON 49.9–83.4ms로 반복 변동이 남았다. 캐시 팬 3회는 16.8ms·추가 요청0회였다. 36개 확장 조건을 함께 확인했다. 50ms 목표를 모든 반복에서 달성한 상태로 표시하지 않는다. 정확도·성능·한계와 전체 검사 결과는 [후속 검증](../diagnostics/2026-10-01-backfill-hover/follow-up-validation.md)에 기록한다.
