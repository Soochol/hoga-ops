# 전 대상 분봉 조건검색 개선안

상태: 2026-11-01 사용자 승인 후 작업 트리에 구현했다. 실행 중인 사용자 앱에 배포하지 않았다.
아래 검토안과 함께 실제 구현 범위·검증 기록을 보존한다.

## 구현 결과

- `screener_minute_scope`가 KST 검색 거래일·하루 범위와 장전 대기를 담당한다.
- `screener_minute_run`이 `/runs`의 분봉 단계를 이어 실행한다. 기존·새 계산 정책을 모두 지원한다.
- 동일 종목·주기의 여러 조건은 한 묶음 안에서 자료를 공유하고, 공용 캐시가 퇴거돼도 완료 판정은 작업 체크포인트에 남긴다.
- 결과 정렬·표시 상한과 N+1 여부, 발생 근거와 보조 커버리지를 여러 묶음에 걸쳐 보존한다.
- 새 계산 정책의 AND 사전 판정은 분봉 없이 탈락이 확실한 종목만 제외한다. OR 후보는 유지한다.
- 최신 분봉의 날짜 범위 조건이 검색 거래일 밖이면 명시적인 보류 사유로 남긴다. 저장 조건을 자동 변경하지 않는다. 고정 과거 스냅샷은 기존 읽기 경로를 유지한다.
- 장중 진행 봉 포함 검색은 종목별 실제 관측값을 사용한다. 서로 다른 관측 시각을 단일 과거 스냅샷으로 표현하지 않고 기존 기준·보완 시각 필드로 알린다. 완료봉 검색과 저장 순위의 과거 상한은 고정한다.
- 기존 범위 제한 실시간 감시의 준비 자료에도 당일 제한을 적용했다. 전 시장 동시 실시간 감시를 새로 지원하는 변경은 아니다.
- 초기 제외 목록 복원은 완료된 분봉 결과를 제한된 `/scan` 결과로 덮어쓰지 않는다. 명시적인 제외·복원에 따른 분봉 재검색은 전체 실행 경로를 사용한다.

검증: [구현 검증 기록](../diagnostics/2026-11-01-screener-full-minute-scan/validation.md).

## 사용자 확정 규칙

- 거래일에는 장중·장 마감 후 모두 당일 분봉을 검색한다.
- 주말에는 마지막 거래일의 분봉을 검색한다. 공휴일 등 휴장일도 마지막 거래일을 사용하는 방향으로 설계한다.
- 검색 자료도 해당 하루로 제한한다. 비교용 이전 거래일 분봉을 추가로 가져오지 않는다.
- 100봉 비교·이동평균 등 조건에 필요한 봉이 부족하면 그 조건을 판정 보류한다. 비교 기간을 임의로 줄이지 않는다.

기준일은 KST와 기존 거래일 달력으로 결정한다. 달력이 부족하면 날짜를 추측하지 않고 확인 불가로 처리한다.
거래일 장전의 당일 분봉이 아직 없으면 장 시작 전·자료 대기로 표시하고 이전 거래일로 대체하지 않는다.
검색 실행이 시작될 때 기준일과 평가 상한을 고정한다. 날짜가 바뀌면 다른 날짜의 자료를 같은 실행에 합치지 않는다.

공급자가 한 응답에 이전 날짜도 보내더라도 평가 자료는 선택 거래일만 남긴다.
기존 분봉의 시장·장시간 규칙을 유지하며 일봉 기준일을 분봉 검색일로 대신 사용하지 않는다.
기간 지정 분봉 조건과 고정 과거 스냅샷 재실행은 이 규칙과 충돌하므로, 적용 범위와 기존 저장 조건 호환을 구현 전에 명시해야 한다.
과거 요청을 조용히 오늘로 바꾸지는 않는다.

## 현재 확인한 문제

- `screener_bar_volume.evaluate`는 새 분봉 요청을 한 번에 최대 64종목으로 제한하고 다음 조회에서 순환한다.
- 공용 캐시는 최대 512개 항목·250,000봉이다. 일반 조회는 15초, 성공한 고정 과거 조회는 300초 유효하다.
- 따라서 반복 클릭만으로 전 대상 결과가 안정적으로 누적된다고 보장할 수 없다.
- 현재 커버리지의 미확인 수는 조건별 실패 종목의 합집합이다. AND/OR 최종 조합식의 판정 불가 수와 같지 않을 수 있다.
- `CalculationNotice`와 `BarVolumeCoverage`가 같은 상세를 중복 표시한다.
- 기존 `ScreenerRuns`의 자동 준비는 주로 일봉을 다루며 분봉 전 대상 완주를 보장하지 않는다.

## 제안하는 실행 방식

1. 일반 `갱신`은 기존 전체 등록 종목의 최근 일봉 점검 역할을 유지한다.
2. `조회` 한 번으로 조건에 필요한 전체 대상의 분봉 검색 작업을 서버에 등록한다.
3. 64종목은 처리 묶음 크기로 활용하되 사용자 재클릭 없이 다음 미처리 종목으로 진행한다. 공용 governor의 background 우선순위·동시 실행 상한을 지킨다.
4. 작업별로 조건·범위·거래일·평가 상한·수정 기준을 고정하고, 완료한 종목의 판정·발생 근거를 누적한다. 공용 캐시 만료나 LRU 퇴거가 완료 판정을 지우지 않는다.
5. 동일 종목·주기·기준일의 진행 중 자료 요청은 공유한다. 같은 주기의 여러 조건은 필요한 범위를 합쳐 중복 요청을 줄인다.
6. 해당 하루의 응답에서 필요한 자료가 부족하면 판정 보류로 종료한다. 이전 날짜를 향한 추가 페이지는 요청하지 않는다.
7. 조건별 충족·미충족·미확인을 구분해 최종 AND/OR 판정을 계산한다. 일봉 조건만으로 확실히 탈락한 후보는 분봉 호출을 생략할 수 있으나 OR 후보를 잘못 제거하지 않는다.
8. 새로고침은 서버 작업에 재연결한다. 재시작 뒤에는 저장된 진행·평가 근거가 유효한 항목만 재사용하고 미완료 항목을 이어 처리한다.

진행 중 봉은 조회 시작 당시의 정확한 OHLCV를 나중에 복원할 수 없을 수 있다. 완료봉 기준과 진행 중 봉 포함 조건을 구분하고,
관측 시각이 다른 자료를 동일 시점의 완전한 스냅샷으로 표시하지 않는다. 지원하지 못하는 복원은 명시적으로 보류한다.

원본 분봉의 영구 디스크 캐시를 새로 만들지는 않는다. 실행 결과·진행 기록과 분봉 캐시를 구분한다.
[ADR-0095](../adr/0095-kis-past-minute-candle-disk-cache-reaffirm-memory-only.md)와
[ADR-0136](../adr/0136-kis-removal-kiwoom-full-replacement.md)의 memory-only 결정을 유지한다.

## 속도 기대와 한계

- 해당 하루를 얻은 뒤 과거 페이지로 내려가는 작업을 없애므로 긴 비교·기간 조건의 요청량과 계산량을 줄일 수 있다.
- 기존 하루 조회 어댑터 `kiwoom_minute_candles.fetch_day`가 있다. 구현 시에도 governor를 우회하지 않고 실제 반환 날짜·봉 범위를 검증한다.
- 이미 첫 응답으로 충분했던 종목은 네트워크 호출 수가 그대로일 수 있다. 일정 배수의 속도 개선을 보장하지 않는다.
- 거래일·평가 상한·조건·수정 기준이 같은 완료 자료와 판정은 재사용한다. 장중 진행 중 봉과 장마감 자료의 갱신 정책은 구분한다.
- 2,843종목 전체를 처리하는 비용 자체는 남는다. 64종목짜리 부분 결과를 받던 기존 시간과 새 전 대상 완료 시간을 직접 속도 비교하지 않는다.
- 전 시장 동시 실시간 감시의 지원을 뜻하지 않는다. 해당 검토는 [기존 분봉 감시 계획](2026-10-20-screener-live-volume.md)을 따른다.

## 화면

중복 안내를 한 곳으로 합치고, 기준 거래일·최종 판정 완료 수·전체 수·현재 일치 수를 먼저 표시한다.
자료 부족과 전송 오류는 미처리 대기와 구별한다. 여러 조건의 중복 사유를 종목 수로 더하지 않는다.

예: `10/30 분봉 검색 중 · 640/2,843종목 판정 · 현재 일치 12종목`

종료 예: `10/30 분봉 검색 종료 · 일치 35종목 · 판정 보류 16종목` + 상세 사유.

## 구현 검증 기준

- 장중·장마감·주말·공휴일·장전·달력 부족·자정 경계의 검색일 결정.
- 당일 봉 부족 시 이전 거래일 요청 0회, 비교 기간 축소 0회, 해당 조건 판정 보류.
- 64종목을 넘는 대상의 자동 완주, 캐시 만료·퇴거 뒤에도 완료 결과 유지.
- AND/OR와 날짜·수정 기준·진행 봉을 포함한 일괄 평가 정답과의 동등성.
- 재연결·중복 합류·재시작 복구·조건 변경 시 이전 결과 혼입 방지.
- 중복 안내 제거, 검색 진행 중 부분 결과 표시, 실패와 자료 부족의 구별.
- 실측 지표: 전 대상 완료 시간, 종목·주기별 페이지 수, 캐시 재사용률, 판정 보류 사유별 수, foreground 차트 조회 지연.

이번 검토에서는 실자격증명 요청·운영 서버 재시작·구독 확대를 수행하지 않았다. 위 개선의 실제 성능 수치는 아직 측정하지 않았다.
