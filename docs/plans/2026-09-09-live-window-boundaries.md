# /live 창 경계 식별 개선 플랜

작성일: 2026-09-09
상태: 구현 완료, 검증 결과는 아래 실행 기록 참조.

## 문제와 목표

여러 창이 겹치면 창 본문과 뒤쪽 창의 내용이 이어져 보이고, 각 창이 어디까지인지 구분하기 어렵다. 헤더가 가려져도 노출된 변과 모서리로 창 경계를 식별하고, 현재 조작 중인 창을 빠르게 알아볼 수 있게 한다.

변경 전 `/live`의 `WindowFrame`은 공유 `WindowFrameCore`에 `flat`을 전달한다. 코어는 외곽선 없이 `bg-bg`를 쓰며, 평상시 그림자를 제거하고 포커스는 헤더 틴트로만 표현한다. 이동 중에만 `shadow-modal`을 적용한다. 창 사이 시각 간격은 2px이며 바깥 rect와 리사이즈 핸들 안쪽에 카드가 놓인다.

## 확정할 표현

| 상태 | 표현 |
| --- | --- |
| 모든 일반 창 | 중성색 1px 외곽선 + 짧고 은은한 그림자 |
| 활성 창 | 동일한 중성색 1px 외곽선 + 기존 헤더 선택 틴트 유지 |
| 이동 중 | 외곽선 유지 + 기존 shadow-modal로 그림자 교체 |
| 최대화 | 같은 외곽선 규칙 적용. 기존 최대화·복원 동작 유지 |

- 모든 창의 외곽선 색은 `--border-strong`을 사용한다. 실제 겹침 화면에서 기본 선이 묻히면 창 전용 토큰만 조정한다.
- 그림자는 모든 창에 적용해 앞뒤 관계를 보조한다. 겹침 여부를 계산하는 로직은 추가하지 않는다.
- 짧은 그림자의 초기값은 다크 `0 2px 8px rgba(0,0,0,.28)`, 라이트 `0 2px 8px rgba(30,39,50,.12)`로 두고 시각 검증에서 확정한다.
- 그룹 색은 기존 배지에만 사용한다. 본문 격자·헤더 구분선·리사이즈 호버 막대는 추가하지 않는다.
- 2026-08-09에 제거한 2px 리사이즈 호버 accent 막대는 유지하지 않기로 한 기존 결정이다. 이번 변경은 모든 창의 경계와 활성 상태를 표시하는 1px 프레임이며, 해당 호버 동작을 복원하지 않는다.

## 구현 순서

### 1. 창 전용 스타일 토큰

대상: `frontend/src/styles/tokens.css`

- `--window-border`, `--window-shadow`를 정의한다.
- 외곽선 토큰은 기존 테마 변수에 연결하고 그림자는 기존 네 테마의 밝기 계열에 맞게 정의한다.
- 기존 `--border-strong`, `--shadow-panel`, `--shadow-modal` 자체는 바꾸지 않는다.
- 일반 CSS에서 변수를 직접 사용한다. Tailwind 토큰 생성 체계 변경은 필요하지 않다.

### 2. 공유 프레임에 선택 가능한 경계 표현 추가

대상: `frontend/src/workspace/WindowFrame.tsx`, `frontend/src/styles/global.css`

- 코어에 `outlined?: boolean`을 추가하며 기본값은 `false`로 둔다. `flat`은 배경 선택이라는 기존 역할을 유지한다.
- 보이는 카드에 경계 스타일을 전달한다. 카드에 `position: relative`를 부여하고, 내부에 절대 배치된 장식 레이어로 1px 선을 그린다.
- 장식 레이어는 `inset: 0`, `border-radius: inherit`, `pointer-events: none`으로 두고 본문·헤더보다 위에 그려 선이 자식 배경이나 차트 캔버스에 가려지지 않게 한다. 콘텐츠보다 높은 최소 z-index를 사용하고 메뉴 표시도 확인한다.
- 선은 장식 레이어의 inset box-shadow로 그린다. 실제 카드 border나 padding을 늘리지 않아 콘텐츠 폭·높이를 보존한다.
- 바깥 깊이 그림자는 카드에 적용한다. 우선순위는 `lifting → shadow-modal`, `outlined → window-shadow`, 나머지는 기존 `flat` 정책이다.
- 현재 `contain: layout paint`, `overflow-hidden`, 둥근 모서리와 그림자의 상호작용을 브라우저에서 확인한다. 장식 레이어가 카드 내부에 그려지도록 한다.
- 바깥 rect, 2px 간격, z-order 로직, 8방향 리사이즈 히트박스는 그대로 사용한다.

### 3. /live 연결 및 문서 정리

대상: `frontend/src/live/workspace/WindowFrame.tsx`, `DESIGN.md`

- `/live` 래퍼에서 `outlined`를 활성화한다. 모든 live 창 종류가 같은 프레임을 사용한다.
- 코어 옵션 기본값은 false로 둔다. 구현 시 확인 결과 `/study`는 이미 `/live`로 리다이렉트되는 경로이며, 별도 프레임 소비자는 없다.
- `focused`와 `flat` 주석의 '헤더로만 표현', 'live 안착 그림자 없음' 등 이번 변경과 충돌하는 설명을 갱신한다.
- DESIGN.md의 live 외곽선 없음 규칙을 새 규칙으로 교체하고 변경 이유를 기록한다. 과거 호버 막대 삭제 이력은 보존한다.

## 검증

이 변경의 핵심 검증은 실제 렌더링이다. CSS 클래스 존재만 검사하는 신규 테스트는 추가하지 않는다.

1. 기존 `WindowFrame.test.tsx`의 flat 관련 설명·기대값을 검토해 새 live 정책과 충돌하는 부분만 갱신한다. 관련 프레임·핀 테스트를 실행한다.
2. 네 테마에서 차트·호가·투자자 창 3개를 서로 어긋나게 겹쳐 확인한다. 헤더가 가려진 뒤쪽 창도 노출된 변과 모서리가 구분되어야 한다.
3. 창을 차례로 클릭해 헤더 틴트가 최상단 창으로 이동하되 모든 창의 중성 외곽선은 동일하게 유지되는지 확인한다.
4. 맞닿은 창, 자유 배치, 작업 영역 가장자리, 최대화에서 선의 잘림·불필요한 두께 증가·그림자 과장을 확인한다.
5. 변경 전후 동일 배치에서 바깥 창과 콘텐츠 영역의 bounding box가 같은지 확인한다. 이동, 가장자리·모서리 리사이즈, 스냅, 최대화·Escape 복원, 닫기, 그룹 메뉴를 점검한다.
6. `/study`는 별도 페이지가 아니므로 독립 시각 검증 대상에서 제외한다.
7. `frontend`에서 `npm run typecheck`, `npm run build`, 관련 Vitest 테스트와 기존 `tests/e2e/live-window-ux.spec.ts`를 실행한다. 시각 비교 결과를 변경 설명에 첨부한다.

## 완료 기준

- 헤더가 가려진 경우에도 노출된 경계로 각 창을 구분할 수 있다.
- 모든 창의 외곽선은 동일한 중성색이고 활성 창은 헤더 틴트로 구분된다.
- 선이 차트·호가 내용에 덮이지 않으며 클릭이나 드래그를 가로막지 않는다.
- 창·콘텐츠 크기, 저장된 배치, 리사이즈·스냅 동작이 동일하다.
- 네 테마에서 확인했고 live 래퍼에서만 경계 옵션을 활성화한다.

## 범위와 전달 단위

프론트엔드 스타일 및 프레임 표현을 한 변경으로 구현한다. 백엔드, 레이아웃 저장 형식, 겹침 감지, 사용자 설정 추가는 포함하지 않는다. 구현 후 시각 검증에서 외곽선 색과 그림자 수치를 확정한다.

## 실행 기록

- `outlined` opt-in과 창 전용 CSS 변수를 구현했다. 본문은 isolation으로 스택을 분리해 내부 차트 요소가 외곽선을 덮지 않게 했다.
- Obsidian, Ledger, Toss Light, Toss Dark에서 빈 창 3개를 겹쳐 외곽선과 그림자를 직접 확인했다. 초기 토큰 수치를 유지한다. 실시간 데이터가 채워진 차트의 시각 검증은 이 확인에 포함되지 않는다.
- 브라우저에서 클릭한 창만 활성 외곽선을 갖는 것, 그룹 메뉴가 열리는 것을 확인했다.
- 외곽선을 숨기기 전후 카드·본문 bounding box가 동일했고 장식 레이어 3개 모두 pointer-events:none이었다.
- 타입 검사를 통과했다. 최초 전체 Vitest 실행은 7,290건 통과, Screener 테스트 2건 실패였고 해당 파일과 프레임 테스트를 재실행해 51건 모두 통과했다. `--maxWorkers=4` 전체 재검증에서 **556개 파일, 7,292건 모두 통과**했다.
- `npm run build` 통과. 전체 Playwright E2E **93건 통과**(4.3분), live 창 최대화·Escape 복원 및 기본 너비 검증 포함.

### 후속 조정 — 활성 외곽선 강조 제거

사용자 피드백에 따라 활성 외곽선의 accent 색상과 전용 토큰·상태 속성을 제거했다. 모든 창의 중성 외곽선과 그림자는 유지하며 포커스는 기존 헤더 틴트로만 표시한다. 위 실행 기록의 활성 외곽선 검증은 최초 구현 시점의 이력이다.
