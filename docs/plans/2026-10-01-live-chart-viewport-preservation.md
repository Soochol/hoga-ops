# 관심종목 선택과 캔들 화면 위치 보존 개선 계획

작성일: 2026-10-01 KST  
상태: 핵심 위치 보존 구현 완료 · 통합 검증 진행  
검토 기준: `e6f0703ba76c60a4d8817a5c1400567964cd68a8`와 현재 작업 트리의 미커밋 차트 최적화 코드

관심종목을 클릭하면 선택한 종목의 최신 캔들이 우측에 보이고, 이후 과거 캔들이나 지표가 도착해도 그 위치가 유지돼야 한다. 사용자가 과거 구간으로 이동했다면 데이터 갱신 후에도 보던 날짜와 줌을 유지한다. 이번 개선은 화면 주변만 차트에 전달하는 렌더링 최적화에 이 두 동작을 보장하는 작업이다.

권장 방향은 **실제 시각을 기준으로 화면을 복원하고, 한 번의 데이터 반영에서 화면 위치를 정하는 주체를 하나로 모으는 것**이다. 초기 배치를 매번 최신으로 재실행하거나 모든 과거 추가에 백필 보정 게이트를 여는 방식은 사용자의 스크롤 취소와 추가 조회 반복을 만들 수 있어 채택하지 않는다.

구현 결과: 이전/새 Virtual Axis 변환을 렌더링 어댑터에 전달해 데이터 배치 안에서 실제 시각 앵커를 보존하고, 기존 백필의 일반 재투영은 중복 실행하지 않도록 했다. 소스 교체와 명시적 복원은 기존 상위 정책을 유지한다. 오늘 시드, 지표 단독 변경, 최신 성장, 드래그 연속성, 애니메이션 목적지 갱신을 같은 어댑터에서 처리한다. 아래 단계별 제안은 검토 당시 기록이며, 실제 구현 파일·검증 범위·반복 계측 보완은 [구현 검증 기록](../diagnostics/2026-10-01-watchlist-date/implementation-validation.md)을 기준으로 한다.

## 확인한 문제와 검증 범위

현재 `WindowedChart.flush()`는 새 시리즈의 시간 합집합을 만들면서 이전 논리범위를 유지한다. `render()`는 데이터 교체 후 이 범위를 다시 적용한다. 과거 데이터가 앞에 추가되면 같은 날짜의 봉 번호가 증가하지만 화면 우단은 이전 번호에 남는다. 기존 lightweight-charts가 수행하던 위치 조정도 이 쓰기로 덮인다.

오늘 캔들을 먼저 받는 `todayFirst` 경로와 이 동작이 결합해 증상이 발생한다. 분봉 초기 배치는 한 번만 실행하고, `useViewportBackfill`은 `historicalFromDate === null`인 일반 프리펜드의 보정을 건너뛴다. 최신 봉은 데이터에 있으나 화면 밖에 놓인다.

증거는 [최초 진단](../diagnostics/2026-10-01-watchlist-date/diagnosis.json), [기존 차트](../diagnostics/2026-10-01-watchlist-date/native.json), [최적화 차트](../diagnostics/2026-10-01-watchlist-date/windowed.json), [추가 계측 요약](../diagnostics/2026-10-01-watchlist-date/review-summary.json)에 있다. 진단용 하네스는 제품 경로 전체에 대한 회귀 테스트를 대체하지 않는다.

## 분봉으로 이동한 뒤 과거를 넓히는 동작

추가 제보의 재현 순서는 브라우저 새로고침, 초기화, 일봉 창의 「분봉으로」 클릭, 분봉 차트를 잡고 좌우로 드래그하는 동작이다. 사용자가 드래그임을 확인했다. 클릭 시점의 날짜가 분봉 데이터의 우측 기준으로 유지돼야 한다.

코드 검토상 과거 날짜로 점프하면 `useMinuteJumpTarget.asOfDate`가 데이터 우단을 정하고, 백필은 시작일만 넓힌다. 일반 휠은 `computeWheelOutcome`에서 마지막 실제 캔들을 픽셀 기준점으로 삼아 확대와 축소를 한다. 이 두 계약을 함께 검증한 실제 차트 테스트는 현재 확인되지 않았다. 관련 휠과 기간 점프의 단위 및 훅 테스트 80개는 통과했으나, 이번 제보가 해결됐다는 증거는 아니다.

드래그는 화면을 이동시키므로 사용자 이동량에 따라 화면 우측에 보이는 날짜가 과거로 바뀌는 것 자체는 현재의 팬 동작이다. 이를 앞서 확인한 초기 프리펜드 오류와 같은 원인으로 단정하지 않는다. 드래그를 멈춘 뒤 백필 반영 때문에 화면이 추가로 이동하거나, 데이터 우단인 점프 기준일 자체가 바뀌면 별도 오류다. 입력에 의한 이동량과 데이터 반영에 의한 이동량을 분리해 계측한다.

이 경로의 회귀 테스트는 클릭 당시 날짜, `asOfDate`, 조회의 우단, 전체 마지막 캔들 날짜, 화면의 마지막 캔들 날짜, 기준 봉 x 좌표를 함께 기록한다. 드래그 중에는 입력한 만큼 이동하고, 손을 놓은 뒤 백필로 보던 봉이 추가로 움직이지 않아야 한다. 좌측 백필 후 조회 우단과 전체 마지막 캔들도 동일해야 하며, 기간 동기화로 일봉 창이 움직여도 이미 발행한 점프의 기준일은 바뀌지 않아야 한다. 일반 휠 확대와 축소에서는 클릭한 기준일의 마지막 캔들이 기존 우측 위치를 유지해야 한다.

드래그해도 화면 우측 날짜를 고정하고 왼쪽 범위만 넓히는 동작이 목표라면 현재 팬을 확대와 축소 동작으로 바꾸는 별도 요구사항이다. 이 계획의 버그 수정에 그 제스처 변경을 섞지 않는다. 화면 우측 고정 요구가 데이터 우단 유지인지 제스처 변경인지 확인한 뒤 후자의 구현 범위를 정한다.

과거 점프에서는 실제 오늘과 기준일이 달라 `todayFirst` 시드 경로가 켜지지 않는다. 따라서 최초 시드의 예외 처리만 고쳐서는 이 제보를 해결했다고 볼 수 없다. 일반 백필과 공유 시간축 갱신까지 포함하는 2단계의 위치 보존 계약 및 아래 통합 검증을 완료 조건으로 삼는다.

## 추가 검토에서 드러난 설계 제약

### 실제 날짜와 차트 시각을 구분한다

`VirtualAxis`는 밤과 휴일을 접은 시각을 사용한다. 과거 세션이 추가되면 축 원점과 같은 날짜에 대응하는 차트 시각이 바뀔 수 있다. 따라서 어댑터가 이전 `Time` 값을 새 격자에서 다시 찾는 것만으로는 날짜 보존을 보장하지 못한다.

이전 축으로 화면의 기준점을 실제 KST ms로 변환하고, 새 축으로 다시 투영해야 한다. 축 원점 고정은 기존 날짜 눈금 오류 방지 계약을 깨므로 해결책에서 제외한다. `useViewportBackfill`의 기존 `prevAxisRef`와 `preSwapRef` 계약을 확장해 사용한다.

### 데이터 반영과 위치 보정의 책임을 분리한다

어댑터는 전체 시간 합집합과 화면 주변 구간의 좌표 변환을 담당한다. 최신 따라가기, 저장뷰 착석, 소스 교체, 백필 클램프 등 의미상의 위치 결정은 실제 축과 캔들 데이터를 가진 상위 제어기가 담당한다.

현재는 어댑터의 `render`, 초기 배치, 백필 보정, 소스 교체, 기간 동기화가 같은 범위를 쓴다. 새 구조에서는 데이터 반영마다 상위 제어기가 최종 위치를 한 번 결정하고, 어댑터는 그 범위를 최종 렌더에 적용한다. 어댑터가 자동 보존한 뒤 기존 훅이 다시 이동하는 두 단계 보정을 기본 계약으로 만들지 않는다.

### 최초 과거 로딩과 사용자 백필을 구분한다

`historicalFromDate === null`은 사용자가 움직이지 않았다는 증거가 아니다. 이미 받은 구간 안에서 뒤로 이동하면 이 값이 계속 null일 수 있다. 반대로 최초 시드는 정상적으로 왼쪽에 빈공간을 확보하므로 음수 논리범위가 곧 사용자 백필 의도도 아니다.

최초 과거 수집 중인지 나타내는 기존 `isInitialMinuteHistoryPending` 신호와 창의 `viewKey`, 사용자 입력 버전을 함께 사용한다. 거래량 0, 휴일, 오늘 시드 실패 후 과거 폴백에서도 단계가 종료되도록 한다. 기존 조회 예산과 종료 조건은 유지한다.

### 지표만 바뀌는 반영도 포함한다

시리즈는 캔들용 `chartBundle` 외에 호가와 라이브 번들도 읽는다. 캔들 번들과 축 참조가 그대로인데 다른 pane만 바뀌면, 그 두 참조에 의존하는 보정 effect가 다시 실행되지 않을 수 있다. 어댑터의 자식 단독 갱신과 microtask flush도 같은 위치 보존 계약을 거쳐야 한다.

범위 이벤트는 최종 시리즈와 최종 위치가 정착한 뒤 발행한다. 중간 범위로 과거 날짜 칩을 갱신하거나 다른 창을 동기화하거나 백필을 발사하지 않도록 데이터 반영 식별자와 입력 원인을 구분한다.

## 목표 동작과 위치 보존 규칙

기준점에는 `viewKey`, 이전 축 세대, 실제 기준 시각, 그 기준점의 화면 내 논리 위치, 표시 폭, 최신 캔들 뒤 여백, 최신 구간 여부, 사용자 입력 버전을 기록한다. 새 격자의 전체 합집합 인덱스로 위치를 계산하며, 캔들 배열 인덱스와 공유 시간축 인덱스를 동일하게 취급하지 않는다.

| 상황 | 위치 결정 |
| --- | --- |
| 새 종목의 첫 유효 캔들 도착 | 해당 종목의 마지막 실제 캔들과 기존 분봉 초기 폭으로 배치 |
| 최초 과거 청크 추가 중 최신 구간 유지 | 새 최신 캔들 기준으로 기존 폭과 우측 여백 유지 |
| 최초 과거 청크 대기 중 사용자가 뒤로 이동 | 실제 시각 기준점과 화면 내 위치 유지 |
| 이미 받은 구간의 지표 시각 추가 또는 제거 | 같은 실제 시각이 같은 픽셀 위치에 보이도록 재투영 |
| 실시간 봉 추가 중 최신 구간 유지 | 최신 캔들이 기존 우측 위치를 유지하도록 따라감 |
| 실시간 봉 추가 중 과거 구간 유지 | 보던 날짜 유지 |
| 백필 대기 중 드래그나 휠 입력 | 응답 직전의 사용자 위치 승계, 요청 시작 당시 위치로 되돌리지 않음 |
| 화면 대부분이 로드 범위 밖의 빈공간 | 기존 백필의 재투영 자격 판정 유지, 무조건 최신으로 이동하지 않음 |
| 저장뷰 열기 또는 기간 점프 | 명시적 목적지 우선, 최초 로딩 자동 보정으로 덮지 않음 |
| 소스 교체 또는 실제 데이터 트림 | 기존 소스 교체와 클램프 정책을 먼저 평가한 뒤 최종 범위를 한 번 적용 |

최신 구간 판단과 최근 시각 복귀의 기준은 **마지막 실제 캔들**이다. 시리즈 합집합의 마지막 시각은 지표의 whitespace나 늦은 포인트일 수 있다. 현재 초기 배치가 쓰는 `latestIndex + 1 + padding`과 라이브러리 `scrollPosition`이 쓰는 마지막 인덱스 기준의 차이도 변환 함수 한 곳에서 명시한다.

사용자 입력 버전이 바뀌면 오래된 위치 예약은 폐기하거나 새 위치로 다시 계산한다. 드래그 중 구간을 다시 구성할 때는 현재 포인터 위치를 기준으로 드래그 기준점도 갱신해 다음 이동에서 화면이 튀지 않도록 한다.

## 구현 순서

### 1단계 최초 로딩 회귀를 고정한다

실제 `useLivePastCandles` 경로에서 오늘 시드만 먼저 반환하고 과거 응답을 대기시키는 테스트를 만든다. 관심종목 클릭으로 종목을 교체한 뒤 시드 도착, 과거 청크 도착, 로딩 완료의 각 시점에서 최신 날짜와 캔들 픽셀 위치를 기록한다. 빠른 A 종목에서 B 종목으로의 전환도 포함한다.

현재 단위 테스트는 프리펜드 후 이전 숫자 범위를 유지하고 호출자가 수동 보정하는 것을 정답으로 둔다. 어댑터 내부 동작을 확인하는 테스트와 사용자가 보는 날짜 보존 테스트를 구분하고, 통합 테스트에 수동 `setVisibleLogicalRange`를 넣어 실패를 숨기지 않는다. `LiveChartRoot`의 부분 차트 mock은 어댑터를 우회하므로 실제 차트를 사용하는 회귀 테스트가 필수다.

정상 동작 회복 전 최적화를 별도 작업에 합쳐 적용해야 한다면 `createWindowedChart`를 내부 개발 플래그 뒤에 두고 기본 렌더링을 사용한다. 사용자 설정을 새로 만들지 않는다. 이는 구현 중 적용을 위한 안전장치이며 최종 해결로 처리하지 않는다.

주요 파일: `frontend/src/api/livePastCandles.test.tsx`, `frontend/src/live/LiveChartRoot.test.tsx`, `frontend/src/chart/windowedChart.test.ts`, 새 관심종목 최초 로딩 E2E.

### 2단계 데이터와 화면 위치를 함께 반영한다

`WindowedChart`의 처리 순서를 **새 격자 준비 → 최종 위치 계산 → 공통 렌더 구간 적용 → 위치 정착 후 이벤트 발행**으로 나눈다. 새 격자 조회는 가능하지만 native 시리즈를 아직 교체하지 않은 준비 단계에서 상위 제어기가 위치를 결정할 수 있도록 작은 명시적 계약을 추가한다. 전체 시간 합집합을 두 번 만드는 구현은 피한다.

상위 제어기는 기존 pre-swap 스냅샷을 실제 시각 기준으로 유지하고, 최초 과거 수집 단계에서도 좁은 조건으로 위치를 복원한다. `historicalFromDate` 게이트를 전체 분봉 프리펜드에 대해 제거하지 않는다. 최신 구간, 과거 구간, 명시적 점프, 소스 교체를 동일한 위치 결정 절차에 연결한다.

`LiveChartRoot`의 매 렌더 flush와 `useViewportBackfill`의 효과 실행 순서를 명시적으로 재구성한다. 지표만 바뀌는 커밋과 자식 단독 갱신도 동일한 준비와 반영 계약을 사용한다. 캔들 축이 바뀐 커밋은 이전 가상시각으로 복원하지 않으며, 축이 그대로인 지표 갱신도 실제 기준점을 재사용한다.

기존 차트 API 호출을 받는 어댑터는 동일한 global-to-local 변환을 사용한다. 범위 적용과 스크롤 오프셋 적용을 섞는 경로는 한 곳으로 모으고, API가 다음 프레임에 적용되는 동안 오래된 범위를 다시 쓰지 않도록 반영 버전을 검사한다. 내부 라이브러리 필드는 수정하지 않는다.

주요 파일: `frontend/src/chart/windowedChart.ts`, `frontend/src/live/LiveChartRoot.tsx`, `frontend/src/live/useViewportBackfill.ts`, `frontend/src/live/viewportAnchor.ts`. 위치 계산은 순수 함수로 분리해 검증한다.

### 3단계 실시간 성장과 명시적 복귀를 연결한다

시리즈 값만 바뀌면 같은 범위를 유지하고, 새 봉이나 새 시각이 추가되면 앞 절의 위치 보존 규칙을 적용한다. 사용자 과거 구간과 최신 구간을 구분해 실시간 성장을 처리한다. 최신 봉을 따라가도록 시간 합집합 길이를 무조건 더하는 방식은 사용하지 않는다.

최근 시각 복귀는 마지막 실제 캔들을 대상으로 잡는다. 애니메이션 중 새 봉이나 과거 데이터가 도착하면 새 격자에서 목적지를 다시 계산하며, 사용자 입력과 종목 교체는 이전 애니메이션을 취소한다. 한 프레임에서 논리범위와 스크롤 오프셋을 서로 다른 기준으로 중복 적용하지 않는다.

우측 과거 날짜 칩은 최종 캔들 위치와 일치해야 한다. 단독 하네스의 복귀 성공만으로 사용자 화면에서 확인한 복귀 후 날짜 변경을 해결했다고 판단하지 않는다. 동일한 지표와 창 구성을 재현해 별도 완료 단언으로 확인한다.

주요 파일: `frontend/src/chart/windowedChart.ts`, `frontend/src/live/LiveChartRoot.tsx`, `frontend/src/live/workspace/ChartWindow.tsx`, `frontend/src/live/useRangeSync.ts`의 연결 경로.

### 4단계 기능 정확도와 성능을 함께 검증한다

아래 회귀 표를 통과한 뒤 기존 [과거 캔들 성능 개선 계획](2026-10-01-live-backfill-interaction-performance.md)의 큰 이력과 다중 창 조건을 다시 측정한다. 화면 위치 보존을 위해 매 틱마다 전체 재렌더링하거나 조회를 늘리는 해결은 완료 기준을 충족하지 않는다.

| 검증 묶음 | 필수 조건 |
| --- | --- |
| 초기 로딩 | 1분과 15분의 오늘 시드 후 1회 및 여러 청크 프리펜드, 시드 실패 폴백, 오늘 봉 없음 |
| 종목 전환 | A에서 B로 빠르게 교체, 이전 응답 지연 도착, 같은 종목 재선택, 웜 캐시로 복귀 |
| 사용자 위치 | 과거 팬 후 프리펜드, 음수 범위의 시드, 로드 경계 밖 대부분 빈공간, 응답 대기 중 드래그 |
| 지표 도착 | 캔들 번들 불변 상태의 호가와 사이드카 도착, 지표 켜고 끄기, 희소 선과 whitespace |
| 실시간 | 기존 봉 값 수정, 새 봉 추가, 프리펜드와 새 봉 동시 도착, 과거 구간 유지 |
| 명시적 이동 | 새로고침과 초기화 후 「분봉으로」 클릭과 좌우 드래그 및 일반 휠 확장, 최근으로 복귀, 복귀 애니메이션 중 갱신과 입력, 저장뷰, 기간 점프, 범위 동기화 |
| 표시 구간 | 4000점 경계와 큰 줌아웃, full-render 폴백, 캐시 안 구간 이동, 창 리사이즈 |
| 수명 | 창 두 개 이상의 독립 반영, 창 닫기, 봉 주기 교체, 이전 viewKey의 예약 취소 |

최신 기준일은 고정된 테스트 시각과 응답의 마지막 유효 거래일로 정한다. 휴일이나 오늘 캔들이 없는 종목에 당일 날짜를 강요하지 않는다. 대표지수, 초봉, 일봉, 주봉, 월봉과 터치 환경은 기존 경로를 유지하며 공통 제어기 변경에 대한 회귀를 확인한다.

## 완료 기준과 적용 조건

- 최초 시드와 과거 응답의 도착 순서에 관계없이 마지막 유효 캔들이 우측에 보인다. 예약된 프레임과 지표가 정착한 뒤에도 같은 날짜가 유지된다.
- 정지 상태의 데이터 반영에서 기준 봉의 이동은 1 CSS px 이내, 표시 폭과 봉 간격은 유지된다. 드래그 중에는 사용자 이동분을 분리해 비교한다.
- 과거를 보는 사용자는 데이터 갱신 후에도 같은 날짜를 본다. 새 봉 성장 중 최신 구간에서는 우측 여백과 최신 봉 위치가 유지된다.
- 데이터 반영만으로 최초 과거 수집 요청이 취소되거나 추가 백필 예산이 생성되지 않는다. 이미 받은 캔들과 지표 커버리지 안 이동은 추가 요청 0회다. 부족한 지표는 기존 coverage gap 정책만 수행한다.
- 범위 이벤트, 과거 날짜 칩, 다른 창에 발행하는 기간이 최종 위치와 일치한다. 중간 잘못된 날짜가 외부 제어기에 발행되지 않는다.
- 큰 이력에서도 native 렌더 입력은 기존 최적화의 화면 주변 크기를 유지한다. 성능은 동일한 기기와 지표 조건에서 기존 성능 계획의 기준과 비교한다.

구현 완료 시 프론트 전체 typecheck, Vitest, Vite build, Playwright를 저장소 지침대로 실행한다. 기능 검사와 성능 계측은 동시에 실행하지 않는다. 사용자 서버 5173과 8000은 유지하고 격리된 포트와 fixture를 사용한다.

현재 단계에서는 **확인한 초기 프리펜드 회귀와 단독 어댑터의 추가 위험을 구분한 개선 계획까지 작성**했다. 제품 코드 수정과 배포는 수행하지 않았다. 최적화 적용은 위 정확도 조건을 먼저 통과한 뒤 진행하며, 실패한 구성은 기존 native 경로로 되돌리고 진단 사유를 남긴다.

ADR-0054의 공개 시간축 확장, ADR-0139의 봉 수신 해상도, ADR-0104와 ADR-0105의 백필 예산, ADR-0157의 저장뷰 착석 계약을 유지한다. 변경되는 것은 렌더링 최적화와 위치 보정의 반영 순서이며, 데이터 저장 형식이나 관심종목 클릭의 대상 창 선택 정책은 변경하지 않는다.
