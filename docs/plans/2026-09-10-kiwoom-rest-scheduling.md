# 키움 REST 중복 호출·대기·인증 분류 개선

작성: 2026-09-10. 기준: main의 PR #1801 반영본. 상태: 구현 및 전체 로컬 검증 완료. PR: #1802.

## 목표와 확인된 문제

1. 실행 중인 background 요청의 user_visible 승격으로 동일 key가 두 번 실행된다.
2. 버킷 대기 후 양보한 요청의 inflight 기록이 cleanup에서 지워져 동일 key가 다시 제출된다.
3. 기본 워커 4개가 특정 TR의 호출 간격을 기다리면 여유 있는 다른 TR도 실행할 수 없다.
4. 토큰 provider의 일시 장애(503·전송 오류·발급 cooldown)가 일반 인증 오류로 바뀌어 앱키 실패 판정과 불필요한 invalidate를 만든다.

기존 관련 테스트 72개는 통과했으나 별도 모의 입력에서 위 문제를 재현했다. 실제 벤더 지연 기여도와 장중 발생 빈도는 아직 측정하지 않았다.

## 구현 순서

### 1. 요청 소유권과 중복 제거

- 동일 key의 공유 future를 완료까지 유지한다. 실행 중인 요청에는 새 실행 레코드를 만들지 않는다.
- 대기 중 승격은 허용하되 오래된 우선순위 레코드는 실행 전에 걸러낸다.
- 인증·유량 재시도 중에도 동일 future를 유지하고 각 재시도 상한은 기존대로 지킨다.
- 한 대기자의 취소는 다른 대기자를 취소하지 않는다. 스케줄러 종료 시에는 대기·실행 중 요청을 모두 정리한다.

### 2. 호출 가능 요청 선택

- 우선순위 큐에서 즉시 호출 가능한 계정/TR 요청을 먼저 고른다. 호출 간격을 기다리는 요청은 큐에 유지한다.
- 준비된 요청이 없으면 가장 가까운 가능 시각 또는 새 요청 도착을 기다린다. 타이머/이벤트 대기는 워커 수 이내로 제한하고 busy loop를 만들지 않는다.
- 계정/TR별 페이싱과 실제 HTTP 동시 실행 상한은 유지한다. 이미 진행 중인 HTTP를 선점하거나 워커 수를 무작정 늘리지 않는다.
- 준비된 user_visible 요청은 준비된 background보다 먼저 처리한다. 특정 TR의 대기가 다른 TR의 실행을 차단하지 않게 한다.
- 큐 상한과 queued 관측은 승격용 중복 레코드가 아닌 고유 대기 요청 수를 기준으로 한다.

### 3. 일시 인증 장애 보존

- provider의 일시 장애를 REST 도메인에서도 구분한다. 앱키 연속 실패 카운터와 token invalidate를 적용하지 않는다.
- 일시 장애 계정은 선택 후순위로 보내고 건강한 다른 계정이 있으면 제한된 횟수 내에서 재시도한다. 다른 계정이 없으면 빠르게 일시 실패를 반환한다.
- 화면의 기존 일시 전송 오류 정책을 사용한다. 진짜 인증 오류·지정 단말 오류·유량 초과의 기존 정책은 유지한다.

## 검증과 완료 기준

- 변경 전 재현: 실행 중 승격, 양보/대기 중 동일 key 재요청, 다른 TR의 독립 진행, 503/cooldown 오분류.
- 변경 후: 같은 key 호출 1회, 차단된 TR보다 준비된 TR이 먼저 실행, 일시 장애 시 앱키 실패 표시와 invalidate 0회.
- 추가 경계: 대기 중 승격의 잔여 레코드, unique 큐 상한, 취소/종료, 유량 재시도·인증 failover, 계정별 페이싱.
- 필수 로컬 Ruff·백엔드 전체 테스트, 프론트 타입 검사·Vitest·빌드. 프론트 변경 시 E2E 전체 추가.
- 열린 PR 파일 중복 확인, 최신 main 반영 및 영향 검증, 검증 커밋과 PR head 일치 확인 후 squash merge.
- 사용자 개발 서버 및 자격증명은 건드리지 않는다. 실 벤더 호출·운영 배포는 이번 범위에 포함하지 않는다.

## 설계 관계

ADR-0136의 단일 우선순위 큐·중복 제거·승격·양보와 ADR-0138의 계정/TR 버킷을 유지한다. 양보 시점을 워커가 버킷에서 깨어난 뒤가 아니라 호출 가능한 요청 선택 시점으로 옮긴다. HTTP 실행 중 요청을 선점하지 않으므로 모든 워커가 실제 HTTP를 처리하는 경우의 대기까지 제거하는 것은 아니다.

## 구현 및 검증 기록

- 변경 전: 실행 중/대기 중 승격, 다른 TR 차단, 503/cooldown 오분류의 신규 테스트 5개가 모두 실패했다.
- 변경 후: 관련 테스트 216개 통과. 기존 양보 테스트는 버킷 내부 수면 대신 큐의 호출 가능 시각을 제어하도록 바꾸고, 동일 key 재요청의 실제 실행 횟수도 검사한다.
- 큐 선택은 `_next_ready`가 수행한다. 대기 시 가장 가까운 TR 가능 시각과 새 제출 이벤트를 함께 기다리며, obsolete 승격 레코드는 제거한다. 작업을 대기 상태로 유지하므로 이전의 양보→cleanup→inflight 유실 경로를 제거했다.
- 고유 대기 key가 큐 상한과 `queued`의 기준이다. `background_deferred_due_to_user_visible`은 준비된 화면 요청에 양보한 대기 요청을 요청당 한 번 센다. wire 필드/타입은 추가하지 않았다.
- 일시 토큰 실패는 `KiwoomAuthTransientError`로 보존한다. 기존 `transport_error` 정책으로 재시도 가능 상태를 표시하며, 투자자 추정 API도 `credentials_missing` 대신 기존 `api_error`로 반환한다.
- 실제 provider/API 계층을 연결한 모의 테스트, HTTP 응답의 경고 직렬화, 정상 계정 failover, 반복 일시 장애의 재시도 상한, 승격 시 unique 큐 상한, 종료/재시작, 계정별 250ms 슬롯 간격을 검증했다. 시간 간격 검증에는 수동 monotonic clock을 사용해 실제 대기시간에 의존하지 않는다.
- 프론트 코드나 공개 응답 필드·enum은 변경하지 않았다. 과거 재생·저장 포맷·10초 저장 주기·WS 프로토콜도 유지한다.
- 최종 검증: 백엔드 4,988 passed, 2 skipped, 13 deselected (`not wallclock`); 프론트 559개 파일·7,314개 테스트 통과. Ruff·타입 검사·프로덕션 빌드·diff whitespace 검사 통과. 기존 Vite 대형 chunk 경고는 유지된다. 검증 커밋은 PR 본문에 기록한다.
- 프론트 변경이 없어 이번 PR의 Playwright E2E 재실행 대상은 아니다. 실제 키움 장중 지연 개선 폭과 운영 적용 검증은 별도로 남긴다.
