# 관심종목·히트맵의 3·5·10분봉 WS 신고거래량 감시

사용자 구현 요청: 관심종목·히트맵으로 한정한 WS 감시를 3·5·10분봉으로 확장하고,
처음 자료 준비와 누락 보충만 API로 수행한다. 기존 1분봉 감시와 같은
`new_high_vol`·`new_high_vol_today` 최근 방식, 진행 봉 포함 조건에 적용한다.

## 자료와 판정

- 선택한 관심종목·히트맵 범위의 합집합만 감시한다. 범위가 없는 전 대상 분봉 검색은
  기존 서버 실행/API 경로를 사용한다. 새 브로커 연결이나 전체 시장 구독은 추가하지 않는다.
- 종목별 당일 1분봉을 API로 한 번 준비하고 모든 조건·화면·주기가 같은 이력을 공유한다.
  이후 기존 KRX 원본 체결의 절대 분 거래량 상태를 받아 09:00 기준 3·5·10분봉으로 합친다.
  15:30 종가 체결은 독립 봉으로 두며, 장 마감 이후에는 완료된 API 자료로 판정한다.
- 주말·확인된 휴장일은 마지막 거래일, 장전은 당일을 선택한다. 거래일이 바뀌면 전날
  비교 봉·하한·정본 증거를 초기화한다. 지연된 전날 API 응답은 당일 이력을 덮지 않는다.
- 비교 봉과 최근 봉이 당일에 충분하지 않으면 판정 보류다. 저장 이력의 잘린 첫 묶음은
  온전한 비교 봉으로 인정하지 않으며, 빈 분/빈 묶음의 거래량을 임의로 만들지 않는다.
- API와 WS 거래량을 더하지 않는다. 기존 중복·누적값·부분 관측 보호를 유지하고,
  진행 봉 하한을 합쳐진 주기의 시작 시각에 표시한다. 미확인 종료 봉은 비교에서 제외한다.
- IPC replay 범위를 넘는 공백·재연결·불완전한 종료 봉은 해당 종목만 API로 보충한다.
  정상 수신 중이고 비교 자료가 충분하면 5분마다 전체 API를 다시 조회하지 않는다.
  부족한 이력의 제한된 재확인과 실패 백오프·최대 4개 동시 준비 큐는 유지한다.
- 결과 읽기는 API 준비를 직접 시작하지 않는다. 준비·복구는 서버 소유 작업이다.
  각 주기의 봉 교체·최대 도달·품질 변화는 기존 WS 이벤트로 페이지와 패널에 전달한다.

## 자원과 경계

원본 1분 이력만 보유하고 큰 주기의 비교에 필요한 분 수와 경계 여유를 용량 계산에
반영한다. 기존 512종목·250,000봉·64MiB 예약·감시 lease 한도를 유지하며, 불가능한
예약은 기존 감시를 보존한 채 거절한다. 영구 분봉 저장소를 추가하지 않는다.

일/주/월, 날짜 구간, 가격·기타 지표는 기존 계산 경로를 사용한다. 이 확장은 최근 방식의
신고거래량 감시 범위다. 실제 공급자의 장중 지연이나 속도 배수는 측정하지 않았다.
