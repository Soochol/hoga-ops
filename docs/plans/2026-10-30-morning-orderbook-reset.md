# KRX 아침 호가 초기화와 장전 잔량 표시

## 요구와 범위

- 호가주문창의 `저장된 마지막 호가 · 20:00:00 · KRX · 거래일 미제공` 상시 안내를 제거한다.
- NXT 미지원 종목은 다음 평일 08:30 KST에 전일 사다리와 전체 호가 탐색을 초기화한다.
- 08:30 전후에 도착하는 장전 시간외 매도·매수 총잔량을 수신 즉시 표시한다.
- 당일 현재 호가가 WS로 오면 정규장 시작 시각을 기다리지 않고 즉시 사다리를 갱신한다.

## 확인한 기존 경로

1. `useLiveSeries`는 NXT 미지원 종목의 통합 선택을 KRX로 해석한다.
2. 서버 WS 연결 창은 거래일 08:00–20:00이다. `0D` 사다리와 `0E` 시간외 잔량을
   같은 열람 구독으로 받는다. `0E` 파서는 잔량이 있는 프레임에 별도 시각 하한을 두지 않는다.
3. 기존 표시층은 전일 사다리를 만료시킨 뒤에도 날짜 없는 `ka10004` REST/저장본으로
   다시 채울 수 있었다. 이때 총잔량 스트립에서도 REST가 당일 `0E`보다 우선했다.
4. 이전 장전 실측은 [2026-08-19 조사](../research/2026-08-19-krx-pre-market-orderbook.md)에
   있다. 이번 작업에서 실벤더 아침 수신을 새로 측정한 것은 아니다.

## 표시 결정

두 호가창의 `useBookSessionDisplay`에서 유효시장·날짜·수신 데이터를 함께 판정한다.
저장소나 원본 시리즈를 삭제하지 않아 과거 커서와 재시작 복원을 보존한다.

| 관측 상태 | 표시 |
|---|---|
| KRX 평일 08:30 전, 당일 데이터 없음 | 전일 마지막 사다리 열람 유지 |
| 당일 0E가 08:30 전에 먼저 수신됨 | 전일 사다리를 내리고 총잔량 표시 |
| 08:30 도달, 당일 데이터 없음 | 사다리 초기화, 수신 대기, 상세정보 유지 |
| 0E만 수신됨 | 사다리를 만들지 않고 매도·매수 총잔량 표시 |
| 당일 0D 수신됨 | 즉시 현재 사다리와 그 총잔량 표시 |
| KRX 평일 08:30–20:00, 현재 사다리 없음 | 날짜 없는 REST/저장본 표시·조회 차단 |
| 장 종료 후 또는 주말 | 기존 마지막 호가 열람 허용 |
| 과거 커서 | 현재 시각의 초기화·현재 잔량을 적용하지 않음 |

08:30은 전일 값의 최종 초기화 시각이다. `0E`·`0D` 수신을 허용하는 시작 시각으로
사용하지 않는다. 08:40·08:50·09:00에도 수신을 막는 하드코딩을 추가하지 않는다.
살아 있는 사다리와 시간외 잔량 사이의 기존 프레임 시각 비교를 유지하므로 현재 사다리가
오면 과거 시간외 잔량이 그 총잔량을 덮지 않는다.

호가주문은 기존 초 경계 시계를, 10호가는 이미 상태 판정에 쓰던 초 경계 시계를 공유한다.
다른 수신이 없어도 08:30을 넘으면 초기화하며 숨겨진 탭은 다시 보일 때 시계를 맞춘다.
주문 신선도는 날짜 있는 WS 사다리의 기존 30초 검사를 유지한다.

## 검증

- 단위: 08:29:59 → 08:30 초기화, 캐시된 REST 재노출 차단, 유효시장 UN → KRX,
  조기/정각/지연 0E, 08:49:59·08:50·09:00 당일 사다리 전환, 과거 커서 보존.
- 브라우저: 08:29:59·08:30:00·08:32:00 잔량 수신과 08:50·09:00 WS 전환을 두
  호가창에서 확인한다. 주말 마지막 호가, 실패/빈 상태, 기존 장후 총잔량 표시도 확인한다.
- 백엔드: 기존 WS 연결 창·0D/0E 파서·NXT 미지원 구독의 회귀 검사를 실행한다.
- 이번 검증은 무자격 격리 환경과 합성 프레임이다. 공급자의 실제 최초 송신 시각이나
  수신 지연을 보장하지 않는다. 휴일은 기존 프론트 정책대로 주말만 구분한다.

프론트 단위 485개·백엔드 회귀 139개, 아침 브라우저 시나리오 15회(3개 × 5회),
기존 브라우저 회귀 6개가 통과했다. 앱·단위·E2E 타입 검사와 Vite 빌드도 통과했다.
