# Live 종목 검색 UX 개선

## 목적과 범위

`/live`에서 `/`로 여는 검색창을 빠른 종목 전환에 맞춘다. 사용자 요청은
2026-09-09 UI/UX 검토에 이어 계획 작성 후 구현이다.

이번 구현은 검색창 표현과 선택·삭제·키보드 조작을 다룬다. 기존
`activationTarget`의 링크 그룹 선택 및 고정 창 제외 계약(ADR-0153)을 유지한다.
초성 검색, 개인화 정렬, 지수 검색 별칭은 후속 단계로 둔다. 공통 검색 결과
순서를 바꾸기 전에 캡처·히트맵 등 소비처의 기대를 함께 검토해야 한다.

## 화면 결정

- 최대 폭 640px, 상단 위치 12vh. 작은 뷰포트에서는 좌우 16px 여백을 확보한다.
- 기존 테마·Pretendard·그림자 토큰을 사용한다. 입력과 종목명은 `text-base`,
  코드·시장은 보조 위계로 둔다. 전역 폰트/간격 토큰은 변경하지 않는다.
- 보이는 제목 `종목 검색`, 입력 안내 `종목명·코드·지수 검색`, 닫기 버튼을 둔다.
- 적용 대상은 `적용 대상: 그룹 N · 창 M개`로 읽히게 한다. 고정 창 제외 설명과
  모든 창 고정·빈 워크스페이스 안내를 유지한다.
- 최근 검색과 입력 결과 모두 세로 행으로 표시한다. 종목명 가까이에 코드·시장을
  배치하고 보조 작업은 오른쪽으로 분리한다.
- 최근 기록 삭제는 독립 버튼이다. 삭제 시 종목 변경·검색창 닫힘이 없어야 한다.
  기존 최대 5개 및 localStorage 키를 유지한다.
- 하단에 `↑↓ 이동 · Enter 적용 · Esc 닫기`를 표시한다. 목록만 스크롤하고
  제목·입력·적용 대상·도움말은 남긴다.
- 기록이 없는 초기 상태에도 검색 방법을 안내한다.

## 구현 순서

1. `LiveSymbolSearch`의 초기/결과 상태를 같은 행 구조로 통합하고 삭제·닫기 동작을
   분리한다. 저장소 쓰기 실패가 종목 전환이나 닫기를 중단하지 않도록 한다.
2. 공통 `useCombobox`에 한글 조합 중 키 처리 보호와 항목 수 변경 후 유효한 선택
   범위를 보장한다. Live 검색창은 선택 행 ID와 `aria-activedescendant`, 키보드
   이동 후 자동 스크롤을 연결한다.
3. 닫기/선택 후 이전 포커스를 복원하되 외부 클릭으로 옮겨 간 포커스를 빼앗지
   않는다. Escape가 배경의 창 최대화 해제까지 전달되지 않도록 한다.
4. 현재 디자인 결정과 검증 결과를 문서에 기록한다.

실제 화면 검증에서 관심 그룹 메뉴가 검색창 뒤에 가려지는 기존 문제를 확인했다.
`WatchlistGroupPicker`를 검색 표면 위에 표시하고 중첩 포털 레이어로 등록한다.
공통 콤보박스의 닫기 콜백도 안정화해 렌더링마다 부모 레이어 순서가 바뀌지 않게 한다.

전체 E2E에서 창 최대화·복원 테스트가 초기 캔버스 크기 재계산 전에 기준 높이를
읽는 간헐 실패(648px → 606px)를 확인했다. 무자격 픽스처의 연결 안내 배너가
표시되고 기본 전고 창이 부모 캔버스 높이에 맞춰진 뒤 기준을 측정하도록 테스트를
안정화한다. 복원 전후 위치·폭·높이 비교는 유지하며 앱 창 배치 코드는 바꾸지 않는다.

## 검증

- Vitest: 최근 삭제 후 종목 불변·저장·빈 상태, 조합 중 Enter 미선택, 항목 삭제 후
  선택 범위, 선택/닫기, 지수·관심 그룹 기존 동작, ARIA 선택 연결.
- Playwright: 짧은 뷰포트에서 마지막 결과까지 키보드 이동·스크롤, 최근 삭제와
  재선택, Escape가 검색창만 닫는지 확인한다. 독립 워크트리 자원을 사용한다.
- `npm run typecheck`, 전체 Vitest, Vite 빌드, 전체 Playwright를 실행한다.
- 실제 렌더링에서 검색 폭·행 위계·긴 이름·목록 스크롤과 테마 가독성을 확인한다.
