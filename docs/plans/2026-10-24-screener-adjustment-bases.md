# 수정주가와 신고거래량 기준 분리 설계안

작성일: 2026-10-24 KST  
상태: 사용자 승인 후 별도 계산 경로 구현. [구현·검증 범위](2026-10-24-screener-bases-implementation.md)를 따른다. 운영 데이터 재보정·배포·전 종목 수량 이력 자동 검증은 미실행.

## 1. 결정 요약

가격 분석에는 **공급자 수정주가**, 신규 일/주/월봉 신고거래량에는 **주식 수 단위 보정 거래량**을 사용한다. 가격 조정계수의 역수를 모든 거래량에 적용하지 않는다. 현금배당·ETF 현금 분배금은 신규 신고거래량 수치를 바꾸지 않는다.

기존 원주가·수정주가·계수·저장된 조건검색·발생 제외·저장 결과는 보존한다. 기존 요청과 저장 조건은 기존 계산 정책으로 해석하고, 새 기준은 명시된 새 계산 정책에서만 사용한다. 기존 수정주가의 값이 달라져야 하는 경우에는 새 데이터 버전을 생성한다.

| 용도 | 신규 정책의 기준 | 보존·호환 정책 |
|---|---|---|
| 국내 개별 종목 D/W/M 차트의 가격, 신고가·이동평균 등 가격 조건 | 동일 기준일의 공급자 수정 OHLC | 기존 화면은 기존 경로 유지. 새 경로에서 기준일·버전을 명시 |
| 신규 D/W/M 신고거래량 | 주식 수 단위 보정. 실제 거래량 선택도 제공 | 필드 없는 기존 조건은 기존 수정 거래량 |
| 분봉 신고거래량 | 공급자 원본 거래량 | 기존 의미 유지. 이번 설계에서 분봉 수량 보정 추가 안 함 |
| 거래대금 조건 | 수신한 실제 거래대금 우선, 없으면 원주가 OHLC 평균 × 원본 거래량 추정 | 기존 조건의 계산식은 기존 정책에서 유지 |
| 공급자 수정 거래량 | 대조·진단용 관측값으로 보존 | 기존 정책의 거래량과 같은 값이라고 자동 판정하지 않음 |

‘수정주가’는 총수익률이나 실제 체결 가격이라는 뜻이 아니다. 공급자가 제공하는 수정 가격의 방법·기준일을 따르는 가격 분석용 시계열이다. 국내 대표지수·미국 종목/지수·파생상품의 수집 및 보정 계약은 이번 전환 범위 밖이다.

## 2. 근거와 기존 결정의 변경 범위

현재 경로:

- `hoga/api/screener_factors.py`: 종가 쌍에서 계수를 역산하고 1% 문턱으로 구간을 압축한다. 가격에는 곱하고 거래량에는 나눈다.
- `hoga/api/screener_history_storage.py`: 재구성 거래량의 정확 일치, 기존 수정 관측값의 완전 재현을 요구한다.
- `hoga/api/screener_history_jobs.py`: 공급자 일봉 한 행의 위반도 종목 전체 오류로 바꾸고 상세 날짜를 버린다.
- `hoga/api/screener_scan.py`: 가격·거래량·거래대금 조건이 공통 `adj`의 OHLCV에 의존한다.
- `hoga/api/screener_history_coverage.py`: 종목이 factor 파일에 있는지를 보정 증거로 삼는다. 날짜별 이벤트 검증 범위를 표현하지 못한다.

2026-10-21 보고서는 검사 988종목, 실패 987종목, 공급자 이력 미확인 1종목, 보충 0행이다. 오류는 거래량 불일치 896, 가격 불일치 12, 공급자 행 오류 72, 기존 수정값 충돌 6, 기존 범위 미충족 1이다.

2026-10-24 읽기 전용 재조회에서 공급자 수정일·수정비율을 사용한 세 표본의 거래량 불일치는 모두 0이었다. 반면 기존 알고리즘은 각각 37/37, 20/254, 577/600행의 거래량이 달랐다. 동원개발은 1996-09-18의 OHLC 불일치 한 행이 종목 전체 보충을 막았다. 이는 당시 987종목 전체의 동일 원인이나 복구 성공을 증명하지 않는다.

**수정비율과 주식 수 변환비율은 구별한다.** 위 표본 검증은 공급자 수정 가격·거래량의 재현 검증이다. `upd_rt`만으로 무상증자 비율이나 분할 비율을 확인한 것이 아니다. 표본의 `upd_stkpc_tp=4/256`도 검증 없이 사건 종류나 수량비율에 매핑하지 않는다.

관련 기존 결정:

- [ADR-0057 — factor store](../adr/0057-screener-kis-authoritative-factor-store.md): **본 제안은 종가 비율 단일 계수로 가격과 거래량을 함께 파생하는 부분을 대체한다.** 이미 수신한 공급자 수정 OHLCV 관측값도 보존한다. 원주가 보존과 재사용 가능한 파생 데이터라는 목적은 유지한다.
- [ADR-0136 — 키움 전환](../adr/0136-kis-removal-kiwoom-full-replacement.md): 국내 소스·수집 거버너 분담을 유지한다. ADR-0057의 과거 KIS 표기를 현재 소스로 오해하지 않는다.
- [ADR-0055 — 당일/기간내 조건](../adr/0055-today-breakout-distinct-condition-type.md): 두 조건의 독립 타입·판정식 공유·동률 인정은 유지한다.
- [날짜 범위 신고거래량 설계](2026-09-09-screener-historical-volume.md): **신규 정책은 ‘공급자 수정 거래량과 일치해야만 신고거래량 이력이 완전하다’는 규칙을 대체한다.** 공급자 대조와 주식 수 보정 검증을 분리한다. 기존 정책에서는 기존 규칙을 유지한다.
- CONTEXT의 원주가 아카이브·보충 시 기존 값 보존 계약은 유지한다. 신규 파생 버전의 재보정까지 금지하는 뜻으로 확대하지 않는다. 구현 PR에서 용어·문서를 함께 개정한다.

이 문서는 승인된 새 ADR이 아니다. 구현 단계에서 관련 ADR의 변경안을 제시하며, 새 ADR 번호는 당시 열린 PR까지 확인해 정한다.

## 3. 가격·거래량·거래대금의 정확한 의미

### 3.1 가격

- `price_basis=vendor_adjusted`: `adjusted_as_of`를 명시한 공급자 수정 OHLC를 사용한다. 원본 응답·공급자·venue·통화·관측 시각·기준일·검증 범위를 함께 기록한다.
- 이미 수신한 수정 가격을 버리고 반올림된 종가에서 전 필드를 재구성하지 않는다. 수정 이벤트 기반 로컬 파생은 검증된 구간에서만 캐시로 허용하고, 해당 공급자의 반올림 규칙까지 검증한다.
- 새로운 수정 이벤트 또는 공급자 정정으로 과거 가격이 달라지면 새 버전이다. 이전 버전을 덮어쓰지 않는다.
- W/M은 같은 일봉 버전에서 첫 시가·최고 고가·최저 저가·마지막 종가를 집계한다. 서로 다른 기준일의 페이지·종목별 응답을 하나의 검증 완료 시계열처럼 섞지 않는다.
- 현재 차트용 `past-daily-candles`는 메모리 캐시 경로다. 스크리너 파일로 일괄 치환하지 않고, 같은 가격 정책·기준일 계약을 공유한다. 결과에서 차트를 열 때 해당 계산 기준을 전달하며, 그 버전을 차트가 지원하지 않으면 ‘현재 기준 차트’임을 표시한다.

### 3.2 신규 D/W/M 신고거래량

신규 생성 조건의 기본은 `volume_basis=share_adjusted`, 선택지는 `share_adjusted | raw` 두 개다. 기존 방식은 이전 저장 조건의 호환용이며 신규 조건의 선택지를 불필요하게 늘리지 않는다.

| 이벤트 | 주식 수 단위 보정 | 필요한 증거 |
|---|---|---|
| 액면분할 1주→5주 | 효력일 전 거래량 ×5 | 명시된 변환비율과 효력일 |
| 주식병합 5주→1주 | 효력일 전 거래량 ÷5 | 명시된 변환비율과 효력일 |
| 기존 보유자에게 비례 배정되는 무상증자·주식배당 | 확인된 배정비율로 보정 | 동일 종목의 주식 수 변환비율·적용일 |
| 현금배당·ETF 현금 분배금 | 보정하지 않음 | 이벤트 분류 확인 |
| 유상증자·전환·합병·분할상장·종목 정체성 변경 | 첫 버전에서 자동 연결하지 않음 | 명시적 연속성·수량비율 정책이 마련되기 전 해당 비교 구간은 보류 |
| 종류·비율·적용일 미확인 | 1이나 가격계수로 추정하지 않음 | 보정 이력 부족으로 표시 |

이벤트 가격 조정률은 수량비율 증거를 대신할 수 없다. `upd_rt=-49.39`를 보고 `1/0.5061`을 주식 수 증가배수로 간주하지 않는다. 공급자가 명시한 수량 이벤트 또는 거래소·발행사 공시에서 확인한 수량비율을 원문 출처와 함께 사용한다. 수량 이벤트의 검증된 수집 경로는 운영 전환의 필수 선행 작업이다.

평가일 `d`, 비교일 `t≤d`에 대해:

```text
Q(t,d) = t < 효력일 ≤ d 인 검증된 수량 이벤트의 ‘신주수 / 구주수’ 곱
보정 거래량 V(t;d) = 원본 거래량(t) × Q(t,d)
신고 조건 = V(d;d) > 0 이고 V(d;d) ≥ 비교 창의 최대 V(t;d)
```

- 기존처럼 당일 포함 M봉, 동률 인정, 완전한 비교 창을 사용한다. 거래일·달력 연수 경계는 기존 계약을 유지한다. 신규 정책은 최근 방식에서도 0만 있는 창을 신고로 인정하지 않는다.
- 각 후보 발생일의 단위로 비교하므로 그 발생일 이후의 수량 이벤트를 미리 적용하지 않는다. 이후 알려진 정정 사실을 반영하는지 여부는 스냅샷의 관측 시각으로 구별한다.
- 수량비율은 정수 분자/분모로 보존한다. 비교 중 주 단위 정수로 반올림하지 않는다. 병합에서 생긴 분수 수량은 유리수/고정 정밀도로 비교하고, 표시에서만 반올림한다. 범위를 넘어서는 정밀도·오버플로는 보류한다.
- 이벤트 목록이 비었다는 것만으로 `Q=1`을 증명하지 않는다. **요청 구간의 이벤트 조회가 검증 완료**된 경우에만 ‘이벤트 없음’으로 인정한다.
- D/W/M의 완성 봉과 진행 중 봉에 같은 수량 정책을 적용한다. W/M은 구성 일봉을 후보 봉의 평가 기준일 단위로 바꾼 뒤 합산한다. 무보정 주봉을 합산한 후 단일 계수를 곱하지 않는다.
- 진행 중 W/M의 평가 기준일은 마지막 실제 관측 거래일이며 주말·월말의 미래 날짜가 아니다. 동일 주 안에 수량 이벤트가 있으면 이벤트 전 일봉만 보정한다.
- `raw`는 실제 수신 수량을 비교한다. 분할을 경계로 거래 단위가 다를 수 있다는 의미를 도움말에 적는다. 보정 이력 부족으로 `share_adjusted`가 불가능해도 자동으로 `raw`로 바꾸지 않는다.

예: 분할 전 100주, 분할 후 400주, 1→5 분할이면 100주는 현재 단위 500주다. 따라서 실제 거래량 기준에서는 400주가 신고지만 수량 보정 기준에서는 신고가 아니다. 현금배당만 생긴 경우 100주는 그대로 100주다.

### 3.3 분봉과 장중 오버레이

- 분봉 신고거래량은 기존 원본 거래량을 유지한다. D/W/M 선택값을 분봉에 복사하지 않는다. 명시적으로 `share_adjusted` 분봉을 요청하면 422로 지원 범위를 알린다. 필드가 없는 기존 분봉 요청은 계속 원본 기준이다.
- 일봉의 오늘 원본 누적량은 오늘 기준 수량이므로 오늘 수량배수는 1이다. 과거 비교 일봉을 같은 기준으로 환산한다.
- WS 누적량·REST 보정·하한 표시·조회 실패 시 확정 데이터 대체는 기존 계약을 유지한다. 장중 관측 시각·공급자·venue가 다른 값을 보정 기준 변경으로 위장해 섞지 않는다.
- 장중 가격 오버레이도 과거 가격과 같은 수정 기준일이어야 한다. 오늘 효력 이벤트를 확인하지 못하면 과거 계수 1로 추측하지 않고 해당 조건을 보류한다.

### 3.4 거래대금

신규 정책에서는 가격 표시 기준과 독립된 `trade_value_won`을 사용한다.

1. 해당 종목·일자·venue의 검증된 공급자 실제 거래대금이 있으면 사용한다. 단위와 수정 여부를 공급자별로 검증한다.
2. 없으면 원주가 OHLC 평균 × 원본 거래량을 **추정 거래대금**으로 계산한다.
3. W/M은 같은 방법의 일별 금액을 합산하고, 실제치·추정치 혼합 여부를 응답한다. 집계 OHLC × 합산 거래량으로 재추정하지 않는다.

가격을 수정했다고 거래대금도 함께 바꾸거나, 금액을 보존하려고 거래량을 인위적으로 바꾸지 않는다. 기존 거래대금 조건의 계산 결과는 `legacy_v1`에서 유지한다.

## 4. 기존 데이터 보존과 새 저장 구조

### 4.1 최초 이관

- 기존 세 파일 `daily_unadjusted.parquet`, `daily_adjusted.parquet`, `factors.parquet`과 관련 status/evidence/saves/exclusions를 하나의 일관된 **baseline**으로 백업한다. 파일 해시·행 수·종목 수·날짜 범위·프로그램 버전을 기록한다.
- 기존 writer와 같은 잠금으로 일관된 묶음을 확보한다. 복사 실패·공간 부족·검증 실패 시 이관 완료 표식을 만들지 않는다. inode를 공유하는 가변 하드링크를 백업의 유일한 수단으로 사용하지 않는다.
- 기존 값은 ‘legacy import’ 관측이다. KIS·키움·과거 시드의 출처가 구분되지 않으면 `source=legacy_unknown`으로 남긴다. 기존 파일 전체를 ‘키움 검증 완료’로 재라벨링하지 않는다.
- 기존 수정 가격에서 나눗셈으로 원주가·수량 이벤트를 복원하지 않는다. 기존 원주가 관측은 보존하고, 공급자와 다르면 새 정정 후보 관측으로 보관한다.

### 4.2 논리 저장소

```text
screener/
  legacy/<baseline_id>/       # 기존 파일·저장 조건·검증 지문, 읽기 전용
  observations/              # 원주가·공급자 수정 OHLCV·거래대금, 변경 이력 포함
  actions/                   # 가격 이벤트·수량 이벤트와 검증 범위, 개정 이력
  objects/<content_hash>/    # 종목 단위의 불변 데이터 조각·파생 조각
  snapshots/<snapshot_id>/manifest.json
  current.json               # 완성된 신규 스냅샷을 가리키는 원자적 포인터
```

- 물리 데이터는 매 버전마다 전 코퍼스를 복제하지 않는다. manifest가 변경되지 않은 조각을 재사용한다. 초기 baseline 파일 참조와 이후 종목별 조각을 병합하는 읽기 어댑터를 둔다. 스캔용 묶음 파일은 재생성 가능한 캐시다.
- 관측 식별에는 종목 코드뿐 아니라 instrument 정체성·공급자·시장/venue·통화·거래일·기준일·수신 시각을 포함한다. 종목코드 재사용·합병 전후를 자동 연결하지 않는다.
- 공급자 수정 OHLCV는 `vendor_adjusted` 관측으로 보존한다. 여기에 기록된 거래량을 `share_adjusted`라고 이름만 바꾸지 않는다.
- 가격 이벤트에는 공급자 원래 종류/비율 문자열·효력일·관측 시각·출처·검증 결과를 보존한다. 수량 이벤트에는 별도의 정수 비율·확인 출처·연속성 판정을 둔다. 충돌하는 관측은 삭제하지 않고 판정 기록으로 해결한다.
- manifest에는 원본 버전, 이벤트 버전, 계산 정책 버전, 가격 기준일, 구간별 검증 상태, 달력 버전, 파일 해시와 부모 스냅샷을 담는다. 파생값 변경은 새 manifest와 새 조각으로 공개한다.
- 읽는 쪽은 scan 시작에 스냅샷을 한 번 고르고 결과·커버리지 계산이 끝날 때까지 고정한다. 서로 다른 세대의 가격·거래량·이벤트를 읽지 않는다.
- 한동안 legacy writer와 신규 수집이 공존한다. legacy 공개 완료 후의 일관된 묶음을 어댑터로 가져오되, 신규 writer가 기존 파일을 덮어쓰지 않는다. 읽기 기본 경로도 활성화 전에는 바꾸지 않는다.
- 명시적으로 보존한 결과가 참조하는 스냅샷과 baseline은 회수하지 않는다. 임시 결과가 참조하는 버전도 수명 동안 유지한다. 보존기간·사용량 상한·명시적 정리 기능을 정하기 전 자동 GC는 활성화하지 않는다. 공간 부족 시 신규 작성을 중지하고 마지막 완성 버전을 유지한다.

### 4.3 보충·정정·재보정의 분리

| 작업 | 기존 관측값 | 결과 |
|---|---|---|
| 누락 보충 | 동일 키가 있으면 변경하지 않음 | 없는 날짜의 검증된 관측만 새 버전에 추가 |
| 공급자 정정 반영 | 이전 관측을 보존 | 전후 값·이유·출처가 있는 새 관측 버전 |
| 수정 기준 갱신 | 원본 관측을 변경하지 않음 | 새 이벤트/기준일로 파생한 새 버전 |

새 수정 이벤트가 검증됐다면 신규 파생값이 옛 수정값과 다르다는 이유만으로 실패하지 않는다. 대신 변경 범위·종목·검색 결과 차이를 기록한다. 자동화된 정상 이벤트 갱신도 기존 스냅샷을 보존한다. 공급자 정정은 보충 버튼이 몰래 승인하지 않고 별도 차이 검토 대상으로 남긴다.

## 5. 요청·저장 조건·결과 계약

### 5.1 정책 선택과 하위호환

요청 루트에 `calculation_policy: legacy_v1 | separate_bases_v2`를 둔다. 부재는 `legacy_v1`이다. 기존 `basis=eod/auto/intraday`는 시점 선택이므로 이름·의미를 그대로 유지한다.

신규 화면이 만드는 요청과 신규 저장 조건에는 `separate_bases_v2`를 명시한다. 기존 저장 조건을 불러오면 ‘기존 계산 기준’으로 표시하고, 사용자 동작 ‘새 기준으로 복사’가 새로운 조건검색 사본을 만든다. 기존 id·조건·발생 제외는 덮어쓰지 않는다. 이전 화면의 미저장 빌더도 필드가 없으면 기존 정책이다.

```json
{
  "calculation_policy": "separate_bases_v2",
  "basis": "auto",
  "conditions": [{
    "id": "volume-1",
    "type": "new_high_vol",
    "params": {
      "timeframe": "D", "include_open_bar": true,
      "lookback": 60, "period": 250,
      "volume_basis": "share_adjusted"
    }
  }]
}
```

- `volume_basis`는 신고거래량의 최근/날짜/당일 파라미터 모두에 추가한다. 현재 공유 `PeriodParams`를 직접 확장해서 신고가까지 수량 옵션을 노출하지 않는다.
- v2에서 필드가 없는 D/W/M 신고거래량은 `share_adjusted`, 분봉은 `raw`로 해석한다. FE는 신규 저장 시 해석 결과를 명시한다. legacy에서 필드가 없으면 D/W/M은 기존 수정 거래량, 분봉은 기존 원본이다.
- `legacy_v1`에 신규 명시 기준을 섞은 요청은 422로 거절한다. 의미 변경은 정책과 조건을 함께 전환한다. 미지원 조합 오류와 데이터 부족에 따른 unknown은 구별한다.
- 기존 서버는 `extra=forbid` 파라미터를 사용한다. 새 필드를 구서버에 보내 조용히 동작한다고 가정하지 않는다. 기능 지원 조회 후 FE를 활성화하고 BE/FE/wire 미러를 함께 배포한다.
- 기존 저장 파일의 schema를 덮어쓴 뒤 구서버로 되돌아가는 롤백을 금지한다. 새 형식 저장은 별도 파일/버전으로 관리하고, 구서버는 보존된 기존 저장소를 사용한다. v2에서 만든 조건은 롤백 중 숨겨지더라도 원본 파일을 삭제하지 않는다.

### 5.2 결과와 재현성

응답에는 `calculation_policy`, `snapshot_id`, `price_basis`, `adjusted_as_of`, `event_revision`, 실제 평가 시각을 담고, leaf별 증거에 해석된 `volume_basis`, 원본 거래량, 비교에 사용한 보정량·최대값·단위·보정 적용 구간을 포함한다. 서로 다른 leaf가 다른 수량 기준이면 하나의 전역 `volume`로 설명하지 않는다.

- ‘저장된 조건검색’은 질문이다. 다시 실행하면 선택한 정책의 최신 데이터로 평가한다.
- ‘저장 결과/실행 기록’은 당시 답이다. 계산 정책·스냅샷·조건 원문·실제 대상 종목 집합·달력/마스터 버전·발생 제외 버전·평가 코드 버전과 결과를 보존한다. 질문과 답을 자동으로 같은 방식으로 갱신하지 않는다.
- 현재 우측 패널의 `lastScan`은 유효기간이 있는 화면 캐시다. 이를 영구 재현 가능한 실행 기록이라고 부르지 않는다. 명시적 저장 결과가 있을 때만 버전 보존을 보장한다.
- 장중/분봉 실행은 실제로 사용한 오버레이·관측 cutoff까지 보관해야 정확히 재현할 수 있다. 이번 첫 구현은 확정 일봉 결과의 재현부터 제공한다. 장중 저장 결과는 당시 답과 관측 시각을 보존하되, 입력 오버레이가 없으면 ‘정확 재실행 미지원’으로 표시한다. 모든 모니터 틱을 영구 저장하지 않는다.
- 과거 스냅샷이 없는 기존 결과를 이번 이관으로 완전 재현 가능해졌다고 표시하지 않는다. 기준일을 지정했다고 당시까지 알려진 정보만 사용한 백테스트가 되는 것도 아니다. 관측 이력·당시 유니버스가 없는 과거는 point-in-time 재현 범위 밖이다.

### 5.3 발생 제외·캐시

현재 `screener_exclusions.condition_key`는 params를 해시한다. 새 필드의 기본값이 생겼다는 이유로 옛 해시가 바뀌면 안 된다.

- legacy의 부재/동일 의미 기본값은 해시 직전에 기존 형식으로 정규화한다. 기존 제외 id·해시 fixture를 유지한다.
- v2 키는 계산 정책과 해석된 수량 기준을 포함한다. 실제량의 제외를 수량 보정량 결과에 자동 적용하지 않는다.
- snapshot id는 조건의 의미가 아니므로 제외 키에 넣지 않는다. 스냅샷/이벤트/달력/오버레이 버전은 **평가 캐시 키**에 넣는다. 발생일·분봉 시작 시각의 기존 식별 계약은 유지한다.
- 새 기준으로 복사할 때 기존 제외는 기본적으로 복사하지 않는다. 기존 제외를 보존한 원본은 그대로 남는다.

## 6. 오류·커버리지·공개 절차

검증은 `(종목, 시계열 기준, 날짜 구간)`별이다. 가격이 준비됐다는 이유로 수량 이력까지 완전하다고 판정하지 않는다.

| 상태 | 처리 |
|---|---|
| 누락 일봉 | 해당 비교 창 unknown. 보충 가능 범위 표시 |
| 공급자 OHLC 오류 | 원문·날짜를 격리. 그 날짜를 필요로 하는 창만 보류 |
| 가격 이벤트 미확인 | 수정 가격이 필요한 창만 보류 |
| 수량 이벤트·검증 범위 미확인 | `share_adjusted` 창만 보류. `raw`는 원본 이력이 충분하면 평가 가능 |
| 이벤트 종류 미지원/비율 충돌 | 그 경계를 건너는 창만 보류 |
| 공급자 이력 미제공 | 조회 범위·관측일·재확인 시점을 기록. 상장 전/정지라고 추정하지 않음 |
| 기존 관측과 공급자 정정 충돌 | 기존 값 유지, 별도 정정 후보. 누락 보충 성공분과 분리 집계 |

원본 자체의 오류는 raw에도 영향을 준다. 반대로 단순 수량 이벤트 미확인이 가격까지 막아서는 안 된다. 요청 구간과 관계없는 1996년 행의 오류로 2026년 원본 거래량 비교를 막지 않는다. 오래된 이벤트의 인자가 현재 보정 구간에 실제로 필요하면 그 의존성은 보류한다.

수집 → 불변 관측/이벤트 조각 저장 → 후보 manifest 파생·검증 → 공유 writer 잠금에서 부모 버전 확인 → current 포인터 원자 교체 순서다. 네트워크 동안 writer 잠금을 잡지 않는다. 부모가 바뀌면 최신 관측 위에 멱등 병합하고 다시 검증한다. 실패한 후보는 공개하지 않고 마지막 완성 버전을 계속 읽는다. 파일·manifest fsync 및 journal 복구를 검증하며 디스크 전원 장애 전체를 무조건 복구한다고 주장하지 않는다.

동시 일일 갱신·과거 보충·CLI·이벤트 갱신 모두 같은 writer 조정에 참여한다. 각 작업의 취소·재개는 불변 조각과 체크포인트를 사용하고, 이미 완료된 부분은 재조회하지 않는다. 수집은 기존 프로덕션 클라이언트·페이지별 background 거버너를 사용하며 별도 인증 프로세스를 만들지 않는다.

화면은 종목별 상호 배타적인 완료/부분 완료/보류 수를 표시하고, 가격 오류·수량 오류·공급자 행 오류 등 중복 가능한 세부 사유는 별도로 표시한다. 일봉 ‘추가 행’은 `(종목, 날짜)`로 세며 관측 버전 수나 바뀐 파생 행 수를 보충 개수에 더하지 않는다. last_refresh에는 완료 시각·대상 범위·정책·데이터 버전을 표시한다.

## 7. 단계별 전환과 롤백

1. **기준선 확보:** 기존 파일·저장 조건·제외·결과를 백업하고 지문 기록. 신규 수집/정정은 실행하지 않는다. legacy 요청·결과·제외 해시 회귀 fixture 확보.
2. **관측 보존·진단 보강:** 수신 중인 가격 이벤트 필드와 실패 날짜/실제값을 버리지 않게 한다. 수량 이벤트 소스·종류 매핑·비율·검증 범위를 검증한다. 이 단계만으로 주식 수 보정 지원 완료를 선언하지 않는다.
3. **별도 계산·저장 경로:** v2 manifest와 가격/거래량/거래대금 resolver 구현. 기존 값을 읽어 만드는 별도 데이터 디렉터리에서 검증. legacy 기본 경로 유지.
4. **병행 평가:** 동일 유니버스·거래일에서 기존/신규 결과를 나란히 계산한다. 차이는 정상 수량 정책 변경·계산 오류 수정·이력 부족·원인 미확인으로 분류한다. 원인 미확인 차이가 남은 종목/구간은 활성화하지 않는다.
5. **신규 조건 활성화:** 검증된 지원 범위에서 신규 FE가 v2를 명시. 기존 저장 조건은 유지하고 사본 전환 제공. 가격/수량 기준을 결과·차트에 전달한다. 수량 이력이 부족하면 결과를 늘려 보이게 하는 폴백 대신 부족 사유를 보여준다.
6. **운영 보충:** 기존 988종목을 새 정책으로 다시 계획한다. 전 종목을 즉시 다시 받지 않고 캐시·검증 이벤트·기존 일봉을 재사용해 필요한 구간부터 보충한다. 무제한 재시도·매 클릭 전 역사 조회는 금지한다.

롤백은 FE 신규 기능을 비활성화하고 legacy reader/보존된 저장소로 되돌린다. 새 관측·v2 조건·결과는 보존한다. 구버전 프로그램이 v2 파일을 열어 격리·초기화하지 않도록 경로를 분리한다. legacy 경로를 제거하거나 데이터 버전을 회수하는 일은 이 설계의 최초 전환에 포함하지 않는다.

## 8. 검증과 완료 기준

| 검증 | 통과 조건 |
|---|---|
| 기존 데이터 보존 | baseline 해시 동일. 보충 전후 기존 관측 변경 0. 정정 후보와 새 파생 버전만 추가 |
| 작은 이벤트 | -0.05%/-0.24%를 정확한 효력일에서 가격에 반영. 새 수량 기준에는 현금 이벤트 영향 0 |
| 분할·병합·무상증자 | 검증된 수량비율·효력일로 앞선 일봉을 환산. 분수·동률·연속 이벤트·정정·동일일 다중 이벤트 검증 |
| 미래 정보 경계 | 후보일 뒤 수량 이벤트 추가가 당시 수량 단위 판정을 바꾸지 않음. 당시 미관측 정보 재현의 한계 표시 |
| 원본/보정량 분리 | 1→5 분할 예제에서 raw=신고, share_adjusted=미신고. 현금배당만으로 둘의 수량이 달라지지 않음 |
| 공급자 대조 | vendor 가격·수정량 재현을 가격/대조 검증으로 기록. share_adjusted와 vendor 수정량이 달라도 정책상 정상인 경우를 허용 |
| 정밀도 | 가격 반올림 규칙 검증. 수량 판정 전 반올림 0회. 거래량 정확 일치를 느슨한 비율 허용으로 우회하지 않음 |
| 구간 격리 | 1996년 불량 행이 무관한 2026년 창을 막지 않으며, 불량 행이 필요한 창은 완전으로 표시하지 않음 |
| W/M·장중 | 이벤트가 주중에 생겨도 일봉별 환산 후 합산. 진행 중 포함/하한/REST 정정 및 실패 시점 계약 유지 |
| 거래대금 | 공급자 실제치/원주가 추정치 구분. 배당 가격 조정으로 수량·금액을 상호 보정하지 않음 |
| 저장 조건·제외 | 옛 요청과 저장 조건의 legacy 해석·해시 동일. 복사한 v2는 새 의미의 키. 원본 id·제외·결과 보존 |
| 버전 일관성 | 동시 writer·취소·디스크 부족·프로세스 종료에도 scan이 세대를 섞지 않음. 실패 후보 미공개 |
| 재현성 | 보존된 확정 일봉 실행의 입력·유니버스·정책·코드 버전으로 같은 결과. 스냅샷 없는 기존/장중 결과의 한계를 표시 |
| 성능·공간 | 운영 규모 표본의 소요시간·최대 메모리·추가 저장량 측정. 매 갱신 전 코퍼스 영구 복제 없음. 이벤트 루프에서 대형 동기 I/O 없음 |

구현 PR에서는 BE Pydantic 모델·FE 손수 미러·Literal enum·실제 HTTP 직렬화·wire 계약 검사를 함께 갱신한다. 관련 단위/통합 검사와 FE 타입·빌드, 새 조건 저장·전환·결과·차트 표시 E2E를 실행한다. 검증 환경에는 자격증명을 주입하지 않는다. 이번 문서 작성 단계에서 운영 보충이나 데이터 마이그레이션을 테스트 명목으로 실행하지 않는다.

구현 대상은 기존 `screener_factors`, `screener_history_*`, `screener_scan/runner`, `screener_intraday`, `screener_bar_*`, `screener_exclusions`, 저장 조건 모델·FE 조건 폼/요약·결과·차트 연결이다. 신규 모듈은 관측/이벤트 저장, 정책별 값 선택, 스냅샷 공개의 세 책임으로 나눈다. 커버리지·실제 scan·수집 preview가 같은 정책 resolver를 사용해야 한다.

완료는 ‘실패 수가 줄어듦’이 아니다. **기존 관측과 조건의 의미가 보존되고, 사용자가 선택한 수량 기준으로 재현 가능한 신고 판정을 하며, 부족한 구간을 숨기지 않는 것**이다.
