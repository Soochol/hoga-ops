# 체결 창의 분봉·초봉 커서 연동 검토안

작성: 2026-10-25 KST
검토 기준: `cf51438a22c5ebf483c6c563467fa56ef475487c`
상태: 사용자 승인 후 구현 완료. 검증 결과는 9절과 검증 기록을 참조한다.
운영 서버·저장 정책은 변경하지 않았다. 아래 1~8절은 승인된 설계와 사전 검토 기록이다.

## 1. 추천 결정

기존 체결 창에 **최신 모드 / 선택 봉 구간 모드**를 둔다. 기존 차트의 커서 연동
스위치와 상단 `KRX에서 hogaplay 우선` 설정을 그대로 사용한다.

- 최신 모드: 현재 체결 창의 당일 상세 체결 조회 + WS 꼬리와 스크롤을 유지한다.
- 선택 봉 모드: 별도 읽기 API로 `[봉 시작, 다음 봉 시작)` 안의 데이터를 조회한다.
- hogaplay: 저장된 원본 체결 한 건을 표의 한 행으로 표시한다.
- 프로젝트 WS: `second_trades`의 1초·가격·방향별 합산량과 관측 건수를 표시한다.
  당일과 과거에 같은 표현을 사용한다. 최근 WS 버퍼 유무에 따라 원본/집계가 바뀌지 않는다.
- 기존 10초 WS 집계는 선택 봉 모드의 대체 원천으로 사용하지 않는다.
- WS 원본 틱을 전량 영구 저장하는 변경은 이 기능에 필요하지 않다.

이는 **개별 틱 조회와 1초 집계 조회를 구분하는 설계**다. 프로젝트 WS 과거분을
개별 틱으로 복원한다는 약속은 하지 않는다. 모든 구간에서 개별 체결만 필요하다면
별도 원본 틱 저장 설계와 용량·부하 검증이 선행되어야 한다.

## 2. 코드와 재현 실험으로 확인한 사실

| 대상 | 확인 내용 | 설계에 미치는 영향 |
|---|---|---|
| `TradeWindow.tsx` | 현재 날짜로 `useTradeHistory`를 호출하고 WS 수신분을 이어 붙임 | 기존 목록을 커서로 필터링하는 것만으로 과거일·미조회 구간을 지원할 수 없음 |
| `trade_history_api.py` | `ka10003`은 날짜 입력이 없어서 당일 외 요청을 거절 | 과거 커서 이동을 공급사 상세 내역 연속조회로 해결하지 않음 |
| `trades.py` | hogaplay 원본의 시각·seq·가격·수량·방향·누적량 보존 | 원본 틱의 범위 조회와 안정적인 페이지네이션 가능 |
| `stream.py` | 원본 틱 표시와 저장 집계를 분리 | 화면에 틱이 보인다는 사실이 원본 영구 저장의 증거는 아님 |
| `second_trade_agg.py` | 같은 초·가격·방향의 수량과 건수를 합침 | 1초 경계 조회는 가능하지만 개별 수량과 체결 순서는 복원 불가 |
| `downsampler.py` | flush 구간의 수량을 가격·방향별로 합치고 구간 라벨만 저장 | 10초 경계뿐 아니라 분 경계를 걸친 실제 체결도 분리 불가 |
| `second_trade_api.py` | `source_pref` 입력이 없고 하루 WS 집계가 있으면 hogaplay를 조회하지 않음 | 체결 창에 이 API를 그대로 연결하면 상단 설정을 지키지 못함 |

임시 Parquet과 실제 ASGI 라우터로 다음을 재현했다. 운영 데이터·증권사 연결은 쓰지 않았다.

1. 같은 날짜에 hogaplay 가격 100과 WS 가격 200을 준비하고 기존
   `/api/live/second-aggregates?...&source_pref=hogaplay` 요청:
   HTTP 200이지만 `source=second_trades`, 가격 200을 반환했다.
   미선언 쿼리 파라미터가 무시되므로 URL에 설정만 붙여서는 해결되지 않는다.
2. hogaplay는 09:00, WS는 09:10에만 있는 상태에서 09:00~09:01을 요청:
   `source=second_trades`, `status=unavailable`, 빈 봉 목록을 반환했다.
   이는 기존 API가 일 단위 WS 존재로 원천을 고른다는 증거다.
3. 같은 가격·방향에 수량 `2+8`과 `5+5`를 같은 두 시각·순번으로 입력:
   저장된 1초 레코드가 완전히 동일했다. 개별 6주 이상 체결은 전자에만 있지만
   집계에서는 이를 구분할 수 없다. 개별 체결금액 필터도 같은 제약을 받는다.
4. 09:00:59의 2주와 09:01:01의 3주를 입력하고
   09:00:55~09:01:05 flush를 수행: 09:00:55 라벨에 5주가 저장됐다.
   원래 09:00분의 수량은 2주다. 기존 10초 저장분은 분봉에서도 정확한 경계 조회를
   보장하지 못한다. 단순히 10초 이상의 차트에 허용하는 방식은 채택하지 않는다.
5. hogaplay만 있는 날짜의 NXT·UN 요청은 unavailable이었다. 시장 격리는 유지해야 한다.

## 3. 소스 선택

`ordered_sources(source_pref)`와 `source_covers_venue`를 재사용한다.
`useOrderflowSourcePref()`가 설정을 읽기 전에는 조회하지 않는다.

| 유효 시장과 설정 | 우선순위 |
|---|---|
| KRX, hogaplay 우선 켜짐 | hogaplay 원본 → 프로젝트 WS 1초 집계 |
| KRX, hogaplay 우선 꺼짐 | 프로젝트 WS 1초 집계 → hogaplay 원본 |
| NXT·UN | 해당 시장의 프로젝트 WS 1초 집계 |

우선순위와 **그 차원에 사용할 수 있는 데이터가 있는지**를 분리한다(ADR-0121).
호가 파티션의 건강 상태만 보고 상세 체결 지원을 판정하지 않는다. WS 1초 저장분은
`second_trades`에 별도로 있으므로 `kiwoom_live/trades.parquet`의 존재가 필요조건이 아니다.
응답의 source는 `hogaplay | kiwoom_live`이고, 저장 형식은 별도 representation이다.

처음에는 종목·거래일·유효 시장·설정별로 사용 가능한 원천 하나를 고정한다.
선호 원천이 없거나 이 기능의 해상도를 지원하지 않을 때 다음 후보를 고른다.
커서 봉의 행 수가 0이라는 이유로 다른 원천으로 바꾸지 않는다. 무거래·미관측·미수집을
현재 메타데이터만으로 항상 구분할 수 없기 때문이다. 설정으로 고른 원천의 공백을
다른 원천으로 봉마다 메우거나 두 원천의 수량을 더하지 않는다.

파일 손상·읽기 실패는 정상적인 소스 부재로 처리하지 않고 오류와 재시도를 제공한다.
완결성 등급으로 우선순위를 다시 정렬하지 않는다. 실제 선택한 소스와 조회 품질을 표시한다.

## 4. 조회 API와 모듈 경계

제안: 새 `GET /api/trades/spot` 경로. 삭제된 옛 `/api/trades?t=&limit=`와
현재 당일 공급사 조회 `/api/live/trades/history`의 의미를 섞지 않는다.

입력: `code`, `date`, `venue`, `source_pref`, `from_ms`, `to_ms`,
페이지 크기(기본 200, 서버 상한), 다음 페이지 커서. 두 경계는 같은 KST 날짜 안에 두고
`from_ms < to_ms`를 검증한다. 범위 조회는 정수 1초 경계를 지원한다.

응답 계약은 Pydantic과 FE 미러를 함께 정의한다.

- 요청 식별: Code·날짜·시장·구간·적용한 source preference.
- 실제 `source`, `representation=ticks | second_price_aggregate`.
- 행: 안정적인 id, 시각, 가격, 수량, 방향, 관측 건수(틱은 1).
- 상태: 조회됨 / 선택 구간 관측 행 없음 / 데이터 미보유 / 해상도 부족.
- coverage는 확인된 범위만 표시. 현재 초 집계처럼 미검증이면 unverified를 유지한다.
- 페이지 커서와 데이터 세대/revision. 전일 종가는 선택일 기준 값이며 오늘 값을 쓰지 않는다.

권장 모듈 책임:

- 소스 선택기: 공통 우선순위 + 시장 필터 + 틱/1초 집계 가용성 판정.
- hogaplay 조회 어댑터: 기존 Parquet을 범위·정렬·limit 조건으로 조회.
  시각 인코딩 변환은 경계에서 한 번만 수행하고, `price > 0`, `qty > 0`인 실제 체결을
  읽는다. 가격 0의 단일가 요약을 체결로 표시하지 않고 유효한 side 0 체결은 보존한다.
- WS 조회 어댑터: `SecondTradeStore`의 디스크 + 진행 중 메모리를 최신 revision으로
  대체 병합한다. 같은 초의 두 revision을 합산하지 않는다. 수집 프로세스 RPC 소유권과
  장애 격리는 ADR-0174를 따른다. 과거일 조회는 수집 프로세스와 독립적으로 처리한다.
- 공통 읽기 서비스: 응답 정규화·페이지네이션·상태만 소유한다.
- FE: `TradeLatestContent`와 `TradeSpotContent`를 분리하고 공통 외형만 공유한다.
  선택 봉 모드가 최신 목록 전체를 계속 재계산하거나 공급사 과거 페이지를 소진하지 않게 한다.

초봉·매물대용 `/second-aggregates`의 우선순위와 응답 의미는 이번에 바꾸지 않는다.
저수준 읽기는 공유하되 체결 창을 위한 전체 틱을 RangeBundle에 넣지 않는다.

## 5. 커서와 화면 계약

- `sidebarCursorMs`와 origin을 사용한다. 그룹뿐 아니라 Code도 일치해야 한다.
  핀으로 다른 종목을 보는 창에 같은 시각을 적용하지 않는다.
- 커서 발행 차트의 실제 봉 주기와 날짜를 쓴다. 현재 날짜로 과거 커서를 조회하지 않는다.
- 차트의 유효 시장도 전달한다. 저장 학습뷰의 KRX 고정을 전역 UN 선택으로 덮지 않는다.
  현재 origin에는 venue가 없으므로 원본 발행 창의 조회 문맥을 추가로 전달해야 한다.
- 발행 중복 제거는 시각만 비교하지 않고 창·그룹·Code·주기·시장도 비교한다.
  같은 시각의 다른 차트로 이동해도 조회 문맥이 바뀌어야 한다.
- 기존 120ms leading/trailing throttle을 재사용하고 별도 debounce를 겹치지 않는다.
- 분봉과 1·5·10·30초봉을 지원한다. 달력 봉은 최신 모드를 유지한다.
- 봉 내부의 원본 틱은 시각·seq 내림차순이다. 같은 값의 반복 체결을 값 해시로 제거하지 않는다.
- 집계 행은 초 내림차순, 같은 초는 가격·방향의 결정적 순서다. 실제 체결 순서라고 표시하지 않는다.
- 원본은 `시각 / 체결가 / 체결량`, 집계는 `시각 / 가격 / 합산량`으로 구분한다.
  합산량에 `2건`처럼 관측 건수를 함께 표시하고 `WS · 1초 집계`를 짧게 표시한다.
- 선택 구간도 보조 글씨로 표시한다. 폰트·테마·행 높이는 기존 디자인을 따른다.
- 개별 체결금액 필터와 대량 체결 강조는 원본 틱에만 적용한다. WS 집계 모드에서는
  설정값을 보존하되 일시 중지 상태와 이유를 표시한다. 합산금액을 개별 체결금액으로
  바꾸어 적용하지 않는다. 합산금액 필터가 필요하면 별도 의미를 가진 기능으로 다룬다.
- 가격은 실제 체결 당시 원주가를 유지한다. 수정주가 차트와 척도가 다를 때 이를 표시한다.
  필터 금액과 강조 판정도 실제 가격×수량으로 계산한다.
- 봉 변경은 처음 200행과 상단으로 초기화한다. 커서 해제는 최신 모드로 돌아간다.
  **순수 hover 상태에서 마우스를 체결창으로 옮기면 최신으로 돌아가므로, 초기 UI는
  봉 안의 최근 200행 미리보기와 추가 행 존재 표시까지 제공한다.** 기존 최신 모드의
  스크롤은 유지한다. 위 API의 추가 페이지 계약은 확장 가능한 읽기 경계이며, hover
  상태에서 사용자가 직접 페이지를 넘길 수 있다고 설명하지 않는다.
- 한 봉의 수천 건을 직접 스크롤하며 읽는 UX가 필요해지면 별도 `선택 봉 고정/최신 복귀`
  동작을 설계해야 한다. 초기에는 기존 10호가와 같은 커서 수명을 유지한다.

## 6. 정확성·캐시·성능

- 범위는 반열린 구간이다. 다음 봉 시작 정각의 체결은 다음 봉 소속이다.
  차트의 기존 버킷·세션 규칙을 사용하고 UI에서 보이는 다음 봉의 시각으로 범위를
  늘리지 않는다. 중간 무거래 봉·휴장 구간을 포함시키는 실수를 막는다.
- 조회 키에는 Code·KST 날짜·유효 시장·주기·시작/끝·설정·필터를 포함한다.
  파일 generation/revision 변경 시 캐시를 무효화한다. 과거일도 hogaplay 재수집 후 갱신된다.
- 새 키로 이동하면 이전 요청은 취소하고 이전 키의 행을 새 구간 아래 표시하지 않는다.
- 과거 페이지는 source·representation·데이터 세대·조회 범위에 묶는다. 중간에 데이터가
  교체되면 처음부터 재조회하게 하여 누락·중복 페이지를 방지한다.
- 진행 중인 봉은 최대 초당 한 번 최신 revision을 읽는다. 사용자가 과거 페이지를 읽는
  동안 목록 세대를 섞지 않고, 새 자료가 있음을 알린 뒤 수용 시 재조회한다.
- 200행 제한은 서버 페이징이다. 개별 체결금액 필터는 limit 전에 적용하고,
  필터 결과가 적다고 하루 전체나 많은 과거 페이지를 자동 조회하지 않는다.
- hogaplay 원본 전체를 커서 이동마다 Python 객체로 펼치지 않는다. 기존 쿼리 워커의
  I/O·연산 경계를 사용한다. 처음에는 기존 1초 읽기 캐시를 재사용하되 일 단위
  cold read 비용을 측정하고 필요할 때만 범위 pushdown을 추가한다.
- 공급사 REST 호출·새 WS 구독·수집 대상 확대·WS 원본 영구 저장은 추가하지 않는다.
- 관측하지 않은 체결, 분실된 시각, 10초 집계의 내부 분배를 만들어내지 않는다.

## 7. 대안 비교

| 방법 | 판단 |
|---|---|
| 현재 체결창 목록을 클라이언트에서 필터 | 당일 미조회 과거와 과거일을 지원하지 못해 제외 |
| 기존 second-aggregates를 그대로 연결 | 설정을 무시하고 hogaplay도 집계하므로 제외 |
| 별도 spot 읽기 + hogaplay 틱 / WS 1초 집계 | 기존 저장을 활용하고 의미를 보존하므로 추천 |
| WS 틱 원본 전량 저장 | 모든 WS 날짜의 개별 체결 분석이 요구될 때 별도 검토 |
| 기존 10초 저장분도 봉에 배분 | 분·초 경계의 원래 시각을 잃어서 제외 |

ADR-0047의 옛 사이드바 FillTape와 `/api/trades` 복원은 하지 않는다.
현재 독립 체결 창에 새 범위 조회를 추가하는 범위다. 기존 1초 집계 설계의
원본 틱 미보존 결정(`2026-09-30-second-trade-aggregation.md`)도 유지한다.

## 10. 후속 승인 구현: 체결창 스크롤 탐색 (2026-10-25)

사용자의 후속 구현 요청으로 §5의 **최초 200행 미리보기만 제공**하는 제한을 확장한다.
기존 일반 호버와 ADR-0044의 분봉 대표 호가 / 초봉 시점 이전 최근 호가 의미는 유지한다.

- `tradeBrowse.ts`는 마지막 차트 선택을 체결창으로 최대 2초 동안 전달하고, 첫 스크롤에
  탐색 소유권을 고정한다. 헤더 아래 첫 온전한 행이 기준 봉이다. 별도의 일시 상태로
  기존 호버 버스를 쓰지 않으며 차트의 합성 재그림이 소유권을 가져가지 못하게 한다.
- 봉당 최대 200행인 서버 페이지를 먼저 소진한다. 마지막 페이지 이후에는 새 응답 필드
  `previous_observed_ms`를 실제 분봉/초봉 버킷으로 해석한다. 같은 날짜의 관측 봉만
  방문하며 원본 금액 필터를 만족하지 않는 틱과 빈 봉은 건너뛴다. WS에서는 기존대로
  개별 금액 필터를 적용하지 않는다. 정규장 필터의 시작·종료 경계도 유지한다.
- `useTradeBrowsePages`는 요청 취소·중복 방지·안정된 초기 구간 키를 사용한다. 뒤쪽
  페이지의 원천/표현 방식 또는 hogaplay 파일 세대 변경은 409로 취급하며 기존 행을 유지한다.
  WS revision은 구간별 값이므로 다른 봉 사이의 revision을 직접 비교하지 않는다. 409 재시작은
  이전 커서를 버리고 첫 봉부터 다시 읽는다. 일반 실패는 같은 페이지를 재시도한다.
- `TradeBrowseContent`는 아래에만 행을 추가하고 TanStack Virtual로 표시 범위를
  제한한다. 로딩·오류 버튼은 스크롤 목록 바깥에 두고 브라우저 자동 앵커를 끄므로
  조회·재시도가 읽던 위치를 이동시키지 않는다. 서버 조회만으로 시간은 이동하지 않는다.
- `TradeBrowseCrosshair`는 실제 존재하는 캔들의 종가에 합성 커서를 그린다. 대상이
  화면 밖이면 논리 범위 폭을 유지하며 최소한 팬한다. 팬을 실제로 그린 다음 프레임에
  십자선을 적용한다. 같은 프레임에서 적용하면 lwc가 저장한 x 좌표를 옆 봉으로
  재해석하는 회귀를 native crosshairMove 시각 검증으로 재현하고 수정했다. 초봉의 일반 64페이지 탐색 예산을
  넘어가거나 큰 공백을 건너도 `loadSecondHistoryAt`이 해당 시각의 240봉 구간 하나를
  읽고 기존 history/viewport writer에 설치한다. 빈 캔들을 만들지 않는다.
- 10호가는 탐색의 봉 시각을 명시적으로 전달받는다. 소스 우선순위는 상단 설정을
  그대로 따르며 다른 그룹·Code의 창은 영향을 받지 않는다. 위로 돌아오면 이미 읽은
  봉을 다시 선택한다. 호가 캐시 적중 시 HTTP 재요청 없이 실제 표시가 복원된다.
- `최신으로`와 실제 차트 포인터 입력, 연동 OFF, 종목/그룹/시장/주기/정규장/금액 필터/
  원천 설정 변경, 원본 차트나 체결창 닫기는 탐색을 종료한다. 상태는 저장하지 않는다.

검증은 신규 `trade-scroll-navigation.spec.ts`의 1·5분 / 1·5·10·30초 실제 스크롤,
현재 봉 페이지 우선, 빈 봉 건너뛰기, 추가 로드 전후 앵커, 위로 복귀, 차트 팬·배율,
실제 10호가 수량 변경, 합성 재그림의 소유권 보존, 그룹 격리, 실패/409 복구,
미조회 과거 초봉 로드와 원천 설정 전환을 포함한다. 최종 결과와 입력 지문은
`docs/diagnostics/2026-10-25-trade-scroll/verification.json`에 기록한다.
