# 조건검색 실행에 일봉 준비 통합

2026-11-01 사용자 요청으로 [실험·제안](../diagnostics/2026-11-01-screener-auto-preparation/README.md)의
자동 준비 경로를 구현했다. 페이지와 드로어에서 `조회`를 누르면 필요한 과거 일봉을
확인하고 부족분을 준비한다. 별도 수집 체크와 `새 기준 일봉 준비` 버튼은 표시하지 않는다.
조건을 편집하거나 저장본을 선택하는 행위만으로 새 수집을 시작하지 않는다.

## 실행과 자료 계약

`POST /api/screener/runs`의 입력은 기존 `ScanRequest`, 응답은 `ScreenerRun`이다.
동일 날짜·요청·종목 범위·달력·수량 근거·정정·제외 문맥의 실행 중 작업은 같은 ID로
합류한다. 완료 후 다시 실행하면 별도 ID를 부여해 이전 결과를 보존한다.
`GET /api/screener/runs/{id}?after_revision=n`은 진행 상태와 변경된 결과만 돌려준다.
기존 `/scan`과 고정 스냅샷 재실행은 읽기 경로를 유지한다.

서버가 실행을 소유한다. 브라우저 연결 해제·조건 변경은 해당 화면의 수신을 중단하고
다른 소비자의 수집을 취소하지 않는다. 이미 시작한 ID만 탭 sessionStorage에 보관한다.
새로고침 시 GET으로 연결하고, 서버가 재시작됐으면 원래 ID·조회 문맥으로 재개한다.
날짜·달력·종목 범위·검증 근거·제외가 바뀌면 기존 실행을 중단 상태로 보존한다.

v2 준비 계획은 실제 조합식에서 참조한 D/W/M 조건의 비교 날짜를 계산한다.
가격·원본 거래량/금액과 검증된 수량 변환 이력은 독립적으로 판단한다. 가격 수집으로
해결할 수 없는 수량 근거 부족은 판정 보류로 남기며 가격을 반복 수집하지 않는다.
AND/OR의 다른 조건을 평가할 수 있으면 그 결과는 유지한다. 정정 승인과 수량 근거를
자동 생성하지 않으며 원본 parquet·기존 계산 정책·저장 조건을 전환하지 않는다.

순위의 날짜·저장 기록·확정 시각 검증을 일봉 준비 전에 수행한다. 저장 순위는 당시의
후보·관측 상한으로 계획하며 이후 일봉을 사용하지 않는다. 실시간 순위는 전체 시장의
원래 순위를 유지한다. 혼합 요청은 새로운 순위와 시세를 평가하는 기존 경로를 사용한다.
순위·분봉·호가 전용 조회는 새 일봉 준비 경로에 넣지 않는다.

legacy 과거 조건은 기존 history 작업의 admission·수집·publisher를 재사용한다.
기존 수동 관리 API와 운영 복구 경로도 유지한다.

## 속도와 장애 복구

- 새 기준 준비는 서버 공용 최대 4종목이다. 기존 governor의 background 우선순위와
  계정별 한도를 지키며 일반 `갱신`의 동시 3종목 예산은 변경하지 않는다.
- 날짜가 바뀌면 필요한 가격을 새 수정 기준일로 재확인한다. 같은 기준일의 재조회는
  완료한 자료를 재사용한다.
- 종목·요청 범위·수정 기준일이 같은 진행 중 수집을 공유한다. 더 넓은 진행 중 범위도
  재사용한다. 실제 공개 페이지의 API·body·연속 커서가 같을 때만 공용 요청을 공유하고,
  독립 재확인 회차는 별도로 요청해 기존 2초 확인 간격을 유지한다.
- 수신 후보를 불변 객체와 영속 체크포인트에 먼저 저장한다. 공개가 실패하면 재실행에서
  검증한 staging을 재사용한다. 첫 공개는 즉시, 뒤의 공개는 최대 8건/250ms로 묶어
  같은 writer lock 안에서 기존 writer의 변경과 합친다. 다른 수정 기준일은 섞지 않는다.
- 전송·유량의 일시 오류는 30분 후 자동 재시도하며 날짜·범위별 최대 2회로 제한한다.
  기다리는 동안 수집 슬롯을 차지하지 않고 다른 종목을 계속 처리한다. 예산은 재시작과
  재조회에도 보존한다. 자격증명 부재는 호출 시도로 차감하지 않는다.
- 준비된 종목의 부분 결과를 먼저 표시하고 약 1초 단위로 갱신한다. 확정 D/W/M 요청은
  새로 준비된 종목만 추가 평가한다. 기존 입력·메타데이터 변경은 전체 평가를 다시 해
  사라진 일치 종목과 limit 밖 후보를 올바르게 반영한다. 실시간 혼합은 기존 전체 평가를
  사용한다. 정렬·limit·제외·관측 기준은 그대로 유지한다.

상태는 평가 완료·준비 중·검증 대기·확인 실패로 구분한다. 일부 자료를 평가하지 못한
검색을 완전 평가의 0건으로 표시하지 않는다. 재시도가 예정되면 KST 시간을 보여주며
모든 남은 작업이 재시도 대기일 때 상태 폴링도 최대 30초 간격으로 줄인다.

## 검증과 적용 범위

HTTP 직렬화, 중복 합류, 무호출 재조회, 부분 결과, staging 장애 복구, 재시작, 예산,
소비자 취소, 날짜 경계, 입력 문맥 변경, 전체 평가 동등성, 순위 원래 모집단·과거 상한과
legacy 정책 보존을 검사한다. 브라우저에서는 조회 한 번·조건 변경·부분 표시·새로고침
후 POST 중복 없이 재연결하는 경로를 검사한다.

명령·입력 지문·도구 버전·실제 결과는
[구현 검증 기록](2026-11-01-screener-auto-preparation-validation.json)에 남긴다.
모의 공급자와 격리 데이터로 수행한 검증이며 실자격증명·운영 수집·사용자 서버 재시작은
포함하지 않는다. 선행 오프라인 비교 수치는 실제 벤더의 종단 간 속도 보장이 아니다.
실제 앱의 응답 시간·호출량·foreground 경합은 적용 후 별도로 관측해야 한다.
